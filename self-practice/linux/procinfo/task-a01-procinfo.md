## Задание

Утилита на C: принимает PID как аргумент командной строки, читает `/proc/<pid>/status`, выводит:
- имя процесса (Name)
- PID
- потребление памяти VmRSS в МБ

Без использования внешних утилит (ps, top и т.д.).

**Функции для использования:**
- `strtoull` — парсинг PID из argv
- `snprintf` — сборка пути `/proc/<pid>/status`
- `fopen` / `fgets` / `fclose` — построчное чтение файла
- `strncmp` + `sscanf` — поиск и парсинг нужных полей

**Где сохранить:** `self-practice/linux/procinfo/procinfo.c`

---

## Моё решение

Разбил на три части:
1. Парсинг аргумента: `strtoull` + проверка `endptr` и `errno`
2. Сборка пути: конкатенация строк через `strncat` (потом заменил на `snprintf`)
3. Построчное чтение файла: `fgets` + `strncmp` для поиска нужных полей

Для конвертации памяти: прочитал kb, поделил на 1024.

## Ключевые функции

| Функция | Зачем |
|---------|-------|
| `strtoull` | безопасный парсинг строки в uint64_t с обнаружением ошибок |
| `fopen` / `fgets` / `fclose` | буферизованное чтение файла построчно |
| `strncmp` | безопасное сравнение строк с ограничением по длине |
| `sscanf` | извлечение значения из строки формата `Key:   value` |
| `snprintf` | сборка пути в один вызов |

Выбор `fopen` вместо `open`: `/proc` — текстовый файл, нужно читать построчно. `fopen` даёт `fgets`, `open` потребовал бы ручного буфера.

## Что узнал

- `fopen` — для текстовых файлов где нужны `fgets`/`fscanf`; `open` — для бинарных или прямого контроля (флаги O_NONBLOCK и т.д.)
- `snprintf` всегда лучше `strncat`-цепочки: один вызов вместо трёх, нет лишних переменных
- `PRIu64` из `<inttypes.h>` вместо `%llu` — портируемость
- Внешний мир (аргументы, файловая система) — обрабатывать ошибки всегда; внутренняя логика — можно упростить
- VmRSS может отсутствовать у потоков ядра — стоит проверять что все три поля найдены

## Ошибки и трудности

**Сборка пути через strncat-цепочку:**
```c
// Написал:
char path[64] = "/proc/";
strncat(path, pid_string, 21);
strncat(path, "/status", 7);

// Надо:
char path[64];
snprintf(path, sizeof(path), "/proc/%llu/status", pid);
```

**`%llu` для `uint64_t` непортируемо** — надо `PRIu64` из `<inttypes.h>`.

**`\n` в stderr** — забыл, сообщения об ошибках слипались с приглашением терминала.

**Форматирование вывода** — `\t` вместо пробелов, вывод выглядел некрасиво.

## Что бы сделал иначе

- Сразу использовать `snprintf` для форматирования строк
- Добавить проверку что все три поля найдены
- Не забывать `\n` в stderr
