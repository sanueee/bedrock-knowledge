# task-a08 — pthreads

## Задание

Написать утилиту `procthreads` на C.

**Что делает:**
- Читает список всех PID из `/proc`
- Запускает 4 потока, каждый обрабатывает свою часть PID
- Каждый поток читает `/proc/<pid>/status` и достаёт `Name` и `VmRSS`
- Потоки пишут результат в общий массив через мьютекс
- После `pthread_join` — вывод `PID | Name | VmRSS (kB)`, отсортированный по VmRSS убыванию

**Функции:** `pthread_create()`, `pthread_join()`, `pthread_mutex_t`

**Компиляция:** `gcc procthreads.c -o procthreads -lpthread`

---

## Моё решение

Глобальный массив `results[1024]` + мьютекс. Список PID делится на 4 части через `ThreadArg` — структуру с указателем на начало диапазона и количеством элементов. Каждый поток читает `/proc/<pid>/status` локально, мьютекс берётся только в момент записи в общий массив. После `pthread_join` — `qsort` по `rss` и вывод.

## Ключевые функции

| Функция | Зачем |
|---------|-------|
| `pthread_create()` | запустить поток, передать `ThreadArg` |
| `pthread_join()` | дождаться завершения потока перед сортировкой |
| `pthread_mutex_lock/unlock()` | защита `results_count++` от data race |
| `PTHREAD_MUTEX_INITIALIZER` | статическая инициализация мьютекса |

## Что узнал

- Поток — параллельный путь выполнения внутри процесса с общей памятью
- Функция потока всегда `void *func(void *arg)` — обобщённый интерфейс, не переносимость
- `void *arg` → каст к нужному типу внутри функции
- `pthread_join` обязателен — без него `main` убивает потоки раньше завершения
- Мьютекс нужен только на общий ресурс, локальные переменные потока защищать не нужно
- `idx++` — не атомарная операция: LOAD → ADD → STORE. Два потока могут затереть друг друга
