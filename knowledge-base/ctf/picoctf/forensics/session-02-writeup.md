# Forensics Session 02 — сводный writeup (4 таска)

Сессия про **утилитарную грамотность**: половина forensics-задач превращается в "30 секунд работы" если знаешь правильную утилиту и флаг. Конспект построен от инструментов, не от решений.

## Главный вывод сессии

Магии нет. Есть знание инструментов. Пока инструменты "не в пальцах" — решение задачи и её невозможность выглядят одинаково: ступор. После того как утилита освоена — задача становится Easy. Поэтому ниже — таблица инструментов **первая**, разбор тасков — после.

## Инструменты forensics — карточки

### `exiftool <file>`

Что: читает метаданные изображений и других файлов (EXIF, XMP, IPTC, ICC profile, PNG chunks).
Зачем в forensics: **первый** инструмент когда видишь изображение в задаче. Часто флаг лежит в нестандартном поле метаданных.
Признак подозрительного поля: значение не похоже на формат, который ожидает поле (URL не начинается с `http`, дата не дата, описание — строка `[A-Za-z0-9+/]+=*`).
Ключевой кейс: **CanYouSee** — флаг в base64 внутри `Attribution URL` (XMP).

### `strings <file>`

Что: вытаскивает все последовательности печатаемых ASCII длиной ≥ N подряд.
Дефолт N=4. По умолчанию ищет только ASCII (для UTF-16 LE — `-e l`).
Полезные флаги:
- `-n N` — минимальная длина (`-n 8` отрезает шум).
- `-t x` — печатать hex-offset где найдена строка (для контекста).
- `-a` — обработать как бинарь даже если кажется текстом.

Идиомы:
```
strings file | grep -i picoctf       # быстрый шот в флаг
strings file | grep '==$'            # хвост base64-padding
strings -n 20 file | grep -E '^[A-Za-z0-9+/]+=*$'   # base64-кандидаты
```

### `xxd <file>`

Что: hex-дамп файла. Формат: `<offset>: <hex по 2 байта>  <ASCII>`.
Зачем: смотреть **magic bytes** в начале файла и структуру байтов.
Идиомы:
```
xxd file | head                # первые байты — magic bytes
xxd file | tail                # хвост — корректен ли trailer
xxd file | less                # листать руками
xxd file | grep -i pattern     # искать в hex
```

Обратная операция (hex → бинарь): `xxd -r`.

### `file <file>`

Что: определяет тип файла по magic bytes (читает первые байты, сравнивает с базой libmagic).
Возврат `data` — значит magic bytes не совпали ни с чем известным. **Сильный сигнал**: либо сломанный заголовок, либо нестандартный/самодельный формат, либо polyglot.
Идиома:
```
file *                # быстро определить типы пачки файлов
```

### `sha256sum <file>`

Что: считает SHA-256 хеш файла. Вывод: `<хеш>  <имя>`.
Идиомы:
```
sha256sum files/*                              # хеш всех файлов директории
sha256sum files/* | grep <начало известного хеша>   # найти файл по хешу
```
Аналоги: `md5sum`, `sha1sum`, `sha512sum`. На macOS встречаются `shasum -a 256` и `md5` (короткое имя).

### `base64`

Что: кодирует/декодирует base64.
Признаки base64-строки: алфавит `[A-Za-z0-9+/]`, хвост `=` или `==` (padding до длины кратной 4).
Идиомы:
```
echo '<строка>' | base64 -d            # декодировать (macOS/Linux)
base64 file                            # закодировать файл
echo -n 'plaintext' | base64           # закодировать строку, без \n
```

### `dd` для **точечной правки байтов** в файле

Ключевой флаг — `conv=notrunc`: писать **не обрезая** файл. Без него `dd of=file` обрежет файл до длины записанного. Это самая частая ошибка.

Полезные параметры:
- `bs=1` — размер блока 1 байт (для точечной записи).
- `count=N` — записать N блоков.
- `seek=N` — смещение в **выходном** файле (куда писать).
- `skip=N` — смещение во **входном** файле (откуда читать).
- `of=`, `if=` — output/input file.

Идиомы:
```
# Заменить первые 2 байта на 0xFF 0xD8
printf '\xff\xd8' | dd of=file conv=notrunc bs=1 count=2

# Вырезать кусок начиная с offset N
dd if=src of=out bs=1 skip=N
```

### `grep -aob 'pattern'`

Часть `grep` которая редко всплывает в обычной разработке, но критична в forensics.
- `-a` — обработать **бинарь** как текст (иначе grep на бинаре молчит или говорит "Binary file matches").
- `-o` — печатать только **совпадение**, не всю строку.
- `-b` — печатать **byte-offset** совпадения.

Идиома "найти где в файле спрятан другой формат":
```
grep -aob '%PDF' polyglot          # offset начала PDF
grep -aob 'PK\x03\x04' file        # offset начала ZIP
```

### `binwalk <file>` (опционально, через brew)

Что: сканирует файл на известные сигнатуры и выдаёт карту вложенных форматов.
`binwalk -e file` — попытка извлечь все embedded файлы.
В этой сессии не понадобился — `grep -aob` + `dd` решили polyglot руками. Но знать о существовании полезно.

### Magic bytes — must-know таблица

| Формат | Hex | ASCII |
|--------|-----|-------|
| PNG    | `89 50 4E 47 0D 0A 1A 0A` | `.PNG....` |
| JPEG   | `FF D8 FF` (+`E0`/`E1`)   | — |
| GIF    | `47 49 46 38`             | `GIF8` |
| PDF    | `25 50 44 46 2D`          | `%PDF-` |
| ZIP/JAR/docx/apk | `50 4B 03 04`   | `PK..` |
| ELF    | `7F 45 4C 46`             | `.ELF` |
| Mach-O 64 | `CF FA ED FE`          | — |

PNG также **обязан** заканчиваться на `IEND` chunk (`49 45 4E 44 AE 42 60 82`). JPEG — на `FF D9` (EOI). PDF — на `%%EOF`.

## Таск 1 — CanYouSee (метаданные)

**Условие.** Скачать JPEG, найти флаг.

**Подход.** `exiftool ukn_reality.jpg` — посмотреть метаданные.

**Что нашлось.**
```
Attribution URL : cGljb0NURntNRTc0RDQ3QV9ISUREM05fM2I5MjA5YTJ9Cg==
```

Поле `Attribution URL` должно содержать URL (`http://...`), а тут — строка из `[A-Za-z0-9+/]` с хвостом `==`. Это base64.

**Решение.**
```
echo 'cGljb0NURntNRTc0RDQ3QV9ISUREM05fM2I5MjA5YTJ9Cg==' | base64 -d
```

**Альтернатива без exiftool:**
```
strings ukn_reality.jpg | grep '==$'
```

**Главное.** В forensics всегда смотри метаданные первой командой. Подозрительное содержимое поля (формат не соответствует семантике поля) — почти всегда указатель на флаг.

## Таск 2 — Verify (поиск файла по хешу)

**Условие.** SSH в инстанс picoCTF, в `files/` лежит куча файлов, известен SHA-256 нужного, нужно найти и расшифровать его `./decrypt.sh`.

**Подход.**
1. `ls files/` — пачка файлов, имена не говорят ничего.
2. Открыть редактором не получилось (на инстансе нет `nano`/`vim`). Но **не нужно** — задача про хеш, не про чтение.
3. `sha256sum files/* | grep 03b52eabed517...` — нашёлся `files/00011a60`.
4. `cat files/00011a60` показал бинарный мусор с префиксом `Salted__` — фирменный маркер `openssl enc -salt`. Это шифрованный файл, читать `cat`'ом бесполезно.
5. `./decrypt.sh files/00011a60` — скрипт раскрыл флаг.

**Главное.**
- **Не пытайся открыть encrypted-файл редактором.** Префикс `Salted__` (8 байт ASCII) — сразу `openssl enc -d`.
- Просмотр текстовых файлов на минимальном shell без редактора: `cat`, `less`, `head`, `tail`.
- Полезно прочитать сам `decrypt.sh` (`cat decrypt.sh`) — увидишь конкретный синтаксис OpenSSL.

## Таск 3 — Corrupted file (битые magic bytes JPEG)

**Условие.** Файл "сломан, пара байт может всё починить". `file <f>` возвращает `data`.

**Подход.**
1. `xxd file | head` — посмотреть начало.
   ```
   00000000: 5c78 ffe0 0010 4a46 4946 ...   \x....JFIF...
   ```
2. После offset 2 структура файла валидна: `ff e0 00 10 J F I F` — это типичное начало JPEG/JFIF.
3. Первые 2 байта должны быть `FF D8` (SOI — Start Of Image), но там `5c 78` — что в ASCII читается как `\x` (буквально — кто-то заменил magic bytes на текст `\x`).

**Решение.**
```
printf '\xff\xd8' | dd of=file conv=notrunc bs=1 count=2
file file   # → JPEG image data, JFIF standard 1.01 ...
mv file file.jpg && open file.jpg
```

Флаг был нарисован на восстановленной картинке.

**Главное.**
- `file <f>` → `data` = подозрение на сломанные magic bytes.
- `xxd | head` сравнить с эталонной таблицей magic bytes.
- **`dd conv=notrunc`** — критичный флаг. Без него `dd of=file` обрезал бы файл до 2 байт и уничтожил картинку.
- "Пара байт" в условии = ровно 2 байта SOI.

## Таск 4 — Secret of the Polyglot (PNG + PDF)

**Условие.** Странный файл, разные программы выдают разный тип. Имя — `flag2of2-final.pdf`.

**Подход.**
1. `exiftool flag2of2-final.pdf` сказал `File Type: PNG` и в самом конце:
   ```
   Warning: [minor] Trailer data after PNG IEND chunk
   ```
   Это **главная зацепка**: после `IEND` (официального конца PNG) в файле есть ещё байты.
2. Имя `flag2of2-final.pdf` + расширение `.pdf` подсказали — там PDF приклеен к PNG. Это **polyglot**: один файл валиден сразу как два формата.

**Решение.**
```
# Где начинается PDF
grep -aob '%PDF' flag2of2-final.pdf
# 0001234:%PDF        (условно — offset нашёлся)

# Извлечь PNG-часть (расширение даст просмотрщику намёк)
cp flag2of2-final.pdf out.png && open out.png
# (вторая половина флага — на картинке 50×50)

# Извлечь PDF-часть с найденного offset
dd if=flag2of2-final.pdf of=out.pdf bs=1 skip=<offset>
open out.pdf
# (первая половина флага — в PDF)
```

Склеить две половинки → отправить.

**Главное.**
- Признак polyglot: `exiftool` пишет `Trailer data after ... chunk`, или `file` и расширение расходятся.
- Структура: `[формат A до маркера конца][формат B со своим magic]`.
- Поиск второго формата: `grep -aob '<magic>'` → offset → `dd skip=<offset>`.
- Это **не уязвимость одной программы** — это уязвимость **разногласия парсеров**. PNG-вьюверы читают до `IEND` и игнорируют хвост; PDF-ридеры ищут `%PDF` от начала. Реальный malware-вектор: вкладывают JS-стейджер в PDF, который одновременно — валидный JPEG.

## Ключевые термины (English)

- **magic bytes / file signature** — фиксированные первые байты файла, идентифицирующие формат.
- **polyglot file** — файл, валидный как несколько форматов одновременно.
- **trailer / footer** — данные в конце файла после официального маркера конца.
- **SOI / EOI** (Start/End Of Image) — JPEG-маркеры `FF D8` / `FF D9`.
- **IEND chunk** — обязательный последний chunk PNG, маркер конца.
- **XMP / EXIF** — стандарты метаданных; XMP — Adobe XML-based, EXIF — TIFF-based.
- **salt** (в `Salted__`) — рандом, добавляемый в KDF, чтобы одинаковые пароли давали разные ключи. Префикс `Salted__` — фирменный маркер `openssl enc -salt`.
- **hex dump** — представление бинаря в виде hex + ASCII.
- **byte offset** — смещение в байтах от начала файла.
- **truncate** — обрезать файл до новой длины (что делает `dd` **без** `conv=notrunc`).
