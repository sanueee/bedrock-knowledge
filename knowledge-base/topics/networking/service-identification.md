# Service identification (scanner v2)

Свести две машины в один инструмент: «какие порты открыты» (B-10) + «что за сервис» (B-13), и **извлечь деталь** из ответа (версию/`Server:`). Расширяет [[service-fingerprint]] шагом извлечения.

## Две фазы — разные модели I/O

Discovery и identification — **два раздельных прохода**, потому что I/O у них разный.

| Фаза | Вопрос | Модель I/O | Сокеты |
|------|--------|------------|--------|
| 1. discovery | «порт открыт?» | non-blocking + `epoll`, окно слотов (машина B-10) | много сразу, закрываются сразу после вердикта |
| 2. identification | «что за сервис + версия?» | blocking, `SO_RCVTIMEO`, обмен payload (машина B-13) | по одному, свежий коннект |

**Стык фаз:** фаза 1 отдаёт **массив номеров открытых портов** (не живые сокеты), фаза 2 коннектится к каждому **заново**. Trade-off: +1 RTT на открытый порт (их мало) ради чистого разделения. Переиспользовать сокет нельзя — B-10 закрывает его, определив открытость через `getsockopt(SO_ERROR)` **до** всякого payload; хранить N живых сокетов вернуло бы проблему лимита fd, которую bounded concurrency в B-10 как раз решает.

**Окно ≠ результат** — две разные структуры данных:
- окно `probe_port slots[WINDOW]` (`fd`+`port`+`deadline`) — активные коннекты фазы 1, слот освобождается после разбора события;
- результат `long *opened_ports` — итоговый список, живёт до конца.

Индексируются **разными** счётчиками: слот — позицией `i` в окне, результат — отдельным `n_opened`. Слить их в одну переменную (частая ошибка при copy-paste) → негде хранить `fd`/`deadline`.

## Извлечение детали — развилка по классу ответа

`memmem` нашёл паттерн (`SSH-`/`HTTP/`) → сервис распознан. Дальше вынуть **человекочитаемую деталь**. Формат ответа разный → две функции, развилка по полю `service`:

```
strcmp(pr.service, "http") == 0  →  extract_http_server()   (заголовок Server:)
иначе                            →  extract_banner_version() (первая строка баннера)
```

**HTTP** — деталь в заголовке, среди многих строк:
```
HTTP/1.0 200 OK\r\n
Server: SimpleHTTP/0.6 Python/3.13.5\r\n   ← memmem("Server:") → пропустить пробел → до \r
Date: ...\r\n
```

**Баннерные (SSH/SMTP/FTP)** — деталь = первая строка целиком:
```
SSH-2.0-OpenSSH_9.6p1\r\n   ← memchr('\r') → всё до него
```

## Дисциплина byte-exact (критично — недоверенные данные)

Буфер от `recv` **не терминирован** `'\0'`. Значит внутри `extract_*`:

1. **Никаких `strlen`/`strchr`/`strcmp` по буферу** — они бегут до `'\0'`, которого может не быть до `buf+res` → out-of-bounds read (UB). Пример бага: `strcmp(p, " ")` вместо `*p == ' '`. (`strlen` по **строковому литералу** `"Server:"` — безопасен, он терминирован.)
2. `end = buf + res` — жёсткий предел. Поиск границ: `memchr(p, '\r', end - p)`, `NULL` → граница `= end`.
3. Сдвиг `p += k` (напр. за `"Server:"`) может выскочить за `end` на обрезанном ответе → сверять `p < end` **до** разыменования. Образование заграничного указателя — уже UB (см. [[pointer-arithmetic-ub]]).
4. Копирование в out-буфер: `n = min(need, out_size - 1)`, `memcpy`, вручную `out[n] = '\0'`.

**Куда писать результат — в переданный буфер, не возвращать указатель.** `extract_*(buf, res, out, out_size)`: caller владеет `out`, контролирует его размер и время жизни. Вернуть `char*` внутрь `buf` → dangling pointer: `buf` перезапишется следующей пробой / уйдёт из scope. `out_size` — **вход** (capacity, не меняется); фактическую длину, если нужна, возвращают через `return`, а не через `out_size`.

## Санитизация вывода (terminal injection)

Извлечённая деталь — всё ещё **недоверенные данные (untrusted data)** от удалённого хоста. Печать сырьём (`%s`/`%.*s`) → злонамеренный баннер с ANSI-escape (`\033[2J`, `\033[...`) переписывает / красит терминал оператора (terminal injection). Защита: при копировании в `out` пропускать через `isprint((unsigned char)c)`, непечатаемые → `.` (как `cat -v`/`strings`). Приведение к `unsigned char` обязательно — на байтах ≥ 0x80 знаковый `char` даёт отрицательное значение → UB в `isprint`.
