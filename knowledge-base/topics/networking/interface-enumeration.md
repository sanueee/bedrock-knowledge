# Interface enumeration / Перечисление сетевых интерфейсов

## Что это
Как программа узнаёт **свои** сетевые интерфейсы (имя, IPv4, маску) и **default gateway** — то есть
«в какой я подсети» и «где выход наружу». Два независимых источника ядра, сшиваемых по имени
интерфейса: `getifaddrs()` (адреса) + `/proc/net/route` (маршруты).

## Ключевые термины (English)
- **interface enumeration** — перечисление сетевых интерфейсов и их параметров.
- **`getifaddrs()` / `freeifaddrs()`** — API, отдающий связный список всех адресов всех интерфейсов; парная функция освобождает список.
- **`struct ifaddrs`** — узел списка: `ifa_name`, `ifa_addr`, `ifa_netmask`, `ifa_next`, `ifa_flags`.
- **socket address polymorphism** — `ifa_addr` это `struct sockaddr *` (общий тип), реальный тип определяется по `sa_family`.
- **prefix length / CIDR** — длина маски в битах (`/24`), = число единичных бит маски.
- **routing table** — таблица правил «пакет в такую-то сеть → доставить так»; ядро выбирает по dst-IP.
- **destination** — целевая **сеть** правила маршрута (не хост).
- **gateway / next hop** — IP следующего узла (роутера), которому отдать пакет, если сеть не локальная.
- **default route** — правило `destination = 0.0.0.0/0`, совпадает со всем; его gateway = «выход наружу».
- **host byte order / network byte order** — порядок байт в CPU (little-endian на x86) vs в сети (big-endian).

## Как работает

### Источник 1 — getifaddrs (адреса интерфейсов)
`getifaddrs(&head)` выделяет в куче **односвязный список** и кладёт указатель на голову в `head`.
Почему список, а не массив: число узлов заранее неизвестно (у разных машин разное), список строится
инкрементально без предварительного подсчёта.

**Один узел = один адрес, НЕ один интерфейс.** `eth0` с IPv4 + IPv6 + MAC даст **три** узла с
одинаковым `ifa_name == "eth0"`, но разным `ifa_addr->sa_family` (`AF_INET` / `AF_INET6` / `AF_PACKET`).
Идёшь по плоскому списку через `ifa_next` до `NULL` и сам фильтруешь нужное семейство.

**Владение памятью:** весь список — одна аллокация. `freeifaddrs(head)` ровно один раз, на голову.
Строки `ifa_name` и структуры `ifa_addr` живут **внутри** аллокации → после `freeifaddrs` любой
сохранённый указатель на них dangling. Собираешь в свой массив — копируй **значения**, не указатели.

### Полиморфизм sockaddr — почему проверка sa_family ДО каста
`ifa_addr` и `ifa_netmask` объявлены как `struct sockaddr *` — общий «базовый» тип, чтобы один
указатель нёс и маленький `sockaddr_in` (IPv4), и больший `sockaddr_in6` (IPv6). Первое поле у всех —
`sa_family`, оно валидно всегда. Алгоритм:
1. `ifa_addr != NULL && ifa_addr->sa_family == AF_INET` (порядок в `&&` важен: NULL-guard первым,
   иначе на записи без адреса правое условие разыменует NULL);
2. только теперь безопасно `(struct sockaddr_in *)ifa_addr`.

### Маска → префикс (popcount)
Маска приходит как `sockaddr_in` (не как `in_addr`!). Достаёшь `nm->sin_addr.s_addr` (32 бита) и
считаешь единичные биты: `__builtin_popcount(...)` = длина префикса. `255.255.255.0` → 24 единицы → `/24`.
**`ntohl` тут не нужен:** popcount считает количество единиц, перестановка байт его не меняет.
(Нужен был бы, если бы считал «слева направо до первого нуля» — там важна позиция бита.)

### Источник 2 — /proc/net/route (маршруты)
Виртуальный файл — текстовая проекция таблицы маршрутизации ядра. Формат:
```
Iface  Destination  Gateway   Flags ... Mask ...
eth0   00000000     0100A8C0  0003      00000000   ← default route (наружу)
eth0   0000A8C0     00000000  0001      00FFFFFF   ← локальная сеть (прямая доставка)
```
- Первая строка — заголовок (пропустить одним `fgets`), дальше по строке на маршрут.
- `Destination` — целевая **сеть** правила. `00000000` = `0.0.0.0` = **default route** («всё остальное»).
- `Gateway == 0` → сеть локальная, доставка **напрямую** (ARP по самому получателю).
- `Gateway != 0` → сеть не наша, отдать пакет **роутеру** с этим IP (ARP по gateway, кадр — гейтвею,
  IP внутри — на конечного получателя).
- Ядро само gateway не «выясняет»: локальные маршруты заводятся автоматически при назначении IP+маски,
  а default route обычно приходит по DHCP (option 3 `Router`) → DHCP-клиент пишет в ядро через rtnetlink.

**Сшивка:** для интерфейса `X` из `getifaddrs` печатаешь gateway, если в таблице есть default-строка
(`Destination == 0`) с `Iface == X` (`strncmp` с `ifa_name`), иначе `(no gateway)`. Default route в
системе обычно один → у всех прочих интерфейсов (и у `lo`) закономерно `(no gateway)`.

## Модель маршрутизации — суть (было узким местом)
На **каждый** исходящий пакет ядро задаёт вопрос: «получатель — в моей локальной сети (дотянусь сам)
или снаружи (отдать тому, кто знает дорогу)?». Таблица маршрутов = список правил-ответов. Из подходящих
правил берётся самое специфичное (длиннейший префикс). Default route (`0.0.0.0/0`) совпадает со всем —
это «если ничего конкретнее не подошло, шли на роутер». Пакету наружу нужен **MAC гейтвея**, а не MAC
конечного сервера: до сервера напрямую L2-кадр не дойдёт (он в другой сети), роутер — первый достижимый
по L2 хоп, дальше форвардит он.

## Endianness — где какой вид (было узким местом)
Три «представления» одного IPv4-адреса, не путать:

| Где | Вид | Пример 192.168.0.1 |
|-----|-----|--------------------|
| в памяти для `in_addr`/сети | network order (big-endian): байты `C0 A8 00 01` | `s_addr` хранит именно так |
| строка для человека | `inet_ntop` печатает из network-order байт | `"192.168.0.1"` |
| hex в `/proc/net/route` | host order слово (ядро печатает `%08X` сырого `__be32`) | `0100A8C0` |

Ключ: `sscanf("%x")` из `/proc` даёт `uint32_t`, который **уже** лежит в памяти как network-order байты
(на little-endian). Поэтому `g.s_addr = gw` **как есть** — без `ntohl`/`htonl`. Печать и парсинг идут на
одной машине → «переворот» при печати ядром и при чтении программой взаимно гасятся. Проверка истины —
`route -n` / `ip route`: если вышло «задом наперёд» (`1.0.168.192`) — byte order перепутан.

**Правило на будущее:** не спрашивать «нужен ли ntohl вообще», а спросить «в каком представлении данные
СЕЙЧАС и какое ждёт потребитель». `getifaddrs` → уже network order (готово для `inet_ntop`). `/proc`-hex →
host-order слово, но на LE совпадает с network-байтами. popcount → представление вообще неважно.

## Пример (из сессии — ifenum.c, ядро логики)
```c
// фильтр узла
if (p->ifa_addr == NULL || p->ifa_addr->sa_family != AF_INET) continue;
struct sockaddr_in *addr = (struct sockaddr_in *)p->ifa_addr;
inet_ntop(AF_INET, &addr->sin_addr, buf_ip, sizeof buf_ip);

// маска → префикс
struct sockaddr_in *mask = (struct sockaddr_in *)p->ifa_netmask;   // sockaddr_in, не in_addr!
int mask_bit = __builtin_popcount(mask->sin_addr.s_addr);          // ntohl не нужен

// gateway из /proc: найти default-строку интерфейса, потом печать ОДИН раз
if (strncmp(iface, p->ifa_name, 16) == 0 && dest == 0) {
    struct in_addr g; g.s_addr = gw;                              // как есть, без ntohl
    inet_ntop(AF_INET, &g, buf_gw, sizeof buf_gw);
    has_gw = 1;
}
```
Вывод в Docker: `lo 127.0.0.1 /8 (no gateway)` + `eth0 172.17.0.2 /16 gw 172.17.0.1`.

## Подводные камни
- **Каст `ifa_netmask` в `(struct in_addr *)` вместо `(struct sockaddr_in *)`** → `s_addr` читает
  `sin_family`+`sin_port` (смещение 0..3), а не адрес (он с байта 4). Итог: popcount(2)=1 → всегда `/1`.
  Причина: в `sockaddr_in` поле `sin_addr` лежит **после** `sin_family`(2) + `sin_port`(2), на offset 4.
- **`ifa_addr` / `ifa_netmask` бывают `NULL`** → guard перед разыменованием.
- **Печать внутри цикла по строкам `/proc`** → интерфейс с локальной строкой печатает лишнее
  `(no gateway)`, а интерфейс без совпадающих строк (`lo`) не печатается вовсе. Решение: цикл только
  **находит** default (флаг `has_gw`), печать — **один раз после** цикла, по `ifa_name` (не по `iface`
  из последней строки — там уже мусор для этого интерфейса).
- **`%c` вместо `%d` для префикса** → печатает символ с кодом 24 (control char), а не «24».
- **`sscanf` без ширины в `%s`** → переполнение буфера `iface`; всегда `%15s` для `char[16]`.
- **Спам в stderr на фильтре** — не-AF_INET узлов много (IPv6/MAC на каждом интерфейсе); фильтр должен
  молча `continue`, без печати.
