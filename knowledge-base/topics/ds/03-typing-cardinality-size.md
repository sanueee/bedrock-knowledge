# Типизация, мощность (#) и размер (sizeof)

## Что это

Сквозной аппарат экзамена. **Мощность (cardinality, `#`)** — сколько *различных
значений* может принять тип (логика). **Размер (`sizeof`)** — сколько *байт* занимает
(железо). Две разные вещи, их нельзя путать.

## Ключевые термины (English)

- **cardinality (`#`)** — мощность: число различных значений типа.
- **size (`sizeof`)** — размер в байтах.
- **product type** — произведение (запись/`struct`): поля сосуществуют.
- **sum type** — сумма (объединение/`union`, вариант): в момент времени живо одно поле.
- **padding / alignment** — выравнивание (добавочные байты в записи).
- **strong / weak typing** — сильная/слабая типизация (C — слабая).

## Сильная vs слабая типизация

**Сильная типизация — 4 признака:**
1. Каждый объект имеет **уникальный тип**.
2. Каждый тип задаёт **множество значений + множество операций**.
3. В присваивании типы левой и правой части **эквивалентны** (нет неявного преобразования).
4. Любая операция должна входить в **множество допустимых** (см. п.2).

**C — слабо типизирован:** есть неявные преобразования (`int`↔`char`, `int`↔`double`),
cast указателей, array-to-pointer decay. Pascal строже.

## Формулы

| Тип | Мощность `#` | Размер `sizeof` |
|-----|--------------|------------------|
| массив | `(#Tbase) ^ (#Tindex)` (**степень**) | `sizeof(Tbase) · #Tindex` |
| запись (product) | `#T₁ · #T₂ · … · #Tₙ` (**произведение**) | `Σ sizeof(Tᵢ)` (**+ padding**) |
| объединение (sum) | `#T₁ + #T₂ + … + #Tₙ` (**сумма**) | `max sizeof(Tᵢ)` (**максимум**) |

**Почему у массива степень:** `#Tindex` ячеек, каждая **независимо** выбирает из `#Tbase`
значений → `#Tbase · … · #Tbase` (`#Tindex` раз) = степень.

**⚠️ Вопрос-ловушка с лекции: верна ли `#union = #record`?** — **Нет.** Запись хранит все
поля сразу (product → произведение), объединение — одно из (sum → сумма). Поэтому
`#union = Σ #Tᵢ`, а не `∏ #Tᵢ`.

**Дуальность (запоминать как перекрёст):**
- запись: мощность = **произведение**, размер = **сумма**;
- объединение: мощность = **сумма**, размер = **максимум**.

## Числовые примеры (по 2 расчёта на тип: мощность + размер)

Везде: `bool` → `#=2`, `sizeof=1`; `char` → `#=2⁸=256`, `sizeof=1`;
`int` → `#=2³²≈4.29·10⁹`, `sizeof=4` байта.

### Простые типы

```
#bool = 2                    sizeof(bool) = 1 байт
#char = 2⁸ = 256             sizeof(char) = 1 байт
#int  = 2³² ≈ 4.29·10⁹       sizeof(int)  = 4 байта
```

### Массив — пример A: `bool A[3]` (для интуиции — маленькие числа)

```
Мощность: #A = (#bool)^#Tindex = 2³ = 8
          (8 комбинаций — как 3 независимых бита)
Размер:   sizeof(A) = sizeof(bool)·#Tindex = 1·3 = 3 байта
```

### Массив — пример Б: `int A[10]` (реалистичный)

```
Мощность: #A = (#int)^#Tindex = (2³²)¹⁰ = 2³²⁰   (астрономическое число)
Размер:   sizeof(A) = sizeof(int)·#Tindex = 4·10 = 40 байт
```

### Запись — `struct rec { bool f; char c; int n; };`

```
Мощность: #rec = #bool · #char · #int = 2 · 256 · 2³² = 2¹·2⁸·2³² = 2⁴¹ ≈ 2.2·10¹²
Размер:   наивно Σ sizeof = 1 + 1 + 4 = 6 байт
          с выравниванием = 8 байт
          (после char вставляется 2 байта padding, чтобы int лёг на адрес,
           кратный 4: [f:1][c:1][pad:2][n:4] = 8)
```

### Объединение — `union un { bool f; char c; int n; };`  (те же поля!)

```
Мощность: #un = #bool + #char + #int = 2 + 256 + 2³² = 4 294 967 554 ≈ 2³²
Размер:   sizeof = max(1, 1, 4) = 4 байта
```

### Контраст record vs union на одних полях

| | мощность | размер |
|---|---------|--------|
| `struct rec` | `2·256·2³²` = **2⁴¹** | **6 → 8** байт (с padding) |
| `union un` | `2+256+2³²` ≈ **2³²** | **4** байта |

Одни и те же три поля: запись — больше и по значениям, и по байтам; объединение —
экономит память (один слот на наибольшее поле), но и значений меньше.

## Параллель (для устного)

Это фундамент **алгебраических типов данных**: в Rust `struct` = product type,
`enum` = sum type (то есть `union` + тег). Названия *product*/*sum* — ровно из этих
формул мощности.

## Подводные камни

- Путать мощность и размер — это разные оси (значения vs байты).
- Для массива брать произведение вместо степени.
- Для `union` брать произведение (как у записи) — мощность это **сумма**.
- Забыть padding при размере записи (`Σ sizeof` — нижняя оценка, реальный размер ≥).
