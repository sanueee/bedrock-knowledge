## Шаблон разбора структуры (формат препода — режим B `/exam` следует ему)

Для **каждой** структуры экзамен ждёт ответ по этой схеме:

1. **Определение** — что это, абстрактно.
2. **Пример** — на C (или Pascal/др.), как объявляется/выглядит.
3. **Особенности** — чем характерна, нюансы реализации.
4. **Плюсы и недостатки**.
5. **Где применяется** (+ реальные системы — для «блеснуть»).
6. **Операции** — от банальных (инициализация, индексация, присваивание, сравнение)
   до специфичных (обновление высот и баланс-фактора в деревьях, рехеширование, ...).
7. **Сложность** — Big-O по операциям, **средний/худший случай, при необходимости с
   вероятностями** (любимое у препода).

Плюс, где уместно, — обогащение для устного: **параллели Python/Rust**, **аналоги и
trade-offs**.

## Сквозные темы экзамена (тестируются на любой структуре)

Это не отдельные структуры, а призмы, через которые препод спрашивает всё подряд.
Знать твёрдо — окупается на каждом вопросе.

- **Мощность (#)** — число различных значений типа. `#array = #Tbase ^ #Tindex`,
  `#record = #T1 · #T2 · … · #Tn`, `#union = ?` (вопрос с лекции — подумать).
- **Размер (sizeof)** — `sizeof(array) = sizeof(Tbase) · #Tindex`,
  `sizeof(record) = Σ sizeof(Ti)` (+ padding!), `sizeof(union) = max sizeof(Ti)`.
- **Представление в памяти** — машинное слово (word), `sizeof(data)` vs `sizeof(word)`
  (кратно / меньше / больше), **упакованные vs неупакованные** (`__attribute__((packed))`,
  `#pragma pack`), выравнивание (alignment) и padding; **row-major (по строкам) vs
  column-major (по столбцам)** для многомерных массивов + формулы доступа `A[i][j]`.
- **Анализ сложности** — Big-O / Θ / Ω, амортизированный анализ, **вероятностный анализ**
  среднего случая.
- **Проблемы памяти** — **фрагментация внутренняя и внешняя**, **висячие указатели
  (dangling pointers)**, **use-after-free**, утечки. Возникают у динамических структур.
- **Сильная vs слабая типизация** — C слабо типизирован; 4 признака сильной типизации.

## Слабые места

> Сюда `/exam` пишет после пробного экзамена конкретные пробелы (тема + что именно
> не понято). Это вход для следующих сессий — слабое приоритетнее непройденного.

- **⚠️ ТОП — Анализ сложности (вероятностный + амортизированный) всё ещё зыбок** (самооценка
  день 3, 2026-06-12). Несмотря на закрепление (средний с весом p, ×g→O(1), +k→O(n) на push),
  пользователь сам не уверен. **Нужны ещё повторы расчётами; обязательно перепроверить на
  пробнике №2.** Не считать закрытым.
- **🟡 Рекурсия — мини-сессия пройдена (2026-06-14), но свежо.** Написал руками в `ds/bst.c`:
  count/height/inorder (читающая), insert/search (различитель `child=recurse;return root` vs
  `return recurse`), delete (3 случая + in-order преемник), free (post-order). Конспект
  [[15-recursion-bst-c]]. Пойманы и поняты баги: потерянный return в search; `return bst_delete`
  вместо `child=...;return root`; отсутствие `else` между спуском и удалением; лист не
  обработан (case A через `left==NULL`); ловушка макроса max; dangling при shallow-copy payload.
  **Перепроверить удержание на AVL** (там та же рекурсия + повороты) и на пробнике №2. Прыжок
  веры зашёл — но удаление давалось с подсказками, не «с нуля». Дать ещё рекурсию руками на AVL.
- **⚠️ #1 — Вывод сложности (формальная математика)** (пробник №1, 2026-06-12). Два под-пробела:
  (а) **вероятностный средний случай** — не довёл `E = Σ i·P(i) = (1/n)·n(n+1)/2 = (n+1)/2`;
  (б) **«суммарно vs на одну операцию»** — путал суммарную стоимость серии с амортизированной
  на push (для +k: суммарно O(n²), но на push O(n)). Лекарство: amortized = сумма / число операций;
  средний = Σ i·P(i). Прогнать ещё расчётами. См. [[04-complexity]], [[11-dynamic-array]].
- **⚠️ #2 — Выравнивание в struct** (пробник №1). Дал sizeof=12 вместо 8: переравнял `short` на 4.
  Правило: поле выравнивается **по своему размеру** (short→2, int→4), padding — до ближайшего
  кратного. См. [[06-records-struct]].
- **⚠️ #3 — Поиск багов в ЧУЖОМ коде** (пробник №1 + явная просьба пользователя). Писать свой
  код с краевыми случаями умеет, но в dequeue не нашёл «нет проверки пустой» и «dangling tail
  при снятии последнего». **Давать больше заданий «найди ошибку в голом коде».** (Чтение ≠ письмо.)
- **Операции с указателями: dangling/UAF при перецепках** (2026-06-11) — ✅ ЗАКРЫТО на пробнике №1
  (Q5 destroy, Q17 realloc→dangling — оба идеально). Вчерашняя работа сработала. Реальные проявления: разрыв цепи в enqueue, мусорные поля после
  malloc, шаг по обменянному полю в reverse_deque (вечный цикл), «предыдущий vs следующий»
  у головы очереди. Мотив-лекарство: «сохрани, пока живо». **Прогнать на пробнике №1
  вопросами «что не так с этим кодом».**
- **Union: type punning ≠ конвертация** (2026-06-11, вскрылось на прожарке union). Ответил
  «float обрежется до целой части» — это поведение cast'а, а union реинтерпретирует биты
  (5.5f → 1085276160, не 5). Различитель: cast сохраняет значение/меняет биты, union
  сохраняет биты/меняет интерпретацию. См. [[07-union-variant]]. **Перепроверить на пробнике №1.**

## Примерный план на 10 дней

> Теории много, поэтому план плотный. Принцип: сначала закрыть сквозные темы
> (мощность/размер/память/сложность — они тестируются на всём), параллельно идти по
> модулям. Лекции Л1–Л3 (есть электронные конспекты) — закрыть первыми.

- **Дни 1–2:** Модуль 0 (классификация) + Модуль 1 (простые типы) + **сквозные**:
  мощность/размер, типизация. Л1–Л2.
- **Дни 3–4:** Модуль 2 (массивы, записи, объединения, представление в памяти,
  множества, последовательности) + сквозное «представление в памяти». Л2–Л3.
- **Дни 5–6:** Модуль 3 (сложность + проблемы памяти) + Модуль 4 (линейные
  динамические). **Пробный экзамен №1 (диагностика)** в конце дня 6.
- **Дни 7–8:** Модуль 5 (деревья: BST → AVL → красно-чёрные → B → splay/optimal) +
  добивание слабого из пробника. Самый объёмный блок.
- **День 9:** Модуль 6 (хеш) + Модуль 7 (графы) + **Пробный экзамен №2 (генеральная
  репетиция)**.
- **День 10:** повторение слабого, шлифовка формул мощности/размера и Big-O-таблиц,
  быстрый прогон сквозных тем.
