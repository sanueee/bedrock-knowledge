## Шаблон разбора структуры (формат препода — режим B `/exam` следует ему)

Для **каждой** структуры экзамен ждёт ответ по этой схеме:

1. **Определение** — что это, абстрактно.
2. **Пример** — на C (или Pascal/др.), как объявляется/выглядит.
3. **Особенности** — чем характерна, нюансы реализации.
4. **Плюсы и недостатки**.
5. **Где применяется** (+ реальные системы — для «блеснуть»).
6. **Операции** — от банальных (инициализация, индексация, присваивание, сравнение)
   до специфичных (обновление высот и баланс-фактора в деревьях, рехеширование, ...).
7. **Сложность** — Big-O по операциям, **средний/худший случай, при необходимости с
   вероятностями** (любимое у препода).

Плюс, где уместно, — обогащение для устного: **параллели Python/Rust**, **аналоги и
trade-offs**.

## Сквозные темы экзамена (тестируются на любой структуре)

Это не отдельные структуры, а призмы, через которые препод спрашивает всё подряд.
Знать твёрдо — окупается на каждом вопросе.

- **Мощность (#)** — число различных значений типа. `#array = #Tbase ^ #Tindex`,
  `#record = #T1 · #T2 · … · #Tn`, `#union = ?` (вопрос с лекции — подумать).
- **Размер (sizeof)** — `sizeof(array) = sizeof(Tbase) · #Tindex`,
  `sizeof(record) = Σ sizeof(Ti)` (+ padding!), `sizeof(union) = max sizeof(Ti)`.
- **Представление в памяти** — машинное слово (word), `sizeof(data)` vs `sizeof(word)`
  (кратно / меньше / больше), **упакованные vs неупакованные** (`__attribute__((packed))`,
  `#pragma pack`), выравнивание (alignment) и padding; **row-major (по строкам) vs
  column-major (по столбцам)** для многомерных массивов + формулы доступа `A[i][j]`.
- **Анализ сложности** — Big-O / Θ / Ω, амортизированный анализ, **вероятностный анализ**
  среднего случая.
- **Проблемы памяти** — **фрагментация внутренняя и внешняя**, **висячие указатели
  (dangling pointers)**, **use-after-free**, утечки. Возникают у динамических структур.
- **Сильная vs слабая типизация** — C слабо типизирован; 4 признака сильной типизации.
