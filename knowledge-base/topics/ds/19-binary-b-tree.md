# Двоичные B-деревья (binary B-trees, ДБ)

> Историческая цепочка (важно понимать связь!):
> **B-дерево (Bayer 1970) → двоичное B-дерево / ДБ (Bayer 1971) → симметричное
> двоичное B-дерево / СДБ (Bayer 1972) → красно-чёрное (Guibas–Sedgewick 1978)**.
> ДБ — первый шаг от «толстого» B-дерева к двоичному представлению; СДБ и КЧ — его прямые
> потомки. Если понял ДБ — КЧ зайдёт почти даром (это та же идея в других терминах).

## 1. Определение

**Двоичное B-дерево (ДБ)** — это двоичное представление B-дерева малого порядка
(степени 1, т.е. 2–3-дерева), где «толстый» узел B-дерева с несколькими ключами
разворачивается в цепочку двоичных узлов, связанных **горизонтальными** связями.

Ключевая идея: у узла связи бывают **двух видов**:
- **вертикальная связь (vertical link)** — обычное ребро «вниз на следующий уровень»;
- **горизонтальная связь (horizontal link)** — связь с узлом **того же уровня**,
  который на самом деле принадлежит **одному и тому же** узлу B-дерева.

То есть два двоичных узла, соединённых горизонтальной связью, — это один узел B-дерева
с двумя ключами (3-node). Горизонтальная связь = «будущее **красное** ребро» в КЧ-дереве.

В классическом ДБ (Bayer 1971) горизонтальные связи **асимметричны** — разрешены только
в одну сторону (вправо). Снятие этого ограничения (горизонтали в обе стороны) даёт СДБ.

## 2. Пример (на C)

Узел такой же, как у BST, но с пометкой типа связи (или хранят флаг «горизонтальна ли
связь с правым ребёнком» — что эквивалентно цвету):

```c
typedef struct bb_node {
    int key;
    struct bb_node *left;
    struct bb_node *right;
    int right_horizontal;   // 1 = связь right горизонтальная (red), 0 = вертикальная (black)
} BBNode;
```

Соответствие 2–3-дереву:
```
B-дерево (узел с 2 ключами [A | B]):

   ┌───────┐
   │ A | B │            горизонталь
   └───────┘     →     A ──────────► B      (A и B — один узел B-дерева)
                       │            │ \
                      <A   (A..B)    > B

Вертикальные связи (│) ведут на следующий уровень — это «настоящие» уровни B-дерева.
```

## 3. Особенности (инварианты)

- Горизонтальная связь соединяет узлы **одного уровня B-дерева** (это «расщеплённый» узел).
- **Не может быть двух горизонтальных связей подряд** — иначе это был бы узел B-дерева с
  3+ ключами, что нарушает порядок 2–3-дерева. (Прямой аналог «нет двух красных подряд».)
- Все пути от корня до листьев проходят **одинаковое число вертикальных связей** — это и
  есть равная высота B-дерева. (Аналог «равная чёрная высота».)
- В ДБ (асимметричном) горизонтали только вправо → дерево «кренится» вправо
  (left-leaning/right-leaning — вопрос соглашения; у Bayer вправо).

## 4. Плюсы и недостатки

**Плюсы:**
- Двоичная структура (проще обхода/реализации, чем многоключевой B-узел), но сохраняет
  баланс B-дерева → высота O(log n).
- Балансировка локальна: повороты + смена типа связи, без массового перемещения ключей.
- Один служебный бит на узел (тип связи / цвет) — экономно по памяти.

**Недостатки:**
- Асимметрия (только правые горизонтали) усложняет некоторые случаи и даёт менее
  «ровное» дерево, чем симметричный вариант → отсюда и появился СДБ.
- Менее наглядно, чем «толстое» B-дерево: один логический узел размазан по двум двоичным.

## 5. Где применяется

- **Историческая роль** — мост между B-деревьями и красно-чёрными. Прямого «промышленного»
  применения сегодня почти нет; используют его потомков (КЧ).
- Идея «горизонтальная связь = расщеплённый узел» жива в **left-leaning red-black trees
  (LLRB, Sedgewick 2008)** — современной упрощённой реализации КЧ как 2–3-дерева.
- B-деревья (родитель ДБ) — индексы СУБД (PostgreSQL/SQLite), файловые системы (ext4 htree).

## 6. Операции

- **Поиск** — как в обычном BST: горизонтальная или вертикальная связь, для поиска без
  разницы, идём влево/вправо по ключу. O(log n).
- **Вставка** — вставляем новый узел снизу как лист с горизонтальной связью (red), затем
  чиним инварианты снизу вверх:
  - если получилось две горизонтали подряд (узел B-дерева «переполнился» до 3 ключей) →
    **разделение (split)**: средний ключ «выталкивается» вверх (его связь с родителем
    становится горизонтальной), что соответствует росту B-дерева вверх. Реализуется
    **поворотом** + переключением типа связи.
- **Удаление** — зеркально: при недостатке ключей — заём (borrow) или слияние (merge)
  соседних узлов, как в B-дереве; в двоичной форме — повороты + смена типов связей.

Механика split в двоичной форме = ровно повороты КЧ-дерева; см. [[20-red-black]].

## 7. Сложность

```
Операция   | Среднее   | Худший
-----------|-----------|----------
Поиск      | O(log n)  | O(log n)
Вставка    | O(log n)  | O(log n)
Удаление   | O(log n)  | O(log n)
```
Высота гарантированно O(log n), потому что структура эквивалентна сбалансированному
2–3-дереву: число вертикальных связей на всех путях одинаково, а горизонталей между
двумя вертикалями не больше одной → высота ≤ 2·log₂(n+1) (как у КЧ).

## Сквозные темы

- **Память:** один служебный бит (тип связи) на узел. Динамическая структура → возможны
  висячие указатели (dangling pointers) и use-after-free при ошибках в перецепке во время
  split/merge — та же группа рисков, что и у любого дерева с ручной балансировкой.
- **Представление:** флаг `right_horizontal` часто паковали в младший бит указателя (указатели
  выровнены → младшие биты свободны) — классическая упаковка (packed representation).

## Параллели и trade-offs

- **vs B-дерево:** то же логическое дерево, но двоичная форма (узлы по 1 ключу + связи) vs
  многоключевые узлы. ДБ удобнее для RAM, B-дерево — для диска (узел = страница).
- **vs КЧ:** КЧ = СДБ в цвето-терминах; ДБ = асимметричный предок. «Горизонтальная связь»
  ↔ «красное ребро», «вертикальная» ↔ «чёрное ребро».

## Ключевые термины (English)

- **binary B-tree** — двоичное B-дерево (ДБ).
- **horizontal link / vertical link** — горизонтальная / вертикальная связь.
- **3-node / 2-node** — узел 2–3-дерева с 2 / 1 ключами.
- **split** — разделение переполненного узла (рост вверх).
- **left-leaning / right-leaning** — кренящийся влево/вправо (направление горизонталей).
- **LLRB (left-leaning red-black tree)** — современная реализация на той же идее.
