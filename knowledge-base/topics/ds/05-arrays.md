# Массив / Array

## Определение

Упорядоченный набор элементов **одного типа**, доступ по индексу; в памяти лежат
**подряд** (contiguous). Статический массив — размер фиксирован на этапе компиляции.

## Ключевые термины (English)

- **array** — массив; **contiguous** — расположенный подряд в памяти.
- **row-major / column-major** — хранение по строкам / по столбцам.
- **direct-address table** — таблица прямой адресации (индекс = ключ).
- **bias / offset** — смещение индекса (для отрицательных ключей).
- **data-independent (oblivious)** — время не зависит от расположения данных.

## Особенности

Имя массива в C — **константный указатель на начало блока**. Отсюда: нельзя
присвоить/сравнить массивы целиком; имя «распадается» в указатель (decay).

## Плюсы и минусы

- **+** доступ по индексу O(1); максимальная плотность памяти (нет указателей);
  дружелюбен к кэшу (locality of reference).
- **−** размер фиксирован; вставка/удаление в середину O(n) (сдвиг); нельзя
  `=`/`==` целиком.

## Где применяется

Буферы, таблицы, матрицы, **таблица прямой адресации** (lookup по индексу). Пиксели,
аудиосэмплы, hardware-регистры, lookup-таблицы.

## Операции (C-ловушки — спрашивают)

```
индексация      A[i]                        O(1)
присваивание    A = B;   ← ОШИБКА (const pointer)
                → цикл for  или  memcpy(A, B, sizeof(B))
сравнение       A == B   ← сравнивает АДРЕСА, не содержимое
                → цикл  или  memcmp(A, B, sizeof(B)) == 0
подмассив       встроенного нет — копировать циклом
инициализация   int A[5] = {1,2};  → {1,2,0,0,0}  (хвост обнуляется)
```

## Сложность

```
доступ по индексу         O(1)
поиск (неотсортир.)       O(n)      отсортир. + бинарный → O(log n)
вставка/удаление в конец  O(1)      (если есть место)
вставка/удаление середина O(n)      (сдвиг хвоста)
```

## Представление в памяти (сквозное)

```
Двумерный A[nrows][ncols], элемент (i, j):

row-major (по строкам, так в C):     линейный индекс = i·ncols + j
column-major (по столбцам, Fortran): линейный индекс = j·nrows + i

C-эквивалент: A[i][j] == *(*(A + i) + j)
```
C хранит по строкам → проход по строкам быстрее (кэш), чем по столбцам.

## Мощность и размер

```
#array  = (#Tbase) ^ (#Tindex)         (степень — ячейки независимы)
sizeof  = sizeof(Tbase) · #Tindex      пример: int A[10] → 4·10 = 40 байт
```

## Практика — `ds/array_freq.c` (частотный счётчик / direct-address table)

Массив как таблица прямой адресации: `freq[a[i]]++` — индекс это само значение,
подсчёт за один проход.

**Сложность:** построение O(n), поиск моды O(K) → итог **Θ(n + K)**.
`K` нельзя отбросить: если диапазон значений велик, доминирует `K`.
**Best = worst = average**, потому что алгоритм **data-independent** — нет ранней
остановки/ветвления по данным (контраст с линейным поиском, где `break` по находке
давал разные случаи). Отсюда точная граница Θ, а не просто O.

**Память O(K)** — зависит от **диапазона значений** (max+1), не от `n`. Это ахиллесова
пята прямой адресации.

### Находки из прожарки

- **Разрежённость**: значения 0..1 000 000 при n=10 → `freq` на ~4 МБ (`int`=4 байта)
  ради 10 чисел. Лечится: хранить только присутствующие значения (отсортированный
  массив = «множество как массив») **или** — каноничнее — **хеш-таблица / ассоциативный
  массив** (O(1) средн., не зависит от диапазона ключей). ← мостик: зачем в курсе после
  массива идут хеши.
- **Отрицательные значения**: `freq[-3]` = выход за границы = **undefined behavior**
  (не «неверный ответ», а порча памяти). Фикс — **bias**: `R = max−min+1`, индекс
  `a[i]−min`, запомнить `min`.
- **n = 0**: все `freq` нулевые → поиск моды ложно вернёт значение 0 (т.к. `max`
  инициализирован 0). У пустого входа моды нет — нужна отдельная проверка.
  *(в коде осознанно не дописано — нехватка времени)*

## Подводные камни

- `A = B` / `A == B` — не работают как ожидается (адреса, не содержимое).
- Отрицательный/выходящий за границу индекс — UB.
- Память прямой адресации зависит от диапазона ключей, а не от n.
