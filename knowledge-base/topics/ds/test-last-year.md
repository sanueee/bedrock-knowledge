## Раздел 1 — Тестовые вопросы (54)

**1)** A=B для двух массивов одного типа и длины — скопирует B в A?

**40)** В вещественных вычислениях важно внимание к чему?
— Точность и устойчивость.

**47)** Когда возникает коллизия хеш-функции?

**48)** Вынос инварианта может давать обратный эффект?
— Верно.

**49)** B-дерево порядка n: сколько ключей на странице?

## Раздел 2 — Вопросы по лабам (устный собес)

### Лаба 1 — Статические структуры данных ✅

- **Определение массива** — упорядоченный набор элементов одного типа, доступ по индексу; в памяти подряд (contiguous).
- **Определение указателя** — переменная, хранящая адрес объекта в памяти.
- **Связь массива и указателя** — имя массива — const-указатель на первый элемент (`A` ≡ `&A[0]`); индексация — арифметика указателей.
- **`A[i]` через указатель** — `A[i] == *(A + i)` (и `== i[A]`, сложение коммутативно).
- **Статические vs динамические (память/время жизни)** — статические: размер на этапе компиляции, живут в стеке/статич. сегменте, освобождаются автоматически; динамические: размер в runtime (`malloc`), живут в куче до `free`.
- **Ограничения статических при переменном объёме** — размер фиксирован на компиляции → нельзя расти; перерасход или нехватка памяти.
- **Почему статич. массивы неэффективны для разреженных данных** — память = O(диапазона), не числа элементов (как `freq[]`); альтернатива — отсортированный массив пар «индекс-значение» (или хеш как динамическая).
- **Что такое выравнивание, как отключить** — alignment: поле кладётся на адрес, кратный его размеру; отключить — `__attribute__((packed))` или `#pragma pack(1)`.
- **Как выравнивание влияет на размер (+пример)** — добавляет padding → `sizeof` ≥ суммы полей. `struct {char a; int b;}` = 8, не 5 (3 байта padding после char).
- **Что такое объединение, применение** — union: все поля делят одну память; экономия памяти, type punning, вариантные данные с тегом, регистры процессора.
- **Что такое перечисление, применение** — enum: именованные целочисленные константы; флаги, состояния, осмысленные имена вместо «магических чисел».
- **Почему размер статич. массива известен на компиляции; можно ли не задавать** — компилятору нужно зарезервировать память; размер можно опустить только при инициализации (`int A[] = {1,2,3}` → 3).
- **Ошибки при выходе за границы; как обнаружить** — UB (порча памяти, краш); инструменты: компилятор-варнинги, ASan (AddressSanitizer), статический анализ (cppcheck, clang-tidy).

### Лаба 2 — Динамическая память, утечки ✅

- **Как проверить, что malloc успешен** — сравнить результат с NULL (`if (p == NULL)`); ошибка — нехватка памяти.
- **Должно ли число malloc == числу free** — да, иначе утечка (каждый malloc — свой free).
- **Инструменты обнаружения утечек** — Valgrind (memcheck), ASan, LeakSanitizer; перехватывают malloc/free, отслеживают неосвобождённые блоки.
- **malloc vs calloc** — calloc обнуляет память и принимает (n, size); malloc — нет, быстрее. calloc — когда нужны нули; malloc — когда сразу перезапишешь.
- **Утечка из-за потери указателя (+фикс)** — `p = malloc(...); p = malloc(...);` (первый блок потерян). Фикс — освободить или не перезаписывать единственный указатель (tmp + проверка).
- **Почему утечки критичны в серверах** — долгоживущий процесс накапливает утечки → исчерпание памяти; консольная утилита завершается, ОС всё освобождает.
- **Что такое dangling pointer** — указатель на освобождённую память; чтение/запись = use-after-free (UB).
- **Как фрагментация влияет при частых malloc/free** — внешняя фрагментация: память порезана на дырки, крупный запрос не выполнить, хотя суммарно свободно.
- **Двойной free** — порча метаданных аллокатора (double free) → краш/уязвимость.
- **Когда оправдан realloc, подводные камни** — рост динамического массива; может **переместить** блок → старые указатели становятся dangling; при отказе вернёт NULL, не потеряв старый блок (нужен tmp).
- **Что с памятью при аварийном завершении (abort/SIGSEGV)** — ОС освобождает всю память процесса при завершении; стандарт C это не описывает (это поведение ОС).
- **Техники безопасного освобождения** — после `free` → `p = NULL`; освобождать вложенные раньше родителя; проверять malloc; идиома tmp при realloc.
- **Как работает free** — возвращает блок аллокатору (по служебному заголовку знает размер); память может не вернуться ОС сразу.

### Лаба 3 — Стек, очередь, дека ✅

- **Когда списки эффективнее динамических массивов** — частые вставки/удаления в середину/начало; размер заранее неизвестен (поток данных).
- **Ключевое преимущество деки** — вставка/удаление с **обоих** концов за O(1); пример — скользящее окно (sliding window maximum).
- **Сложность вставки/удаления в начале/конце: массив vs список** — массив: конец O(1)*, начало O(n) (сдвиг); список: голова O(1), хвост O(1) с tail-указателем.
- **Сравнение сложностей список vs массив** — массив: доступ O(1), вставка/удаление середина O(n); список: доступ O(n), вставка/удаление O(1) при известной позиции.
- **Очередь/стек/дек за O(1) через массивы?** — да: стек (top-индекс), очередь/дек — кольцевой буфер (circular buffer, индексы по `% cap`).
- **Почему стеку — один указатель top, очереди — два (front/rear)** — стек работает с одним концом; очередь кладёт в хвост (rear), снимает с головы (front) — разные концы.
- **Очередь через два стека (+сложность)** — стек-вход, стек-выход; при dequeue перелить вход в выход, если пуст; амортизированно O(1) на операцию.
- **Очередь с get_min() за O(1)** — вспомогательная дека монотонных минимумов (monotonic deque); при enqueue убирать большие с хвоста.
- **Задача, где дек незаменим** — sliding window maximum/minimum за O(n) (монотонный дек).
- **Стек с get_max() за O(1)** — хранить пары (значение, текущий max) или вспомогательный стек максимумов; при push обновлять, при pop снимать синхронно.
- **Переполнение стека на массиве (+стратегия)** — top == cap; динамическое удвоение (realloc ×2) → амортизированно O(1) на push.
- **Что такое стек, операции, сложность** — LIFO; push/pop/peek/is_empty — все O(1).
- **Что такое очередь, операции, сложность** — FIFO; enqueue/dequeue/front — O(1) (с двумя указателями).
- **Что такое дека, операции, сложность** — оба конца; push/pop_front/back — O(1).

### Лаба 4 — Несбалансированные деревья ✅

- **Что такое дерево** — иерархическая структура: узлы + рёбра, один корень, без циклов; каждый узел (кроме корня) имеет одного родителя.
- **Основная проблема несбалансированного BST при отсортированном вводе** — вырождение в линейный список (высота = n), поиск O(n). Пример: вставка 1,2,3,4,5 → правая цепь.
- **Поиск в несбалансированном дереве vs отсортированном массиве** — массив: бинарный поиск O(log n) гарантированно, но вставка O(n); дерево выигрывает при частых вставках/удалениях (массив пришлось бы сдвигать).
- **Когда несбалансированные целесообразнее сбалансированных** — когда данные случайны (средняя 1.39 log n) и не нужна гарантия; проще в реализации (нет поворотов).
- **Какое несбалансированное дерево при разной вероятности данных** — дерево оптимального поиска.
- **Доказать, что in-order BST даёт сортировку** — по свойству BST: для каждого узла L < узел < R; in-order = (L) узел (R) → рекурсивно выдаёт возрастающий порядок (индукция по высоте).
- **Почему удаление узла с двумя детьми — самое сложное (+алгоритм)** — нельзя просто убрать; заменить **in-order преемником** (минимум правого поддерева), затем удалить его (он лист или с одним ребёнком). Проблема: аккуратно перецепить, не нарушив BST.
- **Последовательность для max несбалансированного BST (высота n)** — отсортированная (1,2,...,n или обратная); поиск O(n); средний случай — O(log n) (хуже среднего).
- **Почему рекурсивное удаление неэффективно при ограниченной памяти; итеративный аналог** — рекурсия тратит O(h) стека вызовов; итеративно — идти указателями с запоминанием родителя; плюс — O(1) доп. память, минус — больше кода.
- **BST с size поддерева за O(1)** — хранить в узле поле `size`; обновлять при вставке/удалении по пути; полезно для order statistics (k-й по порядку, ранг элемента).
- **Обнаружить и удалить все листья за один проход** — post-order обход: если у узла нет детей — удалить (обнулить ссылку у родителя); за один проход снизу вверх.
