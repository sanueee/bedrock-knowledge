# Сортировки и поиск (sorting & searching)

> Регламент 2.8.4. Ты отметил: сортировки были в 1 семестре, в этом — под вопросом; точно
> «не знаю heap-сортировку и древесные/новые». Поэтому **heapsort + tree sort — подробно**,
> элементарные/слияние/быстрая — обзором (повторение), поиск — кратко.

## Обзорная таблица (выучить наизусть — частый вопрос «определи сложность»)

```
Сортировка   | Лучший     | Средний    | Худший     | Память   | Стабильна | In-place
-------------|------------|------------|------------|----------|-----------|---------
Bubble       | O(n)*      | O(n²)      | O(n²)      | O(1)     | да        | да
Selection    | O(n²)      | O(n²)      | O(n²)      | O(1)     | нет       | да
Insertion    | O(n)*      | O(n²)      | O(n²)      | O(1)     | да        | да
Merge        | O(n log n) | O(n log n) | O(n log n) | O(n)     | да        | нет
Quick        | O(n log n) | O(n log n) | O(n²)      | O(log n) | нет       | да
Heap         | O(n log n) | O(n log n) | O(n log n) | O(1)     | нет       | да
Tree sort    | O(n log n) | O(n log n) | O(n²)**    | O(n)     | да        | нет
```
\* при почти отсортированном входе. \*\* O(n²) при вырождении BST; со сбалансированным → O(n log n).

**Нижняя граница для сортировок сравнением: Ω(n log n)** — нельзя быстрее, если опираешься
только на попарные сравнения (доказательство — дерево решений: n! листьев, высота ≥ log₂(n!) =
Θ(n log n)). Обойти можно лишь без сравнений (counting/radix sort, при ограничениях на ключи).

## A. Элементарные сортировки O(n²) (повторение, обзором)
- **Bubble (пузырёк):** соседние пары, «всплывание» максимума за проход. Стабильна, in-place.
- **Selection (выбором):** ищем минимум, ставим в начало. **Нестабильна** (дальний обмен),
  всегда O(n²) даже на отсортированном.
- **Insertion (вставками):** берём элемент, вставляем в отсортированную левую часть. Стабильна,
  **O(n) на почти отсортированном** → хороша для малых/почти готовых массивов.

## B. Эффективные сортировки O(n log n)

### Merge sort (слиянием)
Divide-and-conquer: делим пополам, рекурсивно сортируем, **сливаем (merge)** две отсортированные
половины. **Всегда O(n log n)**, **стабильна**, но **O(n) доп. памяти** (не in-place).
Хороша для связных списков (слияние без доп. массива) и внешней сортировки (диск).

### Quick sort (быстрая)
Выбираем **опорный (pivot)**, разбиваем (partition) на «меньше pivot / больше pivot»,
рекурсивно сортируем части. Средн. O(n log n), **in-place**, на практике быстрее merge
(локальность). **Худший O(n²)** при плохом выборе pivot (уже отсортированный + крайний pivot);
лечится случайным/медианным pivot. **Нестабильна.**

### Heap sort (кучей) — ⭐ разобрать подробно

**Куча (binary heap)** — почти полное двоичное дерево в **массиве**:
```
для индекса i (0-based):  родитель = (i-1)/2,  левый = 2i+1,  правый = 2i+2
max-heap: родитель ≥ детей  (в корне A[0] — максимум)
```
**Алгоритм (in-place, по возрастанию через max-heap):**
1. **Build-heap:** превратить массив в max-heap. Идём от последнего внутреннего узла к корню,
   на каждом делаем **sift-down (просеивание вниз)**. Стоит **O(n)** (не O(n log n)! — тонкий
   вероятностно-амортизационный вывод: большинство узлов у дна, у них малая высота).
2. **Извлечение:** n−1 раз — поменять корень (максимум) с последним элементом, «отрезать»
   последний (он встал на место), сделать sift-down корня по уменьшенной куче. Каждое — O(log n).

```c
void sift_down(int *a, int i, int n) {   // a[i] просеять вниз в куче размера n
    while (1) {
        int l = 2*i+1, r = 2*i+2, big = i;
        if (l < n && a[l] > a[big]) big = l;
        if (r < n && a[r] > a[big]) big = r;
        if (big == i) break;
        int t = a[i]; a[i] = a[big]; a[big] = t;   // swap
        i = big;
    }
}
void heap_sort(int *a, int n) {
    for (int i = n/2 - 1; i >= 0; i--) sift_down(a, i, n);   // build-heap: O(n)
    for (int i = n - 1; i > 0; i--) {                        // извлечение: n·O(log n)
        int t = a[0]; a[0] = a[i]; a[i] = t;                 // max → в конец
        sift_down(a, 0, i);                                  // восстановить кучу [0..i)
    }
}
```
**Итог:** всегда **O(n log n)**, **O(1) память** (in-place), **нестабильна**. Куча отдельно —
основа **приоритетной очереди (priority queue)** (таймеры ядра, Дейкстра, [[25-graphs]]).

## C. Tree sort (сортировка деревом) — ⭐ новое для тебя
1. Вставить все n элементов в **BST**.
2. **In-order обход** → элементы в отсортированном порядке.
```
Средний: O(n log n) (n вставок по O(log n)); Худший: O(n²) при вырождении BST (вход
отсортирован → правый список). Со сбалансированным деревом (AVL/КЧ) → O(n log n) гарантировано.
Память O(n) под дерево. Стабильна при аккуратной обработке дубликатов.
```
Связь: heap sort и tree sort — обе «через дерево», но heap — массив-куча in-place O(n log n)
гарантировано, tree — отдельное BST с риском O(n²). Поэтому на практике heap > tree.

## D. Поиск (searching)

### Линейный (linear search)
Перебор подряд. **O(n)**, работает на **любом** (неотсортированном) массиве.

### Бинарный (binary search)
**Только на отсортированном.** Делим пополам, сравниваем с серединой, отбрасываем половину.
**O(log n)**.
```c
int bsearch_i(int *a, int n, int key) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;       // не (lo+hi)/2 — защита от переполнения
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}
```
Связь: бинарный поиск на массиве ≡ спуск по сбалансированному BST (та же логика «отбрось
половину»). Хеш даёт O(1), но теряет порядок (нет диапазонных запросов). См. [[24-hashing]].

## Сквозные темы
- **Анализ сложности** (любимое препода): нижняя граница Ω(n log n) для сравнений; build-heap
  O(n) — нетривиальный вывод (сумма высот узлов = O(n)); худший O(n²) у quick/tree при перекосе.
- **Стабильность и in-place** — частые свойства-вопросы: стабильна (merge/insertion/bubble),
  нестабильна (selection/quick/heap); in-place (quick/heap/элементарные), нет (merge/tree).

## Параллели и trade-offs
- **Merge vs Quick vs Heap:** merge — стабильна+гарантия, но O(n) память; quick — быстра
  на практике, но O(n²) худший; heap — гарантия O(n log n)+O(1) память, но нестабильна и
  медленнее quick (плохая локальность).
- **Python:** `sorted()`/`list.sort()` — **Timsort** (гибрид merge+insertion, стабилен, O(n)
  на почти готовом). **Rust:** `sort()` — стабильный (Timsort-подобный), `sort_unstable()` —
  pattern-defeating quicksort. Куча: Python `heapq` (min-heap), Rust `BinaryHeap` (max-heap).

## Ключевые термины (English)
- **stable / in-place** — стабильная (сохраняет порядок равных) / на месте (O(1) доп. память).
- **divide and conquer** — «разделяй и властвуй».
- **pivot / partition** — опорный элемент / разбиение (quicksort).
- **merge** — слияние (mergesort).
- **binary heap, max-heap / min-heap** — двоичная куча, max-/min-куча.
- **sift-down / heapify, build-heap** — просеивание вниз / построение кучи.
- **priority queue** — приоритетная очередь.
- **comparison sort lower bound Ω(n log n)** — нижняя граница сортировки сравнением.
- **tree sort** — сортировка деревом (BST + in-order).
- **linear / binary search** — линейный / бинарный поиск.
