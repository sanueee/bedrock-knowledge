# Проблемы памяти: фрагментация, висячие указатели, use-after-free

## Что это

Болезни всех **динамических** структур (malloc/free): динмассив, списки, деревья —
наследуют их автоматически. Вопросы 17 и 41 теста прошлого года — отсюда.

## Ключевые термины (English)

- **internal / external fragmentation** — внутренняя / внешняя фрагментация.
- **dangling pointer** — висячий указатель (на освобождённую память).
- **use-after-free (UAF)** — использование висячего указателя.
- **double free** — повторное освобождение; **memory leak** — утечка.
- **slab / memory pool** — пул объектов одного размера (лечит внешнюю фрагментацию).

## Фрагментация — два вида

**Внутренняя** — пустота ВНУТРИ блока (выделено больше, чем нужно):
```
запросили 5 → аллокатор выдал 16:  [ваши 5][░ 11 впустую ░]
```
Padding в struct — та же внутренняя фрагментация на уровне типа.

**Внешняя** — пустота МЕЖДУ блоками (память порезана на мелкие дырки):
```
[занято][дыра 8][занято][дыра 12][занято][дыра 4]
свободно 24, но malloc(20) не выполнить — нет непрерывного куска
```
Возникает от чередования malloc/free разных размеров и освобождения в произвольном
порядке. Запоминалка: **внутренняя — внутри блока, внешняя — между блоками.**

Связный список провоцирует внешнюю фрагментацию сильнее массива: каждый узел —
отдельный точечный malloc, освобождение вразнобой оставляет дырки размером с узел
(+ узлы разбросаны → промахи кэша). Лечение: **slab/pool-аллокаторы** (объекты одного
размера взаимозаменяемы — так живёт ядро Linux, kmalloc-кэши).

## Dangling pointer и use-after-free

**Dangling** — указатель хранит адрес уже освобождённой памяти. **UAF** — чтение/запись
через него: UB, коварен тем, что часто «работает», пока кусок не перевыделят другому
владельцу. ИБ-контекст: UAF — главный класс heap-эксплойтов (освобождённый объект
перевыделяют под контролируемые данные). Rust borrow checker делает dangling ошибкой
компиляции (E0382/E0515) — его главная продажа.

Родня: **double free** (порча метаданных аллокатора), **leak** (потерян последний указатель).

## Правила гигиены (= вопросы теста 17/39/41)

```
1. Вложенные структуры: СНАЧАЛА free вложенных → ПОТОМ родителя
   (иначе теряются указатели на детей = утечка)
2. После free(p) → p = NULL  (free(NULL) — безопасный no-op; NULL-deref
   хотя бы громко падает, UAF портит тихо)
3. Проверять результат malloc (NULL)
4. malloc(n * sizeof(T)), не malloc(n)
```

## Идиома освобождения списка (классика, UAF в одну строку)

```c
// НЕВЕРНО: p = p->next читается ПОСЛЕ free(p) → UAF
for (Node *p = head; p != NULL; p = p->next) free(p);

// ВЕРНО: спасти next, пока узел жив
Node *next;
for (Node *p = head; p != NULL; p = next) { next = p->next; free(p); }
```
«Обход с конца» в односвязном списке невозможен (нет ссылок назад); рекурсивное
освобождение хвоста = post-order, но O(n) стека. Дерево освобождают post-order
(L R A — сначала дети) — здесь обходы встречаются с памятью.

## Подводные камни

- Путать виды фрагментации (внутри блока vs между блоками).
- «UAF сразу падает» — нет, чаще тихо работает до перевыделения.
- free родителя раньше детей; забытый p = NULL; malloc без sizeof.
