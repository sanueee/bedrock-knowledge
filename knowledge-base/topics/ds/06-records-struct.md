# Запись / Record (`struct`)

## Определение

Агрегат, объединяющий поля **разных типов** в одну сущность (массив — один тип,
запись — разные). Каждое поле имеет **свою область памяти**. Это **product type**.

## Ключевые термины (English)

- **record / struct** — запись.
- **field / member** — поле.
- **alignment** — выравнивание; **padding** — байты-заполнители.
- **packed** — упакованная (без padding) запись.

## Пример

```c
struct person { char name[20]; int age; float height; };
struct person p;
p.age = 25;            // доступ через точку
struct person *ptr = &p;
ptr->age = 25;         // через указатель — стрелка ->
```

## Особенности / плюсы-минусы

- **+** логически связанные данные вместе; **`=` работает** (копирует все поля);
  доступ к полю O(1) (фиксированное смещение).
- **−** `==` не работает (сравнивать по полям); padding «съедает» память.

## Где применяется

Узел списка/дерева (`data` + `next`/`left`/`right`), запись БД, сетевой пакет, конфиг.

## Операции (контраст с массивом)

```
доступ        p.field   /   ptr->field            O(1)
присваивание  A = B;   ← РАБОТАЕТ (агрегат; имя записи НЕ const-указатель,
                          в отличие от массива → копируются все поля)
сравнение     A == B   ← НЕ работает → по полям (strcmp + ==),
                          memcmp — ОПАСНО (см. ниже)
инициализация struct person A = {"Ivan", 25, 1.75};
```

**Почему `=` работает у записи, но не у массива** (частый вопрос): имя массива —
константный указатель на блок, присваивать его нельзя; запись — агрегатное значение,
`=` копирует все поля.

## Мощность, размер, выравнивание

```
#record = #T1 · #T2 · ... · #Tn          (произведение)
sizeof  = Σ sizeof(Ti) + padding         (НЕ просто сумма)
```

**Правило выравнивания:** каждое поле кладётся на адрес, **кратный его размеру**.
**Trailing padding:** размер всей структуры округляется вверх до кратного выравниванию
наибольшего поля (чтобы массив структур оставался выровненным).

```
struct pad { char c; int n; }:
  [c:1][pad:3][n:4] = 8 байт   (сумма полей 5, padding 3)

struct { int n; char c; }:
  [n:4][c:1][pad:3] = 8 байт   (padding в конце — trailing)
```

**Управление упаковкой:** `__attribute__((packed))` или `#pragma pack(1)` убирают
padding → компактно, но доступ к невыровненным полям медленнее. (Сквозная тема
«упакованные/неупакованные»: массив в C — упакован; запись — по умолчанию НЕ упакована.)

## ⚠️ Ловушка: `memcmp` для сравнения записей

`memcmp(&A, &B, sizeof)` опасен: **padding-байты не инициализированы** (indeterminate)
→ две логически равные записи могут дать `memcmp != 0`. Сравнивать **по полям**.
(Для массива одного типа `memcmp` безопасен — между элементами padding'а нет.)

## Сложность

Доступ к полю — O(1) (смещение известно на компиляции). Запись — про организацию
данных, не про алгоритмы.

## Параллель

Rust: `struct` = product type; вывод равенства даёт `#[derive(PartialEq)]` (по полям,
не побайтово — именно из-за padding-проблемы).

## Подводные камни

- `==` / `memcmp` для записей — неверно из-за padding.
- Забыть padding при расчёте `sizeof` (это не просто сумма полей).
