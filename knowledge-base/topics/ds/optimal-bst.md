# Дерево оптимального поиска (optimal binary search tree)

> Опора — конспект препода (раздел 1). Здесь развёрнут по шаблону + явный разбор ДП-таблиц.
> **Главная идея:** до сих пор поиск считали равновероятным. В реальности у ключей **разные
> вероятности** обращения → выгодно держать частые ключи **ближе к корню**.

## 1. Определение

**Оптимальное (взвешенно-оптимальное) дерево поиска** — это BST, который при заданных вероятностях/частотах обращения к каждому ключу (p₁…pₙ) и к неудачным поискам (q₀…qₙ) **минимизирует ожидаемую стоимость поиска** (среднее число сравнений).

Мера качества — **взвешенная длина пути (weighted path length)**:
```
p = Σ(i=1..n) aᵢ·hᵢ  +  Σ(j=0..m) bⱼ·h'ⱼ   →  min
```
где aᵢ — число (частота) поисков ключа i, hᵢ — его высота (глубина) в дереве; bⱼ — число неудачных поисков, попадающих в «псевдовершину» j, h'ⱼ — её высота.

> **Контринтуитивный факт из конспекта:** для p₁=1/7, p₂=2/7, p₃=4/7 оптимальным оказывается
> **вырожденное в список** дерево (корень — самый частый ключ 4/7, остальные вниз). «Сбаланси-
> рованное» ≠ «оптимальное», когда вероятности перекошены.

## 2. Пример / постановка

- **Псевдовершины (внешние/fictitious nodes)** — добавляем к дереву листья-заглушки, отвечающие за **неудачные** поиски (поиск отсутствующего ключа попадает в промежуток). n ключей → n+1 псевдовершин (интервалов).
- Переходим от вероятностей к **количествам** поисков (aᵢ, bⱼ) — так удобнее в таблицах.

## 3. Особенности — ключевое свойство

> **Любое поддерево оптимального дерева — тоже оптимально.**

Это **оптимальная подструктура** → задача решается **динамическим программированием (ДП)**, без полного перебора (перебор всех форм — факториально, не годится).

Рекуррентная формула «склейки»:
```
вес дерева:   W(i,j) = W(i, j-1) + aⱼ + bⱼ        (W(i,i) = bᵢ)
стоимость:    p(i,j) = W(i,j) + min over i<k≤j ( p(i,k-1) + p(k,j) )
              p(i,i) = W(i,i)
```
Смысл `min(...)`: перебираем, какой ключ k сделать **корнем** поддерева T(i,j); левое поддерево — T(i,k-1), правое — T(k,j); берём корень, дающий минимум. Вес W прибавляется, т.к. при «опускании» поддеревьев на уровень ниже **каждая** вершина даёт +1 к своей высоте, а сумма всех частот по поддереву = W.

## 4. Плюсы и недостатки

**Плюсы:**
- Минимальная **средняя** стоимость поиска при известном распределении запросов.
- Гарантированно оптимально (ДП находит точный минимум, не эвристику).

**Недостатки:**
- Построение дорогое: **O(n³)** (или O(n²) с оптимизацией Кнута).
- **Статично:** строится один раз под фиксированные вероятности. **Вставки/удаления НЕ поддерживаются** (изменился набор/частоты — надо перестраивать). Это его принципиальное отличие от AVL/КЧ/splay.
- Нужно заранее знать вероятности обращений.

## 5. Где применяется

- **Компиляторы:** таблицы зарезервированных слов/символов с известной частотой → быстрый лексический анализ.
- **Кодирование/сжатие:** идея «частое — ближе к корню» родственна **кодам Хаффмана** (но Хаффман минимизирует длину кода для листьев, а optimal BST — для узлов BST).
- **Статические словари/справочники** с известной статистикой запросов.
- **Splay-дерево** — динамическая «самооптимизирующаяся» альтернатива: частые ключи всплывают к корню сами, без знания вероятностей заранее. См. [[splay]].

## 6. Операции

- **Построение** — заполнение двух таблиц (W и p) по диагонали: сначала диагональ (пустые поддеревья), затем растущие интервалы T(i,j) длиной 1, 2, …, n.
- **Поиск** — обычный BST-поиск по готовому дереву. O(высоты).
- **Вставка/удаление** — отсутствуют (статическая структура; нужна перестройка).

## 7. Сложность

```
Построение | O(n³)  (таблица n×n, в каждой ячейке min по ≤ n вариантам)
           | O(n²)  с оптимизацией Кнута (Knuth, монотонность корней)
Поиск      | O(высоты), в среднем минимально возможный по построению
Память     | O(n²)  под таблицы W и p
```
**Вывод O(n³):** двумерная таблица n×n → O(n²) ячеек; для каждой ячейки p(i,j) считаем `min` по (j−i) кандидатам-корням → ещё ×O(n). Итого O(n²·n) = **O(n³)**.

### Пример (a₁=1, a₂=2, a₃=4, все b=0)

Таблица W (по диагонали нули = b; затем W(i,j)=W(i,j-1)+aⱼ):
```
W   0  1  2  3
0   0  1  3  7
1      0  2  6
2         0  4
3            0
```
Таблица p (p(i,i)=0; p(i,j)=W(i,j)+min(...)):
```
p   0  1  2  3
0   0  1  4  11
1      0  2  8
2         0  4
3            0
```
p(0,3)=11 — совпадает с найденным «вручную» оптимумом (вырожденное дерево с корнем-частым ключом).

## Сквозные темы

- **Вероятностный анализ** (любимое препода): стоимость = математическое ожидание числа сравнений `E = Σ pᵢ·(глубинаᵢ+1)`. Optimal BST минимизирует именно это E.
- **ДП:** оптимальная подструктура + перекрывающиеся подзадачи → таблица, снизу вверх.

## Параллели и trade-offs

- **vs сбалансированное (AVL/КЧ):** те минимизируют **высоту** (под равновероятный поиск); optimal BST минимизирует **взвешенную** стоимость (под известное распределение). При равных вероятностях оба совпадают.
- **vs splay:** splay — динамический «онлайн» аналог: подстраивается под фактический поток запросов амортизированно, не зная вероятностей. Optimal BST — «офлайн», точный, но статичный.
- **vs Хаффман:** обе кладут частое выше; Хаффман — про префиксные коды (вес только на листьях), optimal BST — про сравнения в узлах BST (вес на узлах + псевдовершинах).

## Ключевые термины (English)

- **optimal binary search tree (OBST)** — дерево оптимального поиска.
- **weighted path length** — взвешенная длина пути.
- **expected search cost** — ожидаемая стоимость поиска.
- **dummy / external / fictitious node** — псевдовершина (неудачный поиск).
- **optimal substructure** — оптимальная подструктура.
- **dynamic programming (DP)** — динамическое программирование.
- **Knuth's optimization** — оптимизация Кнута (O(n³)→O(n²)).
