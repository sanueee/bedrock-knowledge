# Стек, очередь, дека

## Определение

Три **дисциплины доступа** поверх списка/массива — ADT определяется не тем, как лежит, а откуда можно класть и брать:

```
стек     LIFO   push/pop с ОДНОГО конца (top)
очередь  FIFO   enqueue в хвост, dequeue из головы — РАЗНЫЕ концы
дека     —      оба конца открыты на вставку и удаление
```

## Ключевые термины (English)

- **LIFO / FIFO** — last/first in, first out.
- **top** — вершина стека; **front/back** — концы очереди/деки.
- **overflow / underflow** — пере-/опустошение (pop из пустого → error).
- **circular buffer** — кольцевой буфер (очередь на массиве, индексы по `% cap`).

## Схема направлений (выправленная — была главная путаница!)

```
head → [1] → [2] → [3] → NULL
 ↑                  ↑
 голова: начало     tail: его next == NULL (инвариант)
 стрелок, СНИМАЕМ   КЛАДЁМ сюда
```
Снимать дёшево там, **откуда стрелки выходят** (head->next известен); класть — где есть прямой указатель (tail). Снять с хвоста односвязного за O(1) нельзя → нужен prev → дека на **двусвязном**.

## Сложность

Все операции всех трёх — **O(1)** (потому они и существуют как ADT). `size` за O(1) — счётчик в обёртке (инкремент/декремент в push/pop), не пересчёт.

## Краевые случаи — главный урок дня

**Правило: случай «один элемент» опасен только там, где указателей на структуру ДВА.**
- Стек (один `top`): особой ветки НЕ нужно — общий путь сам даёт `top = NULL`.
- Очередь/дека (`head`+`tail`): снял последний → **второй указатель обнулить руками** (иначе dangling на освобождённый узел). Удобно через счётчик: `if (size == 0) tail = NULL;`.
- Дека: «у новой головы `prev = NULL`» — только **если она есть** (`if (head)`), после снятия последнего `head->prev` = NULL-deref.

## Идиомы и реальные баги дня (`sections/ds/stack-queue-deque/stack_queue_deque.c`)

- **enqueue: цепь рвётся**, если двинуть tail, не зацепив старый хвост: `q->tail->next = new;` **до** `q->tail = new;` — закон порядка перецепки.
- **malloc даёт мусор**: узел при рождении — полностью определён (`prev = next = NULL`), иначе pop_back прочитает мусорный `prev` (calloc дал бы нули — в13 теста).
- **reverse_queue** = трёхуказательный разворот цепи + обёртка: `old_head` сохранить ДО цикла → `head = prev; tail = old_head;`.
- **reverse_deque** = в каждом узле swap(prev, next) + swap(head, tail) деки. Ловушка: после swap'а `cur->next` смотрит НАЗАД → шаг спасать **до** обмена (`forward = cur->next`), иначе вечный цикл (был!).
- Мотив дня (троекратный): **«сохрани, пока живо»** — next до free, next до разворота стрелки, forward до swap'а. Всё это профилактика dangling/UAF.

## Применение (вопросы теста в3/в16/в51)

```
стек:    вызовы процедур/рекурсия (call stack), выражения (ОПЗ), DFS,
         backtracking (в51 ошибочно приписан очереди!) | ИБ: stack smashing
очередь: BFS (обход в ширину) — главный ответ; разделяемые ресурсы; планировщики
дека:    скользящее окно; work-stealing планировщики
реализации стека (в16): одно-/дву-связный список, массив, две очереди
```

## Параллель

Python: `list` как стек, `collections.deque` (и очередь, и дека). Rust: `Vec` как стек, `VecDeque` (кольцевой буфер). Очередь на массиве = circular buffer (kfifo в ядре).

## Ошибки и трудности (сессия 2026-06-11)

Самое тяжёлое — **операции с указателями: избегать dangling и use-after-free** (перецепки, порядок free, спасение ссылок). Также: направление head/tail в очереди изначально мысленно перевёрнуто (казалось, что новая голова — «предыдущий», пока не выправили схему стрелок). Лечится картинкой направлений (выше) + мотивом «сохрани, пока живо».
