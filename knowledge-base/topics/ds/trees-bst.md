# Деревья и BST (binary search tree)

## Определение

**Бинарное дерево** — каждый узел имеет ≤ 2 детей (левый/правый). Корень — узел без родителя; листья — без детей; **глубина** узла — число рёбер от корня; **высота h** — максимальная глубина.

**BST** — бинарное дерево со **свойством упорядоченности**:
```
для каждого узла:  всё в ЛЕВОМ поддереве < узел < всё в ПРАВОМ поддереве
```

## Ключевые термины (English)

- **binary search tree (BST)** — бинарное дерево поиска.
- **depth / height** — глубина узла / высота дерева.
- **traversal: pre-/in-/post-order, level-order** — обходы.
- **in-order successor / predecessor** — следующий/предыдущий по значению.
- **degenerate tree** — вырожденное (в список) дерево.
- **harmonic number Hn** — гармоническое число (≈ ln n + 0.577).

## Зачем свойство — поиск как бинарный

```
ищем key:  key < узел → влево;  key > узел → вправо;  key == узел → нашли
```
Стоимость поиска узла = его **глубина** = длина пути от корня.

## Обходы (вопросы теста в33/в53/в54)

Для корня A, поддеревьев L, R:
```
pre-order  (префиксный):  A L R
in-order   (инфиксный):   L A R   ← у BST даёт ОТСОРТИРОВАННЫЙ порядок!
post-order (постфиксный): L R A   ← порядок безопасного освобождения (дети раньше)
level-order (BFS):        по уровням, через очередь
```
Пример на дереве `5(3(2,4), 8(_,9))`:
```
in-order:   2 3 4 5 8 9
pre-order:  5 3 2 4 8 9
post-order: 2 4 3 9 8 5
```

## Операции и сложность (завязаны на высоту h)

```
поиск / вставка / удаление:  O(h)
   сбалансированное:  h ≈ log₂ n → O(log n)
   вырожденное (вставка отсортированных 1,2,3,...): h = n → O(n) — список!
```

**Удаление — три случая:**
1. лист — просто убрать;
2. один ребёнок — заменить узел его ребёнком;
3. **двое детей** — заменить **in-order преемником** (минимум ПРАВОГО поддерева = самый левый там) или предшественником (максимум левого), затем удалить тот узел (он лист или с одним ребёнком).

## Средняя сложность поиска (вопрос в42) — результат, не вывод

```
случайный BST:  aₙ ≈ 2·ln2 · log₂ n ≈ 1.386 · log₂ n
```
Смысл: случайный BST в среднем лишь на **~39% хуже** идеального `log₂ n` — без балансировки уже почти оптимален (если ключи случайны). **Это O(log n)-класс**; 1.39 — константа (Big-O её отбрасывает).

**Идея вывода** (а не алгебра — её не учить): обусловиться на корне (корень = ключ i с вероятностью 1/n), рекурсия по поддеревьям размера (i−1) и (n−i), `+1` за спуск через корень. Решение рекуррентности → через гармоническое число `Hₙ ≈ ln n + 0.577`. Единственный полезный инструмент отсюда: **сумма обратных `1+1/2+...+1/n ≈ ln n`**.

**Тонкость моделей (n=3, руками):** формула даёт `8/9`, наивный подсчёт по 5 формам — `14/15`. Разница: формула усредняет по **порядкам вставки** (6 перестановок), где сбалансированное дерево вероятнее — его строят **2** порядка из 6, а каждую цепь —
1. Наивный счёт берёт 5 форм равновероятно. Мораль: **средний зависит от вероятностной модели** (как Σ P·value в линейном поиске). Сбалансированное не только лучше, но и вероятнее при случайных вставках.

## Построение балансного дерева вставкой (задача 15 теста)

Чтобы вставка в BST дала **идеально сбалансированное** дерево: отсортировать; брать **середину** → добавить; разбить ею набор на две половины (без неё); рекурсивно повторить для каждой половины.

## Где применяется

Индексы, словари/множества с порядком, in-order = сортировка, файловые системы (B-деревья). Беда BST — вырождение на отсортированном входе → дальше AVL/красно-чёрные/B (форсируют баланс).

## Подводные камни

- Big-O среднего = O(log n), не «O(1.38 log n)» (константа вне Big-O).
- Вырождение на отсортированном входе → O(n).
- Удаление узла с двумя детьми — только через in-order преемника/предшественника.
