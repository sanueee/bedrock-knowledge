# Анализ сложности алгоритмовм

> Формулы — plain-text (не LaTeX), как договорились. Многошаговые выводы — в code-блоках.

## Что это

Оценка ресурсов (время, память) как **функции размера входа n**, без привязки к железу.
Меряем не секунды, а **как растёт число операций** при росте n.

## Ключевые термины (English)

- **time / space complexity** — временная / пространственная сложность.
- **Big-O (O)** — верхняя граница («не хуже»).
- **Omega (Ω)** — нижняя граница («не лучше»).
- **Theta (Θ)** — точная (зажата сверху и снизу).
- **worst / average / best case** — худший / средний / лучший случай.
- **amortized analysis** — амортизированный анализ (усреднение по серии операций).

## Три нотации

- **O (О-большое)** — верхняя граница. `f(n) = O(g(n))`, если есть c, n0 такие, что
  `f(n) ≤ c·g(n)` для всех `n ≥ n0`.
- **Ω (Омега)** — нижняя граница («не лучше чем»).
- **Θ (Тета)** — точная: `f = Θ(g)` ⟺ `f = O(g)` и `f = Ω(g)` одновременно.

В быту говорят «сложность = O(...)», но строго O — это потолок; точный рост — Θ.

## Иерархия классов роста (учить порядок)

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!)
```

- O(1) — константа (доступ по индексу, push в стек)
- O(log n) — деление пополам (бинарный поиск, сбалансированное дерево)
- O(n) — линейный проход
- O(n log n) — хорошие сортировки (merge, heap)
- O(n²) — вложенный цикл (пузырёк)
- O(2^n), O(n!) — перебор (экспонента/факториал), «практически не решается»

**Правила упрощения:** отбрасываем константы и младшие члены.
`3n² + 5n + 2 → O(n²)`; `O(2n) = O(n)`; `O(log2 n) = O(log n)` (основание — константа).

## Три случая: лучший / худший / средний

- best case — обычно неинтересен.
- **worst case (O)** — гарантия «не хуже», основной ориентир.
- **average case** — ожидание по распределению входов → здесь нужны вероятности.

## Вероятностный вывод среднего случая — линейный поиск (то, что надо уметь руками)

```
Линейный поиск, n элементов, сравниваем по одному.

Случай 1 — элемент ЕСТЬ, равновероятно в любой позиции (P(i) = 1/n):

  E[сравнений] = Σ(i=1..n) i·P(i)
               = Σ(i=1..n) i·(1/n)
               = (1/n)·(1 + 2 + ... + n)
               = (1/n)·( n(n+1)/2 )      ← формула арифм. прогрессии
               = (n+1)/2                  ≈ n/2   →  O(n)

  (худший случай = n сравнений, тоже O(n))


Случай 2 — элемента может НЕ быть (с вероятностью q → тогда n сравнений):

  E = q·n + (1-q)·(n+1)/2

  пример q = 1/2, n = 100:
  E = 0.5·100 + 0.5·50.5 = 50 + 25.25 = 75.25 сравнения   →  O(n)
```

Приём: сумма `Σ i·P(i)` + формула `1+2+...+n = n(n+1)/2`. Это и просит препод «посчитать».

## Амортизированный анализ (без вероятностей — усреднение по серии)

```
push в динамический массив с удвоением ёмкости:
  - обычный push:            O(1)
  - при заполнении: новый массив ×2 + копирование n элементов → O(n), но РЕДКО
  - суммарное копирование за n вставок: 1 + 2 + 4 + ... + n ≈ 2n  (геом. прогрессия)
  - n пушей ≈ 3n операций  →  на один push: O(1) АМОРТИЗИРОВАННО
```

Это **агрегатный метод**: суммарная стоимость серии / число операций. Не путать со
средним случаем: амортизация — про худшую серию, без вероятностей.

## Пространственная сложность (space complexity)

Та же нотация, про память. Рекурсия глубины n → O(n) на стеке вызовов; merge sort → O(n)
доп. памяти; in-place сортировка → O(1) доп.

## Подводные камни

- Путать O (потолок) и Θ (точно).
- Не отбросить константу/младший член (`O(2n)` вместо `O(n)`).
- Путать средний случай (вероятности) и амортизацию (серия без вероятностей).
- Забыть пространственную сложность — спрашивают и про память.
