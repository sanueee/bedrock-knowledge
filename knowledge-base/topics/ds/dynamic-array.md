# Динамический массив / Growable array

## Определение

Массив, растущий в runtime: при заполнении выделяется блок побольше, данные переезжают.
Ключевая пара: **size** (занято) vs **capacity** (выделено). Рост — при size == cap.

## Ключевые термины (English)

- **size / capacity** — занято / выделено.
- **growth factor** — фактор роста (×2, ×1.5).
- **amortized O(1)** — амортизированная константа push.
- **realloc** — расширение блока (на месте ИЛИ переезд + копия + free старого).

## Геометрия vs арифметика роста (вывод — уметь руками)

```
×2 (геометрическая):  переезды на размерах 1,2,4,...,n
  сумма копирований = 1+2+4+...+n ≈ 2·(последний член) ≈ 2n
  (вся геометрическая сумма ≈ удвоенный последний член)
  на push: (n записей + 2n копий)/n ≈ 3 → O(1) амортизированно
  интуиция: переезды дорожают ×2 И редеют ×2 — гасятся

+k (арифметическая):  переезды на размерах k,2k,3k,...,n — каждые k пушей
  сумма = k·(1+2+...+n/k) = k·(n/k)(n/k+1)/2 ≈ n²/(2k)
  на push: ≈ n/(2k) → O(n) — растёт с n!
  интуиция: переезды дорожают, а частота постоянна — копится

n=1024:  ×2 → ~2000 копий (≈2/push);  +4 → ~131 000 (≈128/push)
```

Поэтому Rust `Vec`, Python `list`, C++ `vector` растут геометрически. cap стартует
с 1 особым случаем (`cap ? cap*2 : 1`) — иначе 0·2 = 0 навсегда.

## Плюсы и минусы

- **+** всё от массива (O(1) доступ, кэш) + неограниченный рост.
- **−** отдельный push может стоить O(n) (переезд); cap > size — переплата памятью
  (внутренняя фрагментация в чистом виде).

## Канонический push (из `sections/ds/dynarray/dynarray.c` — выстрадан тремя итерациями)

```c
if (v->size == v->cap) {
    size_t newcap = v->cap ? v->cap * 2 : 1;     // расчёт во ВРЕМЕННУЮ
    int *tmp = realloc(v->data, sizeof(int) * newcap);
    if (tmp == NULL) { perror("realloc"); return; }
    v->data = tmp; v->cap = newcap;              // коммит ПОСЛЕ успеха
}
v->data[v->size++] = x;
```

### Грабли (реальные, из итераций)

1. **`v->data = realloc(v->data, ...)` без tmp** — при отказе realloc старый блок ЖИВ,
   но единственный указатель затёрт NULL → утечка + потеря данных. Идиома: tmp + коммит.
2. **Менять cap до realloc** — при отказе cap врёт. Всё состояние — после успеха.
3. **Двойное удвоение** (слить «посчитай заранее» и «коммить после» в `cap*2` дважды) →
   cap=4 при выделенных 2 → heap overflow. Видно в печати роста: 1→4 вместо 1→2.
4. **vec_free, оставляющий cap=1 при data=NULL** — следующий push пишет в NULL[0].
   Симметрия: init == free == {NULL, 0, 0}.

## realloc может ПЕРЕЕХАТЬ

Любой сохранённый указатель внутрь старого блока (`int *first = &v.data[0]`) после
push с переездом — **dangling pointer**, чтение — UAF. Потому Rust не даёт держать
`&v[0]` поперёк `push` (borrow checker). Связь: [[memory-problems]].

## Сложность

```
доступ по индексу   O(1)
push в конец        O(1) амортизированно / O(n) худший (переезд)
вставка в середину  O(n) (сдвиг)
```
