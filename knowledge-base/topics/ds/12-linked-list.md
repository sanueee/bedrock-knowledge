# Линейный список / Linked list

## Определение

Последовательность узлов: данные + указатель на следующий. Каноничная **рекурсивная**
структура (узел ссылается на такой же узел). Доступ через указатель на голову;
пустой список = `head == NULL`.

```c
typedef struct node { int data; struct node *next; } node;
```

## Виды

```
односвязный    [d|n]→[d|n]→NULL          только вперёд
двусвязный     NULL←[p|d|n]⇄[p|d|n]→NULL  обе стороны, +память на prev
кольцевой      последний→next→голова      нет NULL (Иосиф Флавий, round-robin)
```

## Ключевые термины (English)

- **singly / doubly / circular linked list** — одно-/дву-связный / кольцевой.
- **head / tail** — голова / хвост; **relink** — перецепка указателей.
- **three-pointer reversal** — разворот тремя указателями (prev/cur/next).

## Сложность (вопросы теста в11, в24)

```
вставка в голову                O(1)
вставка ПОСЛЕ узла p            O(1)
вставка ПЕРЕД p: односвязный    O(n) — искать предыдущий с головы (в11)
                 двусвязный     O(1) — p->prev известен (в11)
удаление при ИЗВЕСТНОЙ позиции  O(1) — перецепка (в24; поиск позиции — O(n)!)
доступ по номеру / поиск        O(n)
```

## Применение

Размер задачи определяется в конце потока данных (в23); основа стека/очереди/деки;
intrusive-списки ядра Linux (`list_head`); кольцевой — задача Иосифа (задача 24 теста).

## Идиомы (= задачи теста 9/11/12/18/20; код: `ds/list.c`)

**push в голову (задача 20):** `p->next = *list; *list = p;` — порядок! Сначала новый
узел цепляется за список, потом голова за новый. push в голову переворачивает порядок
ввода (1..5 → печать 5 4 3 2 1).

**reverse in-place (задача 9) — танец трёх указателей:**
```c
node *prev = NULL, *cur = *list;
while (cur != NULL) {
    node *next = cur->next;   // 1. спасти продолжение
    cur->next = prev;         // 2. РАЗВОРОТ стрелки
    prev = cur;               // 3-4. шаг обоих вправо
    cur = next;
}
*list = prev;                 // новая голова = бывший хвост
```
Инвариант: левее cur — уже развёрнуто (голова prev), от cur — нетронутый хвост.
`next` обязателен: шаг 2 перезаписывает `cur->next` — без спасения хвост потерян.

**удаление по значению:** prev/cur; голова (`prev==NULL`) → `*list = cur->next`;
иначе `prev->next = cur->next`; free(cur); **return** (не продолжать цикл с freed cur!).

**освобождение** — см. [[10-memory-problems]]: спасти next до free; `*list = NULL`.

## Почему `node **list` (двойная звёздочка)

В C всё передаётся **по значению** — указатель копируется. Через копию можно менять
УЗЕЛ (`p->data = 5`), но не переменную-указатель вызывающего: `list = p` изменит
локальную копию, `head` в main останется старым. Функции, двигающие голову
(push/delete/reverse/free) — `node **`; print (голову не двигает) — `node *`.

## Грабли (реальные, из итераций `ds/list.c`)

- `node *list;` без `= NULL` → push цепляет хвост в мусор.
- Условие `cur->next != NULL` вместо `cur != NULL` → последний узел не обработан
  (print теряет элемент, delete не удаляет хвост) + краш на пустом списке.
- Продолжение цикла после free(cur) → разыменование освобождённого/NULL.
- В `for` свой инкремент + `cur = tmp` в теле → двойной шаг, утечка каждого второго.

## Параллель

Rust `LinkedList` существует, но документация отговаривает (кэш-промахи) — `Vec`
почти всегда быстрее; ядро Linux наоборот живёт на intrusive-списках (нет аллокаций
на узел — `list_head` встроен в объект).
