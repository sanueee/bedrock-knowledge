# Симметричные двоичные B-деревья (symmetric binary B-trees, СДБ)

> Bayer 1972, «Symmetric Binary B-Trees». **Прямой предок красно-чёрного дерева.** Отличие
> от ДБ ([[binary-b-tree]]) — горизонтальные связи разрешены в **обе** стороны (симметрия),
> а не только вправо. Guibas–Sedgewick (1978) переформулировали СДБ в цвета → получилось КЧ.

## 1. Определение

**СДБ** — двоичное B-дерево, в котором горизонтальные связи (= ребра внутри одного узла
B-дерева) могут идти **и влево, и вправо** от узла. Это снимает асимметрию ДБ и делает
балансировку «зеркально честной»: левый и правый перекосы обрабатываются одинаково.

Эквивалентно **2–3–4-дереву** (B-дереву порядка 2) в двоичном представлении: узел B-дерева
с 1/2/3 ключами кодируется 1/2/3 двоичными узлами, связанными горизонталями.

## 2. Пример (на C)

Узел тот же, что у ДБ, но тип связи может быть горизонтальным с **любой** стороны:

```c
typedef struct sbb_node {
    int key;
    struct sbb_node *left;
    struct sbb_node *right;
    int left_horizontal;    // горизонталь влево
    int right_horizontal;   // горизонталь вправо
} SBBNode;
```
(Эквивалентно: цвет ребра к каждому ребёнку — красный/чёрный.)

## 3. Особенности (инварианты)

- Горизонтали разрешены в обе стороны, **но не две подряд** (узел B-дерева ≤ 3 ключей).
- Все пути от корня до листьев содержат **одинаковое число вертикальных связей** (баланс).
- Симметрия → нет «крена» в одну сторону, как в ДБ; форма ближе к идеально сбалансированной.

Сопоставление с КЧ (один-в-один):
```
горизонтальная связь  ↔  красное ребро
вертикальная связь    ↔  чёрное ребро
«не две горизонтали подряд»          ↔  «нет двух красных подряд»
«равное число вертикалей на путях»   ↔  «равная чёрная высота»
```

## 4. Плюсы и недостатки

**Плюсы:**
- Симметричная балансировка проще и ровнее, чем у ДБ → меньше частных случаев.
- O(log n) гарантировано; эквивалент 2–3–4-дерева.
- Лёг в основу КЧ — проверенная временем модель.

**Недостатки:**
- Терминология «горизонталь/вертикаль» менее наглядна, чем цвета → исторически вытеснена
  красно-чёрной формулировкой (тот же объект, но удобнее объяснять и реализовывать).

## 5. Где применяется

- **Историческая роль:** непосредственная основа красно-чёрных деревьев (всё применение КЧ
  — `std::map`, `TreeMap`, CFS, `epoll` — наследует идею СДБ).
- Самостоятельно сегодня почти не используется — работают с потомком (КЧ/LLRB).

## 6. Операции

- **Поиск** — как BST, тип связи не важен. O(log n).
- **Вставка** — новый узел снизу с горизонтальной связью; при появлении двух горизонталей
  подряд (узел переполнился до 4 ключей) — **split**: средний поднимается вверх, что в
  двоичной форме = повороты + смена типов связей. Симметрично слева и справа.
- **Удаление** — borrow/merge соседних узлов (как в B-дереве) → в двоичной форме повороты
  + перекраска связей.

Операции 1:1 переносятся на КЧ — см. [[red-black]] §6.

## 7. Сложность

```
Операция   | Худший
-----------|----------
Поиск      | O(log n)
Вставка    | O(log n)
Удаление   | O(log n)
```
Граница высоты `h ≤ 2·log₂(n+1)` — та же, что у КЧ (это один и тот же объект в разных терминах).

## Сквозные темы

- **Память:** 2 бита типа связей (или цвет рёбер) на узел; динамика → риски dangling/UAF при
  перецепке.
- **Связь:** B-дерево (порядок 2) → СДБ (двоичная симметричная форма) → КЧ (цветовая форма).
  Знать эту цепочку — частый вопрос «откуда взялись красно-чёрные».

## Параллели и trade-offs

- **vs ДБ:** ДБ — только правые горизонтали (асимметрия), СДБ — обе → ровнее, проще баланс.
- **vs КЧ:** один объект, разные обозначения (связь↔цвет). СДБ исторически первичен.

## Ключевые термины (English)

- **symmetric binary B-tree (SBB)** — симметричное двоичное B-дерево (СДБ).
- **horizontal link (both directions)** — горизонтальная связь в обе стороны.
- **2-3-4 tree** — B-дерево порядка 2 (эквивалент СДБ/КЧ).
- **split** — разделение переполненного узла.
- предок (ancestor) красно-чёрного дерева — direct ancestor of red-black trees.
