# Объединение / Union (+ записи с вариантами)

## Определение

Тип, где **все поля делят одну область памяти** (начинаются с одного адреса). В любой момент «жив» только **один** член; запись в одно поле инвалидирует остальные.

## Ключевые термины (English)

- **union** — объединение; **active member** — активное поле.
- **type punning** — реинтерпретация одних байт как другого типа.
- **tagged union / variant record** — объединение с тегом-индикатором.
- **anonymous union** — безымянный union внутри struct (C11), доступ без `.data`.

## Пример

```c
union data { int i; float f; char str[20]; };
union data d;
d.i = 42;       // активно i
d.f = 5.5f;     // те же байты перезаписаны → i теперь «мусор»
```

## ⚠️ Главная ловушка: union ≠ конвертация

Чтение `d.i` после `d.f = 5.5` НЕ даёт 5 («обрезание дробной части» — ошибка!). Усечение делает **cast** (`(int)5.5f → 5` — пересчёт значения). Union же читает **те же биты** по другой схеме (type punning):

```
5.5 (float, IEEE 754) = 1.011 × 2²
  знак=0 | exp=129=10000001 | мантисса=011000...0
  биты = 0x40B00000

чтение как int: 0x40B00000 = 1 085 276 160   ← не 5!
```

Различитель: **cast сохраняет значение, меняет биты; union сохраняет биты, меняет интерпретацию.**

## Плюсы и минусы

- **+** экономия памяти (типы не нужны одновременно); type punning; основа вариантных данных.
- **−** компилятор НЕ следит за активным полем — обязан программист; одно значение за раз.

## Где применяется

- **Вариантные данные с тегом** (см. ниже) — основное.
- **Type punning**: битовое представление float, парсинг бинарных форматов, сетевые заголовки.
- **Регистры процессора**: RAX/EAX/AX/AH/AL — вложенные struct в union, разные «окна» на одни байты (пример с лекции).

## Операции

```
доступ        d.field / ptr->field          O(1)
присваивание  A = B;    работает (копия max-байтов)
сравнение     A == B    НЕ работает; memcmp мутный (мусор в неактивных байтах)
инициализация union data A = {42};   ← инициализирует ПЕРВОЕ поле
```

## Мощность и размер (+ числовой расчёт)

```
#union  = #T1 + #T2 + ... + #Tn     (СУММА — живо одно поле)
sizeof  = max(sizeof(Ti))           (МАКСИМУМ; кратен выравниванию union)

union { int i; float f; char str[20]; }:
  sizeof = max(4, 4, 20) = 20
  выравнивание = 4 (по int/float; у char — 1)

если str[18]: max = 18 → округление до кратного 4 → sizeof = 20 (padding внутри)
```

Дуальность с записью: record — мощность ∏ / размер Σ; union — мощность Σ / размер max. `#union = #record` — **неверно** (вопрос-ловушка с лекции).

## Записи с вариантами (variant records) = struct + tagged union

Union «слепой» — сам не знает, что в нём. Решение: рядом кладут **тег** (enum):

```c
enum vtype { INT_T, FLOAT_T, STR_T };
struct variant {
    enum vtype tag;
    union { int i; float f; char str[20]; };   // анонимный union (C11)
};
// switch (v.tag) → печатать/читать ТОЛЬКО активное поле
```

Лекционный пример — анкета: по полу либо `year_army`, либо `maiden` (union внутри записи). **Pascal vs C:** в Pascal (`case gender of ...`) компилятор хоть как-то контролирует варианты; в C контроля нет — «программист может всё», возможно противоречивое состояние (пол женский + валидный год призыва). За тег отвечаешь сам.

```
sizeof(struct variant) = 4 (enum=int) + 20 (union) = 24
24 кратно выравниванию (4) → trailing padding НЕ нужен, ровно 24
```

## Параллель (для устного)

Rust `enum` с данными = tagged union, но **компилятор сам следит за тегом** (match не даст прочитать неактивное поле) — безопасная версия этой же конструкции. C даёт ту же механику без страховки.

## Практика

`sections/ds/union-variant/union_variant.c` — tagged union: тег + анонимный union + `switch` по тегу.

## Подводные камни

- «Union обрежет float до int» — НЕТ, это реинтерпретация битов (см. ловушку).
- Читать неактивное поле — мусор (а семантически UB).
- Инициализатор `{...}` относится только к первому полю.
- Рассинхрон тега и данных — никто не проверит, кроме тебя.
