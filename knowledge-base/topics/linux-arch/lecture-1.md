# Лекция 1. Обзор компонентов и интерфейсов Linux

## 1. Интерфейсы взаимодействия с системой

В Unix-системах исторически сложился приоритет **CLI (Command Line Interface)** — интерфейса командной строки. Взаимодействие с системой строится как двусторонний диалог: пользователь вводит команду, система возвращает результат.

**Приглашение командной строки (prompt)** — строка, которую терминал показывает перед курсором. Её формат задаётся переменной окружения `PS1`. Типичный вид:

```
user@hostname:~$
```

- `user` — имя текущего пользователя.
- `hostname` — имя узла (машины).
- `~` — текущий каталог (тильда обозначает домашний).
- `$` — обычный пользователь; `#` — суперпользователь (root).

**Процесс входа (login):** при подключении к системе запускается программа `login`, которая запрашивает имя пользователя и пароль, проверяет их по базе данных (`/etc/passwd` и `/etc/shadow`), после чего запускает командный интерпретатор (shell) в домашнем каталоге пользователя.

## 2. Ядро и его модули

Ядро Linux является **монолитным**: весь код ядра выполняется в одном привилегированном адресном пространстве (kernel space). При этом ядро **модульное** — его функциональность расширяется за счёт загружаемых модулей.

**Модуль ядра (.ko — kernel object):**
- Перемещаемый объектный файл, скомпилированный специально для данной версии ядра.
- Не является самостоятельной программой — не имеет функции `main()` и не может быть запущен напрямую.
- «Пристыковывается» к работающему ядру командой `insmod` или `modprobe`.
- При загрузке модуль получает доступ к символам (функциям и переменным) ядра.

**Управление модулями:**

| Команда | Что делает |
|---------|-----------|
| `lsmod` | Список загруженных в данный момент модулей |
| `modinfo <module>` | Метаданные модуля (описание, версия, параметры) |
| `modprobe <module>` | Загрузить модуль с автоматическим разрешением зависимостей |
| `rmmod <module>` | Выгрузить модуль |

Модули хранятся в `/lib/modules/<версия_ядра>/`. Система может содержать тысячи модулей (драйверы устройств, сетевые протоколы, криптоалгоритмы), но в любой момент загружены только необходимые.

## 3. Программы и библиотеки

### Формат ELF

Большинство исполняемых файлов в Linux имеют формат **ELF (Executable and Linking Format)**. Тип файла можно определить командой `file`:

```
$ file /bin/ls
/bin/ls: ELF 64-bit LSB pie executable, x86-64, ...
```

ELF-файл содержит заголовок (тип файла, архитектура), секции с кодом и данными, таблицу символов и информацию о зависимостях от библиотек.

### Статическая и динамическая компоновка

- **Статическая:** весь необходимый библиотечный код вшивается непосредственно в исполняемый файл. Файл становится большим, но самодостаточным.
- **Динамическая (разделяемые библиотеки `.so`):** библиотечный код хранится в отдельных файлах и загружается в память один раз, но используется несколькими процессами одновременно. Это основной способ компоновки в Linux.

Динамическим компоновщиком является **`ld.so` / `ld-linux.so`** — он разрешает зависимости и подгружает библиотеки при запуске программы.

**`ldd <program>`** — утилита, показывающая дерево зависимостей программы от разделяемых библиотек:

```
$ ldd /bin/ls
    libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
    linux-vdso.so.1 => (vdso)
```

Почти все программы зависят от **`libc`** (библиотека языка C, реализует стандартные функции: `printf`, `malloc`, `open` и т.д.).

**linux-vdso.so.1 (linux-gate)** — виртуальная разделяемая библиотека, реализуемая самим ядром. Она существует только в виртуальном адресном пространстве каждого процесса и предоставляет механизм быстрых системных вызовов без дорогостоящего переключения в режим ядра через инструкцию `int 0x80` или `syscall`.

## 4. Концепция «Всё есть файл»

Это фундаментальный принцип Unix: **любой ресурс системы доступен через файловый интерфейс**. Четыре системных вызова покрывают подавляющее большинство операций:

```c
int fd = open("/proc/meminfo", O_RDONLY);
read(fd, buf, sizeof(buf));
close(fd);
```

Это означает, что одни и те же инструменты (`cat`, `grep`, `echo`) работают как с обычными файлами, так и с устройствами, процессами и ядром.

### Псевдофайловые системы

Файлы в псевдофайловых системах имеют нулевой размер на диске. При обращении к ним ядро генерирует данные «на лету».

**`/proc` — информация о процессах и состоянии ядра:**
- `/proc/PID/` — каталог каждого живого процесса с его параметрами (`cmdline`, `maps`, `fd/`, `status`...).
- `/proc/meminfo` — текущее состояние памяти.
- `/proc/cpuinfo` — характеристики процессора.
- `/proc/modules` — список загруженных модулей ядра.
- `/proc/mounts` — текущие точки монтирования.

**`/sys` (sysfs) — информация об аппаратуре и шинах:**
- Экспортирует дерево устройств: PCI-шины, USB-хабы, сетевые интерфейсы.
- Позволяет не только читать параметры, но и записывать в них значения для настройки устройств прямо из пространства пользователя.

### Файлы устройств (`/dev`)

Специальные файлы, представляющие аппаратные устройства. При чтении или записи в такой файл ядро перенаправляет операцию соответствующему драйверу.

Идентифицируются двумя числами:
- **Major** — номер драйвера (какой драйвер обслуживает устройство).
- **Minor** — номер конкретного экземпляра устройства.

```
$ ls -l /dev/sda
brw-rw---- 1 root disk 8, 0 ... /dev/sda
                         ^  ^
                      Major Minor
```

## 5. Трассировка: инструменты наблюдения

Трассировщики позволяют «видеть» взаимодействие программы с ядром и библиотеками без изменения её кода.

### strace — системные вызовы

`strace` перехватывает и выводит все обращения программы к ядру (системные вызовы):

```
$ strace date
...
openat(AT_FDCWD, "/etc/localtime", O_RDONLY) = 3
read(3, "TZif2...", 4096) = 2847
close(3) = 0
...
```

Это наглядно показывает, что `date` читает файл часового пояса и запрашивает время у ядра через `clock_gettime`.

Полезные флаги:
- `-e trace=network` — только сетевые вызовы.
- `-p PID` — подключиться к уже запущенному процессу.
- `-o file.txt` — вывод в файл.

### ltrace — вызовы библиотечных функций

`ltrace` работает аналогично `strace`, но перехватывает вызовы к функциям **разделяемых библиотек** (например, `libc`):

```
$ ltrace ls
__libc_start_main(...)
opendir(".")
...
```

Разница принципиальная: `strace` показывает границу **user space / kernel space**, `ltrace` — вызовы внутри user space между программой и библиотеками.
