# Лекция 2. Основы Linux: UNIX, стандарты, пользователи и вход в систему

## 1. Что такое UNIX

**UNIX** — это не одна конкретная операционная система, а **семейство систем** и одновременно **торговая марка**, которой обозначают системы, прошедшие официальную сертификацию. К семейству относятся: Linux (не сертифицирован формально, но POSIX-совместим), FreeBSD, macOS (Darwin), Solaris, AIX, HP-UX.

**История:**
- 1969–1970 гг. — в лаборатории Bell Labs (AT&T) Кен Томпсон и Деннис Ритчи создали систему **UNICS** (UNiplexed Information and Computing Service) — однозадачный ответ на Multics. 1 января 1970 года принято за точку отсчёта времени Unix (Unix Epoch = 0).
- Постепенно система была переписана на языке C, что сделало её переносимой.
- В 1970–80-е годы из AT&T UNIX выросли две ветки: **System V** (коммерческая) и **BSD** (Berkeley Software Distribution, академическая).
- 1991 г. — Линус Торвальдс написал первое ядро Linux под вдохновением от Minix.

## 2. Стандарты: POSIX и SUS

Раздробленность Unix-систем создала проблему несовместимости. Ответом стала стандартизация интерфейсов.

**POSIX (Portable Operating System Interface):**
- Суффикс «X» заимствован из названия семейства UNIX.
- Публикуется как серия стандартов **IEEE 1003.x**.
- Делится на два уровня:
  - **POSIX.1 (IEEE 1003.1)** — стандарт интерфейсов между ядром (kernel mode) и приложениями (user mode): системные вызовы для работы с файлами, процессами, сигналами, памятью.
  - **POSIX.2 (IEEE 1003.2)** — стандарт пользовательского CLI: синтаксис команд, обязательный набор утилит (`ls`, `cat`, `grep`...), поведение оболочки.

**SUS (Single UNIX Specification):**
- Объединяет IEEE 1003.x и ряд других стандартов в один документ.
- Издаётся организацией The Open Group.
- Системы, прошедшие сертификацию SUS, получают право называться «UNIX».

**Практическая ценность:** навыки и программы, написанные под POSIX, переносимы между всеми совместимыми системами (Linux → macOS → Solaris и обратно).

## 3. Архитектура UNIX как набор интерфейсов

Правильный способ изучения UNIX — через **интерфейсы услуг**, которые предоставляет операционная система. Архитектуру можно представить концентрическими кольцами:

```
+---------------------------------------------------+
|           Пользовательские приложения             |
+---------------------------------------------------+
|       Командный интерпретатор (Shell)             |
+---------------------------------------------------+
|       Системные библиотеки (libc и др.)           |
+---------------------------------------------------+
|        POSIX API (системные вызовы)               |
+-------------------+---------+--------------------+
|                   |  ЯДРО   |                    |
|   Файловая    | Процессы |   Устройства       |
|   система     |  памяти  |   драйверы         |
+---------------------------------------------------+
|                 Аппаратура                        |
+---------------------------------------------------+
```

CLI — не просто удобный инструмент, а **главный интерфейс** для понимания системы. Специалист, понимающий внутреннее устройство ОС, принципиально отличается от того, кто просто знает набор команд.

## 4. Учётные записи пользователей

### Зачем нужны учётные записи

Система должна знать, **кто** что делает, чтобы обеспечить разграничение доступа к файлам, процессам и ресурсам. Учётные записи — механизм идентификации субъектов (людей или служб).

### Модель DAC (Discretionary Access Control)

Linux использует **дискреционное разграничение доступа**: каждый объект (файл, каталог) имеет **владельца**, который самостоятельно определяет права доступа для других пользователей. Права проверяются ядром на основе числовых идентификаторов — UID и GID.

### Поля учётной записи пользователя

Хранятся в `/etc/passwd` (незащищённые поля) и `/etc/shadow` (хэш пароля):

| Поле | Описание |
|------|----------|
| **Login Name** | Строковой идентификатор для входа. Используется при аутентификации. |
| **Password** | Средство аутентификации. В `/etc/shadow` хранится не сам пароль, а его хэш (обычно SHA-512). |
| **UID (User IDentifier)** | 32-битное целое число. Ядро использует именно его — не имя — при проверке прав. |
| **GID (Group IDentifier)** | Идентификатор первичной группы пользователя. |
| **GECOS** | Поле комментария: настоящее имя, телефон, кабинет. Используется командой `finger`. |
| **Home Directory** | Путь к домашнему каталогу — личному пространству пользователя. |
| **Shell** | Полный путь к командному интерпретатору, запускаемому при входе. |

### Суперпользователь root

- UID = **0** — зарезервировано за root.
- Ядро обходит все проверки DAC при UID=0: суперпользователь может читать, писать и выполнять любой файл независимо от прав, убивать любой процесс, монтировать файловые системы и т.д.
- Это делает компрометацию root критичной для безопасности системы.

## 5. Групповые учётные записи

### Назначение

Группы созданы для **удобства администрирования**: вместо назначения прав каждому пользователю по отдельности можно назначить их группе целиком.

Пример: группа `developers` имеет доступ к репозиторию — все, кто входит в группу, автоматически получают этот доступ.

### Поля группы (`/etc/group`)

| Поле | Описание |
|------|----------|
| **Name** | Строковое имя группы. |
| **Password** | Атавизм из ранних Unix — в современных системах практически не используется. |
| **GID** | 32-битный идентификатор группы. |
| **Member List** | Список логинов пользователей, входящих в группу. |

### Первичная и дополнительные группы

- **Первичная (PRIMARY):** указана в `/etc/passwd`. Файлы, созданные пользователем, получают GID первичной группы.
- **Дополнительные (SUPPLEMENTARY):** перечислены в `/etc/group`. Пользователь наследует права всех своих дополнительных групп одновременно.

### Проблема списка членов

Список членов группы в `/etc/group` хранится по **Login Name**, а не по UID. Это создаёт потенциальную несогласованность: если пользователь переименован, его членство в группе нужно обновлять вручную. Исторически это было компромиссом — в эпоху до списков членов пользователи сами переключались между группами командой `newgrp`.

## 6. Вход в систему и терминалы

### Процесс входа

1. **getty** — программа, отслеживающая физический или виртуальный терминал, выводит строку `login:`.
2. **login** — принимает имя пользователя, запрашивает пароль, проверяет его хэш в `/etc/shadow`.
3. При успехе запускается указанный в `/etc/passwd` **Shell** в домашнем каталоге пользователя.

### Терминалы

**Виртуальные терминалы (VT, tty1–tty6):**
- Linux поддерживает несколько независимых текстовых сеансов на одной машине.
- Переключение: `Alt+F1`…`Alt+F6` (в текстовом режиме) или `Ctrl+Alt+F1`…`Ctrl+Alt+F6` (из графики).
- Каждый VT — отдельное устройство: `/dev/tty1`, `/dev/tty2` и т.д.

**Графический сеанс:**
- X Window System или Wayland — это обычная пользовательская служба, запущенная на одном из виртуальных терминалов (как правило, tty7 или tty8).
- Внутри графической оболочки эмуляторы терминала (xterm, gnome-terminal) создают **псевдотерминалы (pts)** — `/dev/pts/0`, `/dev/pts/1`...

**CLI vs GUI:**
- CLI компактнее, мощнее для автоматизации, не требует графической подсистемы.
- GUI удобнее для работы с множеством окон и визуального контента.
- Специалист по Linux обязан свободно работать в CLI.

## 7. Ключевые команды

| Команда | Что делает |
|---------|-----------|
| `whoami` | Имя текущего пользователя (по UID процесса) |
| `id` | UID, GID и список всех групп пользователя |
| `hostname` | Имя узла |
| `pwd` | Текущий рабочий каталог |
| `tty` | Имя устройства текущего терминала (`/dev/tty1`, `/dev/pts/0`) |
| `users` | Список пользователей, вошедших в систему (краткий) |
| `who` | Кто вошёл, с какого терминала и когда |
| `w` | Расширенный `who`: ещё показывает, что делает каждый пользователь |
| `finger <login>` | Подробная информация: полное имя, домашний каталог, время последнего входа |
| `sudo <команда>` | Выполнить команду с правами root (SuperUser Do); требует пароль текущего пользователя |

**Условное «3D пространство» CLI:**
- Горизонталь — несколько одновременных терминальных сеансов.
- Вертикаль — переключение между виртуальными терминалами.
- Глубина — история команд, фоновые процессы.

Это принципиально отличает CLI от GUI, где пользователь всегда «в одном месте».
