# pipes — межпроцессный канал данных

## Что это

Pipe — однонаправленный буфер в памяти ядра с двумя файловыми дескрипторами: один конец пишет, другой читает.

## Как работает

```
pipe(fd) создаёт:
  fd[0] — читающий конец  (read end)
  fd[1] — пишущий конец  (write end)

Процесс A           ядро (буфер)          Процесс B
write(fd[1]) ──→  [ h e l l o \n ]  ──→  read(fd[0])
```

1. `pipe(fd)` — вызвать ДО `fork()`, иначе процессы получат разные несвязанные трубы
2. После `fork()` оба процесса наследуют оба конца
3. Каждый закрывает ненужный конец — иначе EOF никогда не придёт
4. Пишущий: `write(fd[1], buf, strlen(buf))` — не `sizeof`, строка может быть короче буфера
5. Читающий: цикл `while ((n = read(fd[0], buf, sizeof(buf)-1)) > 0)`, `buf[n] = '\0'`
6. При закрытии пишущего конца — `read()` вернёт 0 (EOF)

## Пример

```c
int fd[2];
pipe(fd);

if (fork() == 0) {       // дочерний
    close(fd[0]);
    char buf[256];
    while (fgets(buf, sizeof(buf), stdin) != NULL)
        write(fd[1], buf, strlen(buf));
    close(fd[1]);
} else {                 // родитель
    close(fd[1]);
    char buf[128]; int n;
    while ((n = read(fd[0], buf, sizeof(buf) - 1)) > 0) {
        buf[n] = '\0';
        fprintf(stdout, "[parent received] %s", buf);
    }
    waitpid(-1, NULL, 0);
}
```

## Подводные камни

| Ошибка | Последствие |
|--------|-------------|
| `pipe()` после `fork()` | Процессы не связаны, данные не передаются |
| Не закрыть ненужный конец | `read()` блокируется навсегда, EOF не приходит |
| `write(fd[1], buf, sizeof(buf))` | Отправляется мусор после нуля |
| `read()` без нуль-терминатора | `printf` читает мусор за пределами строки |
| `buf[n] = '\0'` когда `buf[n]` — выход за границу | Если `n == sizeof(buf)`, запись за массив |
