# Красно-чёрные деревья (red-black trees, КЧ)

> Опора — конспект препода (раздел 3). Здесь он развёрнут по 7-пунктовому шаблону +
> сквозные темы + параллели. **КЧ = симметричное двоичное B-дерево (СДБ) в цвето-терминах**
> (Guibas–Sedgewick 1978): красное ребро = горизонтальная связь, чёрное = вертикальная.

## 1. Определение

**Красно-чёрное дерево** — самобалансирующееся двоичное дерево поиска (BST), где у каждого узла есть дополнительный атрибут **цвет** (красный/чёрный), а баланс поддерживается пятью правилами окраски. Гарантирует поиск/вставку/удаление за **O(log n)** в худшем случае.

**Пять свойств (инвариантов):**
1. Каждый узел либо красный, либо чёрный.
2. **Корень всегда чёрный.**
3. Все листья (NULL-узлы, NIL) считаются чёрными.
4. **Если узел красный — оба его потомка чёрные** (нет двух красных подряд).
5. **Для каждого узла все пути от него до листьев содержат одинаковое число чёрных узлов** — это **чёрная высота (black height)**.

Свойства 4 и 5 вместе и дают баланс: самый длинный путь (чередование красных и чёрных) не более чем **вдвое** длиннее самого короткого (только чёрные).

## 2. Пример (на C)

```c
typedef enum { RED, BLACK } Color;

typedef struct rb_node {
    int key;
    Color color;
    struct rb_node *left;
    struct rb_node *right;
    struct rb_node *parent;   // родитель нужен для балансировки (смотрим дядю/деда)
} RBNode;
```
Отличие от обычного BST: поле `color` + **указатель на родителя** `parent` (балансировка смотрит вверх — на отца P, деда G, дядю U).

## 3. Особенности

- Обозначения при вставке: **N** — новый узел, **P** — отец, **G** — дед, **U** — дядя (брат P, второй сын G).
- Новый узел всегда вставляется **красным** (чтобы не нарушить свойство 5 о чёрной высоте — красный не меняет число чёрных на пути). Нарушиться может свойство 4 (два красных подряд).
- Баланс **ослабленный** по сравнению с AVL: КЧ не держит строгую разницу высот ≤1, поэтому КЧ может быть выше AVL, но **перебалансируется дешевле** (меньше вращений на вставку/удаление).

## 4. Плюсы и недостатки

**Плюсы:**
- O(log n) гарантированно на всех операциях (худший случай).
- **Вставка/удаление дешевле, чем в AVL** по числу вращений (≤2 на вставку, ≤3 на удаление) → выгодно при частых модификациях.
- Один служебный бит (цвет) — экономно по памяти.
- Локальная балансировка (перекраски + малое число вращений).

**Недостатки:**
- **Поиск медленнее, чем в AVL** в среднем (дерево выше — слабее баланс).
- Сложнее в реализации, особенно удаление (4 случая с «двойной чёрнотой»).

> Правило выбора: **много чтения → AVL** (строже баланс, ниже дерево); **много вставок/
> удалений → КЧ** (дешевле перебалансировка). См. [[avl]].

## 5. Где применяется

- **C++ STL:** `std::map`, `std::set`, `std::multimap` — на КЧ-дереве.
- **Java:** `TreeMap`, `TreeSet`.
- **Ядро Linux:** планировщик **CFS** (дерево задач по vruntime); **`epoll`** хранит отслеживаемые fd в rbtree; управление **VMA** (областями виртуальной памяти процесса). → Прямая связь с твоим системным/сетевым вектором.
- Многие C-библиотеки ассоциативных массивов.

## 6. Операции

### Поиск
Как в обычном BST (цвет на поиск не влияет): `key < node->key` → влево, иначе вправо. O(log n).
```c
RBNode* rb_search(RBNode* root, int key) {
    if (!root || root->key == key) return root;
    return key < root->key ? rb_search(root->left, key)
                           : rb_search(root->right, key);
}
```

### Вставка (балансировка по случаям)
Вставили N красным как лист. Дальше чиним свойство 4 снизу вверх:
1. **N — корень** → перекрасить в чёрный. Готово.
2. **P чёрный** → всё сбалансировано (красный N под чёрным P не нарушает правил). Готово.
3. **P и U оба красные** → **перекраска**: P и U → чёрные, G → красный. Затем повторить проверку для G (нарушение могло «всплыть» вверх). Это дешёвый случай — без вращений.
4. **P красный, U чёрный (или NIL)** → **вращения** (большой/малый поворот), затем перекраска. Подслучаи по форме (LL/LR/RR/RL — как в AVL):
   - N и P с одной стороны (LL/RR) → одно вращение деда G + перекраска P↔G.
   - N и P с разных сторон (LR/RL) → сначала вращение P, сводим к предыдущему, потом G.

### Удаление
Удаляем как в BST (узел с 2 детьми → замена на преемника/предшественника). Проблема, если удалили **чёрный** узел (нарушится свойство 5 — чёрная высота). Чиним по 4 случаям через брата (sibling) S удаляемого «двойного-чёрного» места:
- **Случай 1:** брат красный → перекраска + вращение (сводим к случаю с чёрным братом).
- **Случай 2:** брат и оба его потомка чёрные → перекрасить брата в красный, «дефицит чёрного» поднять к родителю и продолжить вверх.
- **Случай 3:** брат чёрный, его **ближний** потомок красный, дальний чёрный → вращение брата (сводим к случаю 4).
- **Случай 4:** брат чёрный, его **дальний** потомок красный → перекраска + вращение — завершает балансировку.

## 7. Сложность

```
Операция   | Худший случай
-----------|---------------
Поиск      | O(log n)
Вставка    | O(log n)   (вращений ≤ 2)
Удаление   | O(log n)   (вращений ≤ 3)
Память     | O(n) + 1 бит цвета на узел
```
**Граница высоты:** `h ≤ 2·log₂(n+1)`. Вывод (идея): пусть bh — чёрная высота корня. По свойству 5 на любом пути ровно bh чёрных узлов; по свойству 4 красных не больше, чем чёрных (не идут подряд) → полная высота h ≤ 2·bh. Поддерево с чёрной высотой bh содержит ≥ 2^bh − 1 внутренних узлов → n ≥ 2^bh − 1 → bh ≤ log₂(n+1) → **h ≤ 2·log₂(n+1) = O(log n)**.

## Сквозные темы

- **Память:** 1 бит цвета (часто паковали в младший бит выровненного указателя на родителя). Динамика → риски dangling pointer / use-after-free при ошибках перецепки во вращениях.
- **Связь с B-деревом:** КЧ ≡ 2–3–4-дерево (узел B-дерева = чёрный узел + его красные дети). Чёрная высота КЧ = высота соответствующего B-дерева.

## Параллели и trade-offs

- **Python:** в stdlib нет КЧ напрямую; `dict`/`set` — хеш. Упорядоченность — через `sortedcontainers` (B-tree-подобное) или `bisect` на списке.
- **Rust:** `BTreeMap`/`BTreeSet` — это **B-дерево**, не КЧ (для cache-эффективности).
- **vs AVL:** AVL строже (h ≤ 1.44·log₂n), быстрее поиск, дороже вставка; КЧ слабее баланс, дешевле модификации. См. [[avl]].
- **vs хеш:** КЧ держит **порядок** (можно обходить по сортировке, диапазонные запросы), хеш даёт O(1), но порядка нет. См. [[hashing]].

## Ключевые термины (English)

- **red-black tree** — красно-чёрное дерево.
- **black height (bh)** — чёрная высота (число чёрных узлов на пути до листа).
- **NIL / sentinel leaf** — чёрный лист-ограничитель.
- **recoloring** — перекраска; **rotation** — вращение (left/right).
- **uncle / sibling** — дядя (при вставке) / брат (при удалении).
- **double black** — «двойная чёрнота» (дефицит чёрного при удалении чёрного узла).
- **left-leaning red-black (LLRB)** — упрощённый вариант Седжвика (как 2–3-дерево).
