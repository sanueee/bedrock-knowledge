# Хеш-таблицы и ассоциативные массивы (hash tables)

> У тебя по теме было пусто — конспект по общим источникам. Канон препода (тест прошлого года):
> «подсчёт **строк / символов / бинарных операций** → хеш-таблица». Это его опорная ассоциация.

## 1. Определение

**Хеш-таблица** — структура для хранения пар «ключ → значение», обеспечивающая в среднем **O(1)** на вставку/поиск/удаление. Идея: **хеш-функция** `h(key)` отображает ключ в индекс массива (бакет, bucket), куда кладётся элемент. **Ассоциативный массив (associative array / map / dictionary)** — это абстрактный тип (ADT), который хеш-таблица реализует (другая реализация того же ADT — сбалансированное дерево, см. [[red-black]]).

## 2. Пример (на C)

```c
#define M 1024                 // размер таблицы (число бакетов)

typedef struct entry {         // элемент цепочки (для chaining)
    char *key;
    int value;
    struct entry *next;
} Entry;

Entry *table[M];               // массив указателей на цепочки

unsigned hash(const char *s) { // пример: полиномиальный хеш строки
    unsigned h = 0;
    while (*s) h = h * 31 + (unsigned char)*s++;
    return h % M;
}
```

## 3. Особенности

- **Хеш-функция** должна быть: детерминированной, быстрой, **равномерно** распределять ключи (минимум коллизий), использовать все биты ключа.
- **Коллизия (collision)** — два разных ключа дали один индекс. Неизбежна при n > m (принцип Дирихле); нужна стратегия разрешения.
- **Коэффициент загрузки (load factor)** `α = n/m` (n элементов, m бакетов) — главный параметр производительности. При росте α растут коллизии → **рехеширование (rehashing)**: новый массив большего размера (обычно ×2) + перевставка всех элементов.

## 4. Плюсы и недостатки

**Плюсы:**
- Среднее **O(1)** на поиск/вставку/удаление — быстрее любого дерева.
- Просто и компактно для задач «есть ли элемент», «посчитать частоты».

**Недостатки:**
- **Нет порядка** — нельзя обойти по сортировке, нет диапазонных запросов, нет min/max за O(log n) (в дереве — можно). За этим → к BST/КЧ.
- **Худший случай O(n)** (все ключи в один бакет / кластеризация).
- Качество целиком зависит от хеш-функции; уязвимо к **hash-flooding** атакам (специально подобранные ключи в один бакет → DoS; защита — рандомизированный seed, SipHash).
- Рехеширование — редкая дорогая операция O(n) (амортизируется).

## 5. Где применяется

- **Ядро ОС:** таблицы процессов, инодов, страничные кеши (по хешу адреса/inode).
- **Компиляторы:** таблицы символов (symbol table) — идентификаторы → атрибуты.
- **Кеши, дедупликация, индексы в памяти**, множества (set), подсчёт частот.
- **Языки:** Python `dict`/`set`, Java `HashMap`, C++ `unordered_map`.
- **Безопасность:** проверка целостности (хеш файла), но это **криптографические** хеши — другое (стойкость к коллизиям), не путать с хеш-таблицами (там важна скорость+равномерность).

## 6. Операции — разрешение коллизий (главная тема)

### Метод цепочек (separate chaining)
Каждый бакет — связный список (или дерево) элементов с одинаковым индексом.
```
table[h] → [k1|v1] → [k2|v2] → NULL
```
- Вставка O(1) (в голову), поиск — пройти цепочку (в среднем α элементов).
- Простой, не «ломается» при α>1, но накладные расходы на указатели + промахи кеша.

### Открытая адресация (open addressing)
Все элементы — **в самом массиве**; при коллизии ищем следующий свободный слот по правилу **пробирования (probing)**:
- **Линейное (linear probing):** `h, h+1, h+2, …` (mod m). Просто, кеш-дружелюбно, но даёт **первичную кластеризацию (primary clustering)** — длинные занятые участки.
- **Квадратичное (quadratic probing):** `h, h+1², h+2², …` — лечит первичную, даёт вторичную.
- **Двойное хеширование (double hashing):** шаг = вторая хеш-функция `h₂(key)` — лучшее распределение, нет кластеризации.
- Требует α < 1 (массив не должен переполниться); удаление сложнее (нужны «надгробия», tombstones, чтобы не разорвать цепочку проб).

```
Chaining vs Open addressing:
chaining       — память динамическая, α может быть >1, удаление простое
open addressing— всё в массиве, кеш-дружелюбно, α<1, удаление через tombstone
```

## 7. Сложность

```
                  | Среднее | Худший
------------------|---------|--------
Поиск             | O(1)    | O(n)
Вставка           | O(1)    | O(n)   (+ амортизир. O(n) рехеш)
Удаление          | O(1)    | O(n)
Память            | O(n + m)
```
- **Среднее O(1)** — при хорошей хеш-функции и ограниченном α (держат α ≤ ~0.7 для open addressing, ~1 для chaining); ожидаемая длина цепочки = α = O(1).
- **Худший O(n)** — все ключи в один бакет (плохой хеш или атака) → вырождение в список.
- Рехеширование — O(n), но редко → амортизированно O(1) на вставку.

## Сквозные темы

- **Память:** chaining → динамические узлы (риск dangling/UAF, фрагментация); open addressing → один массив (лучше локальность, но tombstones засоряют). Связь с [[memory-problems]].
- **Мощность/равномерность:** хорошая хеш-функция «размазывает» #ключей по m бакетам равномерно.

## Параллели и trade-offs

- **vs сбалансированное дерево (КЧ/AVL):** хеш — O(1) средн., **без порядка**; дерево — O(log n), **с порядком** (обход по сортировке, диапазон, min/max). Выбор: нужен порядок → дерево.
- **vs битовое множество ([[set]]):** bitset — для плотного диапазона малых целых (O(1), компактно); хеш — для произвольных/разреженных ключей.
- **Python `dict`** — open addressing; **Java `HashMap`** — chaining (+ переход на дерево в бакете при длинной цепочке, с Java 8); **Rust `HashMap`** — open addressing (SipHash по умолч.).

## Ключевые термины (English)

- **hash table / hash function** — хеш-таблица / хеш-функция.
- **bucket / slot** — бакет / слот.
- **collision** — коллизия.
- **load factor α = n/m** — коэффициент загрузки.
- **separate chaining** — метод цепочек.
- **open addressing / probing** — открытая адресация / пробирование.
- **linear / quadratic probing, double hashing** — линейное/квадратичное пробирование, двойное хеширование.
- **primary / secondary clustering** — первичная / вторичная кластеризация.
- **rehashing** — рехеширование (расширение + перевставка).
- **tombstone** — «надгробие» (метка удаления при open addressing).
- **associative array / map / dictionary** — ассоциативный массив (ADT).
