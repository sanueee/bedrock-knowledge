# Множество / Set

## Определение

Неупорядоченная коллекция **уникальных** элементов. Элемент либо есть, либо нет; дубликатов и порядка не существует. Главная операция — **принадлежность** (membership).

## Ключевые термины (English)

- **set** — множество; **membership** — принадлежность (`x in A`).
- **universe (U)** — юниверс: множество всех возможных элементов (базовый тип).
- **bit set / bit vector** — битовое множество (1 бит на элемент юниверса).
- **union / intersection / difference / symmetric difference** — ∪ / ∩ / − / Δ.
- **direct-address table** — прямая адресация (≠ open addressing — это про коллизии в хеше!).

## Юниверс

Юниверс = базовый тип множества (как Tbase у массива): `set of 1..10` в Pascal — кандидаты только из 1..10. Размер юниверса = мощность базового типа.

## Операции (Pascal-нотация из лекции → битовые операторы C)

```
операция            Pascal     C (битсет)
принадлежность      x in A     (A >> x) & 1
объединение  A∪B    A + B      A | B
пересечение  A∩B    A * B      A & B
разность     A−B    A - B      A & ~B
симметр. Δ          —          A ^ B
подмножество        A <= B     (A & B) == A
```

⚠️ **Pascal-операторы `+ * -` в C — арифметика, не множества!** `A + B` при общих битах даёт перенос (carry) → мусорные элементы. Только битовые `| & ~ ^`. (Реальная ошибка из практики: написал `set_print(A+B)` — Pascal-синтаксис в C.)

## В C типа set нет — реализации и сложность (ядро темы, Л3)

```
                          membership   вставка      память
битовое множество         O(1)         O(1)         O(U) бит — от ЮНИВЕРСА
неотсорт. массив          O(n)         O(n)*        O(n)
отсорт. массив            O(log n)     O(n) сдвиг   O(n)
связный список            O(n)         O(n)*        O(n) + указатели
BST (сбалансир.)          O(log n)     O(log n)     O(n) + указатели
хеш-таблица               O(1) средн.  O(1) средн.  O(n)…O(m)
```

`*` — «O(1) со звёздочкой»: запись в конец O(1), но уникальность требует membership-чека ПЕРЕД вставкой → честная вставка O(n).

**Выбор:** юниверс маленький (≤ десятков тысяч) → битсет. Юниверс огромный / разрежённый (0..10⁶ при 2 элементах: битсет = 125 КБ впустую) → **хеш-таблица** (хеш-функция загоняет любой диапазон в строгие границы). Та же болезнь, что у direct-address `freq[]` из [[arrays]].

## Битовое множество (звезда темы)

Каждому элементу юниверса — один бит: множество = число. `A = {1,3,5,9}` → биты 1,3,5,9 → как число 554. Pascal `set of 1..100` внутри так и устроен.

```c
*s |=  (uint64_t)1 << x;     // add
*s &= ~((uint64_t)1 << x);   // remove (инвертированная маска!)
(s >> x) & 1                 // has
```

∪/∩ целых множеств — **одна процессорная инструкция** на 64 элемента.

### C-ловушки (из практики `knowledge-base/university/2-semester/ds/practice/bitset/bitset.c`)

- Сдвигать **`(uint64_t)1`**, не литерал `1` (он `int`; сдвиг ≥ 32 — UB).
- `remove`: `0 << x` == 0 → `&= 0` стирает ВСЁ множество. Нужна маска «все, кроме x» = `~(1 << x)`.
- `has`, возвращающий `int`: `s & (1<<x)` для x ≥ 32 усекается до 0 → нормализовать (`!= 0` или `(s >> x) & 1`).

## Где применяется

Unix-права `rwxr-xr-x` (битовая маска), `fd_set` в `select()`, `sigset_t`, bitmap-аллокаторы в ФС, флаги компиляторов.

## Параллели

Python `set` — хеш-реализация; Rust `HashSet` (хеш) / `BTreeSet` (дерево, с порядком) — выбор = строка из таблицы сложностей.

## Подводные камни

- Pascal `+ * -` ≠ C `| & ~` (carry портит результат).
- Память битсета — от размера **юниверса**, не от числа элементов.
- Прямая адресация ≠ открытая адресация (первая — индекс=ключ; вторая — разрешение коллизий в хеш-таблице).
