# B-дерево / B-tree

> Построено руками: вставка `20 40 10 30 15 35 5 25 50 45` (рост высоты на 5),
> удаление `50 25 30 5` (каскадный merge → высота 3→2). Код — `knowledge-base/university/2-semester/ds/practice/btree/btree.c` (планируется).
> Мотив: уменьшить **высоту** → меньше обращений к диску. Растёт **вверх** (раскол корня),
> сжимается **через корень** (merge до корня).

## Что это
Сбалансированное **multi-way** дерево поиска: в узле много ключей и много детей, **все листья на одном уровне**. Спроектировано под блочную/дисковую память (узел = блок диска). Прямое обобщение BST: k ключей → k+1 поддерево, каждый ключ — разделитель между соседними поддеревьями.

## Зачем (мотивация — единственная)
Узкое место на диске — не сравнения CPU, а **обращения к диску** (одно ≈ миллионы тактов). Высота AVL на 1e9 ключей ≈ 30 → 30 чтений. B-дерево с узлом на 100 ключей → высота ≈ 4–5. Набиваем узел ключами под размер блока → высота падает. Всё.

## Терминология «степень» — ОСТОРОЖНО, перегружена
Одно дерево описывают тремя способами, и все три зовут «степень/порядок». На экзамене: **не держи слово, держи пару чисел (min ключей, max ключей).** Перевод:
```
КОНВЕНЦИЯ          параметр   max ключей   max детей    что меряет
порядок m          m          m-1          m            МАКСИМУМ детей
мин. степень t     t (CLRS)   2t-1         2t           МИНИМУМ детей (не-корень)
степень d (Вирт)   d          2d           2d+1         МИНИМУМ ключей (не-корень)
```
Связи: `m = 2t`, `d = t-1`. Пример коллизии у препода:
- слайд «B-дерево степени 1» (Вирт d=1) → max 2 ключа → **2-3 дерево** (= мой порядок m=3);
- слайд кода `#define N 2 // мин. степень`, `keys[2N-1]` (CLRS t=2) → max 3 ключа → **2-3-4 дерево**. «степень N-1 = BST» — **неверно**: BST = max 1 ключ на узел (`m=2`), вырожденный случай.

## Инварианты (B-дерево порядка m)
```
1. каждый узел:        ≤ m детей,  ≤ m-1 ключей
2. каждый НЕ-корень:   ≥ ⌈m/2⌉ детей,  ≥ ⌈m/2⌉-1 ключей   (узел заполнен ≥ наполовину)
3. корень:             ≥ 1 ключ (≥ 2 детей, если не лист)
4. все листья на ОДНОМ уровне
5. ключи в узле отсортированы; k ключей → k+1 ребёнок  ← главный контроль при построении
```
Инвариант 2 (нижняя граница) — сердце: не даёт дереву выродиться в высокое/редкое → высота O(log n). Это то, чего нет у BST; баланс держится **расколом/слиянием**, а не поворотами (как AVL/RB).

## Пример (узел = массивы)
```c
#define M 5                      /* порядок: ≤ M детей, ≤ M-1 ключей */
typedef struct BTreeNode {
    int n;                       /* текущее число ключей */
    int keys[M - 1];             /* отсортированы по возрастанию */
    struct BTreeNode *child[M];  /* n+1 детей (на 1 больше ключей) */
    int leaf;                    /* 1 = лист */
} BTreeNode;
```
Геометрия: `всё в child[i] < keys[i] < всё в child[i+1]`.

## Операции
- **search** — как BST, но внутри узла линейный/бинарный поиск по массиву ключей; спуск в нужный промежуток. На уровень — 1 чтение диска.
- **insert** — всегда в **лист**. Переполнение (m ключей) → **split**: медиана наверх, два крайних расходятся; родитель получает +1 ребёнка. Каскад вверх; раскол корня → высота +1.
  > Рост — ТОЛЬКО через раскол корня (следствие «все листья на одном уровне»). Растёт ВВЕРХ.
- **delete** — свести к листу: ключ во внутреннем узле → заменить на **преемника/предшественника** (он в листе) → удалять из листа. Underflow (ключей < минимума) чиним:
  - **borrow** (брат богатый, ключей > минимума): разделитель родителя ↓ к нам, крайний ключ брата ↑ в родителя (у левого брата — его max, у правого — его min); крайний ребёнок брата переходит к нам;
  - **merge** (все братья на минимуме): наш узел + разделитель родителя + брат → один узел; родитель теряет ключ → может уйти в underflow → чиним ВВЕРХ; корень опустел → высота −1.

## split ↔ merge — зеркало (ключ к каскаду)
```
split (вставка):  один узел → ДВА узла; дети РАСПРЕДЕЛЯЮТСЯ между половинами (каждый отдельно)
merge (удаление): ДВА узла → один узел; дети СОБИРАЮТСЯ вместе         (каждый отдельно)
```
Сливаются/раскалываются только сами «коробки с ключами». **Дети — готовые поддеревья, они НЕ слипаются между собой**, просто встают в ряд (разделённые ключами в правильном порядке).

## Сложность — вывод высоты
```
t = ⌈m/2⌉ (мин. детей не-корня).  Минимум узлов по уровням даёт макс. высоту:
  ур.0:1  ур.1:2  ур.2:2t  ур.3:2t² ... ур.h:2t^(h-1)
  n ≥ 1 + (t-1)·(2 + 2t + ... + 2t^(h-1)) = 2·t^h − 1
  ⇒ t^h ≤ (n+1)/2  ⇒  h ≤ log_t((n+1)/2)  ⇒  h = O(log_t n)
```
| операция | сравнения  | обращения к диску |
|----------|------------|-------------------|
| search   | O(log n)   | O(log_t n) = O(h) |
| insert   | O(log n)   | O(log_t n)        |
| delete   | O(log n)   | O(log_t n)        |

Тонкость препода: внутри узла ещё O(t) работы → строго `O(t·log_t n)` сравнений, но **число обращений к диску = высота = O(log_t n)** — метрика, ради которой структуру и придумали.

## B-дерево vs B+-дерево
```
B-tree:  данные и во внутренних узлах, и в листьях.
B+-tree: ВСЕ данные только в листьях; внутренние — только ключи-разделители;
         листья связаны в список → диапазонный обход = пройти по листьям слева направо.
```
БД используют B+ (range scan без возврата вверх + внутренние узлы ветвистее).

## Плюсы / минусы
**+** малая высота → мало disk reads; отличный range scan/сортированный обход; баланс без поворотов. **−** сложнее BST; узлы заполнены частично (~75%) → перерасход памяти; в RAM избыточно (RB/AVL проще).

## Где применяется
- **Индексы БД** — PostgreSQL, SQLite, MySQL/InnoDB (на практике B+).
- **Файловые системы** — ext4 (HTree), NTFS, Btrfs, HFS+, XFS. Узел = страница 4–16 КБ.
- **ИБ/форензика** — разбор B-tree каталогов FS при восстановлении удалённых записей.
- **Rust:** `std::collections::BTreeMap`/`BTreeSet` — это B-дерево (сортированный обход + `.range()`), в отличие от `HashMap`. Ответ на «зачем BTreeMap при HashMap»: **порядок + диапазоны** ценой O(log n).

## Подводные камни (вскрылось при построении руками 2026-06-15)
- **«k ключей → k+1 ребёнок» — главный самоконтроль.** Посчитал детей ≠ k+1 → потерял узел (типичная ошибка: при split родитель забыл получить нового ребёнка).
- **Каскадный merge:** при merge ВНУТРЕННИХ узлов легко по ошибке слить ДЕТЕЙ двух узлов в один лист (`[35]`+`[45]`→`[35 45]`). Нельзя: дети остаются отдельными поддеревьями, собираются в ряд и разделяются ключами. Сливаются только сами узлы + разделитель родителя.
- **Underflow внутреннего узла чинится ТЕМ ЖЕ правилом**, что и лист (borrow/merge) — просто у узла есть дети, которые при merge собираются, при borrow — один крайний передаётся вместе с ключом.
- **преемник vs предшественник** (слабое место, [[trees-bst]]): преемник = min правого поддерева, предшественник = max левого. Оба годятся для удаления из внутреннего узла.

## Ключевые термины (English)
- **B-tree / order m / minimum degree t** — B-дерево / порядок / минимальная степень.
- **multi-way search tree** — сильно ветвящееся дерево поиска.
- **split / merge / borrow (rotate)** — раскол / слияние / заём у соседа.
- **underflow / overflow** — дефицит / переполнение узла.
- **median promotion** — поднятие медианы вверх при расколе.
- **separator key** — ключ-разделитель родителя между двумя детьми.
- **disk block / page** — блок диска / страница (узел B-дерева = один блок).
- **B+ tree / range scan** — B+-дерево / диапазонный обход.
