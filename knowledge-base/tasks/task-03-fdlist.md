# Task 03 — fdlist

## Задание

Утилита на C: принимает PID как аргумент, выводит все открытые файловые дескрипторы этого процесса.

```
$ ./fdlist 1234
fd 0 -> /dev/null
fd 1 -> /dev/null
fd 2 -> /var/log/nginx/error.log
fd 4 -> socket:[12345]
```

Требования:
- Читать `/proc/<pid>/fd/` через `opendir`/`readdir`
- `readlink` для каждой записи
- Без внешних утилит

## Моё решение

1. Принять PID из `argv[1]`, собрать путь `/proc/<pid>/fd` через `snprintf`
2. `opendir` на эту директорию, `readdir` в цикле
3. Фильтровать `.` и `..` через `strcmp`
4. `snprintf` полный путь к симлинку, `readlink` → буфер с целью
5. Нуль-терминировать буфер вручную (`target[len] = '\0'`)
6. Вывести `fd N -> target`

## Ключевые функции

| Функция | Зачем |
|---|---|
| `opendir` / `readdir` | итерация по `/proc/<pid>/fd/` |
| `snprintf` | сборка путей `/proc/<pid>/fd` и `/proc/<pid>/fd/<name>` |
| `readlink` | читает куда ведёт симлинк, не следуя по нему |
| `strcmp` | фильтр `.` и `..` |

## Тест на Linux (Ubuntu 24.04, aarch64)

```bash
./fdlist $$          # fd шелла: 0,1,2 -> /dev/tty1, fd 255 -> /dev/tty1
sudo ./fdlist $(pgrep systemd-journal)   # полная картина демона логов
```

Вывод fdlist на systemd-journal показал: сокеты от других процессов, файлы journal на диске,
`/dev/kmsg` для логов ядра, `anon_inode` — специальные механизмы ядра (epoll, signalfd, timerfd).

**Баги найденные на Linux:**
- `full_path[128]` — компилятор предупредил о возможном переполнении. Увеличил до 384.
- `%llu` для `uint64_t` — на Linux это `%lu`, не `%llu`. Заменил на `PRIu64` из `<inttypes.h>`.

**Права:** `/proc/<pid>/fd` чужого процесса требует root. Без sudo — "error: opening". Это не баг.

## Ошибки и трудности

**Симлинки остались абстрактными** — концептуально понял (файл-ярлык), но интуиции пока нет. Помогло бы потрогать руками: создать симлинк через `ln -s`, посмотреть `ls -la`, затем `readlink`. Разрыв между "понимаю объяснение" и "вижу в системе" пока есть.

**`readlink` не добавляет `\0`** — неочевидно из сигнатуры. Нужно помнить: `ssize_t len = readlink(..., buf, sizeof(buf)-1); buf[len] = '\0';`

**`full_path` слишком мал** — `char full_path[128]` при `path[128]` — компилятор предупреждает. Буфер результата должен быть не меньше суммы входных строк.

## Что бы сделал иначе

- Сначала поиграть с симлинками в шелле (`ln -s`, `ls -la`, `readlink`) — потом писать код
- Добавить `perror` вместо голого `fprintf(stderr, ...)` для сообщений об ошибках
- Сразу использовать `PRIu64` вместо `%llu` — портируемость с первого раза
