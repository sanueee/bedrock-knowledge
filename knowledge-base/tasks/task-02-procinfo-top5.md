# Task 02 — procinfo top5

## Задание

Расширение procinfo: если запустить без аргументов — вывести топ-5 процессов по VmRSS (самые прожорливые по памяти).

Требования:
- Без ps/top/внешних утилит
- Нужно перебрать все процессы в `/proc/`
- Динамический массив или фиксированный буфер
- Сортировка по убыванию VmRSS

## Моё решение

Реализовал `ProcessTop()`. Алгоритм:
1. `opendir("/proc/")` — открыть директорию
2. `readdir()` в цикле — перебрать все записи
3. Фильтрация числовых имён через `strtoul` + проверка `endptr`
4. Для каждого PID — `fopen("/proc/<pid>/status")` + `fgets` в цикле
5. Накопление в фиксированный массив `ProcInfo proc_arr[1024]`
6. `qsort` с компаратором по `vmrss_kb` по убыванию
7. Вывод первых `min(5, count)` записей

Структура данных:
```c
typedef struct {
    char     pid[21];
    uint64_t vmrss_kb;
    char     name[64];
} ProcInfo;
```

## Ключевые функции

| Функция | Зачем |
|---|---|
| `opendir` / `readdir` / `closedir` | итерация по содержимому `/proc/` |
| `strtoul` + проверка `endptr` | фильтр: имя папки — число => это PID |
| `snprintf` | сборка пути `/proc/<pid>/status` в один вызов |
| `fopen` / `fgets` / `fclose` | чтение status-файла построчно |
| `qsort` | сортировка массива структур |

## Ошибки и трудности

**Путаница в типах функций** — сложнее всего было помнить что именно принимает каждая функция: `qsort` ожидает `const void *` в компараторе, `opendir` возвращает `DIR*`, `readdir` — `struct dirent*`. Решение: читать сигнатуру в man page перед использованием.

**`#include <cstdio>` вместо `<stdio.h>`** — случайно добавил C++ заголовок, компилятор не ругался сразу, но это неправильно для C.

**`proc_arr` и `curr_proc` объявил внутри цикла по строкам файла** — в итоге добавлял элемент в массив на каждой строке, а не на каждый процесс. Нужно было поднять объявления на уровень выше.

**Неверная сигнатура компаратора** — написал `int cmp_proc(ProcInfo *a, ProcInfo *b)`. `qsort` ожидает `const void *` — компилятор ругается. Внутри нужно делать явное приведение типа.

**Многострочный `fprintf` с `\`** — отступы после `\` входят в строку вывода. Колонки съехали. Надо либо убирать отступы после `\`, либо бить на отдельные вызовы.

## Что бы сделал иначе

- Сразу инициализировать `curr_proc = {0}` — защита от мусора на стеке
- Использовать `i < 5 && i < count` вместо проверки `vmrss_kb == 0` — надёжнее
- Не трогать `#include` не глядя
