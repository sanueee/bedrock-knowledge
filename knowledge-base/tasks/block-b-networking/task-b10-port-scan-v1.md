# B-10 — port-scan v1 (интеграционное)

Интеграционное задание блока B (сетевой стек, C). Фаза 2. **Первая интеграционная точка блока.**
Новой теории нет — задача сшивает три последних атомарных примитива в один инструмент.

**Синтезирует (все три реально задействованы):**
- **B-6** — non-blocking `connect()` / `EINPROGRESS` (`topics/networking/nonblocking-poll.md`). Здесь: каждый порт пробивается неблокирующим `connect`, чтобы держать десятки проб в полёте одновременно.
- **B-7** — epoll event loop / `EPOLLOUT` (`topics/networking/event-loop-epoll.md`). Здесь: **один** epoll-инстанс отслеживает готовность **всех** сокетов сразу; главный цикл `epoll_wait` разгребает готовые.
- **B-8** — connect-with-timeout, три исхода open/closed/filtered (`topics/networking/connect-timeout-scan.md`). Здесь: та же логика `getsockopt(SO_ERROR)` + дедлайн, но масштабированная на диапазон.

**Перед стартом перечитай эти три конспекта.** B-10 — ровно их сумма, без нового API.

---

## Что написать

Утилита `portscan`: connect-scan диапазона TCP-портов **одного** хоста. По каждому порту — вердикт `open` / `closed` / `filtered`, в конце — сводка (сколько каждого).

Вызов:
```
./portscan <ip> <port_from> <port_to> <timeout_ms>
```
например `./portscan 127.0.0.1 1 1024 300`.

Код: `networking/portscan.c`.
epoll — Linux-only. Гоняем в Docker gcc-контейнере, как B-7/B-8 (не на macOS clang).

### Три исхода (те же, что в B-8 — не путай различение)
- **open** — после `EPOLLOUT` `getsockopt(SO_ERROR) == 0`.
- **closed** — после `EPOLLOUT` `SO_ERROR == ECONNREFUSED` (пришёл RST).
- **filtered** — за отведённый таймаут сокет так и не стал готов (`epoll_wait` не принёс по нему события до дедлайна). Фаервол дропает молча.

Напоминание из B-8: сам факт `EPOLLOUT` **не** означает «открыт» — writable-событие приходит и при успехе, и при отказе. Открытость решает только `SO_ERROR`. Смасштабировав на диапазон, легко про это забыть — не забудь.

## Что здесь НОВОГО по сравнению с B-8

B-8 был про **один** порт: один сокет, один `connect`, один дедлайн. B-10 — про **много портов в полёте одновременно**. Инженерная разница — в этих четырёх местах, они и есть цель задания:

1. **fd → port.** epoll в событии отдаёт тебе `fd` (или `data.ptr`), а тебе нужно знать, **какой порт** за этим сокетом. Нужна ассоциация. Простейшее — `int port_of_fd[FD_SETSIZE]` (или связать через `epoll_event.data.u32 = port` / `.data.ptr = &slot`). Реши, как хранить, и держи консистентно с закрытием сокетов.

2. **Ограничение параллелизма (bounded concurrency).** Нельзя разом открыть 65535 сокетов — упрёшься в `RLIMIT_NOFILE` (обычно 1024 fd на процесс) и получишь `EMFILE`. Держи **окно** из N сокетов в полёте (например 64–256): открыл N проб → крутишь epoll → по мере закрытия готовых доливаешь новые порты из диапазона, пока диапазон не кончится. Это ядро масштабирования.

3. **Дедлайн на весь скан (или на каждую пробу).** В B-8 таймаут был на единственный `connect`. Здесь порт может «висеть» filtered. Нужно решить: общий дедлайн на весь диапазон, или per-socket дедлайн (запомнить время старта каждой пробы и на каждой итерации вычислять, какие уже просрочены). Начни с **per-socket дедлайна** — он честнее и прямо продолжает B-8.

4. **Учёт «не пришедших».** open/closed приходят как события epoll. А filtered — это **отсутствие** события. Значит после дедлайна нужно активно пройтись по ещё-открытым слотам окна, закрыть их и засчитать как filtered. Событие тебе про них не придёт — молчание и есть вердикт.

## Механика по шагам (словами, без кода)

1. Распарсить argv: `ip`, `port_from`, `port_to`, `timeout_ms`. Провалидировать диапазон (1..65535, from ≤ to).
2. `inet_pton(AF_INET, ip, ...)` — один раз, адрес общий для всех проб, меняется только `sin_port` (`htons(port)`).
3. `epoll_create1(0)` — один инстанс на весь скан.
4. Массив слотов окна: `struct probe slots[WINDOW]` — каждый слот хранит `fd`, `port`, `deadline` (момент старта + timeout_ms). Свободный слот помечается (например `fd = -1`).
5. **Запуск пробы** (функция `start_probe`): `socket()` → выставить `O_NONBLOCK` → `connect()`. Ожидаемый возврат — `-1` c `errno == EINPROGRESS` (это норма, а не ошибка). Зарегистрировать fd в epoll на `EPOLLOUT`. Записать `port` и `deadline` в слот, `port` — в ассоциацию fd→port.
   - Пограничный случай: `connect` иногда возвращает `0` сразу (loopback, порт открыт) — тогда порт уже open, можно не гонять через epoll. Решить, обрабатывать ли этот путь или пустить всё единообразно через `EPOLLOUT`.
6. **Главный цикл** — пока есть незавершённые пробы ИЛИ в диапазоне остались непройденные порты:
   - Долить окно: пока есть свободные слоты и остались порты — `start_probe` следующего порта.
   - Посчитать таймаут для `epoll_wait` = ближайший дедлайн среди активных слотов минус «сейчас» (не блокируйся дольше, чем до ближайшего просроченного).
   - `epoll_wait(epfd, evs, WINDOW, timeout)`.
   - На каждое событие: по `fd` найти слот/порт → `getsockopt(SO_ERROR)` → вердикт open/closed → `epoll_ctl(DEL)` + `close(fd)` → освободить слот.
   - После обработки событий: пройтись по активным слотам, у кого `deadline` уже прошёл — вердикт filtered → закрыть → освободить слот.
7. Сводка: печатать вердикты по ходу (`port N: open`) и в конце строку `open=.. closed=.. filtered=..`.

## Security / низкоуровневые заметки (держать в голове при написании)

- **`RLIMIT_NOFILE` / `EMFILE`** — главный ресурсный риск. Без окна параллелизма скан «широкого» диапазона исчерпает дескрипторы. `start_probe` обязан корректно обработать `socket()`/`connect()` возврат `-1` c `EMFILE` (сузить окно / подождать), а не молча потерять порт.
- **Утечка fd** — каждый вердикт (open/closed/filtered) обязан вести к `close(fd)` **и** `epoll_ctl(EPOLL_CTL_DEL)` (или хотя бы close — epoll сам чистит закрытые fd, но полагаться на это неаккуратно). Забыл закрыть filtered-слоты — утечёшь ровно на числе отфильтрованных портов.
- **fd→port рассинхрон** — если переиспользуешь `port_of_fd[fd]` и не затираешь запись при close, следующий сокет с тем же номером fd прочитает чужой порт. Ядро переиспользует освободившиеся номера fd агрессивно — это реальный класс багов здесь.
- **`getsockopt(SO_ERROR)` обязателен** — доверять `EPOLLOUT` как «открыт» = ложные open на закрытых портах (из B-8, легко потерять при масштабировании).
- **`CLOCK_MONOTONIC`, не `REALTIME`** — дедлайны на реальных часах ломаются при NTP-коррекции/переводе времени.
- **Границы буферов** — вывод по портам форматируй с фиксированными размерами; никаких `%s` по неполным данным (мышца из B-9).

## Ключевые термины (English)

- **bounded concurrency** — ограничение числа одновременных проб фиксированным окном (`WINDOW = 256`), чтобы не исчерпать дескрипторы
- **in-flight probes** — пробы «в полёте»: сокеты, по которым `connect` отправлен, но вердикт ещё не вынесен
- **window / slot** — массив слотов фиксированного размера; слот = одна активная проба (`fd == -1` → свободен)
- **file descriptor exhaustion** — исчерпание fd (`RLIMIT_NOFILE`), `socket()` → `EMFILE`
- **relative vs absolute timeout** — `epoll_wait` ждёт **относительный** интервал (мс от «сейчас»), не абсолютный момент на оси времени
- **monotonic clock** — `CLOCK_MONOTONIC` для дедлайнов; не ломается от NTP-коррекции
- **liveness condition** — условие продолжения главного цикла: остались порты **ИЛИ** есть активные пробы
- `EINPROGRESS`, `ECONNREFUSED`, `SO_ERROR`, `EMFILE`, `EPOLLOUT`

## Разбор / что получилось

Написан за одну сессию, отревьюен через `/check` в **4 итерации**. Три вердикта (open/closed/filtered) проверены end-to-end в Docker gcc-контейнере: loopback со слушателем `python3 -m http.server 8080` (open + closed соседи), недостижимый `10.255.255.1` (filtered по таймауту).

**Найденные и закрытые баги (по итерациям `/check`):**
1. **epoll_wait: абсолютное время вместо относительного.** Передавал `now + timeout` в 4-й аргумент вместо `min_deadline - now`. Скан фактически блокировался до события; filtered (отсутствие события) не вычищался вовремя. Плюс поиск ближайшего дедлайна шёл по **просроченным** слотам вместо активных.
2. **условие выхода главного цикла** — `while (next_port <= port_to)`: цикл выходил, как только все порты **запущены**, не дожидаясь висящих проб. На loopback баг прятался (open/closed резолвятся мгновенно в тот же `epoll_wait`); вылез только на filtered, где вердикт = **ожидание** дедлайна. → `next_port <= port_to || active > 0`.
3. **счётчик `active` рассинхрон** — лишний `active--` в ветке `CONNECT_ERROR`, где слот не занимался (не было парного `active++`). Ушёл бы в минус на немедленных ошибках `connect` (`ENETUNREACH`).
4. **`inet_pton == -1`** — кривой IP возвращает `0`, не `-1` → сканировался `0.0.0.0`. → `!= 1`.
5. **валидация timeout как порта** — `get_ull` зажимал таймаут потолком 65535. Портовые проверки вынесены отдельно в `main`, на `ull` (до сужения в `int`).
6. **отрицательный epoll timeout** — после `-= now_ms()` мог стать `< 0` → `epoll_wait` трактует как «бесконечно». Добавлен кламп в 0.

**Design decisions:**
- **fd→port через `epoll_event.data.u32 = slot_idx`** (индекс слота), не `port_of_fd[]` — рассинхрон fd→port структурно невозможен.
- **per-socket дедлайн** (не общий на скан) — честнее, прямое продолжение B-8.
- Немедленный `ECONNREFUSED` всё равно гонится через epoll (единообразие): `EPOLLOUT` приходит на упавшем сокете, `getsockopt(SO_ERROR)` даёт `ECONNREFUSED`.
- Счётчик `active` даёт liveness-условие за `O(1)` (хотя проход по 256 слотам на фоне `epoll_wait` ничтожен — обсуждали, оптимизация тут преждевременна).

**Затык сессии:** не логика (она была ясна), а **навигация по объёмному файлу** (~260 строк) — масштаб вложенных развилок и циклов потерялся с первого прохода. Логика каждого куска понятна, но целостная карта «какой цикл что делает, где какой слот освобождается, какой `active--` парен какому `++`» собиралась тяжело.

**Осталось (опционально, устойчивость):** `perror` при `inet_pton == 0` (errno не установлен), непроверенные возвраты `getsockopt`/`epoll_ctl`/`fcntl`, `EPOLL_CTL_DEL` перед `close`.
