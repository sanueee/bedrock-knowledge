# Task 01 — procinfo

## Задание

Утилита на C: принимает PID как аргумент командной строки, читает `/proc/<pid>/status`, выводит:
- имя процесса (Name)
- PID
- потребление памяти VmRSS в МБ

Без использования внешних утилит (ps, top и т.д.).

## Моё решение

Разбил на три части:
1. Парсинг аргумента: `strtoull` + проверка `endptr` и `errno`
2. Сборка пути: конкатенация строк через `strncat`
3. Построчное чтение файла: `fgets` + `strncmp` для поиска нужных полей

Для конвертации памяти: прочитал kb, поделил на 1024.

## Ключевые функции

| Функция | Зачем |
|---|---|
| `strtoull` | безопасный парсинг строки в uint64_t с обнаружением ошибок |
| `fopen` / `fgets` / `fclose` | буферизованное чтение файла построчно |
| `strncmp` | безопасное сравнение строк с ограничением по длине |
| `sscanf` | извлечение значения из строки формата "Key:   value" |
| `strncat` | сборка пути (потом заменил на snprintf — см. ошибки) |

Выбор `fopen` вместо `open`: `/proc` — текстовый файл, нужно читать построчно. `fopen` даёт `fgets`, `open` потребовал бы ручного буфера.

## Ошибки и трудности

**Трудность 1: когда использовать `open()`, а когда `fopen()`**
Долго выбирал. Итог: `fopen` — для текстовых файлов где нужны `fgets`/`fscanf`. `open` — для бинарных или когда нужен прямой контроль (флаги O_NONBLOCK и т.д.).

**Трудность 2: когда обрабатывать ошибки**
Обрабатывал всё подряд — стало громоздко. Вывод из ревью: внешний мир (аргументы, файловая система) — обрабатывать всегда. Внутренняя логика — можно упростить.

**Ошибка в коде: сборка пути через strncat-цепочку**
```c
// Написал:
char path[64] = "/proc/";
strncat(path, pid_string, 21);
strncat(path, "/status", 7);

// Надо:
char path[64];
snprintf(path, sizeof(path), "/proc/%llu/status", pid);
```
Три вызова вместо одного. Лишняя переменная `pid_string`.

**Ошибка: `%llu` для `uint64_t` непортируемо**
Надо `PRIu64` из `<inttypes.h>`. На Linux с gcc работает, но не гарантия.

**Ошибка: `\n` в stderr**
Забыл `\n` в конце сообщений об ошибках — они слипались с приглашением терминала.

**Ошибка: форматирование вывода**
Использовал `\t` вместо пробелов — вывод выглядел некрасиво.

## Что бы сделал иначе

- Сразу использовать `snprintf` для форматирования строк
- Добавить проверку что все три поля найдены (VmRSS может отсутствовать у потоков ядра)
- Не забывать `\n` в stderr
