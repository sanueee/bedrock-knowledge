## Задание

Написать программу `signals` на C.

**Поведение:**
- При запуске программа пишет в лог-файл `signals.log` строку: `[PID] started`
- Программа входит в бесконечный цикл (`pause()`)
- При получении `SIGINT` (Ctrl+C) — писать в лог `[PID] caught SIGINT`, продолжать работу
- При получении `SIGTERM` — писать в лог `[PID] caught SIGTERM, shutting down` и корректно завершаться (exit 0)
- При завершении — писать в лог `[PID] exited`

**Технические требования:**
- Использовать `sigaction()`, не `signal()` — они похожи, но `sigaction` предсказуем
- Для маски сигналов: `sigemptyset()`, `sigaddset()`
- Лог писать через `fprintf()` в FILE*, не через printf
- PID получать через `getpid()`

**Где сохранить:** `linux/proc/signals.c`

**Как проверить:**
```bash
gcc -o signals signals.c
./signals &          # запустить в фоне
kill -SIGINT <PID>   # отправить SIGINT
kill -SIGTERM <PID>  # завершить
cat signals.log      # посмотреть лог
```

**Man-страницы:** `man 2 sigaction`, `man 7 signal`, `man 2 pause`

## Моё решение

Написал `linux/proc/signals.c`: обработчики SIGINT и SIGTERM через `sigaction()`, лог в FILE*.
Программа запускается в фоне, ловит сигналы, корректно завершается по SIGTERM.

Проверено через `kill` из терминала — `[1]+ Done` подтвердил exit 0.

## Ключевые функции

| Функция | Зачем |
|---------|-------|
| `sigaction()` | регистрация обработчика (предпочтительнее `signal()`) |
| `sigemptyset()` | инициализация пустой маски сигналов |
| `pause()` | блокировать процесс до прихода сигнала |
| `getpid()` | PID текущего процесса |
| `exit(0)` | корректное завершение из обработчика |

## Что узнал

- `sigaction()` стабильнее `signal()` — поведение `signal()` зависит от платформы
- `sigaction()` должен быть до цикла, не внутри него
- `pause()` блокирует процесс и возвращает управление когда приходит сигнал
- Разница `SIGKILL` vs `SIGTERM`: `SIGKILL` нельзя перехватить и заблокировать — ядро убивает процесс немедленно
- Что такое `SA_RESTART`: автоматически перезапускает прерванные системные вызовы после обработчика

## Ошибки и трудности

**`sigaction()` внутри цикла после `pause()`** — регистрация обработчика происходила уже после сигнала. Исправил: `sigaction()` до цикла.

**Пропущен `getpid()` в `fprintf`** — `%u` читал мусор со стека, в логе появился мусорный PID.

**`\n` в конце строк `fprintf` отсутствовал** — строки сливались в лог-файле.

**Концепция сигналов в целом** — осталась новой, нужно встретить снова в следующих задачах.
