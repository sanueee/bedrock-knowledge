## Задание

Утилита на C: принимает PID как аргумент, выводит все открытые файловые дескрипторы этого процесса.

```
$ ./fdlist 1234
fd 0 -> /dev/null
fd 1 -> /dev/null
fd 2 -> /var/log/nginx/error.log
fd 4 -> socket:[12345]
```

**Требования:**
- Читать `/proc/<pid>/fd/` через `opendir`/`readdir`
- `readlink` для каждой записи
- Без внешних утилит

**Функции для использования:**
- `opendir` / `readdir` — итерация по `/proc/<pid>/fd/`
- `snprintf` — сборка путей
- `readlink` — куда ведёт симлинк, не следуя по нему
- `strcmp` — фильтр `.` и `..`

**Где сохранить:** `linux/fd/fdlist.c`

**Как проверить:**
```bash
./fdlist $$                              # fd текущего шелла
sudo ./fdlist $(pgrep systemd-journal)   # полная картина демона логов
```

---

## Моё решение

1. Принять PID из `argv[1]`, собрать путь `/proc/<pid>/fd` через `snprintf`
2. `opendir` на эту директорию, `readdir` в цикле
3. Фильтровать `.` и `..` через `strcmp`
4. `snprintf` полный путь к симлинку, `readlink` → буфер с целью
5. Нуль-терминировать буфер вручную: `target[len] = '\0'`
6. Вывести `fd N -> target`

## Ключевые функции

| Функция | Зачем |
|---------|-------|
| `opendir` / `readdir` | итерация по `/proc/<pid>/fd/` |
| `snprintf` | сборка путей `/proc/<pid>/fd` и `/proc/<pid>/fd/<name>` |
| `readlink` | читает куда ведёт симлинк, не следуя по нему |
| `strcmp` | фильтр `.` и `..` |

## Что узнал

- `readlink` не добавляет нуль-терминатор — нужно: `ssize_t len = readlink(..., buf, sizeof(buf)-1); buf[len] = '\0';`
- `/proc/<pid>/fd` чужого процесса требует root — без sudo получишь "error: opening", это не баг
- `full_path` должен быть не меньше суммы длин входных строк
- Разница `open` / `fopen`: `open` для бинарных и прямого контроля, `fopen` для текстовых с построчным чтением

## Ошибки и трудности

**`readlink` не добавляет `\0`** — неочевидно из сигнатуры. Прочитал данные, вывел мусор в конце строки.

**`full_path[128]` слишком мал** — при `path[128]` компилятор предупреждает о переполнении. Увеличил до 384.

**`%llu` на Linux (aarch64)** — `uint64_t` там `%lu`, заменил на `PRIu64` из `<inttypes.h>`.

**Симлинки остались абстрактными** — концептуально понял, но интуиции нет. Помогло бы сначала потрогать руками: `ln -s`, `ls -la`, `readlink`.

## Что бы сделал иначе

- Добавить `perror` вместо голого `fprintf(stderr, ...)` для сообщений об ошибках
- Сразу использовать `PRIu64`
