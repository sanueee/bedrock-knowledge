# Top K Frequent Elements

- **Раздел:** Arrays & Hashing
- **Сложность:** Medium
- **Теги:** #hashmap #bucket-sort
- **Дата:** 2026-07-12
- **Далось:** со скрипом

## Идея (паттерн)

Нам важны не значения, а их **частоты**, а частота — это целое число `1..len(nums)`. Значит её можно закодировать как **индекс** массива-корзин той же длины: `arr[частота]` = список элементов с этой частотой. Тогда «k самых частых» = пройти корзины с конца (от большой частоты к малой) и собрать первые k. Сравнений между элементами нет → `O(n)` вместо `O(n log k)` у heap/`most_common`.

## Ловушка / что не сразу увидел

- **Размер массива `len(nums) + 1`, не `len(nums)`.** Макс. частота = `len(nums)` (все элементы одинаковы), индекс должен доставать до неё → иначе `IndexError` на входе `[1,1,1,1]`.
- **Корзина — список, не одна ячейка.** Несколько разных чисел с одинаковой частотой; `arr[v] = key` затирает, нужен `arr[v].append(key)`.
- **Не переиспользовать имя `k`.** `for k, v in c.items()` затирает параметр `k` (сколько вернуть) — молчаливый баг, результат едет.
- Ноль — валидное значение `nums`, поэтому массив плоских нулей + срез не годится: пустую корзину не отличить от элемента `0`.

## Сложность

- Время: O(n) — Counter за O(n), заполнение корзин O(m уникальных), сбор с конца проходит корзины и их элементы суммарно за O(n). Циклы не вложены по n.
- Память: O(n) — массив корзин длиной n+1 плюс Counter.
