# WinRM и PowerShell Remoting

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Сетевой стек Windows и удалённое управление
>
> **Кейсы:** [3.06 NFS](../../cases/windows/3.06%20NFS.md), [3.07 Сетевой стек](../../cases/windows/3.07%20Сетевой%20стек.md)

**Windows Remote Management** (WinRM) - реализация Microsoft протокола WS-Management, используется для удалённого управления системой через web-сервисный SOAP-подход. Microsoft описывает WinRM как компонент **Windows Hardware Management**, реализующий **WS-Management** и предоставляющий **API**, командные инструменты и интеграцию с **WMI**. Транспортом служит **HTTP** на порту TCP 5985 или HTTPS на порту TCP 5986, обслуживает протокол одноимённая служба **Windows Remote Management** (WinRM).

**PowerShell Remoting** обычно использует **WinRM** как транспорт. Microsoft прямо указывает, что **PowerShell Remoting uses WinRM**, а **WinRM** - реализация **WS-Management**. См. [**Security considerations for PowerShell Remoting using WinRM**](https://learn.microsoft.com/en-us/powershell/scripting/security/remoting/winrm-security).

> **WinRM** - это служебная телефонная линия для удалённого администрирования. В отличие от рации **RPC**, по которой передаются короткие приказы, **WinRM** - это полноценный двусторонний канал: специалист видит вывод команд так же, как если бы сидел перед локальной консолью. Канал шифрованный и аутентифицированный, но если этот телефон попадёт не в те руки - удалённый абонент получит полный shell на хосте.

Важно разделить:

- **WinRM** - транспортная служба Windows для удалённого управления. Сама по себе она ничего не "выполняет", а только принимает входящие запросы и передаёт их соответствующим компонентам
- **PowerShell Remoting** - механизм выполнения **PowerShell**-команд через удалённую сессию. По умолчанию работает поверх **WinRM** как транспорта
- **Методы аутентификации**: **NTLM**, **Kerberos**, **Basic**, сертификаты, **CredSSP** - в зависимости от среды. Из этого списка особенно важен **Basic**: он передаёт логин и пароль практически в открытом виде (Base64 без хэширования) и должен быть отключён во всей инфраструктуре. Этот момент дальше всплывёт в атаке **WinRM Listener Hijacking**

По умолчанию использование **PowerShell Remoting** по **WinRM** разрешено только для членов группы **Administrators**.

С точки зрения атак:

- после получения локальных учётных данных **WinRM** даёт удалённую командную сессию
- графический вход не нужен, в отличие от **RDP**
- активность может выглядеть как легитимное администрирование
- **PowerShell** даёт удобный доступ к объектной модели Windows, **WMI**, реестру, файловой системе

## Атаки на WinRM / PowerShell Remoting

**Lateral Movement через WinRM** (MITRE ATT&CK: [**T1021.006**](https://attack.mitre.org/techniques/T1021/006/))

Использование легитимных учётных данных для удалённого выполнения команд через **PowerShell Remoting**. Атакующий, получивший пароль или хэш администратора (через фишинг, кражу из памяти или утечку), подключается к целевому хосту через **Enter-PSSession** или **Invoke-Command** и получает полноценный командный канал. Сложность детектирования - такая активность визуально не отличается от легитимной работы администратора по удалённому обслуживанию.

**PowerShell Script Block Logging Bypass**

Обход журналирования **PowerShell** для скрытия следов атакующей активности. Атакующий с правами администратора отключает **Script Block Logging** через изменение ключа реестра, после чего его последующие команды не попадают в журнал **Microsoft-Windows-PowerShell/Operational**. Более продвинутая вариация - патчинг функции **EtwEventWrite** в **ntdll.dll** в памяти, что отключает не только **PowerShell**-логирование, но и всю **ETW**-телеметрию процесса. Детальнее **ETW**-атаки будут разбираться позднее в курсе.

**WinRM Listener Hijacking**

Создание подменного **WinRM**-listener'а на нестандартном порту с принудительной аутентификацией **Basic**. Атакующий с правами администратора регистрирует свой listener и ожидает подключений: при **Basic**-аутентификации **WinRM** передаёт логин и пароль в Base64, без хэширования - то есть пароль в практически открытом виде попадает атакующему. Защита от этого - запрет **Basic** во всей инфраструктуре через **GPO**.

**Credential Dumping через WinRM**

Удалённый запуск **Mimikatz** или аналогичных инструментов извлечения хэшей через сессию **WinRM**. После того как атакующий получил **PowerShell**-сессию на целевом хосте, он запускает на нём инструмент дампа памяти процесса **lsass.exe**, извлекает хэши локальных учётных записей и кэшированные доменные секреты. Цепочка работает, пока на хосте не включён **Credential Guard** или **RunAsPPL**.

## Управление WinRM через PowerShell

| Для чего | Команда |
|---|---|
| Проверка статуса службы WinRM | Get-Service WinRM | Select-Object Name, Status, StartType |
| Проверка конфигурации WinRM | winrm get winrm/config/Service |
| Проверка TrustedHosts (wildcard * - небезопасно, должен быть пустым или содержать конкретные хосты) | Get-Item WSMan:\localhost\Client\TrustedHosts |
| Проверка активных WinRM -listener'ов | Get-WSManInstance -ResourceURI winrm/config/Listener -Enumerate |
| Отключение службы WinRM на клиенте | Stop-Service WinRM -Force ; Set-Service WinRM -StartupType Disabled ; Disable-NetFirewallRule -DisplayName "Windows Remote Management*" |
| Просмотр текущих пользователей в WinRM -сессиях | Get-WSManInstance -ResourceURI shell -Enumerate -ComputerName localhost | Select-Object Owner, ClientIP, ProcessID, ShellRunTime |

## Какие механизмы защиты работают на WinRM

- **Отключение WinRM**, если не используется для удалённого администрирования
- **HTTPS вместо HTTP** (порт **5986** вместо **5985**) - обязательное шифрование канала
- **Запрет Basic-аутентификации** на уровне сервиса (**winrm set winrm/config/service/Auth @{Basic="false"}**) - исключает **Listener Hijacking**
- **Минимизация TrustedHosts** - никаких wildcard ***** на клиентах, только конкретные адреса
- **JEA** (**Just Enough Administration**) - делегирование удалённых сессий с ограниченным набором команд вместо полного **PowerShell**
- **Script Block Logging + Module Logging + Transcription** через **GPO** - детектирование подозрительных команд
- **AMSI** (**Antimalware Scan Interface**) - сканирование скриптов до их выполнения
- **Credential Guard** - защита **lsass.exe** от дампа во время **WinRM**-сессий
