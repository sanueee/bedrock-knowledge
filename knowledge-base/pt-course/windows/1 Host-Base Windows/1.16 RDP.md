# RDP

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Сетевой стек Windows и удалённое управление
>
> **Кейсы:** [3.06 NFS](../../cases/windows/3.06%20NFS.md), [3.07 Сетевой стек](../../cases/windows/3.07%20Сетевой%20стек.md)

**Remote Desktop Protocol** (RDP) предоставляет удалённый графический доступ: изображение рабочего стола, ввод с клавиатуры и мыши, виртуальные каналы для устройств и дополнительных функций. Microsoft описывает **RDP** как протокол удалённого отображения и ввода для Windows-приложений, подробнее - в [**Understanding RDP**](https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/understanding-remote-desktop-protocol). Протокол работает на порту TCP 3389 (опционально также UDP 3389 для оптимизации канала), обслуживается службой **Remote Desktop Services** (TermService).

> **RDP** - это окно с прямой трансляцией удалённого рабочего стола, прозрачное в обе стороны. Специалист видит экран так, словно сидит за этой машиной, машина получает клавиатуру и мышь как будто они физически подключены. В отличие от **WinRM**, который даёт только консольный канал, **RDP** даёт полный графический сеанс со всеми правами того пользователя, под которым выполнен вход.

Теоретически важно разобрать:

- **RDP** создаёт интерактивную пользовательскую сессию
- протокол многоканальный: отдельно передаются графика, ввод, устройства, буфер обмена и так далее
- трафик инкапсулируется и шифруется
- современные конфигурации используют **Network Level Authentication (NLA)**
- доступ регулируется локальными правами входа и группой **Remote Desktop Users**

Для одного хоста без домена **RDP** обычно опирается на локальные учётные записи. Это делает особенно важными:

- сложность паролей
- блокировки после неудачных попыток
- запрет входа для ненужных пользователей
- отключение **RDP**, если он не нужен
- запрет публикации **RDP** напрямую в интернет

## Управление RDP через PowerShell

| Для чего | Команда |
|---|---|
| Проверка статуса RDP ( 0 - включён, 1 - отключён) | Get-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server" -Name fDenyTSConnections |
| Проверка NLA ( 1 - обязательно, 0 - небезопасно) | Get-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server\WinStations\RDP-TCP" -Name UserAuthentication |
| Отключение RDP , если не требуется | Set-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server" -Name fDenyTSConnections -Value 1 ; Stop-Service TermService -Force ; Set-Service TermService -StartupType Disabled |
| Список членов группы Remote Desktop Users | Get-LocalGroupMember -Group "Remote Desktop Users" |
| Просмотр активных RDP -сессий | query session |
| Просмотр активных RDP -сессий через CIM | Get-CimInstance Win32_LogonSession | Where-Object { $_.LogonType -eq 10 } |

## Атаки на RDP

**RDP Bruteforce / Password Spraying** (MITRE ATT&CK: [**T1110**](https://attack.mitre.org/techniques/T1110/))

Подбор паролей к учётным записям с правом удалённого входа. Один из самых распространённых сценариев первичного проникновения в инфраструктуру: атакующий сканирует интернет на открытый порт **3389**, находит хост и запускает перебор паролей по списку. Особенно эффективно работает password spraying - перебор одного-двух популярных паролей по большому списку имён пользователей: это обходит блокировки за количество неудачных попыток. Никаких особых навыков не требуется, при наличии слабого пароля любой администратор становится точкой входа.

**BlueKeep** (**CVE-2019-0708**)

Критическая уязвимость удалённого выполнения кода в **RDP** на старых системах (Windows XP, Server 2003, Vista, Server 2008, Windows 7, Server 2008 R2). Уязвимость в обработке запросов сервиса терминалов позволяет получить выполнение кода в контексте **SYSTEM** без аутентификации. По механизму распространения сравнима с **EternalBlue**: червеобразное распространение по сети, если хосты с уязвимостью видят друг друга. Патч **MS19-019** закрывает уязвимость, но в legacy-сегментах с непатченной Windows 7 и Server 2008 R2 проблема актуальна до сих пор.

**RDP Session Hijacking** (MITRE ATT&CK: [**T1563.002**](https://attack.mitre.org/techniques/T1563/002/))

Перехват активной **RDP**-сессии другого пользователя без знания его пароля. Атакующий с правами **SYSTEM** на сервере (например, локальный администратор) запускает утилиту **tscon.exe**, указав идентификатор чужой сессии - и подключается к этому рабочему столу так, словно пользователь сам передал ему доступ. Особенность атаки в том, что она использует абсолютно легитимный системный инструмент, поставляемый вместе с Windows, и не требует ни эксплойтов, ни сторонних утилит.

**RDP Credential Harvesting**

Кража учётных данных в активной **RDP**-сессии. Возможные сценарии: кейлоггер на хосте-источнике, дамп памяти **lsass.exe** на сервере с включённой сессией, копирование файлов с паролями через clipboard redirection или drive redirection. Главный риск - сетевые администраторы часто подключаются к множеству серверов под одной и той же учётной записью, и компрометация одного из серверов с активной сессией даёт доступ к остальным.

**RDP Man-in-the-Middle (MITM)**

Перехват **RDP**-трафика на сетевом пути при отсутствии валидной проверки сертификата сервера. Атакующий, находясь в позиции **MitM** (через **ARP spoofing** или подмену **DNS**), подменяет сертификат **RDP**-сервера на собственный. Если жертва игнорирует предупреждение клиента **mstsc.exe** о неизвестном сертификате, атакующий перехватывает учётные данные и весь трафик сессии. Включённый **NLA** существенно усложняет такую атаку, но не делает её невозможной без правильной настройки доверия сертификатам.

## Какие механизмы защиты работают на RDP

- **NLA (Network Level Authentication)** - проверка учётных данных до установления полноценной **RDP**-сессии. Базовая защита от **BlueKeep**-подобных уязвимостей и пред-аутентификационных атак
- **Не публиковать RDP в интернет** - **RD Gateway** или **VPN** перед **RDP**
- **Account Lockout Policy** - блокировка учётной записи после 5-10 неудачных попыток входа, ломает простой bruteforce
- **MFA для RDP** через сторонние решения (**Duo**, **Azure MFA Server**) - даже скомпрометированный пароль не даёт входа
- **Длинные сложные пароли** (14+ символов) - без этого все остальные меры дырявые
- **Минимизация группы Remote Desktop Users** - регулярный аудит состава, удаление неактивных учётных записей
- **Restricted Admin Mode** для **RDP** - администратор не передаёт хэш пароля на удалённый хост, защищает от **Pass-the-Hash** через **RDP**
- **Запрет Clipboard и Drive Redirection** через **GPO** для критичных серверов - усложняет эксфильтрацию
- **Credential Guard** на серверах - защищает **lsass.exe** от дампа в активных **RDP**-сессиях
- **Установка патчей в приоритете** - **BlueKeep** и подобные уязвимости появляются периодически

Все рассмотренные протоколы - **SMB**, **RPC**, **WinRM**, **WMI**, **RDP** - в Windows-средах часто аутентифицируются через один и тот же механизм. Этот механизм - **NTLM**, главное наследие безопасности в смешанных средах
