# 8. Windows 10 1703–21H2 / Server 2019: sandbox, WSL 2, Secured-core

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Эволюция Windows NT

В эпоху **Feature Updates** изменения в ядре приходили не раз в несколько лет, а итерационно.

**Windows Defender Exploit Guard / Exploit Protection** **DEP**, **ASLR**, **CFG** и другие **mitigations** стали централизованно управляемыми политиками, применяемыми к конкретным процессам ([**Exploit Protection**](https://learn.microsoft.com/en-us/defender-endpoint/exploit-protection-reference)). Теперь не нужно надеяться, что приложение скомпилировано с нужными флагами: администратор может принудительно включить защиты через политику - даже для **legacy**-приложений, собранных без поддержки этих механизмов.

**Windows Sandbox** Одноразовая изолированная Windows-среда на базе **Hyper-V** с отдельным ядром ([**Windows Sandbox**](https://learn.microsoft.com/en-in/windows/security/application-security/application-isolation/windows-sandbox/)). После закрытия - всё исчезает без следа. С точки зрения ИБ: простой и надёжный инструмент для безопасного открытия подозрительных файлов. Поскольку изоляция идёт через гипервизор, а не через **process**-уровень, вредоносному коду внутри нужно эксплуатировать гипервизор, чтобы вырваться наружу - значительно более высокая планка, чем для обычного **sandbox**.

**WSL 2** заменил трансляцию **syscalls** на настоящее Linux-ядро внутри **lightweight utility VM** ([**WSL versions**](https://learn.microsoft.com/en-us/windows/wsl/compare-versions)). Принципиальное отличие от **WSL 1**: изоляция теперь обеспечивается гипервизором. Linux-ядро и Windows-ядро - два отдельных ядра в двух отдельных виртуальных машинах. Побег из **WSL 2** требует уязвимости в гипервизоре или в интеграционных компонентах между **VM**. Обратная сторона: файловая система хоста монтируется внутрь **WSL 2**, и вредоносный скрипт в Linux может по-прежнему обращаться к Windows-файлам через эту точку монтирования.

**Secured-core PC / Server** **Secured-core** - это не новая технология, а требование к конфигурации: **TPM 2.0**, **Secure Boot**, **VBS** и **HVCI** должны быть активированы, верифицированы и защищены от отключения из пространства пользователя ([**Secured-core server**](https://learn.microsoft.com/en-us/windows-server/security/secured-core-server)). По сути, это сертификация того, что все механизмы безопасности включены корректно и их нельзя тихо отключить - ни вредоносным ПО, ни администратором с обычными правами.
