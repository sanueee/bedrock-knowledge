# NTLM

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Сетевой стек Windows и удалённое управление
>
> **Кейсы:** [3.06 NFS](../../cases/windows/3.06%20NFS.md), [3.07 Сетевой стек](../../cases/windows/3.07%20Сетевой%20стек.md)

**NTLM** - протокол аутентификации, который используется поверх **SMB**, **HTTP**, **WinRM**, **RPC**, **RDP** и других механизмов.

**NT LAN Manager (NTLM)** - основной протокол сетевой аутентификации на недоменных узлах Windows. См. [**Microsoft NTLM**](https://learn.microsoft.com/en-us/windows/win32/secauthn/microsoft-ntlm) и [**NTLM overview**](https://learn.microsoft.com/en-ca/windows-server/security/kerberos/ntlm-overview).

Теоретически **NTLM** работает по схеме **challenge-response**:

- пользователь вводит пароль при интерактивном входе
- Windows вычисляет хэш пароля
- при сетевой аутентификации пароль не отправляется напрямую
- сервер отправляет случайный **challenge**
- клиент вычисляет **response** на основе **NTLM**-учётных данных
- сервер проверяет ответ
- для локальной учётной записи проверка идёт против локальной базы **SAM**

> **NTLM** - это секретное рукопожатие у входа. Клиент стучится, сервер задаёт случайный вопрос (**challenge**), клиент возвращает ответ, посчитанный из своего пароля. Если ответ сходится - входи. Беда в том, что подсмотревший рукопожатие либо повторяет его сам без знания пароля (**Pass-the-Hash**), либо мгновенно ретранслирует на соседнюю дверь (**NTLM Relay**) - сервер за соседней дверью пускает, потому что ответ корректен.

Для standalone-хоста особенно важно:

- нет доменного контроллера
- нет обычного **Kerberos**-сценария
- учётные записи и хэши локальные
- одинаковый локальный администраторский пароль на нескольких машинах резко повышает риск
- **NTLM** может использоваться разными протоколами, поэтому проблема не ограничивается **SMB**

## Базовые понятия

| Термин | Описание | Тип |
|---|---|---|
| LM | LAN Manager - устаревший хэш пароля, оставшийся со времён Windows 95. Криптографически слабый, должен быть отключён через NoLMHash = 1 | Версия |
| NTLMv1 | Старая версия протокола, использует DES -шифрование challenge. Устаревший, не должен использоваться | Версия |
| NTLMv2 | Современная версия, использует HMAC-MD5 с дополнительным client challenge и timestamp . Текущий минимум для NTLM -аутентификации | Версия |
| NT hash | Хэш пароля пользователя, который Windows вычисляет один раз при смене пароля и хранит в SAM или NTDS.dit . Используется во всех вычислениях NTLM | Артефакт |
| SAM | Security Account Manager - локальная база учётных записей хоста, хранит NT hash локальных пользователей | Хранилище |
| Negotiate | Этап начала аутентификации, на котором клиент и сервер договариваются о протоколе ( NTLM или Kerberos ) и его возможностях | Этап |

Microsoft отмечает, что **NTLMv2** улучшает механизмы аутентификации и session security по сравнению с историческими **LM**/**NTLMv1**. См. [**How to enable NTLM 2 authentication**](https://learn.microsoft.com/en-gb/troubleshoot/windows-client/windows-security/enable-ntlm-2-authentication).

## Управление NTLM через PowerShell

| Для чего | Команда |
|---|---|
| Проверка уровня совместимости NTLM ( 5 - только NTLMv2 , рекомендуется) | Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name LmCompatibilityLevel |
| Установка только NTLMv2 + отказ от LM | reg add "HKLM\SYSTEM\CurrentControlSet\Control\Lsa" /v LmCompatibilityLevel /t REG_DWORD /d 5 /f |
| Проверка запрета хранения LM -хешей ( 1 - не хранятся, правильно) | Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name NoLMHash -ErrorAction SilentlyContinue |
| Просмотр последних событий NTLM -аутентификации ( ErrorCode 0 - успех, 0xC000006A - неверный пароль) | Get-WinEvent -LogName Security -FilterXPath "*[System[EventID=4776]]" -MaxEvents 20 |

## Атаки на NTLM

**Pass-the-Hash** (MITRE ATT&CK: [**T1550.002**](https://attack.mitre.org/techniques/T1550/002/))

Использование украденного **NT hash** пароля вместо самого пароля для прохождения **NTLM**-аутентификации. Протокол **NTLM** не различает: знает ли клиент пароль или знает его хэш - с точки зрения сервера обе ситуации криптографически идентичны. Атакующий получает хэш одним из способов (дамп **lsass.exe**, чтение **SAM** на захваченном хосте, утечка резервных копий) и использует его на других машинах, где этот пароль установлен. Это базовая техника горизонтального движения в инфраструктурах с одинаковыми паролями локальных администраторов.

**NTLM Relay Attack** (MITRE ATT&CK: [**T1557**](https://attack.mitre.org/techniques/T1557/), [**T1550.002**](https://attack.mitre.org/techniques/T1550/002/))

Механизм **NTLM Relay** в самом общем виде уже разбирался выше на примере **SMB Relay Attack** - шаги те же: атакующий отравляет разрешение имён, перехватывает аутентификацию жертвы, ретранслирует её на целевой сервис. Универсальность атаки в том, что **NTLM Relay** работает не только с **SMB**, но и с любым сервисом, принимающим **NTLM**-аутентификацию: **LDAP**, **HTTP**/**HTTPS**, **MS-SQL**, **IMAP**, **SMTP**.

Условие успеха - на целевом сервере отсутствует обязательная подпись пакетов или **EPA** (**Extended Protection for Authentication**).

**NetNTLMv2 Cracking** (MITRE ATT&CK: [**T1557.001**](https://attack.mitre.org/techniques/T1557/001/))

Офлайн-взлом перехваченного **NetNTLMv2 challenge-response** для восстановления исходного пароля.

Механизм атаки:

1. **Провокация**: Атакующий через **LLMNR/NBNS poisoning** заставляет жертву подключиться к своему хосту
2. **Захват**: При подключении автоматически отправляется **NTLM**-аутентификация, и атакующий получает **NetNTLMv2 challenge-response** жертвы
3. **Подбор**: Запускает офлайн-перебор: для каждого пароля из словаря вычисляет ожидаемый response и сравнивает с захваченным
4. **Успех**: При совпадении - исходный пароль восстановлен

Эффективность атаки полностью зависит от сложности пароля жертвы. Короткие словарные пароли восстанавливаются за минуты, длинные случайные - неподъёмны вычислительно.

**NTLM Downgrade Attack**

Принуждение клиента и сервера к использованию более слабой версии **NTLM** (**NTLMv1** вместо **NTLMv2**). Атакующий в позиции **MitM** модифицирует **Negotiate**-сообщения, удаляя из них флаг поддержки **NTLMv2** - и переговоры падают на **NTLMv1**, который криптографически намного слабее (фиксированный размер response, **DES**, отсутствие **client challenge**). Полученный **NetNTLMv1 response** взламывается на порядок быстрее.

**Golden Ticket / Silver Ticket** (для доменных хостов)

Подделка **Kerberos**-билетов с использованием украденного хэша **krbtgt** (Golden) или сервисной учётной записи (Silver). Атака актуальна для доменных сред с **Active Directory** и упоминается здесь только для полноты картины **NTLM**/**Kerberos**-экосистемы - **NTLM**, **Kerberos** и компрометация контроллеров домена тесно взаимосвязаны. Детально атака разбирается в материалах по **Active Directory**.

## Какие механизмы защиты работают на NTLM

- **LmCompatibilityLevel = 5** - только **NTLMv2**, отказ от приёма любых **LM**/**NTLMv1**
- **NoLMHash = 1** - запрет хранения **LM**-хешей в **SAM**
- **SMB Signing** обязателен - блокирует **NTLM Relay** на **SMB**
- **EPA** (**Extended Protection for Authentication**) - связывание **NTLM**-сессии с **TLS**-каналом, защита от relay на прикладных сервисах (**LDAP**, **HTTP**)
- **Credential Guard** в **VBS** - изоляция секретов **LSASS**, делает **Pass-the-Hash** невозможным без эксплуатации гипервизора
- **LAPS** - уникальные пароли локальных администраторов, ломают горизонтальное распространение через украденный хэш
- **Длинные пароли** (14+ символов, не из словаря) - делают **NetNTLMv2 Cracking** вычислительно неподъёмным
- **Отключение LLMNR и NetBIOS over TCP/IP** - закрывает основной механизм провокации **NTLM**-аутентификации (как разбиралось выше)
- **Переход на Kerberos и Smart Card** для критичных учётных записей в доменной среде
- **ICSP** (**Integrity Channel Session Protection**) в Windows 11 24H2+ - современный механизм защиты сессии
- **Установка обновлений в приоритете** - Microsoft постепенно сокращает поверхность **NTLM**, начиная с Windows 11 / Server 2025

## Чек-лист: безопасность сетевых протоколов Windows

### Обязательные действия (Must Have)

- Отключить **LLMNR** через **GPO**: **Computer Configuration -> Administrative Templates -> Network -> DNS Client**
- Отключить **NetBIOS over TCP/IP** на всех сетевых адаптерах
- Отключить **SMBv1**: **Set-SmbServerConfiguration -EnableSMB1Protocol $false**
- Включить **SMB Signing**: **Set-SmbServerConfiguration -RequireSecuritySignature $true**
- Установить **LmCompatibilityLevel = 5** (только **NTLMv2**)
- Запретить хранение **LM**-хешей: **NoLMHash = 1**
- Включить **NLA** для **RDP**: **UserAuthentication = 1**
- Отключить **Print Spooler** на серверах, не являющихся принт-серверами
- Отключить **WinRM**, если не используется для управления
- Включить аудит (**Event ID 4624**, **4625**, **4688**, **4776**, **5140**, **7045**)

### Рекомендуемые действия (Should Have)

- Включить **SMB Encryption** (**SMB 3.0+**): **Set-SmbServerConfiguration -EncryptData $true**
- Использовать **LAPS** для уникальных паролей локальных администраторов
- Включить **Credential Guard** на поддерживаемых системах (Windows 10/11, Server 2016+)
- Включить **RunAsPPL** для защиты **lsass.exe**
- Настроить **JEA** (**Just Enough Administration**) для **WinRM**
- Использовать **Restricted Admin Mode** для **RDP**
- Включить **Script Block Logging** для **PowerShell**
- Установить **Sysmon** с конфигурацией **SwiftOnSecurity**
- Настроить **WEF** (**Windows Event Forwarding**) для централизованного сбора логов

### Продвинутые меры (Nice to Have)

- Включить **HVCI** (**Hypervisor-Protected Code Integrity**)
- Развернуть **RD Gateway** для безопасного доступа к **RDP** извне
- Использовать **MFA** для **RDP** (**Duo**, **Azure MFA Server**)
- Настроить **EPA** (**Extended Protection for Authentication**) для **NTLM**
- Внедрить **ICSP** (**Integrity Channel Session Protection**) на Windows 11 24H2+
- Сегментировать сеть (**VLAN**, firewall rules между сегментами)
- Развернуть **EDR**-решение с детектом аномалий
- Настроить **SIEM** с корреляционными правилами для детекта атак

## Словарь терминов

| Термин | Расшифровка | Описание |
|---|---|---|
| NDIS | Network Driver Interface Specification | Спецификация драйверов сетевых карт, работающая в режиме ядра |
| NLA | Network Location Awareness | Служба определения сетевого профиля (Domain/Private/Public) |
| LLMNR | Link-Local Multicast Name Resolution | Протокол локального разрешения имён (замена DNS в локальной сети) |
| NBNS | NetBIOS Name Service | Служба разрешения NetBIOS -имён (устаревшая) |
| SMB | Server Message Block | Протокол файлового шаринга и межпроцессного взаимодействия |
| RPC | Remote Procedure Call | Протокол удалённого вызова процедур |
| DCOM | Distributed COM | Расширение COM для сетевого взаимодействия |
| WinRM | Windows Remote Management | Реализация WS-Management для удалённого управления |
| WMI | Windows Management Instrumentation | Инфраструктура управления и мониторинга системы |
| RDP | Remote Desktop Protocol | Протокол удалённого графического доступа |
| NTLM | NT LAN Manager | Протокол аутентификации Windows (challenge-response) |
| NLA | Network Level Authentication | Требование аутентификации до установления RDP -сессии |
| EPA | Extended Protection for Authentication | Защита NTLM от relay-атак через channel binding |
| LAPS | Local Administrator Password Solution | Решение для уникальных паролей локальных администраторов |
| VBS | Virtualization-Based Security | Изоляция секретов через гипервизор |
| HVCI | Hypervisor-Protected Code Integrity | Защита целостности кода ядра через гипервизор |

У Вас в руках теперь подробная карта сетевого стека Windows. Восемь подразделов - это восемь точек, в которых одновременно происходит и легитимная работа администратора, и реальные атаки. Главное, что специалист уносит из этой статьи: проверка любого хоста или сегмента сети начинается с инспекции четырёх плоскостей - брандмауэр и его профили, протоколы файлового обмена (**SMB**, **RPC**), протоколы удалённого управления (**WinRM**, **WMI**, **RDP**) и протокол аутентификации (**NTLM**). К каждой плоскости в статье есть свой набор **PowerShell**-команд - это и есть рабочий минимум для аудита.
