# Локальные политики

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Локальные политики
>
> **Кейсы:** [3.08 LPO](../../cases/windows/3.08%20LPO.md)

**Local Policy Object (LPO)** - это фундаментальный инструмент безопасности Windows, который работает на уровне отдельного хоста (в отличие от доменных групповых политик). Это набор правил, определяющих, как операционная система защищает себя: от сложности пароля до того, кто может завершить системный процесс. Вопрос о том, как заставить компьютер требовать сложный пароль или заблокировать учётную запись после нескольких неудачных попыток входа, решается именно здесь.

Управление локальными политиками ведётся через консоль **secpol.msc** - оснастку **Microsoft Management Console** (**MMC**), которая предоставляет доступ ко всем критическим настройкам безопасности.

> **Важно:** для запуска и, особенно, изменения настроек LPO требуются права **локального администратора**. Обычный пользователь может только просматривать настройки, но не менять их.

После изменения настроек они не вступают в силу мгновенно. Чтобы политики применились немедленно, можно выполнить следующую команду, которая принудительно обновит все политики без перезагрузки: `gpupdate /force`

## Структура LPO

Консоль **secpol.msc** разделена на несколько ключевых категорий, каждая из которых отвечает за свой аспект безопасности.

![](../../_images/85a6a144a88a.webp)

### Политики учетных записей (Account Policies)

Это первая линия обороны. Она управляет тем, как пользователи создают и используют свои пароли, а также как система реагирует на попытки взлома.

**А. Политика паролей (Password Policy)**

Эта группа настроек определяет требования к паролям всех локальных пользователей. Это основной инструмент против атак перебором.

![](../../_images/10ee455b565f.webp)

| Настройка | Рекомендованное значение | Что делает | Почему это важно |
|---|---|---|---|
| Store passwords using reversible encryption | Отключено | Определяет, будет ли система хранить пароли в менее безопасном, обратимом виде | Категорически рекомендуется отключить . Включение этой настройки - грубая ошибка безопасности, так как позволяет злоумышленнику легко расшифровать пароли |
| Maximum password age | 30-90 дней | Через указанное количество дней система потребует сменить пароль | Заставляет регулярно обновлять пароли, ограничивая временное окно для атак |
| Minimum password age | 1-2 дня | Запрещает пользователю сменить пароль повторно до истечения этого срока | Предотвращает мгновенную смену пароля для обхода истории паролей ("сменил и вернул старый") |
| Minimum password length | 10-14 символов | Устанавливает наименьшее допустимое количество символов в пароле | Чем длиннее пароль, тем сложнее его подобрать перебором |
| Password must meet complexity requirements | Включено | Требует, чтобы пароль содержал символы трех из четырех категорий: заглавные буквы, строчные буквы, цифры, спецсимволы | Делает пароли устойчивыми к атакам по словарю |

**Б. Политика блокировки учетной записи (Account Lockout Policy)**

Эта группа настроек защищает от автоматизированных атак перебором паролей.

![](../../_images/e6f99f6699af.webp)

| Настройка | Рекомендованное значение | Что делает |
|---|---|---|
| Account lockout duration | 15-30 минут | Как долго учетная запись будет заблокирована после превышения порога. |
| Account lockout threshold | 3-5 неудачных попыток | Количество неудачных попыток ввода пароля, после которого учетная запись блокируется. |
| Reset account lockout counter after | 15-30 минут | Время, после которого счетчик неудачных попыток обнуляется. |

**Пример атаки:** Если порог блокировки установлен в 3 попытки, а злоумышленник пытается подобрать пароль, автоматическая программа будет заблокирована после трех неверных догадок и не сможет продолжать атаку в течение определенного времени.

### Локальные политики

Политики учётных записей закрывают первый рубеж - управление паролями и блокировками. Следующий уровень - локальные политики, они определяют уже более тонкие вещи: что именно система фиксирует в журналах, какие системные привилегии кому выданы и как ведёт себя сама ОС.

**А. Политика аудита (Audit Policy)**

Аудит - это механизм, позволяющий отслеживать события безопасности. При настройке аудита Windows начинает записывать указанные типы событий в **Журнал безопасности (Security Log)**, который можно просмотреть через **Просмотр событий (Event Viewer)**.

> **Ключевое правило аудита.** Если событие не логируется, оно останется незамеченным.

**Рекомендуемые политики аудита:**

| Категория аудита | Рекомендуемая настройка | Что отслеживает | Почему это важно |
|---|---|---|---|
| Audit logon events | Успех, Отказ | Успешные и неудачные попытки входа пользователей | Обнаружение брутфорс-атак (много событий 4625 ) и несанкционированного доступа |
| Audit account management | Успех, Отказ | Создание, удаление, изменение пользователей и групп | Отслеживание создания скрытых администраторов |
| Audit object access | Успех, Отказ | Доступ к файлам, папкам, ключам реестра | Выявление несанкционированного чтения секретных данных. Требует дополнительной настройки для каждого объекта |
| Audit policy change | Успех, Отказ | Изменение прав пользователей, политик аудита | Обнаружение попыток злоумышленника отключить защиту |
| Audit system events | Успех, Отказ | Перезагрузки, остановки служб, очистка логов | Обнаружение сбоев и действий по заметанию следов (событие 1102 - очистка журнала!) |

**Как включить аудит:**

1. **secpol.msc** → **Параметры безопасности** → **Локальные политики** → **Политика аудита**
2. Дважды кликаем по нужной политике
3. Отмечаем чекбоксы **Успех** (удачные операции) и **Отказ** (неудачные попытки) в зависимости от задачи
4. Нажимаем **OK**

![](../../_images/727a8ca0b4eb.webp)

**Б. Назначение прав пользователя**

Это одна из самых мощных и опасных для экспериментов частей LPO. Она определяет, какие **действия** могут выполнять пользователи или группы на компьютере. Это не разрешения на файлы, а системные привилегии.

![](../../_images/352c878537e6.webp)

| Право пользователя | Рекомендуемое назначение | Что делает | Риски при неправильной настройке |
|---|---|---|---|
| Access this computer from the network | Administrators, Authenticated Users | Определяет, кто может подключаться к общим ресурсам компьютера по сети | Добавление Everyone или Guest открывает доступ анонимам |
| Allow log on locally | Administrators, Users | Определяет, кто может физически войти в систему | Удаление Administrators блокирует физический вход. Добавление Everyone или Guest опасно |
| Allow log on through Remote Desktop Services | Administrators, Remote Desktop Users | Определяет, кто может подключаться удаленно через RDP | Выдача обычным пользователям на сервере - угроза безопасности |
| Shut down the system | Administrators, Backup Operators | Определяет, кто может выключить компьютер | Обычные пользователи не должны выключать сервер |
| Create a pagefile | Administrators | Кто может создавать и изменять размер файла подкачки | Злоумышленник может создать большой файл подкачки для анализа памяти |
| Debug programs | Administrators | Позволяет присоединять отладчик к процессам | Дает полный доступ к памяти процессов, включая LSASS . Выдавать с осторожностью |
| Restore files and directories | Administrators, Backup Operators | Позволяет обходить NTFS -разрешения при восстановлении файлов | Пользователь может перезаписать системные файлы |
| Manage auditing and security log | Administrators | Позволяет просматривать и очищать журнал безопасности | Пользователь с этим правом может замести следы ( Event ID 1102 ) |
| Take ownership of files or other objects | Administrators | Позволяет стать владельцем любого объекта | Владелец всегда может изменить разрешения и получить доступ к любым данным |

**В. Параметры безопасности (Security Options)**

Это большая коллекция логических переключателей, которые включают или отключают различные аспекты поведения системы.

![](../../_images/399f3a996f4d.jpg)

Ключевые из них:

| Категория | Настройка | Рекомендация | Что делает |
|---|---|---|---|
| Учетные записи | Accounts: Administrator account status | Отключено | Включает или отключает встроенную учетную запись администратора |
| Accounts: Guest account status | Отключено | Отключает встроенную гостевую учетную запись |
| Accounts: Rename administrator account | Уникальное имя | Усложняет задачу злоумышленнику, которому нужно найти учетную запись с RID 500 |
| Интерактивный вход | Interactive logon: Do not display last user name | Включено | На экране входа не показывается имя последнего пользователя |
| Interactive logon: Do not require CTRL+ALT+DEL | Отключено | Требовать нажатия Ctrl+Alt+Del для защиты от программ-имитаторов экрана входа |
| Сеть | Network access: Do not allow anonymous enumeration of SAM accounts and shares | Включено | Запрещает анонимное получение списка локальных пользователей |
| Пользовательский контроль учетных записей (UAC) | User Account Control: Behavior of the elevation prompt for administrators in Admin Approval Mode | Запрашивать согласие | Требует явного согласия администратора для действий с повышением прав |
| User Account Control: Behavior of the elevation prompt for standard users | Запрашивать учетные данные | Требует ввода пароля администратора от обычного пользователя |

## Конфигурация расширенной политики аудита

Классическая политика аудита, которую мы настроили выше, работает на уровне категорий и даёт грубый контроль. В современных версиях Windows появился более точный инструмент - расширенная конфигурация аудита, которая позволяет включать отдельные подкатегории событий.

**Ключевые отличия от классического аудита:**

- **Детализация:** Можно включить аудит только создания процессов (**Audit Process Creation**), не включая аудит завершения процессов
- **Гибкость:** Можно настроить аудит для конкретных типов доступа к объектам
- **Конфликт:** Если включена и классическая, и расширенная политика аудита, приоритет имеет расширенная (если она настроена). Microsoft рекомендует использовать только расширенную

## Уязвимости, связанные с настройками LPO

Зная, как устроен **LPO**, важно понять, где именно администраторы чаще всего ошибаются. Неправильная конфигурация - не абстрактная угроза: каждая из приведённых ниже настроек имеет реальный вектор атаки.

### Ошибки конфигурации (Misconfiguration)

Это когда администратор ослабляет защиту "для удобства", создавая дыры.

| Ослабленная настройка | Причины | Чем опасна (уязвимость) |
|---|---|---|
| Отключение UAC ( User Account Control: Run all administrators in Admin Approval Mode ) | Удобство (нет раздражающих запросов), совместимость со старым ПО | Злоумышленник может получить права администратора без ведома пользователя. Малварь может отключить защиту без UAC -запроса |
| Разрешение автоматического входа (Auto Logon) | Удобство для киосков/терминалов, скорость доступа | Пароль в открытом виде хранится в реестре ( HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon ). Любой, кто получит доступ к системе, сможет его прочитать |
| Отключение требования Ctrl+Alt+Del | Устройства без физической клавиатуры (планшеты), упрощение действий для доступа к рабочему месту для избранных сотрудников | Злоумышленник может подделать экран входа (фишинговую форму) и перехватить пароль пользователя |
| Разрешение анонимного перечисления SAM ( Network access: Do not allow anonymous enumeration of SAM accounts ) | Совместимость с legacy-приложениями и сканерами, миграция со старых доменов | Анонимный пользователь может получить список всех учетных записей на компьютере, что упрощает задачу для брутфорса |
| Хранение LM-хеша пароля | Поддержка Windows 95/98/NT4 , устаревшие системы аутентификации, legacy-приложения | LM -хеш крайне ненадежен и легко взламывается за секунды |
| Разрешение установки драйверов в режиме ядра для принтеров | Пользователи могут сами ставить принтеры, снижение нагрузки на Helpdesk | Некачественный или вредоносный драйвер работает в ядре (Ring 0). Его ошибка вызовет BSOD, а вредоносный код получит полный контроль над системой |

### Политики ограниченного использования программ (SRP)

Отдельного внимания заслуживают политики ограниченного использования программ. Это мощный механизм контроля запуска, но при неаккуратной настройке он может заблокировать работу самого администратора.

| Проблема | Описание |
|---|---|
| Блокировка самого себя | Если создать правило, запрещающее запуск regedit.exe или mmc.exe , без прав локального администратора откатить изменения не получится. Решение: всегда исключайте локальных администраторов из действия политик ( secpol.msc → Политики ограниченного использования программ → Принудительный → "Пропустить администраторов") |
| Конфликт правил (путь vs хеш) | Правила на хеш имеют приоритет над правилами на путь. Если запрещён хеш notepad.exe , даже перемещение файла или создание правила на новый путь не снимет блокировку. Правило: при конфликте побеждает более строгое ограничение |

## Экспорт, импорт и применение политик

Настроив политики на одном хосте, имеет смысл зафиксировать конфигурацию и перенести её на другие машины - особенно при развёртывании однотипных рабочих станций или серверов.

Одним из главных преимуществ **LPO** является возможность экспортировать настройки в файл **.inf** и применить их на других компьютерах. Это основа для создания эталонных конфигураций безопасности.

![](../../_images/c18a8ed2d679.jpg)

**Экспорт политики:**

1. Открываем **secpol.msc**
2. Нажимаем **Action** → **Export Policy...**
3. Указываем имя файла и место для сохранения

**Импорт политики:**

1. Открываем **secpol.msc**
2. Нажимаем **Action** → **Import Policy...**
3. Выбираем ранее сохраненный файл **.inf**
4. Политика будет импортирована поверх существующих настроек

## Управление через PowerShell

**PowerShell** предпочтительнее графических инструментов: позволяет автоматизировать проверку политик, работает одинаково на всех версиях Windows 10/11/Server и легко встраивается в скрипты аудита.

| Команда | Что делает |
|---|---|
| gpresult /r | Показывает политики, применённые к компьютеру и пользователю |
| gpresult /h C:\temp\gp_report.html /f | Генерирует HTML-отчёт с полным описанием применённых политик |
| net accounts | Показывает политику паролей: минимальную длину, максимальный срок, порог блокировки |
| auditpol /get /category:* | Показывает все категории аудита и их состояние ( Success, Failure, No Auditing ) |
| auditpol /set /subcategory:"Logon" /success:enable /failure:enable | Включает аудит входов ( успех и отказ ) |
| auditpol /set /subcategory:"Process Creation" /success:enable /failure:enable | Включает аудит создания процессов |
| auditpol /set /subcategory:"Security Group Management" /success:enable /failure:enable | Включает аудит управления группами безопасности |
| Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" | Проверяет текущий уровень UAC ( EnableLUA , ConsentPromptBehaviorAdmin , PromptOnSecureDesktop ) |
| Get-LocalUser | Where-Object { $_.SID -match '-500$|-501$' } | Select-Object Name, Enabled, SID, LastLogon | Проверяет статус встроенных учётных записей Administrator ( RID 500 ) и Guest ( RID 501 ) |
| Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" | Select-Object AutoAdminLogon, DefaultUserName, DefaultPassword | Проверяет наличие автологина (пароль в открытом виде в реестре) |

Команды выше позволяют быстро получить срез состояния безопасности хоста без входа в графический интерфейс. Для регулярного контроля их удобно объединять в скрипт и запускать по расписанию.
