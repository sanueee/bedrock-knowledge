# Сетевой стек Windows

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Сетевой стек Windows и удалённое управление
>
> **Кейсы:** [3.06 NFS](../../cases/windows/3.06%20NFS.md), [3.07 Сетевой стек](../../cases/windows/3.07%20Сетевой%20стек.md)

**Сетевой стек Windows** - это не просто реализация **TCP/IP**, а многоуровневая платформа с политиками, профилями и встроенными механизмами безопасности. После получения **IP**-адреса Linux молча начинает работать, а Windows запускает цепочку скрытых процессов: применяет сетевые профили, меняет правила фаервола, обнаруживает соседей по локальной сети, пытается зарегистрироваться у контроллера домена. Каждый из этих шагов - потенциальная точка атаки или защиты.

В этой статье разбирается, как устроен сетевой стек Windows на уровне ядра, какие сервисы инициализируются при подключении к сети, какие протоколы удалённого управления существуют (**SMB**, **RPC**, **WinRM**, **WMI**, **RDP**) и какие из них наиболее активно используются атакующими.

## NDIS: Network Driver Interface Specification

В фундаменте сетевой архитектуры Windows лежит **Network Driver Interface Specification** (NDIS) - спецификация, работающая на уровне ядра. **NDIS** связывает драйверы физических сетевых карт (**Network Interface Card**, **NIC**) с верхними уровнями сетевого стека. Ключевая особенность - модульность: **NDIS** позволяет встраивать промежуточные фильтрующие драйверы прямо в ядро. Через **NDIS** проходят все сетевые операции, включая фильтрацию, мониторинг и модификацию трафика. Это даёт ядру возможность инспектировать транзитный трафик до того, как он дойдёт до прикладных программ. Именно через **NDIS**-фильтры работают встроенные механизмы фаервола, антивирусные сетевые компоненты и **Sysmon** по сетевым подключениям. Любой **EDR**-агент, анонсирующий "глубокую инспекцию сетевого трафика", регистрирует свой фильтр-драйвер именно в **NDIS**.

> **NDIS** - это строгий логистический диспетчер при сетевой карте. Сетевая карта - водитель грузовика. В Linux водитель просто получает путевой лист и едет. В Windows диспетчер проверяет маршрут, допуски, сканирует тип груза, сверяет номера пломб - и только потом даёт команду заводить двигатель.

## NLA: Network Location Awareness

Как только сетевой интерфейс поднимается и получает **IP**-адрес, вступает служба **Network Location Awareness (NLA)**. Она анализирует окружающее сетевое пространство: пытается разрешить специфические доменные имена, проверяет наличие **SRV**-записей для поиска контроллера домена через **Lightweight Directory Access Protocol (LDAP)**, определяет принадлежность сети к одному из трёх профилей (Domain, Private, Public). Если классический **DNS** недоступен или не может разрешить локальные имена, система активирует протоколы обнаружения соседей: **LLMNR** и **mDNS**. Эти широковещательные протоколы опрашивают все узлы в подсети - и именно этот механизм атакующие используют для перехвата хешей паролей через **LLMNR**/**NBNS poisoning**.
