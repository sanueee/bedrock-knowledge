# SMB

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Сетевой стек Windows и удалённое управление
>
> **Кейсы:** [3.06 NFS](../../cases/windows/3.06%20NFS.md), [3.07 Сетевой стек](../../cases/windows/3.07%20Сетевой%20стек.md)

**SMB** - основной протокол Windows для доступа к файлам, папкам, принтерам и некоторым механизмам межпроцессного взаимодействия по сети. Microsoft описывает [**SMB**](https://learn.microsoft.com/ru-ru/windows-server/storage/file-server/file-server-smb-overview) как сетевой протокол общего доступа к файлам, позволяющий приложениям читать, создавать и изменять файлы на удалённом сервере; полная спецификация - [**MS-SMB**](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb/f210069c-7086-4dc2-885e-861d837df688).

По сети современный SMB работает поверх порта TCP 445 (для обратной совместимости исторически оставлен TCP 139 через NetBIOS). Внутри самой Windows за обработку этого трафика отвечают две системные службы:

- **Server / LanmanServer** — принимает входящие подключения и дает доступ к локальным ресурсам
- **Workstation / LanmanWorkstation** — инициирует исходящие подключения клиента к чужим шарам

Теоретически **SMB** важно разбирать как **протокол состояний с сессией, аутентификацией, доступом к ресурсам и операциями над файлами**. Клиент устанавливает соединение, договаривается о диалекте **SMB**, проходит аутентификацию, подключается к **share** и затем выполняет операции чтения, записи, перечисления, блокировок и так далее.

> **SMB** - это возможность легально зайти в архив чужого офиса и взять нужные папки с документами. **MS-RPC** (будет разбираться в следующем подразделе) - это возможность передать по рации приказ сотруднику в чужом офисе, чтобы он сам выполнил нужную работу и сообщил готовый результат.

## Базовые понятия

| Термин | Описание | Пример / Формат |
|---|---|---|
| SMB Dialect | Версия (диалект) протокола, определяющая его возможности | SMB 2.1 , SMB 3.1.1 |
| Share | Опубликованный сетевой ресурс (папка, принтер) | Docs , Finance |
| UNC-путь | Universal Naming Convention - стандартный формат пути до сетевого ресурса | \host\share |
| IPC$ | Специальная скрытая шара для межпроцессного взаимодействия ( Inter-Process Communication ) | \host\IPC$ |

## Ключевые механизмы (точки интереса для атакующего)

За базовыми терминами скрываются механизмы, на которых строятся основные техники разведки и lateral movement:

**Административные шары (Admin Shares).** Windows автоматически создаёт на каждом хосте скрытые сетевые ресурсы для нужд администраторов. Их имена всегда заканчиваются на знак доллара (**$**), поэтому они не отображаются при обычном перечислении (например, в **net view**):

- **C$** - полный доступ ко всему системному диску
- **ADMIN$** - доступ к директории **%SystemRoot%** (обычно **C:\Windows**)
- **IPC$** - доступ к именованным каналам межпроцессного взаимодействия

Шары доступны только членам группы **Administrators**. Именно через шару **ADMIN$** под капотом работает утилита **PsExec** и большинство техник бокового перемещения: получив права локального администратора, атакующий копирует свой исполняемый файл в эту директорию и удалённо запускает его в виде системной службы.

**Именованные каналы (Named Pipes).** Это механизм межпроцессного взаимодействия в Windows. Когда такой канал публикуется поверх **SMB**, к нему можно обратиться по сети по пути **\host\IPC$\pipe\имя_канала**.

Через named pipes становятся доступны многие критичные **RPC**-интерфейсы. Например, обратившись к **\pipe\samr**, можно взаимодействовать с локальной базой пользователей (**SAM**), а через **\pipe\lsarpc** - с политиками **LSA**. Также часто встречаются **\pipe\netlogon** (доменная аутентификация) и **\pipe\srvsvc** (управление шарами).

## Защита на уровне протокола

Современный **SMB** обладает встроенными механизмами защиты от сетевых атак:

**SMB Signing (Подпись).** Каждое сообщение снабжается криптографической подписью. Получатель проверяет её, чтобы убедиться, что пакет пришёл от ожидаемого источника и не был модифицирован "на лету". Это фундаментальная защита от **MitM**-атак и **SMB Relay**.

**SMB Encryption (Шифрование).** Появилось в новых диалектах протокола. Шифрует саму полезную нагрузку **SMB**-трафика, защищая данные от сниффинга (перехвата) внутри сети.

**Важно понимать разницу диалектов:**

- **SMBv1** - шифрования нет, подпись слабая, протокол изобилует историческими уязвимостями (**EternalBlue**, **WannaCry**, **NotPetya**). Если в инфраструктуре где-то остался включённым **SMBv1** - это критическая проблема, его необходимо отключать немедленно. Современные Windows Server вообще не должны иметь установленный компонент **SMB 1.0/CIFS File Sharing Support**
- **SMBv2** - обязательная подпись через **HMAC SHA-256**. Шифрование появилось только в **SMBv3**
- **SMBv3** - подпись + сквозное шифрование с современными алгоритмами **AES-128-GCM** / **AES-256-GCM**. Базовый стандарт для современной инфраструктуры

Подробнее о современном функционале можете почитать здесь: [**современные функции SMB**](https://learn.microsoft.com/ru-ru/windows-server/storage/file-server/smb-feature-descriptions).

Эти понятия пригодятся при чтении вывода команд ниже. Сами команды покрывают четыре среза - конфигурацию сервера, опубликованные шары, активные сессии и клиентские подключения.

## Управление SMB через PowerShell

| Для чего | Команда |
|---|---|
| Проверка версии SMB и параметров безопасности ( EnableSMB1Protocol = False и RequireSecuritySignature = True обязательны) | Get-SmbServerConfiguration | Select-Object EnableSMB1Protocol, EnableSMB2Protocol, RequireSecuritySignature, EncryptData, RestrictNullSessAccess |
| Список всех SMB -шар с путями | Get-SmbShare | Select-Object Name, Path, Description, CurrentUsers |
| Проверка прав на SMB -шары | Get-SmbShareAccess -Name * | Select-Object Name, AccountName, AccessRight |
| Проверка активных SMB -сессий (кто подключён) | Get-SmbSession | Select-Object ClientComputerName, ClientUserName, NumOpens, SecondsExists |
| Проверка маппинга подключённых сетевых дисков | Get-SmbMapping | Select-Object LocalPath, RemotePath, Status |

## Атаки на SMB

**SMB Share Enumeration** (MITRE ATT&CK: [**T1135**](https://attack.mitre.org/techniques/T1135/))

Данная техника представляет собой массовый сбор информации об открытых сетевых папках в инфраструктуре. Особенность этого этапа разведки заключается в том, что система сама охотно отдаёт список расшаренных ресурсов любому авторизованному (а иногда и анонимному) пользователю в рамках стандартного функционала **SMB**. Злоумышленник просто обходит доступные хосты, выявляя забытые директории, скрытые административные шары или папки со слишком широкими правами доступа.

**SMB Relay Attack** (MITRE ATT&CK: [**T1557**](https://attack.mitre.org/techniques/T1557/), [**T1550.002**](https://attack.mitre.org/techniques/T1550/002/))

Перенаправление **NTLM**-аутентификации на другой хост для получения несанкционированного доступа.

Механизм атаки:

1. **Перехват**: Атакующий отправляет поддельный ответ на широковещательный запрос жертвы (например, через **LLMNR** или **NBNS**)
2. **Начало сессии**: Жертва подключается к машине атакующего и инициирует процесс **NTLM**-аутентификации
3. **Relay**: Вместо того чтобы пытаться расшифровать пароль, атакующий выступает в роли прокси и "на лету" перенаправляет этот **NTLM**-запрос на настоящую цель (например, контроллер домена или файловый сервер)
4. **Авторизация**: Целевой сервер проверяет данные и успешно аутентифицирует жертву через атакующего
5. **Захват**: Атакующий получает полноправный доступ к ресурсам целевого сервера от имени жертвы

Условие успеха атаки - на сервере, куда идёт перенаправление, должна быть отключена обязательная криптографическая подпись пакетов (**SMB Signing**).

![](../../_images/cd5053f97dde.webp)

**EternalBlue / SMBv1 Exploitation** (**CVE-2017-0144**)

Эксплуатация уязвимости переполнения буфера в обработке specially crafted пакетов **SMBv1**. Уязвимость позволяет удалённое выполнение кода с правами **SYSTEM** без аутентификации - то есть атакующему не нужны ни логин, ни пароль, ни даже учётная запись на целевой машине. Именно эта уязвимость легла в основу глобальных эпидемий **WannaCry** и **NotPetya** в 2017 году. Червь распространялся между хостами автоматически, пока находил хотя бы один включённый **SMBv1**. После выхода патча **MS17-010** уязвимость закрыта, но факт остаётся: пока в инфраструктуре есть хосты с активным **SMBv1**, они представляют собой потенциальную точку входа.

> **EternalBlue** - это мастер-ключ к старой модели замка, который десятилетиями использовался в большинстве дверей. После того как ключ попал в чужие руки, новые двери поставили с другим замком - но старые замки никуда не делись. Каждая дверь со старым замком остаётся открытой.

![](../../_images/441411fd388e.webp)

**Pass-the-Hash через SMB** (MITRE ATT&CK:** **[**T1550.002**](https://attack.mitre.org/techniques/T1550/002/))

Использование украденного **NTLM**-хэша пароля для аутентификации без знания самого пароля. Особенность **NTLM**-протокола в том, что он не различает: знает ли клиент пароль, или знает его хэш - с точки зрения сервера обе ситуации выглядят идентично. Получив хэш локального администратора с одного хоста (например, из памяти процесса **lsass.exe**), атакующий может использовать его на других хостах, где этот же пароль установлен. Это классический сценарий бокового перемещения в инфраструктурах без **LAPS** и без **Credential Guard**.

![](../../_images/bee3ff6a9860.webp)

**Null Session Enumeration**

Анонимный доступ к **SMB**-ресурсу **IPC$** без указания учётных данных. На старых системах и при определённых настройках реестра это позволяло получить список локальных пользователей, групп, политик, открытых шар - всю поверхностную информацию для дальнейшей разведки. На современных хостах закрыто через параметр реестра **RestrictAnonymous**, но в legacy-инфраструктурах встречается до сих пор.

## Какие механизмы защиты работают на SMB

Часть мер уже разобрана выше в разделе "Защита на уровне протокола" - **SMB Signing**, **SMB Encryption** и отключение **SMBv1**. Это база, без которой все остальные меры неэффективны. Сводный набор практических действий:

- **Отключение SMBv1** на всех хостах в инфраструктуре (**Set-SmbServerConfiguration -EnableSMB1Protocol $false**). На Windows Server также удалить компонент через **Remove-WindowsFeature FS-SMB1**
- **Принудительный SMB Signing** на серверах и клиентах через **GPO** - чтобы исключить **NTLM Relay** на **SMB**
- **SMB Encryption** для всех шар с чувствительными данными (**Set-SmbServerConfiguration -EncryptData $true**)
- **Credential Guard** - изоляция секретов **LSASS** в **VBS**, ломает **Pass-the-Hash**
- **LAPS** (**Local Administrator Password Solution**) - уникальные пароли локальных администраторов на каждом хосте, ломает горизонтальное распространение по украденному хэшу
- **Минимизация шар и регулярный аудит ACL** на них через **Get-SmbShareAccess**
- **Сегментация сети** - порт **445** не должен быть доступен из интернета. На внутренних сегментах ограничить **SMB** между подсетями по принципу наименьших привилегий
- **Отключение Null Session** через **RestrictAnonymous = 2** и **GPO** "Network access: Do not allow anonymous enumeration of SAM accounts"
- **EPA** (**Extended Protection for Authentication**) - защита **NTLM** от relay на прикладных сервисах (**LDAP**, **HTTP**)

Проверочный минимум по **SMB** на любом хосте: убедиться, что **EnableSMB1Protocol = False**, что **RequireSecuritySignature = True**, что нет null-сессий, что список **Get-SmbShare** не содержит лишних точек входа. Эти четыре среза закрывают большую часть исторических векторов.

**SMB** - это про данные. Параллельно с ним в Windows работает другой механизм - вызов кода на удалённой машине, как если бы он выполнялся локально. Это семейство протоколов **MS-RPC** и его объектные надстройки **COM** / **DCOM**.
