# Event Tracing for Windows

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Расширенное журналирование
>
> **Кейсы:** [3.09 Расширенное журналирование](../../cases/windows/3.09%20Расширенное%20журналирование.md)

**Event Tracing for Windows (ETW)** - низкоуровневая инфраструктура ядра для высокопроизводительного трассировочного журналирования. На **ETW** построено большинство диагностических и мониторинговых инструментов Windows, включая сам **Event Viewer**, **Sysmon**, **Windows Performance Recorder (WPR)** и **Performance Monitor**.

> **Аналогия:** Если **Event Viewer** - это журнал дежурного на входе банка, то **ETW** - это вся система внутренней связи банка: переговоры между отделами, внутренние транзакции, сигналы с камер наблюдения. **Event Viewer** - лишь одна из точек, куда эти сигналы могут быть направлены.

Для специалиста по безопасности **ETW** важен с двух сторон. С одной - это основа всех средств обнаружения: без понимания **ETW** невозможно настраивать сложные правила в **Sysmon** или **SIEM**. С другой - именно **ETW** является целью продвинутых техник обхода журналирования. Эти техники разбираются в следующем подразделе про атаки на инфраструктуру журналирования.

## Архитектура ETW: провайдеры, сессии и потребители

**ETW** работает по модели **публикация-подписка** и состоит из трёх компонентов:

![](../../_images/7d3844b2268c.webp)

### Провайдеры - генераторы событий

Провайдер - это любой компонент системы, зарегистрировавшийся в **ETW** как источник событий. Провайдеры пишут события напрямую в кольцевые буферы памяти - без обращения к диску и без блокировки потока выполнения. Именно это делает **ETW** чрезвычайно быстрым: его можно использовать для логирования сотен тысяч событий в секунду без заметной нагрузки на систему.

Типы провайдеров:

| Тип | Описание | Примеры |
|---|---|---|
| MOF-based | Устаревший формат, использует Managed Object Format (MOF) | Старые системные компоненты |
| WPP ( Windows Software Trace Preprocessor ) | Компактный формат для драйверов и системных компонентов | Сетевой стек, драйверы |
| Manifest-based | Современный формат, описывается XML -манифестом | Большинство компонентов Windows 7+ |
| TraceLogging | Самоописывающийся формат, не требует манифеста | Современные приложения и службы |

Каждый провайдер идентифицируется уникальным **Globally Unique Identifier (GUID)**. Несколько примеров провайдеров, с которыми специалист встречается чаще всего:

- **{54849625-5478-4994-A5BA-3E3B0328C30D}** - **Microsoft-Windows-Security-Auditing** (события безопасности от **LSASS**, тот самый журнал **Security**)
- **{A0C1853B-5C40-4B15-8766-3CF1C58F985A}** - **Microsoft-Windows-PowerShell** (все события **PowerShell** включая **Script Block Logging**, **Event ID 4103**/**4104**)
- **{15CA44FF-4D7A-4BAA-BBA5-0998955E531E}** - **Microsoft-Windows-Kernel-Process** (создание процессов на уровне ядра - источник для **Sysmon Event ID 1**)

Полный список зарегистрированных провайдеров на конкретном хосте:

| Для чего | Команда |
|---|---|
| Список всех зарегистрированных провайдеров | logman query providers |
| Поиск провайдера по имени | logman query providers | findstr /i "PowerShell" |

## ETW Сессии - маршрутизатор событий

Сессия **ETW** - это именованный канал, связывающий провайдеров с потребителями. Сессия принимает события от одного или нескольких провайдеров, буферизует их в памяти и направляет потребителям.

Типы сессий:

| Тип | Описание |
|---|---|
| Real-time | События доставляются потребителю немедленно |
| File-based | События пишутся в .etl -файл для последующего анализа |
| Circular buffer | Кольцевой буфер в памяти - старые события перезаписываются новыми |

Просмотр активных **ETW**-сессий: `logman query -ets`

Среди активных сессий всегда есть несколько критичных - например, **EventLog-Security**, через которую идут события в журнал **Security**. Остановка или повреждение этих сессий равнозначно частичному отключению аудита, и это одна из техник атакующих.

### Потребители - читатели событий

Потребитель подписывается на сессию и получает события в реальном времени или читает их из **.etl**-файла. Большинство инструментов мониторинга Windows - именно потребители **ETW**:

| Потребитель | Что делает с ETW |
|---|---|
| Event Viewer | Читает события через провайдер Microsoft-Windows-Eventlog |
| Sysmon | Подписывается на ETW -провайдеры ядра (процессы, сеть, реестр) |
| WPR ( Windows Performance Recorder ) | Записывает сессии в .etl для анализа в Windows Performance Analyzer (WPA) |
| PerfView | Мощный инструмент анализа .etl -файлов |
| Собственный код | Через API OpenTrace() / ProcessTrace() |

### Практическое использование ETW

В большинстве случаев специалист не работает с **ETW** напрямую - вместо этого он использует надстройки (**Event Viewer**, **Sysmon**, **PerfView**). Но иногда полезно создать собственную сессию для отладки или сбора телеметрии в нестандартной ситуации.

Создание сессии с подпиской на конкретный провайдер: `logman create trace "MyPSTrace" ^ -p "Microsoft-Windows-PowerShell" ^ -o C:\Traces\ps_trace.etl ^ -ets`

Управление сессией:

| Для чего | Команда |
|---|---|
| Остановить и сохранить сессию | logman stop "MyPSTrace" -ets |
| Конвертировать .etl -файл в XML для чтения | tracerpt C:\Traces\ps_trace.etl -o output.xml -of XML |
| Прочитать содержимое .etl -файла из PowerShell | Get-WinEvent -Path C:\Traces\ps_trace.etl | Select-Object TimeCreated, Message |

Дополнительные материалы для углубления - [**ETW: Your Friendly Neighborhood IPC Mechanism**](https://blog.palantir.com/tampering-with-windows-event-tracing-background-offense-and-defense-4be7ac62ac63).

**ETW** даёт инфраструктуру сбора телеметрии. На ней построены десятки инструментов - **Performance Monitor**, **Windows Performance Recorder** и другие. Самый востребованный в задачах безопасности - **Sysmon** от пакета **Sysinternals**, который закрывает слепые зоны штатного аудита.
