# Sysmon

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Расширенное журналирование
>
> **Кейсы:** [3.09 Расширенное журналирование](../../cases/windows/3.09%20Расширенное%20журналирование.md)

Штатные журналы покрывают большую часть базовых сценариев, но у них есть серьёзные слепые зоны. Базовый **Event ID 4688** не скажет, какой именно процесс скачал файл из интернета или изменил критическую ветку реестра автозагрузки. Стандартные логи фиксируют **факты**, но плохо фиксируют **связи** и **скрытое поведение**: какой процесс открыл память **lsass.exe**, какая **DLL** была загружена нестандартным способом, к какому домену ушёл **DNS**-запрос от подозрительного процесса.

Для закрытия этой бреши инженеры Microsoft разработали утилиту **System Monitor (Sysmon)** из пакета **Sysinternals**.

**Sysmon** - системная служба и драйвер уровня ядра. После установки **Sysmon** остаётся резидентным: загружается при старте системы и продолжает работать в фоне, фиксируя события напрямую через **ETW** на уровне ядра. Подробности на официальной странице - [**Sysmon - Sysinternals**](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon).

> **Резидентная программа** - программа, которая после завершения своей основной работы не освобождает **RAM**, а остаётся в ней, активируясь по прерыванию или фоново.

## Sysmon vs штатный аудит

Чем именно **Sysmon** отличается от того, что Windows пишет в **Event Viewer** по умолчанию:

| Характеристика | Стандартный Event Log | Sysmon |
|---|---|---|
| Командная строка процессов | Отключено по умолчанию (требует правки GPO ) | Да - всегда полная командная строка с аргументами ( Event ID 1 ) |
| Криптографические хэши | Нет | Да - SHA-1 , SHA-256 для каждого бинарника, можно искать на VirusTotal |
| Сетевые подключения | Только базовые порты, создаёт огромный шум | Да - Event ID 3 связывает процесс, PID , внешний IP , порт и протокол |
| Изменения реестра | Только при включённом сложном аудите ( Event ID 4657 ) | Да - детальный мониторинг ключей ( Event ID 12 , 13 , 14 ) |
| Создание файлов | Требует настройки аудита папок, сильно грузит диск | Да - фиксация времени создания файлов ( Event ID 11 , 15 ) |
| Доступ к памяти процессов | Нет - невозможно отследить инъекции кода | Да - Event ID 8 ( CreateRemoteThread ), главный детектор инъекций |

> **Аналогия:** Штатный аудит - это охранник на входе, который записывает в журнал, кто и когда прошёл через дверь. **Sysmon** - охранник с детектором металла, видеозаписью и связью со всеми этажами: он знает, что у входящего в карманах, откуда тот пришёл, к кому именно идёт и что делает после прохода. Журнал входов остаётся прежним - но к нему добавляется всё, что происходит **вокруг** этого входа.

## Что Sysmon видит: ключевые Event ID

Каждое событие **Sysmon** - это структурированная запись с десятками полей. Базовый набор Event ID, на которые стоит настроить мониторинг в первую очередь:

| Event ID | Что фиксирует | Зачем | Зачем |
|---|---|---|
| 1 | Создание процесса | Полная командная строка + SHA-256 + родитель + пользователь |
| 3 | Сетевое подключение | IP , порт, протокол - с привязкой к процессу |
| 7 | Загрузка модуля ( DLL ) | Какие библиотеки загружает процесс - детект DLL Hijacking |
| 8 | CreateRemoteThread | Главный детектор инъекций кода в чужие процессы |
| 10 | ProcessAccess | Доступ к памяти чужого процесса (например, к lsass.exe ) |
| 11 | Создание файла | Время создания файла + процесс, его создавший |
| 12 , 13 , 14 | Изменения реестра | Создание/изменение/удаление ключей и значений |
| 15 | Создание файла с Zone.Identifier | Mark of the Web - файл из недоверенного источника |
| 22 | DNS -запрос | С привязкой к процессу - детект LLMNR Poisoning и C2 |
| 16 | Изменение конфигурации Sysmon | Кто-то меняет правила фильтрации - подозрительно |

Этот набор закрывает большую часть слепых зон штатного аудита. **Event ID 8** и **10** особенно ценны для детектирования техник вроде **Pass-the-Hash** и **Process Injection**, которые штатный **Security Log** просто не видит.

## Установка Sysmon

Установка **Sysmon** - это не просто запуск установщика. Инструмент работает на основе **XML**-конфигурации, которая определяет, за какими событиями нужно следить, а какие игнорировать. Без конфигурации **Sysmon** начинает логировать абсолютно всё, создавая гигабайты логов в час - поэтому установка в продакшен всегда идёт с готовой конфигурацией .

Базовые команды:

| Для чего | Команда |
|---|---|
| Установка с конфигурацией по умолчанию (минимальная, не для прода) | sysmon64.exe -accepteula -i |
| Установка с пользовательским XML -конфигом | sysmon64.exe -accepteula -i config.xml |
| Обновление конфигурации без переустановки | sysmon64.exe -c config.xml |
| Просмотр текущей конфигурации | sysmon64.exe -c |
| Удаление Sysmon | sysmon64.exe -u |

После установки логи появляются в **Event Viewer** по пути:

**Applications and Services Logs -> Microsoft -> Windows -> Sysmon -> Operational**

## Конфигурация Sysmon: SwiftOnSecurity

Писать свой **XML**-конфиг с нуля - тяжёлая инженерная задача: нужно знать сотни легитимных процессов Windows и заранее придумать исключения для них. Поэтому в индустрии стандартом де-факто стал готовый набор правил от сообщества - [**SwiftOnSecurity sysmon-config**](https://github.com/SwiftOnSecurity/sysmon-config) на GitHub. Это **XML**-конфиг, который:

- Содержит исключения для легитимного шума Windows (обновления, индексация, антивирус)
- Фокусируется на аномалиях, а не на полном потоке событий
- Регулярно обновляется сообществом по мере появления новых техник атак
- Хорошо документирован: каждое правило прокомментировано прямо в **XML**

В боевой инфраструктуре конфиг от **SwiftOnSecurity** обычно используется как **отправная точка**: его дополняют правилами под специфику конкретной среды (например, исключения для корпоративных приложений, дополнительный мониторинг для критичных систем).

**Sysmon** и **ETW** дают нам глубокую видимость происходящего на хосте. Но атакующие давно научились обходить эту видимость - и сделать это можно как тонко (патчинг функций в памяти процесса), так и грубо (очистка журнала, выгрузка драйвера **Sysmon**). Дальше - конкретные техники атак на инфраструктуру журналирования и то, как их обнаруживать.
