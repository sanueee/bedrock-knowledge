# 10. Windows 11 24H2 / Server 2025: VBS enclaves, масштабирование Hyper-V

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Эволюция Windows NT

**VBS Enclaves** - программная доверенная среда выполнения внутри адресного пространства обычного приложения ([**VBS Enclaves**](https://learn.microsoft.com/sl-si/windows/win32/trusted-execution/vbs-enclaves)). Это принципиально новая модель: раньше **VBS** защищал только системные компоненты - **LSASS** через **Credential Guard**, **Code Integrity** через **HVCI**. Теперь любое приложение может создать **enclave** - изолированный регион памяти, защищённый гипервизором, - и разместить там чувствительный код или данные. Даже процесс с правами **SYSTEM** не может прочитать содержимое чужой **enclave**. Для атакующего это новый барьер при анализе защищённых приложений - **ключи**, **credentials**, чувствительные вычисления могут находиться в **enclave**, недоступной через обычные техники чтения памяти процесса. Для разработчика это возможность защитить секреты не на уровне ОС, а на уровне аппаратной изоляции.

**Hyper-V: масштабирование под AI-нагрузки** **Server 2025** поднял пределы **Hyper-V** до **4 PB RAM** на хост при **5-level paging** ([**Hyper-V scale limits**](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/plan/plan-hyper-v-scalability-in-windows-server)). Добавлена поддержка **GPU Partitioning** с **live migration VM** ([**GPU Partitioning**](https://learn.microsoft.com/en-in/windows-server/virtualization/hyper-v/gpu-partitioning)) - **GPU partition** теперь можно передавать между **VM** без остановки, что критично для **AI**/**ML**-нагрузок. С точки зрения безопасности: **GPU partition** - это прямой доступ к железу, и модель изоляции здесь сложнее, чем для **CPU** и **RAM**.

**NVMe и storage performance** Microsoft указывает оптимизации **NVMe** как одно из заметных улучшений релиза ([**What's new in Windows Server 2025**](https://learn.microsoft.com/en-us/windows-server/get-started/whats-new-windows-server-2025)). Для ИБ-инфраструктуры важно: быстрый storage - это не только производительность приложений, но и пропускная способность систем логирования. **SIEM**-агенты и системы аудита не должны быть узким местом; медленный storage приводит к потере событий под нагрузкой.

**Secured-core и VBS как стандартное серверное требование** **Server 2025** продолжает линию, где гипервизор является частью **надежной вычислительной базы** сервера, а не только платформой для **VM**. Компрометация **kernel** в **VTL0** - это не финал атаки, а только её часть. Чтобы добраться до **Credential Guard** или **Code Integrity**, нужно выйти за пределы **VTL0**, что требует уязвимости в самом гипервизоре.
