# Файловая система, папки и типы файлов

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Файловая система, папки и типы файлов
>
> **Кейсы:** [3.04 Автозапуск и переменные среды](../../cases/windows/3.04%20Автозапуск%20и%20переменные%20среды.md)

Файловая система Windows - это карта, по которой ориентируется и сама **ОС**, и пользователь, и любая программа. Понимание её устройства нужно специалисту по двум причинам. Во-первых, через файловую систему проходит большинство ежедневных задач администратора: установка **ПО**, разграничение прав, разбор инцидентов всегда начинаются с вопроса "где что лежит". Во-вторых, файловая система - один из главных ландшафтов, на котором разворачиваются атаки: подмена имён системных файлов, скрытое размещение полезной нагрузки, манипуляции с расширениями. Защита здесь начинается со знания нормы.

Эта статья - про устройство этой карты: где что лежит в Windows, как ядро отличает один тип файла от другого, какие папки и форматы становятся целью при атаках и что специалист должен видеть, чтобы такие приёмы замечать.

## NTFS как фундамент

Стандартная файловая система Windows - **New Technology File System (NTFS)**. Из её устройства на этом этапе нужны три факта, на которых держится вся локальная безопасность хоста.

- **Списки контроля доступа** (**Access Control Lists**, **ACL**). На каждый файл и каждую папку **NTFS** хранит описание того, кому что разрешено. Это работает на уровне файловой системы, до того как файл откроет какая-либо программа. Старые системы вроде **FAT32** и **exFAT** этого вообще не умеют, поэтому флешки с **FAT32** не годятся для хранения чувствительных данных - кто получил физический доступ, тот и читает. Детали разграничения прав и синтаксиса **SDDL** разбирались ранее в курсе
- **Журналирование**. Перед каждым изменением метаданных **NTFS** записывает план в журнал. Если сервер падает по питанию посередине операции, при следующей загрузке система либо доводит начатое до конца, либо откатывает. Файловая система не превращается в кашу
- **Шифрование** (**Encrypting File System**, **EFS**) и поддержка **BitLocker**. **NTFS** позволяет шифровать отдельные файлы и папки силами системы. Без учётной записи владельца данные превращаются в нечитаемый поток байтов
- **Альтернативные потоки данных** (**Alternate Data Streams**, **ADS**). В одном файле **NTFS** может хранить несколько именованных потоков. Сама Windows этим пользуется, например, для метки **Zone.Identifier** (флаг "файл скачан из интернета"). Злоумышленники используют ту же возможность для сокрытия полезной нагрузки, поэтому специалист должен знать про существование **ADS** и инструменты, которые их показывают

На системные диски Windows ставится только **NTFS**. **FAT32** и **exFAT** живут на флешках, картах памяти и устройствах, которым нужна совместимость с микроконтроллерами. Для проверки целостности тома есть утилита **chkdsk**, для разметки и операций с разделами - **diskpart**. И ту, и другую достаточно знать на уровне "существует, открывается из административной командной строки, делает ровно то, что обещает её документация". Глубоко в их флаги уходить не нужно - они не дают новых векторов и не дают новой защиты, если Вы понимаете файловую систему по существу.

> **NTFS** относится к **FAT32** так же, как офисное здание с турникетом, охраной и журналом посещений относится к складу с распахнутыми воротами. Снаружи и то, и то - "помещение, где хранят вещи". Внутри - две разные модели доверия.

Файловая система - это контейнер, в котором живут все остальные сущности Windows. Теперь о том, как этот контейнер организован: какие каталоги создаются по умолчанию и за что отвечает каждый из них.

## Структура папок Windows

Каждая директория Windows имеет своё назначение и связанные с ним ожидания антивируса, **EDR** и администратора. Знание этих ожиданий - половина детектирования.

**Системный корень: C:\Windows**

Внутри лежат два каталога, на которых держится вся исполняемая часть Windows.

- **C:\Windows\System32** - вопреки имени, в современной 64-битной Windows здесь лежат 64-битные системные библиотеки, утилиты и драйверы. Имя осталось с эпохи 32-битных систем, и его не стали менять, чтобы не сломать программы с захардкоженным путём. Здесь живут **ntoskrnl.exe** (ядро), **lsass.exe** (подсистема безопасности), **svchost.exe** (хост служб), стандартные утилиты вроде **cmd.exe**, **regedit.exe**, **wevtutil.exe**
- **C:\Windows\SysWOW64** - 32-битные системные библиотеки для совместимости. Когда 32-битная программа запрашивает **kernel32.dll**, подсистема **WoW64** (**Windows-on-Windows 64**) прозрачно перенаправляет её сюда вместо **System32**

| Папка | Что лежит | Кто использует |
|---|---|---|
| C:\Windows\System32 | 64-битные библиотеки, драйверы, утилиты ОС | 64-битные программы и сама Windows |
| C:\Windows\SysWOW64 | 32-битные библиотеки и утилиты | 32-битные программы через WoW64 |
| C:\Program Files | Установленные 64-битные программы | Все пользователи |
| C:\Program Files (x86) | Установленные 32-битные программы | Все пользователи |
| C:\ProgramData | Общие конфигурации программ для всех пользователей | Любая учётка, у которой есть доступ |
| C:\Users\Vasya\AppData\Local | Кэш, тяжёлые временные файлы конкретного пользователя | Только владелец профиля |
| C:\Users\Vasya\AppData\Roaming | Лёгкие настройки, синхронизируемые в домене | Только владелец профиля |

**Папка AppData**

Скрытая папка **AppData** внутри профиля пользователя - одно из самых посещаемых злоумышленником мест. Она делится на три подкаталога; интерес представляют два.

- **AppData\Local** - тяжёлый локальный кэш программ: история браузера, временные файлы, базы клиентских приложений. В домене **не синхронизируется** между машинами
- **AppData\Roaming** - лёгкие настройки и конфигурации. В корпоративной сети с настроенными **roaming**-профилями **переезжает** за пользователем на другой хост

Почему **AppData** интересна атакующему: пользователю не нужны права администратора, чтобы писать в свой профиль. Любой бинарник, загрузку которого нужно сделать без **User Account Control** (**UAC**), оказывается именно здесь. Внутри **AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup** живёт пользовательская папка автозагрузки - всё, что туда положено, запускается при следующем входе в систему. Это один из самых старых и до сих пор рабочих способов закрепиться. Системная папка автозагрузки находится по пути **C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup** и срабатывает для всех пользователей хоста.

Практический смысл этого знания: при разборе подозрительной активности на хосте проверка **AppData** и обеих папок автозагрузки - один из первых шагов. Конкретные команды для просмотра содержимого этих папок даны ниже в блоке про **PowerShell**.

## Magic Bytes: чем файл является на самом деле

Расширение файла - это подсказка для проводника, не более. **Windows Explorer** смотрит на три буквы после точки, лезет в реестр, по этим буквам находит ассоциированную программу и иконку - и запускает. Если переименовать **malware.exe** в **resume.txt**, проводник честно нарисует иконку текстового файла. Но это не значит, что файл стал текстовым.

Реальный тип файла определяется первыми байтами в начале содержимого - это так называемые **Magic Bytes**, или сигнатура файла. Загрузчики, антивирусы, средства парсинга и любой профессиональный инструмент смотрят именно сюда, а не на имя.

> Расширение - это наклейка на банке. Сигнатура - это химический состав содержимого. Проводник доверяет наклейке и подбирает чашку для чая. Ядро системы вскрывает банку и проверяет, что внутри.

![](../../_images/2fcfaa4c9b7f.webp)

| Формат | Расширение | Сигнатура (hex) | Что это означает |
|---|---|---|---|
| Portable Executable | .exe , .dll , .sys , .cpl | 4D 5A | Маркер MZ в начале - валидный бинарник Windows |
| ZIP-архив | .zip , .docx , .xlsx , .jar | 50 4B 03 04 | Контейнер ZIP. Современные офисные документы - тоже ZIP внутри |
| PDF | .pdf | 25 50 44 46 | Текстовая строка %PDF |
| Rich Text Format | .rtf | 7B 5C 72 74 66 31 | Открывающий тег {\rtf1 |
| LNK shortcut | .lnk | 4C 00 00 00 | Заголовок ярлыка |

Из таблицы видна, например, неприятная вещь: современный **.docx** и обычная **.zip** имеют одну и ту же сигнатуру. Антивирус, который полагается только на расширение и сигнатуру, обманывается легко. Серьёзные средства защиты разбирают структуру глубже - смотрят, что лежит внутри ZIP-контейнера. Маркер **MZ** в первых двух байтах **PE**-формата - это инициалы Марка Збиковского, инженера Microsoft, который проектировал формат исполняемых файлов **MS-DOS** в 1980-х; современная Windows тащит этот маркер по совместимости и проверяет его при каждой загрузке исполняемого файла в память.

**Библиотеки DLL.** **Dynamic Link Library** (**DLL**) - тот же **Portable Executable**, что и **.exe**, с одним отличием: библиотеку нельзя запустить самостоятельно. Она загружается в адресное пространство другого процесса и предоставляет ему свои функции. Когда программа делает **CreateFile**, она дёргает **kernel32.dll**, которая дёргает **ntdll.dll**, которая делает системный вызов в ядро. Подавляющее большинство функций Windows вынесено в библиотеки, потому что иначе каждая программа таскала бы с собой копии одного и того же кода. Для атакующего это означает простую вещь: если ему удалось положить свою **DLL** туда, откуда её подхватит легитимная программа, его код будет работать в контексте этой программы - с её правами, с её доверием со стороны антивируса. Это сценарий **DLL Hijacking**, который как самостоятельная техника разбирался ранее в курсе.

**Апплеты CPL.** Файлы **.cpl** - элементы Панели управления (Sound, Display, Network Connections). Технически **.cpl** - это обычная **DLL**, переименованная и обязанная экспортировать функцию **CPlApplet**. Когда пользователь открывает элемент Панели управления, системный процесс **control.exe** загружает соответствующий **.cpl** в свою память и вызывает эту функцию. Многие средства контроля приложений разрешают **control.exe** запускаться без лишних вопросов - это доверенный системный процесс от Microsoft. Если злоумышленник скомпилирует свой код в виде **DLL**, переименует её в **update.cpl** и заставит **control.exe** её загрузить, его код окажется внутри доверенного процесса. Это рабочая техника обхода простых allow-list политик, известная как **CPL Side-Loading**.

**Rich Text Format.** **RTF** - текстовый формат с управляющими тегами. Сам по себе он безобиден, проблема в технологии **Object Linking and Embedding** (**OLE**), которая позволяет внедрять в документ внешние объекты - таблицы, картинки, формулы. Именно через **OLE**-объекты в **RTF** доставлялись самые известные эксплойты на офисный пакет - подробнее в разделе про уязвимости ниже.

Расширение и сигнатура - это то, что описывает файл "снаружи". Но **NTFS** позволяет файлу иметь и скрытое "внутреннее" пространство - дополнительные потоки данных, которых стандартные инструменты не видят.

## Альтернативные потоки данных

**NTFS** позволяет хранить в одном файле несколько именованных потоков данных. Обращение к ним происходит через синтаксис **file.txt:имя_потока**. Основные данные файла живут в потоке **:$DATA** - именно его видит любое стандартное приложение. Дополнительные именованные потоки большинством инструментов не отображаются.

Самый распространённый легитимный **ADS** - **Zone.Identifier**. Когда Windows или браузер скачивает файл из интернета, система автоматически прикрепляет к нему этот поток. Содержимое выглядит так:

- **[ZoneTransfer]**
- **ZoneId=3**
- **ReferrerUrl=https://example.com**
- **HostUrl=https://example.com/payload.exe**

Этот маркер называется **Mark of the Web** (**MotW**). Именно его проверяют **SmartScreen**, **Office Protected View** и **Edge**. Файл с **ZoneId=3** при открытии запускается в защищённом режиме или вызывает предупреждение безопасности. Удаление **MotW** - частая цель злоумышленника: без этого маркера Office откроет документ без **Protected View** и без предупреждения о макросах.

Злоумышленники используют **ADS** для сокрытия полезной нагрузки: исполняемый код записывается в именованный поток легитимного файла. Стандартный **dir** и **Explorer** такие потоки не показывают.

![](../../_images/5148e0c8d590.webp)

> Файл с альтернативными потоками данных - это посылка с боковыми карманами. В основном отделении лежит то, что видит любой получатель, открыв посылку (поток **:$DATA**). В боковых карманах могут быть заметки, метки доставки или то, что отправитель спрятал намеренно (именованные потоки вроде **Zone.Identifier**). Стандартный взгляд на посылку показывает только основное отделение - карманы видны только тому, кто знает, что они есть, и проверяет специально.

Практически для специалиста это значит одно: проверка на наличие **ADS** - в обязательном чек-листе при расследовании подозрительной активности на хосте. Конкретные команды для этого - в блоке про **PowerShell** ниже.

Чтобы видеть всё, о чём шла речь выше - и стандартные файлы, и их сигнатуры, и скрытые потоки - администратору и специалисту по безопасности нужен один и тот же инструмент. В Windows это **PowerShell**.

## PowerShell для работы с файлами

В **PowerShell** файловая система - это провайдер **FileSystem**, доступ к которому идёт через те же командлеты, что и к реестру или сертификатам. Базовый набор для специалиста, который проверяет хост на следы вредоносной активности.

Перечислить содержимое пользовательской папки автозагрузки. **Get-ChildItem** - аналог **dir**, возвращающий объекты файловой системы. Переменная **$env:USERNAME** разворачивается в имя текущего пользователя: `Get-ChildItem "C:\Users\$env:USERNAME\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup"`

То же самое, но для системной папки автозагрузки, общей для всех пользователей хоста. Любой посторонний файл в обеих этих папках - повод проверять: `Get-ChildItem "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup"`

Прочитать первые 8 байт файла и вывести их в hex. **-AsByteStream** - чтение в виде потока байтов, без интерпретации как текст. **-TotalCount 8** - ограничение по количеству. Получив байты, можно сверить их с таблицей сигнатур и понять, что на самом деле находится перед Вами, даже если файл лежит под расширением **.txt**: `Get-Content -AsByteStream -TotalCount 8 -Path .\suspicious_file.txt | ForEach-Object { '{0:X2}' -f $_ }`

Перечислить все потоки данных файла. Основные данные лежат в потоке **:$DATA**, но рядом могут быть скрытые именованные потоки. Это одно из любимых мест прятать payload: `Get-Item .\report.docx -Stream *`

Прочитать содержимое конкретного именованного потока **hidden**, привязанного к файлу **report.docx**. Если такой поток есть и в нём лежит исполняемый код - это серьёзный индикатор компрометации: `Get-Content -Path .\report.docx -Stream hidden`

Проверить цифровую подпись бинарного файла. В поле **Status** ожидается значение **Valid**, в поле **SignerCertificate** - сертификат Microsoft. Если запустить эту команду на подозрительном **svchost.exe**, найденном в **AppData**, статус будет **NotSigned** или **HashMismatch** - и это однозначный признак подмены: `Get-AuthenticodeSignature C:\Windows\System32\svchost.exe`

Перечислить все апплеты Панели управления в системной директории с базовыми атрибутами. Любой свежий **.cpl** с датой создания, не совпадающей с датами установки обновлений Windows, заслуживает внимания: `Get-ChildItem C:\Windows\System32 -Filter *.cpl | Select-Object Name, Length, LastWriteTime`

**PowerShell для работы с ADS.** Проверить все потоки файла: `Get-Item .\suspicious_file.exe -Stream`

Прочитать содержимое **Zone.Identifier**, чтобы увидеть исходный **URL** загрузки файла: `Get-Content .\downloaded_file.exe -Stream Zone.Identifier`

Найти все файлы с нестандартными потоками в директории (кроме **Zone.Identifier**) - индикатор того, что кто-то намеренно прятал данные в **ADS**: `Get-ChildItem -Recurse -File | ForEach-Object { $streams = Get-Item $.FullName -Stream * -ErrorAction SilentlyContinue | Where-Object { $.Stream -ne ':$DATA' -and $ .Stream -ne 'Zone.Identifier' }; if ($streams) { Write-Warning "ADS found: $($.FullName)"; $streams | Select-Object Stream, Length } }`

Та же проверка через классическую командную строку (флаг **/r** показывает потоки): `dir /r C:\Users\Public\Downloads\`

Строка **5 file.exe:hidden:$DATA** в выводе означает, что у **file.exe** есть поток **hidden** размером 5 байт - это немедленный повод для расследования.

Команды выше - набор инструментов специалиста. Те же файлы и папки, к которым они применяются, - это объекты, которые злоумышленник использует для маскировки и закрепления. Дальше - несколько классических векторов, на которых это основано.

## Уязвимости и атаки

**Подмена расширений (T1036.007 - Double File Extension).** По умолчанию **Windows Explorer** не показывает расширения известных типов файлов. Этим пользуются злоумышленники, отправляя жертве файл с двойным расширением вида **invoice.pdf.exe**. Проводник прячет **.exe** как "известное расширение" и показывает пользователю **invoice.pdf**. Иконку можно дополнительно подменить через ресурсную секцию **PE**-файла на иконку **Adobe Reader**. Жертва двойным кликом запускает **.exe**, считая, что открывает **PDF**.

![](../../_images/c472a62d39e5.webp)

Вариация - **T1036.005**, **Match Legitimate Name or Location**: вредоносный бинарник называют **svchost.exe** или **lsass.exe** и кладут не в **System32**, а в **C:\Users\Public** или **AppData**. Поверхностный обзор процессов в **Task Manager** показывает "знакомое" имя, но настоящий **svchost.exe** в нормальной системе запускается только из **C:\Windows\System32** и только дочерним процессом **services.exe**.

**CVE-2017-11882: эксплойт Equation Editor через RTF.** В ноябре 2017 года Microsoft закрыла уязвимость **CVE-2017-11882** в компоненте **Microsoft Equation Editor** (исполняемый файл **EQNEDT32.EXE**) - редакторе математических формул в Microsoft Office. Это **stack buffer overflow** в обработке поля **font name** записи **FONT**: имя шрифта длиной более 40 байт переполняло стек и позволяло перезаписать адрес возврата на инструкцию **WinExec** с произвольной строкой команды.

Эксплойт доставлялся через **RTF**-документ с внедрённым **OLE**-объектом класса **Equation.3**. Жертва открывала документ в Word, Word передавал объект редактору формул, редактор формул падал в overflow и выполнял команду атакующего - всё без макросов и без предупреждений. Особенно опасным эксплойт делало то, что **EQNEDT32.EXE** компилировался в 2000 году и не использовал **Address Space Layout Randomization** (**ASLR**) и **Data Execution Prevention** (**DEP**). Microsoft патчила компонент вручную, затем в январе 2018 года полностью удалила его из Office. Несмотря на возраст, **CVE-2017-11882** до сих пор активно используется в фишинговых рассылках - устаревшие установки Office в реальной инфраструктуре никуда не делись.

![](../../_images/5effd90d953d.webp)

**CPL Side-Loading.** Атакующий компилирует свою полезную нагрузку как **DLL**, экспортирующую функцию **CPlApplet**, переименовывает файл в **что-то.cpl** и доставляет жертве. Запуск возможен несколькими путями: двойной клик пользователя (расширение **.cpl** ассоциировано с **control.exe**), команда **control.exe полный_путь.cpl**, ярлык с тем же эффектом. **control.exe** - подписанный системный процесс из **System32**, и средства контроля приложений обычно к нему лояльны. В результате код атакующего выполняется в контексте доверенного процесса. Сценарий применялся, в частности, банковским трояном **Dridex** и группами **APT** для скрытного запуска полезной нагрузки в обход **allow-list** решений.

> **CPL Side-Loading** - это пронести запрещённое в офис, передав посылку через знакомого вахтёра. Сама посылка (вредоносная **DLL**) подозрительна, но вахтёр (**control.exe**) - известный и доверенный сотрудник, и охрана его не проверяет. Снаружи видят только знакомое лицо вахтёра, не то, что у него в руках.

**Boot or Logon Autostart Execution: Registry Run Keys / Startup Folder** - одна из самых популярных техник закрепления, по данным **MITRE** связанная с десятками известных **APT**-групп. Злоумышленник помещает ярлык или сам бинарник в одну из двух папок автозагрузки:

- **C:\Users\Vasya\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup** - сработает при входе конкретного пользователя
- **C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup** - сработает при входе любого пользователя хоста

Первая папка доступна на запись пользователю без прав администратора, и именно поэтому она так удобна для злоумышленника. Реестровая половина этой же техники - ветки **Run** и **RunOnce** - будет разбираться позднее в курсе

![](../../_images/3fe2e6ecda71.webp)

**Злоупотребление Alternate Data Streams.** **NTFS** допускает несколько именованных потоков в одном файле. Основные данные лежат в потоке **:$DATA**, но злоумышленник может прикрепить к легитимному файлу скрытый поток с исполняемым кодом и запустить его - например, через **wmic process call create**, который умеет работать с **ADS**-путями. Стандартный **dir** такие потоки не показывает, нужен ключ **/r** или **PowerShell** с параметром **-Stream**. Этот вектор не так распространён, как **Startup**-папки, но всё ещё работает на хостах без расширенного аудита и встречается в реальных кампаниях по сокрытию payload.

## Защита и обнаружение

Базовая защита, которая закрывает разом большую часть описанных векторов:

- **Включить отображение расширений** в **File Explorer**: откройте **File Explorer**, нажмите **View** -> **Show** -> **File name extensions**. Это делает **T1036.007** видимым невооружённым глазом. На уровне системы то же самое настраивается через ключ реестра **HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\HideFileExt** (значение **0** показывает расширения)
- **Мониторинг папок автозагрузки.** Любая запись в обе **Startup**-папки в нерабочее окно обслуживания - подозрительна. На уровне аудита это **Event ID 4663** (доступ к объекту) на **NTFS**-объектах при включённом аудите доступа, и **Event ID 11** (создание файла) в **Sysmon**. Подробнее про настройку этих источников - в одной из следующих статей курса
- **NTFS ACL на критичные пути.** **System32**, **Program Files**, корни системных папок не должны быть доступны на запись непривилегированным пользователям. Это базовая настройка, проверяется командой **Get-Acl** в **PowerShell**
- **Проверка имени и пути доверенных процессов.** Полный список базовых системных процессов **Windows** с указанием родителей и путей разбирался ранее в курсе. Любое отклонение от этого списка - процесс с системным именем, но из пути вне **System32**, или с неправильным родителем - индикатор маскировки. Для быстрого аудита подходит **Process Explorer** из пакета **Sysinternals**: он показывает полный путь, командную строку, иконку, цифровую подпись и владельца каждого процесса
- **Удаление компонента Equation Editor** на всех машинах со старыми установками Office. Если **EQNEDT32.EXE** есть на диске - **CVE-2017-11882** живёт. Современные сборки Office уже не содержат этот файл, но устаревшие установки и попавшие на хост резервные копии его сохраняют
- **Allow-list политики** уровня **Windows Defender Application Control** (**WDAC**) или **AppLocker**, ограничивающие запуск **.cpl** и **.dll** из пользовательских директорий, закрывают **CPL Side-Loading** и подобные сценарии. Без таких политик запуск произвольной **DLL** из **AppData** через **rundll32.exe** или **control.exe** не вызывает никаких системных предупреждений
- **Обнаружение ADS.** Стандартный обход файловой системы потоки данных не показывает. Утилита **streams.exe** из пакета **Sysinternals** и команда: `dir /r` - перечисляют все потоки в указанном каталоге. На уровне расширенного аудита **Sysmon** отдельным **Event ID 15** фиксирует создание файлов с потоком **Zone.Identifier** и любых других именованных потоков
- **Цифровые подписи бинарников.** Любой **.exe** или **.dll**, претендующий на роль системного, обязан иметь валидную подпись Microsoft. Проверка подписи через **Get-AuthenticodeSignature** в **PowerShell** или вкладку **Digital Signatures** в свойствах файла - быстрый способ отсеять самозванцев

У Вас в руках теперь четыре блока знаний о файловой системе **Windows**: как устроена сама **NTFS** и чем она отличается от старых **FAT32** и **exFAT**; структура системных папок и где злоумышленнику проще всего закрепиться; способы определения реального типа файла через **Magic Bytes** и обнаружения скрытых потоков **ADS**; и набор команд **PowerShell** для всех этих проверок. К этим инструментам Вы будете возвращаться при каждом расследовании подозрительной активности на хосте.

Файловая система - это статичный ландшафт. Дальше он оживает: на нём работают процессы и службы, которые читают и пишут файлы, грузят библиотеки и запускают друг друга. Дальше в курсе - про то, как они устроены и где в этих механизмах находятся уязвимости.
