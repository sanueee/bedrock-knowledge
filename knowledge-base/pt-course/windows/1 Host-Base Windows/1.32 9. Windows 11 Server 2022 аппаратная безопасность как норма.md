# 9. Windows 11 / Server 2022: аппаратная безопасность как норма

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Эволюция Windows NT

**Windows 11** сохранила **NT 10.0**, но изменила базовые требования для всей платформы.

**TPM 2.0 и Secure Boot как обязательное требование** Не опция и не корпоративная функция - базовое требование для установки системы. **TPM** используется для **measured boot**, **BitLocker**, **credential protection** и **attestation** ([**TPM in Windows**](https://learn.microsoft.com/en-us/windows/security/hardware-security/tpm/how-windows-uses-the-tpm)). Системы без **TPM 2.0** официально не поддерживаются: Microsoft явно заявляет о намерении убрать с рынка машины, которые не могут реализовать **современный базовый уровень безопасности**. Практически для ИБ: **TPM** - это аппаратный корень доверия. Все криптографические операции, связанные с доверием к устройству, привязаны в TPM - это значит, что их нельзя подделать программно.

**VBS и HVCI включены чаще по умолчанию** На совместимых устройствах **Windows 11** активнее включает **Memory Integrity** и **VBS**-защиты без явного действия администратора. Для атакующего в корпоративной среде это означает, что техника произвольной загрузки неподписанного кода в ядро больше не работает на большинстве современных машин. **BYOVD** становится одной из немногих рабочих техник для обхода - и то требует уязвимого подписанного драйвера.

**Планировщик для hybrid CPU** **Windows 11** добавила нативную поддержку процессоров с разными типами ядер - **performance** и **efficiency cores**. Планировщик получает информацию о характеристиках каждого ядра и распределяет потоки с учётом типа нагрузки. Для ИБ-инструментов это важно: инструменты с интенсивными вычислениями могут вести себя иначе на гибридных процессорах в зависимости от того, на какое ядро попадает поток.

**Processor Groups: новое поведение по умолчанию** Начиная с **Windows 11** и **Server 2022**, приложения больше не ограничены одной **processor group** по умолчанию ([**Processor Groups**](https://learn.microsoft.com/en-us/windows/win32/procthread/processor-groups)). Это меняет поведение многопоточных инструментов: код, который раньше незаметно использовал только часть процессоров, теперь автоматически получает доступ ко всем.
