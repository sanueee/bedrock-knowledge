## Что такое Code Injection

**Code Injection** - тип уязвимости, при которой специалист по анализу защищенности может внедрить полезную нагрузку в код, что приведет к его выполнению в рамках веб-приложения или сервера. Это может использоваться для получения конфиденциальной информации, развертывания вредоносного ПО или изменения логики приложения.

## Как устроена уязвимость

Данная уязвимость возникает, когда веб-приложение без надлежащей изоляции, валидации или параметризации подставляет пользовательский ввод, влияющий на исполняемое выражение, позволяя пользователю выполнять произвольный код на стороне сервера.
Механизм возникновения уязвимости связан с использованием функций, которые интерпретируют строку как программный код и выполняют её в контексте текущего процесса. К таким функциям относятся:

- **Python:** `eval()`, `exec()`
- **PHP:** `eval()`, `assert()`
- **JavaScript:** `eval()`, `Function()`

Рассмотрим пример уязвимого веб-приложения калькулятора на Python, которое вычисляет математическое выражение, введенное пользователем:

```
from flask import Flask, request

app = Flask(__name__)

@app.route('/calculate', methods=['POST'])
def calculate():
    expr = request.form.get('expression')
    result = eval(expr)
    return f"Результат: {result}"
```

Предполагается, что пользователь будет использовать корректные значения для калькулятора. Однако специалист по анализу защищенности может использовать ввод, к примеру: `__import('os')__.popen('cat /user/secret.txt').read()`
В результате приложение успешно выполнит код, и специалист по анализу защищенности получит содержимое файла **secret.txt**.

![](../../_images/f9d49f776de4.webp)

Полезная нагрузка вида `__import__('os').popen('command').read()`, а не `import os; os.popen('ls').read()` используется из-за того, что **eval **принимает только одно выражение, а не набор инструкций. Через **__import__ **используются свойства импортированного объекта. Функция **popen()** модуля **os** откроет канал для чтения или записи стандартного ввода-вывода запущенной команды **cmd**. Функция **read()** читает весь стандартный вывод процесса в строку.

Аналогичные сценарии возможны и в других языках. Например, в PHP уязвимый код может выглядеть так:

```
<?php
$expression = $_POST['expression'];
$result = eval("return $expression;");
echo "Результат: $result";
?>

```

## Отличия Command Injection, Code Injection, RCE

Для корректного понимания механизмов атак необходимо разграничить понятия **Remote Code Execution (RCE)**, **Code Injection** и **Command Injection**, которые часто используются как синонимы, но имеют существенные различия.

**RCE (Remote Code Execution)** - это обобщённый термин, описывающий ситуацию, когда злоумышленник получает возможность запускать произвольный код на удалённой системе. Это не конкретный тип уязвимости, а скорее итоговый результат атаки.

**Code Injection** - это уже конкретный тип уязвимости, при котором злоумышленник внедряет свой код в приложение, и оно выполняет его в рамках своего процесса.

**Command Injection** - это тип уязвимости, при которой атакующий подсовывает системные команды, которые затем выполняются операционной системой через уязвимое приложение.

## Последствия эксплуатации уязвимости

Успешная эксплуатация уязвимости **Code Injection** приводит к выполнению произвольного кода на сервере в контексте уязвимого приложения. Специалист по анализу защищенности получает доступ к файловой системе, базам данных, конфигурационным файлам и учетным данным, хранящимся в памяти процесса. Благодаря функциям языка программирования атакующий может также выполнять произвольные команды операционной системы, что потенциально может привести к получению полного контроля над сервером.

## Инструменты, используемые атакующими для обнаружения и последующей эксплуатации Code Injection

- [**Burp Suite**](https://portswigger.net/burp) - один из наиболее распространённых инструментов для тестирования безопасности веб-приложений. Используется для перехвата, изменения и анализа HTTP-запросов, а также автоматизированного поиска различных уязвимостей, включая Code Injection.
- [**PyCodeInjection**](https://github.com/sethsec/PyCodeInjection) - инструмент для тестирования Code Injection в веб-приложениях, написанных на Python.
- [**ParamSpider**](https://github.com/devanshbatham/paramspider) - эффективный поисковик веб-параметров для обнаружения мест, потенциально уязвимых для Code Injection.
- [**Arjun**](https://github.com/s0md3v/Arjun) - может найти параметры запроса для конечных точек URL, что также может быть полезно при поиске Code Injection.
