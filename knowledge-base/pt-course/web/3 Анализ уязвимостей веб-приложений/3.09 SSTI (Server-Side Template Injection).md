# SSTI (Server-Side Template Injection)

>
> **Кейсы:** [4.10 Эксплуатация SSTI](../../cases/web/4.10%20Эксплуатация%20SSTI.md)

## Что такое SSTI

**SSTI **(Server-Side Template Injection) - уязвимость, возникающая, когда специалист по анализу защищенности может внедрить произвольные инструкции в шаблон веб-приложения, которые затем выполняются на сервере в контексте шаблонизатора.

Разработчики используют шаблонизаторы для генерации HTML-страниц: они берут статичный шаблон и подставляют в него динамические данные. В безопасной реализации данные передаются отдельно от шаблона и никогда не интерпретируются как код. Если приложение формирует сам шаблон динамически, склеивая строки с пользовательским вводом, возникает возможность для инъекции. В отличие от **XSS**, где внедренный код выполняется в браузере жертвы, при **SSTI**-эксплуатации происходит на стороне сервера. Это делает уязвимость особенно опасной - вплоть до полного контроля над сервером.

## Как возникает уязвимость

Для начала рассмотрим безопасный способ использования шаблонизатора в коде: **template.render("Hello, {{ name }}", name=user_input)**. Здесь пользовательский ввод остаётся строкой, даже если он содержит полезную нагрузку - **{{7*7}}**. При уязвимой реализации приложение вставляет пользовательский ввод в код шаблона **template.render("Hello, " + user_input)**. В этом случае шаблонизатор видит то, что подставил пользователь, и может интерпретировать это как свою конструкцию.

## Пример

Специалист по анализу защищенности регистрируется в веб-приложении. В личном кабинете есть поле «О себе». Значение этого поля после сохранения отображается на странице профиля. Приложение может использовать шаблонизатор, это значит, что пользовательский ввод может вставляться в шаблон небезопасным способом. Для проверки можем ввести в поле «О себе» тестовое выражение **{{7*7}}**.

После сохранения профиля специалист обновляет страницу и видит, что вместо введённой строки отображается число **49**. Это означает, что сервер выполнил выражение внутри фигурных скобок как код. Уязвимость SSTI подтверждена.

![](../../_images/3c24946d8851.webp)

Теперь специалист пробует получить доступ к внутренним данным приложения. Он вводит в поле команду для вывода конфигурации фреймворка **{{config}}**. После сохранения и перезагрузки страницы на экране появляется объект конфигурации.

![](../../_images/f8f166127433.webp)

Среди выведенных данных специалист обнаружил секретный ключ приложения, учётные данные к базе данных, внутренний токен и адрес административной панели - всё это открывает возможность для полной компрометации системы. Это стало возможным потому, что объект config в **Jinja2** хранит полную конфигурацию **Flask-приложения** и доступен в контексте любого шаблона. Поскольку пользовательский ввод вставлялся в шаблон без обработки, шаблонизатор интерпретировал **{{config}}** как обращение к этому объекту и вывел его содержимое на страницу.

![](../../_images/369ec2fe6eec.webp)

Таким образом, специалист получает доступ к конфиденциальной информации.

> **&#39**; - это **HTML-сущность**, которая означает одинарную кавычку

Рассмотрим основные шаблонизаторы.

| Язык | Популярные шаблонизаторы | Синтаксис |
|---|---|---|
| Python | Jinja2, Django Templates, Mako | {{ ... }} |
| PHP | Twig, Smarty | {{ ... }} |
| JavaScript (Node.js) | EJS, Pug, Handlebars | <%= ... %> , #{...} |
| Java | FreeMarker, Velocity | ${...} , # {...} |
| Go | Go Templates | {{ ... }} |

Каждый шаблонизатор имеет свой синтаксис и набор доступных функций. Задача специалиста по анализу защищенности - определить тип шаблонизатора и подобрать полезную нагрузку, которая будет интерпретирована корректно. Делается это перебором пробных выражений, где по реакции приложения на каждое из них шаг за шагом сужают круг до конкретного движка. Схема ниже показывает эту логику в виде дерева решений.

## Последствия эксплуатации SSTI

Последствия SSTI варьируются от утечки данных до полного контроля над сервером. Это зависит от шаблонизатора и глубины проникновения в объектную модель. Атакующий может извлекать конфиденциальные данные, конфигурации, как мы показали в примере, читать или записывать файлы на сервере и обходить аутентификацию, подменяя логику проверки доступа. Также возможен отказ в обслуживании из-за ресурсоемких выражений.

## Инструменты, используемые атакующими для обнаружения и последующей эксплуатации Server-side template injection

- [**Burp Suite**](https://portswigger.net/burp) - используется для перехвата и модификации HTTP-запросов, поиска уязвимостей, включая SSTI.
- [**tplmap**](https://github.com/epinna/tplmap) - автоматизированный инструмент для поиска и эксплуатации SSTI в популярных шаблонизаторах (Jinja2, Twig, Smarty и др.).
- [**wfuzz**](https://github.com/xmendez/wfuzz) - инструмент для брутфорса параметров и тестирования инъекций, включая SSTI.
- [**ysoserial**](https://github.com/frohoff/ysoserial) - генерирует полезную нагрузку для SSTI, если уязвимость приводит к десериализации данных.
- [**SSTImap**](https://github.com/vladko312/SSTImap) - автоматизированный инструмент для поиска и эксплуатации SSTI.
- [**Garud**](https://github.com/r0x4r/garud) - Инструмент автоматизации, который сканирует поддомены, захватывает поддомены, а затем отфильтровывает XSS, SSTI, SSRF и другие параметры точек внедрения.
