# XXE (XML External Entity)

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 3: Анализ уязвимостей веб-приложений / XXE (XML External Entity)
>
> **Кейсы:** [4.09 Эксплуатация XXE](../../cases/web/4.09%20Эксплуатация%20XXE.md)

## Что такое XXE

**XML Injection** - уязвимость, возникающая при небезопасной обработке XML-данных. Если XML-парсер позволяет обрабатывать внешние сущности, специалист по анализу защищенности может просматривать файлы сервера и взаимодействовать с внешними системами, к которым может получить доступ сама система.

## Как устроена уязвимость

**XML** - расширяемый язык разметки, предназначенный для хранения и передачи данных в структурированном виде. **XML**, как и** HTML**, использует теги для данных. Если нам необходимо неоднократно использовать одни и те же данные, в XML есть сущности.
**Сущность XML** - способ представления данных, логическая единица хранения и замещения данных, на которую можно ссылаться по имени или идентификатору в документе. Своего рода переменная, которую можно задать, а затем обращаться к ней, вместо того чтобы вручную вводить данные.

В XML есть три вида сущностей:

**Predefined** - предопределенные сущности в XML, которые зарезервированы. Это те символы, которые могут помешать парсеру разобраться с правильной структурой документа. К таким сущностям относятся:

| Символ | Замена |
|---|---|
| < | \< |
| > | \> |
| & | \& |
| ' | \' |
| " | \" |

**General **- тип сущностей, который используется непосредственно в содержимом XML-документа. Они объявляются в DTD и могут быть использованы в любой части документа для подстановки текста или внешних ресурсов.

**Parameter** - тип сущностей, который используется исключительно внутри DTD (внутреннего или внешнего). Они не могут использоваться в теле XML-документа. Отличительная особенность - символ **%** при объявлении и использовании.

**DTD (Document Type Definition)** - определение типа документа XML. DTD определяет структуру XML-документа, а также допустимые элементы и атрибуты. В нем как раз и задаются сущности. Так, например:

```
<!DOCTYPE root [
<!ENTITY example "XML entity example">
]>
```

В приведенном примере DTD объявляет **general-сущность** с именем **example**. Помимо внутренних значений, DTD поддерживает механизм внешних сущностей, которые загружают данные из внешних источников. Для этого используется ключевое слово **SYSTEM**, за которым следует URI-адрес ресурса:

```
<!DOCTYPE root [
<!ENTITY example SYSTEM "file:///etc/passwd">
]>
```

В качестве схемы URI может использоваться не только file. Это позволяет специалисту по анализу защищенности не только читать файлы на диске, но и инициировать исходящие сетевые запросы, взаимодействовать с внутренними сервисами или выполнять более сложные схемы эксплуатации.

## Виды атак через XXE

**Извлечение содержимого файла**. С помощью XXE специалист может читать файлы на сервере. Некоторые приложения позволяют пользователям загружать файлы, которые основаны на XML, например SVG. Так выглядит содержание SVG-файла:

```
<?xml version="1.0" standalone="yes"?>
<!DOCTYPE test [ <!ENTITY xxe SYSTEM "file:///user/secret.txt" > ]>
<svg width="128px" height="128px" xmlns="http://www.w3.org/2000/svg" xmlns:xlink="http://www.w3.org/1999/xlink" version="1.1">
   <text font-size="16" x="0" y="16">&xxe;</text>
</svg>
```

Внутри содержимого SVG-файла есть DTD, который содержит объявление внешней **general **сущности **xxe**. В данном случае источник данных - файл** /user/secret.txt** на сервере.

Далее сущность встречается в теге **&lt;text>&xxe;&lt;/text>**. В результате это позволяет пользователю прочитать файлы на сервере

![](../../_images/6216f267eaf8.webp)

**SSRF**. Специалист по анализу защищенности может заставить сервер делать запросы к внутренним системам, которые должны быть недоступны извне, используя следующую конструкцию: `<!ENTITY xxe SYSTEM "http://inter-server.local/admin">`

**Blind XXE.** В некоторых случаях ответ с сервера не содержит содержимое запрошенного файла. Однако можно провести атаку через **OAST**. Специалист может заставить сервер инициировать исходящий сетевой запрос к контролируемому домену, передав украденные данные в параметрах этого запроса. Также можно инициировать ошибки синтаксического анализа, чтобы ошибки содержали конфиденциальные данные. Так, например:

```
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY % exfil SYSTEM 'file:///nonexistent/%file;'>">
%eval;
%exfil;
```

В данном случае необходимо использовать **parameter-сущности**, так как это позволяет внутри сущности объявлять другие сущности. Также здесь важно использование сущности внутри сущности. Если использовать просто две сущности:

```
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % exfil SYSTEM "file:///nonexistent/%file;">
%exfil;
```

parameter-сущность **file **не раскроется, и запрос будет содержать просто **%file** как строку. При использовании же сущности в сущности через **%eval**, подставляется строка с объявлением сущности exfil и DTD-парсер заново начинает работу уже с подстановкой %file.

**DOS**. XXE может использоваться не только как доступ к конфиденциальной информации, но и как средство проведения DOS, например через рекурсивные определения сущностей:

```
<!DOCTYPE root [
<!ENTITY a "&b;">
<!ENTITY b "&a;"]>   
<data>&a;</data>
```

В данном примере DTD содержит объявление сущности **a**, внутри которой находится ссылка на сущность **b**. Далее объявляется сущность **b**, внутри которой ссылка на сущность **a**. Когда парсер встречает **\&lt;data\>&a;\&lt;/data\>**, он начинает раскрывать сущность **a**: &a; -> "a&b;", возникает сущность b, которую нужно раскрыть. Далее &b; -> "&a;". Здесь и возникает рекурсия.

## Последствия эксплуатации уязвимости

Уязвимость данного типа позволяет специалисту по анализу защищенности читать произвольные файлы на сервере, инициировать исходящие сетевые запросы от имени приложения и нарушать нормальную работу системы. В первую очередь атакующий получает возможность извлекать конфиденциальную информацию, хранящуюся в файловой системе. Это могут быть конфигурационные файлы, содержащие пароли и ключи шифрования, учетные данные для доступа к базам данных, исходный код приложения, а также системные файлы, раскрывающие информацию об операционной системе и пользователях.

## Инструменты, используемые атакующими для обнаружения и последующей эксплуатации XXE Injection

- [**xxexploiter **](https://github.com/luisfontes19/xxexploiter)- инструмент для автоматизированного поиска и эксплуатации XXE-уязвимостей. Позволяет тестировать различные техники атаки, включая SSRF и OOB-эксфильтрацию данных.
- [**XXEinjector **](https://github.com/enjoiz/xxeinjector)- специализированный инструмент для обнаружения и эксплуатации XXE-уязвимостей. Автоматически тестирует уязвимые точки и позволяет извлекать файлы с сервера.
- [**xxer** ](https://github.com/TheTwitchy/xxer)- легковесный инструмент для тестирования XXE-уязвимостей. Поддерживает различные виды атак, включая Blind XXE и SSRF.
- [**XXElixir**](https://github.com/kljunowsky/XXElixir) - инструмент предназначен для проверки уязвимостей загрузки файлов и XXE.
- [**Burp Suite**](https://portswigger.net/burp) - один из наиболее распространённых инструментов для тестирования безопасности веб-приложений. Используется для перехвата, изменения и анализа HTTP-запросов, а также автоматизированного поиска различных уязвимостей, включая XML Injection.
