# OWASP WSTG (Web Security Testing Guide)

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 2: Классификация и методология тестирования уязвимостей

## OWASP WSTG

**OWASP Web Security Testing Guide** (WSTG) - это подробное руководство по анализу защищенности веб-приложений и веб-сервисов. Оно создано совместными усилиями специалистов по кибербезопасности со всего мира и представляет собой набор лучших практик, используемых специалистами по анализу защищенности. WSTG охватывает тестирование на всех этапах, но основной фокус - на динамическом тестировании работающего приложения методом чёрного ящика, хотя включает и рекомендации по анализу кода.

### Структура WSTG

Руководство организовано по функциональным областям тестирования. Каждая область разбита на отдельные сценарии. Каждому сценарию присвоен уникальный идентификатор в формате **WSTG-<категория>-<номер>**.

Например, **WSTG-INFO-02** означает второй тест в категории "Сбор информации".

**Основные области тестирования WSTG:**

| Категория | О чем |
|---|---|
| INFO - Information Gathering | Получение данных о сервере, приложении, инфраструктуре |
| CONF - Configuration and Deployment Management | Проверка настроек сети, приложений, HTTP-методов, облачных хранилищ |
| IDNT - Identity Management | Тестирование механизмов регистрации, восстановления учётной записи |
| AUTHN - Authentication | Проверка механизмов входа, защиты от подбора |
| AUTHZ - Authorization | Проверка контроля доступа, обхода прав |
| SESS - Session Management | Анализ генерации, хранения и завершения сессий |
| INPVAL - Input Validation | Тестирование на инъекции, XSS и другие атаки через ввод |
| ERROR - Error Handling | Анализ сообщений об ошибках на утечку информации |
| CRYP - Cryptography | Проверка шифрования, защиты каналов связи |
| BUSLOGIC - Business Logic | Поиск нарушений в логике, которые невозможно найти автоматическими сканерами |
| CLIENT - Client Side | Тестирование клиентских уязвимостей |

### 1. Information Gathering

**Что проверяем:** собираем данные о целевом приложении, сервере, инфраструктуре перед началом основной атаки.

**Тест-кейсы:**

- Определение версии веб-сервера (WSTG-INFO-02).
- Запуск поисковых систем и выявление утечек (WSTG-INFO-01).
- Обнаружение скрытых файлов и директорий.

**Зачем:** без разведки мы не знаем, с чем имеем дело. Иногда именно на этом этапе находятся забытые административные панели или старые версии библиотек с известными уязвимостями.

### 2. Configuration and Deployment Management

**Что проверяем:** безопасность сетевой и серверной конфигурации, использование лишних HTTP-методов, настройки облачных хранилищ.

**Тест-кейсы:**

- Проверка HTTP-методов (WSTG-CONF-06) - например, разрешены ли DELETE, PUT, которые злоумышленник может использовать против вас.
- Тестирование захвата поддомена (WSTG-CONF-09).
- Анализ заголовков безопасности (HSTS, CSP и др.).

### 3. Identity Management

**Что проверяем:** механизмы регистрации, восстановления учётной записи, смены пароля.

**Тест-кейсы:**

- Тестирование процесса регистрации.
- Тестирование восстановления пароля.

### 4. Authentication

**Что проверяем:** надёжность механизмов входа, устойчивость к атакам подбора паролей.

**Тест-кейсы:**

- Проверка устойчивости к подбору паролей (WSTG-ATHN-02).
- Тестирование блокировки учётной записи после неудачных попыток (WSTG-ATHN-06).
- Поиск слабых или стандартных паролей (WSTG-ATHN-10).

### 5. Authorization

**Что проверяем:** можно ли получить доступ к данным или выполнить действие без нужных прав.

**Тест-кейсы:**

- Обход схемы авторизации (WSTG-ATHZ-01) - например, доступ к админ-панели через прямой переход.
- Тестирование поднятия привилегий (WSTG-ATHZ-03).

### 6. Session Management

**Что проверяем:** как генерируются, передаются, хранятся и завершаются идентификаторы сессий.

**Тест-кейсы:**

- Анализ предсказуемости идентификатора сессии (WSTG-SESS-02).
- Тестирование фиксации сессии (WSTG-SESS-03) - можно ли навязать пользователю известный сессионный ID.

### 7. Input Validation

**Что проверяем:** все возможные инъекции и атаки через ввод данных. Самая объёмная категория.

**Тест-кейсы:**

- SQL-инъекции (WSTG-INPVAL-05).
- Командные инъекции (WSTG-INPVAL-13) - выполнение команд ОС.
- И другие инъекции.

### 8. Error Handling

**Что проверяем:** не раскрывает ли приложение лишнюю информацию через сообщения об ошибках.

**Тест-кейсы:**

- Анализ страниц ошибок (WSTG-ERRH-01) - не показывают ли они стек вызовов, пути к файлам, версии компонентов.

### 9. Cryptography

**Что проверяем:** надёжность шифрования, защита каналов связи, хранение паролей.

**Тест-кейсы:**

- Проверка слабого TLS/SSL (WSTG-CRYP-01).
- Проверка использования устаревших алгоритмов.

### 10. Business Logic

**Что проверяем:** можно ли обойти или нарушить бизнес-логику приложения. Этот тип уязвимостей практически невозможно найти автоматическими сканерами.

**Тест-кейсы:**

- Возможность подделки запросов (WSTG-BUSLOGIC-01).
- Нарушение последовательности шагов (переход к оплате без заполнения корзины).

### 11. Client Side

**Что проверяем:** уязвимости, исполняемые в браузере пользователя.

**Тест-кейсы:**

- Тестирование clickjacking (WSTG-CLIENT-09) - можно ли замаскировать вредоносную кнопку под легитимную.
- Тестирование иных известных клиентских уязвимостей.
