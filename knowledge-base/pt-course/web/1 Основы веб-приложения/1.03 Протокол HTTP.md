## Что такое HTTP

**HTTP** (HyperText Transfer Protocol) - это протокол прикладного уровня передачи данных. Изначально он создавался для передачи гипертекстовых документов в формате HTML, но сейчас используется для передачи любых данных: изображений, видео, аудио, JSON-документов и многого другого. Протокол HTTP предполагает использование **клиент-серверной архитектуры**:

- **Клиент** (браузер, мобильное приложение) формирует запрос и отправляет его на сервер.
- **Сервер** обрабатывает запрос, формирует ответ и передаёт его обратно клиенту. HTTP работает поверх **TCP**, что гарантирует доставку всех данных в правильном порядке.

![](../../_images/c5a78e465ce6.webp)

### Версии протокола

Протокол HTTP прошёл несколько этапов развития: от минимального протокола загрузки гипертекстовых документов до сложного механизма обмена данными в современных веб-приложениях. Существует несколько версий протокола:

![](../../_images/7df095aa37bf.webp)

Краткий разбор схемы:

- **HTTP/1.1** использует последовательную схему передачи, в которой каждый запрос обрабатывается отдельно, а протокольный стек включает HTTP поверх TCP, IP и технологии канального уровня.
- **HTTPS** - добавлен слой шифрования **SSL/TLS** между HTTP и TCP
- В версии **HTTP/2** появилась возможность мультиплексирования: в рамках одного TCP-соединения могут передаваться несколько независимых потоков данных. Кроме того, протокол производит сжатие заголовков с помощью алгоритма HPACK. Использование TLS 1.2 становится обязательным для большинства реализаций.
- В **HTTP/3** вместо TCP транспортным протоколом выступает QUIC, работающий поверх UDP. Это позволяет ускорить установку соединения. Для сжатия заголовков используется алгоритм QPACK. Требуется TLS версии 1.3 или выше. по состоянию на 2026 год около 39% всех веб-сайтов используют её на практике

> **QUIC** - транспортный протокол, разработанный Google, который заменяет связку TCP и TLS, работает поверх UDP, обеспечивает встроенное шифрование и быстрое установление соединения. Протокол активно используется крупнейшими веб-платформами: в частности, ВКонтакте перешёл на QUIC и Яндекс применяет протокол в своих сервисах.

## Структура HTTP-запроса

**HTTP-запрос** - это сообщение, которое клиент отправляет серверу, чтобы запросить выполнение определённого действия, например получить веб-страницу или отправить данные формы. Обычно HTTP-запрос состоит из трёх частей, которые идут в таком порядке:

1. **Стартовая строка** - содержит строку запроса в случае HTTP-запроса или строку состояния в случае HTTP-ответа. Она указывает тип сообщения.
2. **Заголовки** - содержат дополнительную информацию о сообщении, в том числе параметры передачи и сведения о теле сообщения.
3. **Тело сообщения** - содержит непосредственно передаваемые данные.

Между заголовками и телом сообщения находится **пустая строка**, которая обозначает окончание заголовочной части.

> у HTTP-сообщения могут отсутствовать заголовки и тело, но **стартовая строка является обязательной**, так как именно она определяет тип сообщения.

![](../../_images/e634c9f770ef.webp)

**Методы HTTP**

Метод, указанный в строке состояния, определяет способ воздействия на ресурс, URL которого задан в той же строке. Метод может принимать значения **GET, POST, HEAD, PUT, DELETE** и др.

| Метод | Назначение |
|---|---|
| GET | Предназначен для получения ресурса с указанным URL. Получив запрос GET, сервер должен прочитать указанный ресурс и включить его код в состав ответа клиенту. |
| POST | Основное назначение метода POST - передача данных на сервер. Однако, подобно методу GET, он может применяться по-разному и нередко используется для получения информации с сервера. URL, заданный в строке состояния, указывает на конкретный ресурс. |
| HEAD | Возвращает только заголовки (без тела). Как GET, но без контента. Используется для проверки размера ресурса перед загрузкой. |
| PUT | Создаёт или заменяет ресурс на сервере. |
| PATCH | Вносит частичные изменения ресурса. В отличие от метода PUT , который полностью заменяет объект, PATCH изменяет только те поля, которые передаются в теле запроса, оставляя остальные нетронутыми. |
| OPTIONS | Используется для описания параметров соединения с ресурсом, в том числе информацию о допускаемых к использованию на сервере HTTP-методов. |
| DELETE | Позволяет удалить указанный ресурс на сервере. |
| TRACE | Заставляет сервер отразить (вернуть в теле ответа) точный запрос, который он получил, позволяя клиенту увидеть, какие изменения или дополнения вносит инфраструктура по пути к целевому ресурсу |
| CONNECT | Запускает двустороннюю связь с запрошенным ресурсом. Метод можно использовать для открытия туннеля. |

**Заголовки запроса**

Поля заголовка, следующие за строкой состояния, позволяют уточнять запрос, то есть передавать серверу дополнительную информацию. Поле заголовка имеет следующий формат: **Имя поля: значение**

Назначение поля определяется его именем, которое отделяется от значения двоеточием.

**Основные заголовки запроса:**

| Поле заголовка | Значение |
|---|---|
| Host | Доменное имя или IP-адрес узла, к которому обращается клиент |
| Referer | URL документа, который ссылается на ресурс, указанный в строке состояния |
| From | Адрес электронной почты пользователя, работающего с клиентом |
| Accept | MIME-типы данных, обрабатываемых клиентом. Это поле может иметь несколько значений, отделяемых друг от друга запятыми. Часто используется для того, чтобы сообщить серверу, какие типы файлов поддерживает клиент |
| Accept-Language | Набор двухсимвольных идентификаторов, разделённых запятыми, которые обозначают языки, поддерживаемые клиентом |
| Accept-Charset | Перечень поддерживаемых наборов символов |
| Content-Type | MIME-тип данных, содержащихся в теле запроса (если запрос не состоит из одного заголовка) |
| Content-Length | Число символов, содержащихся в теле запроса (если запрос не состоит из одного заголовка) |
| Range | Присутствует в том случае, если клиент запрашивает не весь документ, а лишь его часть |
| Connection | Используется для управления TCP-соединением. Если в поле содержится Close , это означает, что после обработки запроса сервер должен закрыть соединение. Значение Keep-Alive предлагает не закрывать TCP-соединение, чтобы оно могло быть использовано для последующих запросов |
| User-Agent | Строка, передаваемая браузером или другим клиентским приложением в составе HTTP-запроса, содержащая информацию о типе устройства, операционной системе и версии браузера. |

**Структура HTTP-ответа**

Получив от клиента запрос, сервер должен ответить ему. Подобно запросу клиента, ответ сервера также состоит из четырёх компонентов:

1. Строка состояния
2. Поля заголовка
3. Пустая строка
4. Тело ответа

Также как и для HTTP-запроса, между заголовками и телом сообщения находится **пустая строка**.

**Строка состояния**

Ответ сервера клиенту начинается со строки состояния, которая имеет следующий формат:

**Версия протокола Код ответа Пояснительное сообщение**

- **Версия протокола** задаётся в том же формате, что и в запросе клиента, и имеет тот же смысл.
- **Код ответа** - это трёхзначное десятичное число, представляющее в закодированном виде результат обслуживания запроса сервером.
- **Пояснительное сообщение** дублирует код ответа в символьном виде. Это строка символов, которая не обрабатывается клиентом. Она предназначена для системного администратора или оператора, занимающегося обслуживанием системы, и является расшифровкой кода ответа.

### Коды состояния HTTP

В используемых в настоящее время реализациях протокола HTTP первая цифра кода определяет класс ответов и не может быть больше 5:

![](../../_images/48de825c44e8.webp)

| Диапазон | Тип | Описание |
|---|---|---|
| 1xx | Информационные | Сервер получил запрос и продолжает его обработку. Сообщения данного класса встречаются редко. |
| 2xx | Успешные | Запрос клиента был успешно принят и обработан. |
| 3xx | Перенаправления | Для выполнения запроса клиенту необходимо выполнить дополнительные действия, обычно переход по другому адресу. |
| 4xx | Ошибки клиента | Запрос сформирован некорректно или не может быть выполнен по вине клиента. Ошибка может быть устранена на стороне клиента. |
| 5xx | Ошибки сервера | Сервер не смог выполнить корректно сформированный запрос по причинам, связанным с его внутренним состоянием или конфигурацией. |

**Заголовки ответа**

Рассмотрим основные заголовки ответа:

| Имя поля | Описание содержимого |
|---|---|
| Server | Имя и номер версии сервера |
| Age | Время в секундах, прошедшее с момента создания ресурса |
| Allow | Список методов, допустимых для данного ресурса |
| Content-Language | Языки, которые должен поддерживать клиент для корректного отображения ресурса |
| Content-Type | MIME-тип данных, содержащихся в теле ответа сервера |
| Content-Length | Число символов, содержащихся в теле ответа сервера |
| Last-Modified | Дата и время последнего изменения ресурса |
| Date | Дата и время, определяющие момент генерации ответа |
| Expires | Дата и время, после которого информация считается устаревшей |
| Location | Реальное расположение ресурса. Используется для перенаправления запроса |
| Cache-Control | Директивы управления кэшированием ( no-cache означает, что данные не должны кэшироваться) |

**Тело ответа**

В теле ответа содержится код ресурса, передаваемого клиенту в ответ на запрос. Это не обязательно должен быть HTML-текст веб-страницы. В составе ответа могут передаваться изображение, аудиофайл, фрагмент видеоинформации, а также любой другой тип данных, поддерживаемых клиентом. О том, как следует обрабатывать полученный ресурс, клиенту сообщает содержимое поля заголовка **Content-Type**.

## URI, URL, URN

Веб-серверы хранят множество ресурсов. Чтобы обращаться к ним, нужны специальные адреса.

- **URI** (Uniform Resource Identifier) - унифицированный идентификатор ресурса. Общее понятие для любой строки, идентифицирующей ресурс. Пример: **https://ptsecurity.com/page** или **urn:isbn:978-3-16-148410-0** - оба являются URI, так как просто идентифицируют ресурс.
- **URL** (Uniform Resource Locator) - унифицированный указатель ресурса. Не только идентифицирует, но и указывает, где ресурс находится и как к нему обратиться. Пример: [**https://ptsecurity.com/page**](https://ptsecurity.com/page) - здесь **https** говорит, как обратиться (протокол), **ptsecurity.com** - где находится (адрес сервера), **/page** - конкретный путь к ресурсу.
- **URN** (Uniform Resource Name) - унифицированное имя ресурса. Идентифицирует ресурс по имени, но не указывает его местоположение. Пример: **urn:isbn:978-3-16-148410-0** - это уникальное имя книги по её ISBN. Оно говорит, что это за ресурс, но не говорит, где его найти.

> **ISBN** - международный стандартный номер книги, уникальный цифровой код, присваиваемый каждому изданию.

**Структура URL**

![](../../_images/704e49fc2c8f.webp)

Разберем структуру подробнее:

| Компонент | Описание |
|---|---|
| Scheme | Способ доступа к ресурсу ( http , https , ftp ) |
| UserInfo | Учётные данные пользователя (редко используется в открытом виде) |
| Fully-qualifted Hostname | Доменное имя или IP-адрес сервера |
| Port | Порт, на котором работает служба (по умолчанию: 80 для HTTP, 443 для HTTPS) |
| Path | Конкретный ресурс на сервере |
| Query | GET-параметры, начинающиеся с ? |
| Fragment | Точка на странице, начинающаяся с # . Не отправляется серверу , используется только на клиенте. |
