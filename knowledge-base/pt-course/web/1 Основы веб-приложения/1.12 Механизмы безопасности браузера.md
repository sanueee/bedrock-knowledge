# Механизмы безопасности браузера

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 1: Основы веб-приложения

## Зачем браузеру политики безопасности

Браузер представляет собой среду выполнения скриптов, загруженных с различных веб-сайтов. При отсутствии ограничений одна веб-страница могла бы получать доступ к данным другой. Например, после входа пользователя в корпоративную почтовую систему вредоносный скрипт, выполняющийся в другой вкладке, мог бы прочитать содержимое писем или отправить сообщения от имени пользователя.

Для предотвращения таких сценариев в браузеры встроены механизмы безопасности, ограничивающие взаимодействие между разными сайтами. Три ключевых механизма - **SOP**, **CORS** и **CSP** - работают на уровне HTTP-заголовков и правил обработки контента.

### Same-Origin Policy (SOP)

**SOP** - это фундаментальный механизм безопасности браузера, который ограничивает возможность скриптов с одного веб-сайта получать доступ к данным другого веб-сайта.

**Что такое одинаковый источник**

Два URL считаются имеющими одинаковый источник, если совпадают три компонента:

| Компонент | Пример |
|---|---|
| Протокол (схема) | http:// или https:// |
| Домен (хост) | example.com |
| Порт | 80 , 443 (или явно указанный) |

**Пример:** страница **http://ptsecurity.com/example/page.html** пытается обратиться к разным адресам:

| Целевой адрес | Совпадает ли источник? | Почему |
|---|---|---|
| http://ptsecurity.com/page2.html | Да | Тот же протокол, домен, порт |
| https://ptsecurity.com/page2.html | Нет | Разные протоколы (http и https) |
| http://en.ptsecurity.com/page.html | Нет | Разные домены |
| http://ptsecurity.com:8080/page.html | Нет | Разные порты |

**Что SOP ограничивает**

SOP не блокирует саму загрузку ресурса. Браузер может загрузить изображение, скрипт или стиль с другого сайта. Но SOP запрещает скриптам читать содержимое загруженных данных из другого источника.

Например, вы можете встроить на страницу картинку с другого сайта через тег **&lt;img>**. Она отобразится. Но JavaScript-код вашей страницы не сможет прочитать пиксели этой картинки или её содержимое, потому что это нарушило бы политику одинакового источника.

![](../../_images/139074c1d36d.webp)

**Зачем нужен SOP**

Без SOP любой сайт мог бы прочитать ваши личные сообщения в соцсетях, если вы вошли в них в другой вкладке, получить доступ к вашему интернет-банкингу, украсть cookie и токены авторизации. SOP - это базовая защита, которая изолирует данные разных сайтов друг от друга.

**Исключения и ослабления SOP**

SOP - это строгое правило, однако допускается определенная степень "гибкости" в некоторых случаях:

| Механизм | Назначение |
|---|---|
| CORS | Позволяет серверу добровольно разрешить доступ скриптам с других источников |
| document.domain | Позволяет взаимодействовать между поддоменами. |
| postMessage | Безопасный способ обмена сообщениями между окнами/фреймами с разных источников |

### Cross-Origin Resource Sharing (CORS)

**CORS** - это механизм, который позволяет серверу контролируемо разрешать доступ к своим ресурсам со страниц, загруженных с других источников. CORS не отменяет SOP, а создаёт "разрешённые исключения".

**Когда возникает CORS-запрос**

Запрос считается **cross-origin**, если его источник отличается от источника запрашиваемого ресурса по протоколу, домену или порту.

Пример: HTML-страница с **http://foo.example** загружает изображение с **http://bar.other/image.jpg**. Это **cross-origin-запрос**.

**Типы CORS-запросов**

**1. Простые запросы** это запросы, которые браузер отправляет без предварительной проверки. Условия:

- Метод: **GET**, **POST** или **HEAD**.
- Заголовки: только стандартные (**Accept**, **Accept-Language**, **Content-Language**, **Content-Type** с ограниченными значениями: **application/x-www-form-urlencoded**, **multipart/form-data**, **text/plain**).

Браузер отправляет такой запрос, и сервер в ответе может указать заголовок **Access-Control-Allow-Origin**, чтобы разрешить чтение ответа.

![](../../_images/716831188a34.webp)

**2. Предварительные запросы**

Если запрос не удовлетворяет условиям простого (например, используется метод **DELETE** или заголовок **Content-Type: application/json**), браузер сначала отправляет предварительный запрос методом **OPTIONS**. Он проверяет, разрешён ли фактический запрос.

![](../../_images/29c46bee693a.webp)

Сервер должен ответить на **OPTIONS-запрос** следующими заголовками:

- **Access-Control-Allow-Methods** - какие методы разрешены.
- **Access-Control-Allow-Headers** - какие заголовки разрешены.
- **Access-Control-Max-Age** - как долго кэшировать этот ответ. Только после успешного предварительного запроса браузер отправляет основной запрос.

**Основные CORS-заголовки (со стороны сервера)**

| Заголовок | Назначение |
|---|---|
| Access-Control-Allow-Origin | Указывает, какой источник имеет доступ к ресурсу. Значение * разрешает доступ с любых источников. |
| Access-Control-Allow-Methods | Список HTTP-методов, разрешённых при доступе к ресурсу. |
| Access-Control-Allow-Headers | Список заголовков, которые разрешено использовать в запросе. |
| Access-Control-Allow-Credentials | Указывает, разрешено ли отправлять cookie и данные аутентификации. Если true , то Access-Control-Allow-Origin не может быть * . |
| Access-Control-Max-Age | Время, на которое результат предварительного запроса кэшируется. |

**CORS и cookie**

По умолчанию при cross-origin-запросах браузер не отправляет cookie. Чтобы это разрешить, нужно:

1. На клиенте установить флаг **credentials: 'include'** (в fetch) или **withCredentials = true** (в XMLHttpRequest).
2. На сервере указать **Access-Control-Allow-Credentials: true**.
3. В заголовке **Access-Control-Allow-Origin** **нельзя** использовать ***** - нужно явно указать конкретный источник.

### Content Security Policy (CSP)

**CSP** - это механизм, позволяющий веб-сайту контролировать, какие ресурсы (скрипты, стили, изображения, шрифты и т.д.) могут быть загружены и выполнены на странице. В отличие от SOP и CORS, которые управляют доступом между источниками, CSP фокусируется на внутренней безопасности страницы.

**Как работает CSP**

Сервер включает в HTTP-ответ заголовок **Content-Security-Policy** с набором директив. Каждая директива определяет белый список источников для определённого типа ресурсов.

**Основные директивы CSP**

| Директива | Контролирует |
|---|---|
| default-src | Резервный список для всех типов ресурсов, для которых нет отдельной директивы |
| script-src | Источники JavaScript-кода |
| style-src | Источники CSS-стилей |
| img-src | Источники изображений |
| media-src | Источники аудио и видео |
| font-src | Источники шрифтов |
| connect-src | Источники, с которыми можно соединяться через fetch , XHR , WebSocket |
| frame-src | Источники для встраиваемых фреймов ( &lt;frame> , &lt;iframe> ) |

**Значения для источников**

| Значение | Что означает |
|---|---|
| 'self' | Только текущий источник (свой домен) |
| 'none' | Запретить загрузку ресурсов этого типа полностью |
| * | Любой источник |
| https://example.com | Конкретный домен (только по HTTPS) |
| *.trusted.com | Домен и все его поддомены |

**Пример CSP-заголовка: Content-Security-Policy: default-src 'self'; script-src https://trusted.cdn.com**

**Дополнительные правила для скриптов**

| Правило | Назначение |
|---|---|
| unsafe-inline | Разрешает встроенные скрипты ( &lt;script> без атрибута src ) и обработчики событий ( onclick ). Без этого правила они запрещены. |
| unsafe-eval | Разрешает динамическое выполнение кода ( eval() , setTimeout(string) ). Без этого правила запрещены. |

**Зачем нужен CSP**

- **Борьба с внедрением вредоносных скриптов.** Если cпециалист по анализу защищенности попытается вставить скрипт, не входящий в разрешённый список **script-src**, браузер его не выполнит.
- **Защита от атак на основе встроенного кода.** По умолчанию CSP запрещает использование **unsafe-inline** (встроенных скриптов и обработчиков событий), что блокирует многие распространённые векторы атак.
- **Контроль загрузки ресурсов.** Можно запретить загрузку изображений, стилей, шрифтов и других ресурсов с недоверенных источников.
- **Обеспечение передачи данных только по HTTPS.** С помощью директивы **block-all-mixed-content** или ограничения источников только через **https://** можно гарантировать, что все ресурсы загружаются по защищённому соединению.

### Взаимосвязь SOP, CORS и CSP

| Механизм | Что делает | Роль |
|---|---|---|
| SOP | Ограничивает доступ скриптов к данным с других источников (по умолчанию запрещено) | Базовая защита |
| CORS | Позволяет серверу добровольно разрешать доступ скриптам с других источников | Исключение из SOP |
| CSP | Ограничивает, какие ресурсы может загружать и выполнять сама страница | Дополнительный фильтр |

**Как они работают вместе:**

1. **SOP** блокирует чтение данных с другого источника (например, ответа от API). Это защита по умолчанию.
2. **CORS** разрешает серверу снять это ограничение для конкретных источников через заголовки (**Access-Control-Allow-Origin**).
3. **CSP** ограничивает загрузку ресурсов на самой странице, даже если они из одного источника. Это дополнительный уровень безопасности.
