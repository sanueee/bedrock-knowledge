# Хранение данных на клиенте: localStorage, sessionStorage

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 1: Основы веб-приложения

## Зачем нужно клиентское хранение данных

Веб-приложениям часто нужно сохранять какие-то данные на стороне пользователя: настройки интерфейса (тема оформления, язык), состояние формы, список товаров в корзине до оформления заказа.

Для этого есть несколько механизмов. Самый старый из них - **cookies**, но у них есть ограничения:

- Максимум 4 КБ данных.
- Cookies отправляются на сервер при каждом запросе, что создаёт лишний трафик.
- Сервер может читать и изменять файлы cookie, что не всегда нужно для клиентских настроек.

В **HTML5** появились два новых механизма хранения - **localStorage** и **sessionStorage**. Они специально спроектированы для хранения данных на клиенте без участия сервера.

![](../../_images/d2d54252aa7b.webp)

### Что такое localStorage и sessionStorage

**localStorage** и **sessionStorage** - это объекты браузера, которые позволяют хранить данные в виде пар "ключ - значение". Ключи и значения - это всегда строки. Оба хранилища привязаны к **источнику** - комбинации протокола (http/https), домена и порта. Страницы **https://example.com** и **http://example.com** будут иметь разные хранилища, они не видят данные друг друга.

**Основные отличия между localStorage и sessionStorage:**

| Характеристика | localstorage | sessionstorage |
|---|---|---|
| Время жизни | Бессрочно (пока пользователь не удалит данные вручную) | До закрытия вкладки или окна браузера |
| Доступность между вкладками | Доступен из всех вкладок и окон того же источника | Доступен только в рамках одной вкладки |
| После перезапуска браузера | Данные сохраняются | Данные удаляются |
| Объём хранилища | 5–10 МБ | 5 МБ |

### Когда что использовать

**localStorage** подходит для данных, которые нужны между разными сеансами работы пользователя и между разными вкладками:

- Настройки интерфейса (тема, шрифт, вид отображения).
- Данные, которые должны сохраниться после перезапуска браузера.

**sessionStorage** подходит для временных данных в рамках одной сессии (одной вкладки):

- Черновик формы, которую пользователь заполняет.
- Состояние интерфейса, которое не нужно сохранять между визитами.
- Данные, которые не должны попасть в другие вкладки.

В localStorage и sessionStorage **нельзя хранить конфиденциальные данные** - пароли, номера кредитных карт, персональную информацию. Эти данные доступны любому JavaScript-коду на странице (в отличие от cookie с атрибутом **HttpOnly**).

### Методы работы с хранилищами

Методы **localStorage** и **sessionStorage** используются для работы с клиентским хранилищем данных в браузере и одинаковы для обоих типов хранилищ. Например, в административной панели веб-приложения с их помощью сохраняют выбранную тему оформления или сворачиваемое состояние бокового меню, чтобы при следующем входе интерфейс выглядел так же, как его настроил пользователь.

| Метод/свойство | Что делает |
|---|---|
| setItem(key, value) | Сохранить пару "ключ-значение". Значение автоматически преобразуется в строку. |
| getItem(key) | Получить значение по ключу. Если ключа нет - вернёт null . |
| removeItem(key) | Удалить запись с указанным ключом. |
| clear() | Удалить все записи в хранилище. |
| key(index) | Получить ключ по индексу (0, 1, 2...). |
| length | Количество записей в хранилище. |

**Примеры использования в консоли браузера:**

```
// Запись данных
localStorage.setItem('theme', 'dark');
sessionStorage.setItem('draft', 'Текст письма...');
// Чтение данных
const theme = localStorage.getItem('theme');      // 'dark'
const draft = sessionStorage.getItem('draft');    // 'Текст письма...'
// Удаление одной записи
localStorage.removeItem('theme');
// Получение количества записей
const count = localStorage.length;
// Удаление всего
sessionStorage.clear();
```

### Событие storage

Когда данные в **localStorage** или **sessionStorage** изменяются в одной вкладке, все другие вкладки того же источника получают событие **storage**. Это позволяет разным вкладкам одного сайта обмениваться информацией.

```
window.addEventListener('storage', (event) => {
  console.log('Изменился ключ:', event.key);
  console.log('Старое значение:', event.oldValue);
  console.log('Новое значение:', event.newValue);
  console.log('URL страницы, где произошло изменение:', event.url);
});
```

### Ограничения в современных браузерах

В некоторых браузерах действуют ограничения на время жизни **localStorage**, если пользователь не взаимодействовал с сайтом. В Safari ITP (Intelligent Tracking Prevention) данные из **localStorage** могут быть удалены через 7 дней без повторного посещения сайта. Также в режиме инкогнито / приватного просмотра некоторые браузеры вообще блокируют **localStorage** или создают временное хранилище, которое удаляется после закрытия окна.
