# Что такое веб-приложение

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 1: Основы веб-приложения

## Что такое браузер и какова его роль в работе веб-ресурсов

Для понимания принципов работы веб-сайтов и веб-приложений необходимо прежде всего рассмотреть понятие браузера, поскольку именно он является основной программной средой, через которую пользователь взаимодействует с веб-ресурсами.

### Понятие браузера

**Веб-браузер** - это прикладное программное обеспечение, предназначенное для доступа к веб-ресурсам, получения данных из сети, их обработки и последующего отображения в удобной для пользователя форме. Браузер выступает посредником между пользователем и сервером, обеспечивая обмен информацией посредством сетевых протоколов и предоставляя интерфейс для работы с веб-контентом.

Современные браузеры разрабатываются на основе специальных программных компонентов - **браузерных движков**, отвечающих за обработку HTML, CSS и JavaScript, а также за отображение веб-страниц. В современной веб-разработке фактически используются три основных семейства браузерных движков:

| Движок | Использующие браузеры |
|---|---|
| Blink | Google Chrome, Microsoft Edge, Opera, Brave, Vivaldi и другие Chromium-браузеры |
| WebKit | Safari |
| Gecko | Mozilla Firefox, Tor Browser, LibreWolf, Waterfox |

**Получение данных от сервера**

Когда пользователь вводит адрес веб-ресурса или переходит по гиперссылке, браузер формирует сетевой запрос и отправляет его на сервер, где размещён требуемый ресурс. Сервер обрабатывает запрос и возвращает необходимые данные. В ответ браузер может получить:

- HTML-документ
- таблицы стилей CSS
- программный код JavaScript
- изображения
- видео и аудиоматериалы
- данные в форматах JSON или XML
- другие вспомогательные файлы

После получения данных браузер начинает их обработку. На основе полученной информации браузер формирует визуальное представление страницы, которое отображается пользователю. Этот процесс называется **рендерингом**. Также некоторые ресурсы могут содержать **JavaScript**-скрипты, которые современные браузеры могут выполнять непосредственно на устройстве пользователя за счет встроенных **JavaScript**-движков.

**Взаимодействие браузера с сервером**

Работа большинства веб-ресурсов основана на обмене данными между браузером и сервером. В зависимости от используемых технологий этот обмен может осуществляться различными способами, однако наиболее распространённым остаётся взаимодействие по протоколу** HTTP**.

> Протокол **HTTP **мы изучим далее по курсу

В классическом сценарии процесс выглядит следующим образом:

1. Пользователь инициирует действие (например открывает страницу)
2. Браузер отправляет запрос серверу
3. Сервер обрабатывает запрос и формирует ответ
4. Браузер получает необходимые данные
5. Браузер выполняет обработку полученной информации
6. Пользователю отображается результат

Помимо вышеперечисленного, браузеры реализуют ряд механизмов безопасности, таких как:

- поддержку криптографических протоколов **TLS/HTTPS**, обеспечивающих шифрование передаваемых данных и проверку подлинности веб-серверов;
- политику разграничения источников, ограничивающую доступ веб-страниц к данным, принадлежащим другим сайтам;
- механизмы управления разрешениями, контролирующие доступ веб-приложений к камере, микрофону, геолокации, буферу обмена и другим ресурсам устройства;
- поддержку современных политик безопасности, таких как **Content Security Policy**, предназначенных для снижения риска атак, связанных с внедрением вредоносного кода.

### Веб-сайт и веб-приложение: базовые определения

Рассмотрев устройство и принципы работы веб-браузера, можно перейти к изучению основных типов веб-ресурсов, с которыми пользователь взаимодействует посредством данной программной среды. В современной веб-разработке существует два основных типа цифровых продуктов, которые пользователь воспринимает через браузер: веб-сайты и веб-приложения. Несмотря на внешнее сходство, эти сущности имеют принципиально различную природу, архитектуру и назначение.

**Что такое веб-сайт, преимущества и недостатки**

**Веб-сайт** представляет собой совокупность статических или динамически генерируемых страниц, основная функция которых заключается в предоставлении информации пользователю. Взаимодействие пользователя с веб-сайтом ограничивается навигацией и просмотром контента. Пользователь не может создавать, изменять или удалять данные, влиять на состояние ресурса или получать персонализированный контент, зависящий от его предыдущих действий. Содержимое веб-сайта, как правило, идентично для всех посетителей. Примерами веб-сайтов служат новостные порталы, информационные ресурсы компаний, блоги без возможности комментирования, сайты-визитки.

**Преимущества веб-сайтов:**

- Простота разработки и поддержки, обусловленная отсутствием сложной клиентской логики
- Максимальная совместимость со всеми типами браузеров и устройств
- Мгновенное отображение контента при загрузке страницы

**Недостатки веб-сайтов:**

- Отсутствие персонализации - контент не адаптируется под конкретного пользователя
- Каждое действие пользователя требует перезагрузки страницы
- Ограниченная функциональность по сравнению с полноценными приложениями
- Сложность реализации сложных интерактивных сценариев
- Повышенная нагрузка на сервер при высокой посещаемости

**Что такое веб-приложение, преимущества и недостатки**

**Веб-приложение** представляет собой программное обеспечение, функционирующее в среде браузера, но обладающее интерактивностью, сопоставимой с нативными приложениями. Веб-приложение обрабатывает ввод пользователя, сохраняет состояние, адаптируется под действия пользователя и предоставляет персонализированный опыт взаимодействия. Содержимое веб-приложения динамически изменяется в зависимости от пользователя, его прав доступа и выполняемых действий. Пользователь веб-приложения не просто потребляет информацию, но и создаёт, изменяет и удаляет данные. Примерами веб-приложений служат интернет-банки, электронная почта (**mail.ru, Яндекс.Почта**), социальные сети, CRM-системы, онлайн-редакторы документов (**Google Docs, Figma**), интернет-магазины с личным кабинетом и корзиной.

**Преимущества веб-приложений:**

- Персонализация - интерфейс и данные адаптируются под каждого пользователя
- Высокая интерактивность и отзывчивость интерфейса после начальной загрузки
- Снижение нагрузки на сервер при навигации (сервер отдаёт только данные, а не готовые страницы)
- Возможность работы в офлайн-режиме (при использовании технологий кэширования)

**Недостатки веб-приложений:**

- Более высокая сложность разработки и сопровождения
- Увеличенное время начальной загрузки
- Повышенные требования к безопасности, поскольку критически важная логика выполняется на стороне клиента
- Зависимость от производительности устройства пользователя

## Ключевые технические различия

Для полноценного анализа различий между веб-сайтом и веб-приложением следует рассмотреть несколько ключевых технических характеристик:

### Архитектура

**Веб-сайт**

Классический веб-сайт работает по простой схеме: пользователь что-то нажимает, браузер отправляет запрос на сервер, сервер собирает страницу и отправляет её обратно. При каждом действии пользователя происходит полный цикл, продемонстрированный на схеме ниже. Такой подход называется **Server-Side Rendering (SSR)** - страницы собираются на сервере. Это надёжный и проверенный способ, который хорошо работает для информационных ресурсов, но его недостаток заключается в том, что каждое действие требует времени на ожидание ответа от сервера.

![](../../_images/a1768f5f8621.webp)

**Веб-приложения**

Веб-приложение устроено иначе. Оно загружается один раз при первом открытии. После загрузки всё необходимое для работы уже есть в браузере. Дальше, когда пользователь что-то делает, браузер сам обрабатывает действие и обращается к серверу только за данными, а не за целыми страницами. Сервер присылает только нужную информацию, а браузер сам обновляет интерфейс. Такой подход называется **Client-Side Rendering (CSR)** - страницы собираются на стороне браузера. Пользователь получает мгновенную реакцию на свои действия, потому что интерфейс уже загружен и не требует перезагрузки.

![](../../_images/885e06b238a7.webp)

### Пользовательский интерфейс

**Веб-сайт:** интерфейс формируется заново при каждом переходе между страницами. Пользователь перемещается по отдельным HTML-документам, каждый из которых загружается **независимо**. Это сопровождается характерной перезагрузкой и кратковременным миганием элементов интерфейса.

**Веб-приложение:** интерфейс функционирует по принципу динамического обновления контента без полной перезагрузки страницы. Пользователь взаимодействует с единой средой, что создаёт ощущение работы с настольным программным обеспечением. Все изменения отображаются плавно и оперативно.

### Производительность

**Веб-сайт** при первом открытии сайт загружается быстрее, так как требует меньше ресурсов. Однако при переходе между страницами сайт каждый раз отправляет новые запросы к серверу, что замедляет работу.

**Веб-приложение**, напротив, загружается дольше при первом запуске, но после этого переходы между разделами происходят быстрее, так как основные данные уже подгружены. Интерфейс приложения реагирует на действия пользователя оперативнее, поскольку меньше зависит от постоянных обращений к серверу. При этом приложение требует больше вычислительных ресурсов устройства, чем обычный сайт.
