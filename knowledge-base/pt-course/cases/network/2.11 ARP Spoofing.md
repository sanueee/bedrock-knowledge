# Guided Case 2.11 — ARP Spoofing

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 3. Кибератаки и защита от них / Атаки на L2

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/25cdf29931c7.webp)

**Данная виртуальная инфраструктура состоит из:**

1. **Debian-машины** (**Attacker**) с динамическим сетевым адресом, подключенным к **MikroTik** через сетевой адаптер **Internal Network** с названием **intnet**. Необходимо включить параметр **Promiscuous Mode** со значением **Allow All** в настройках адаптера

> В роли атакующей машины может выступить любая из виртуальных машин, с которыми вы работали ранее. Для данного кейса необходимо установить две утилиты: **arpspoof **(`sudo apt install dsniff`) и **netdiscover **(`sudo apt install netdiscover`). Данные утилиты необходимо запускать с повышенными привилегиями.

1. **Debian-машины** (**Victim**) с динамическим сетевым адресом, подключенным к **MikroTik** через сетевой адаптер **Internal Network** с названием **intnet-debian**
2. **MikroTik** со статическим адресом **10.10.10.1/24** и NAT подключенным к двум устройствам внутреннего широковещательного домена соответствующими сетевыми адаптерами типа **Internal Network**, а также одним адаптером **Bridged Network** с динамическим адресом выданным роутером вашей домашней сети. На сетевых адаптерах, направленных к хостам, должен быть включен параметр **Promiscuous Mode** со значением **Allow All**

В качестве **Debian-машины** (**Victim**) необходимо использовать заготовленный Positive Technologies** OVA-образ** виртуальной машины. Данный образ имеет предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/fc9c19fd5ae146cbaefd/?op=view)

> **В данном кейсе у вас отсутствуют данные для аутентификации, так как для выполнения задания они не требуются.**

Уязвимость протокола ARP связана с тем, что устройства в локальной сети обычно доверяют ARP-ответам и не проверяют, действительно ли указанный MAC-адрес принадлежит заявленному IP-адресу. Из-за этого атакующий может отправлять поддельные ARP-ответы и изменять ARP-таблицы других устройств.

> **ARP Spoofing / ARP Poisoning** — атакующий рассылает поддельные **ARP-ответы**, в которых сообщает жертве, что IP-адрес шлюза находится на MAC-адресе атакующего. В результате жертва начинает отправлять трафик, предназначенный для шлюза, на машину атакующего.

> **Man-in-the-Middle через ARP Spoofing** — после отравления ARP-таблицы жертвы атакующий может включить пересылку пакетов через себя. Тогда трафик жертвы сначала проходит через атакующего, а затем пересылается дальше к настоящему шлюзу. Для жертвы соединение может продолжать работать, но атакующий получает возможность просматривать или анализировать проходящий трафик.

Для начала объединим сетевые интерфейсы ether2 и ether3 в мост и назначим ему адрес с помощью следующих команд:

1. `/interface bridge add name=br`
2. `/interface bridge port add bridge=br interface=ether2 hw=no`
3. `/interface bridge port add bridge=br interface=ether3 hw=no`
4. `/ip address add address=10.10.10.1/24 interface=br`

Теперь настроим DHCP-сервер и поставим его на ранее созданный мост.

1. `/ip pool add name=pool ranges=10.10.10.100-10.10.10.200`
2. `/ip dhcp-server network add address=10.10.10.0/24 gateway=10.10.10.1`
3. `/ip dhcp-server add name=server interface=br address-pool=pool add-arp=no disabled=no`

Так как интерфейс ether1 получает адрес динамически, вручную укажем это, а затем зададим его в качестве выходного интерфейса для NAT трафика.

1. `/ip dhcp-client add interface=ether1 disabled=no`
2. `/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade`

После настройки MikroTik, перейдем к сетевой конфигурации атакующей машины, чтобы также назначить динамическое получение адреса.

```
allow-hotplug enp0s3
iface enp0s3 inet dhcp
```

![](../../_images/487cade8a42a.webp)

Можем увидеть, что интерфейс **enp0s3** получил адрес 10.10.10.199, значит сетевая конфигурация настроена правильно. Так как машины жертвы настроена заранее, она сама автоматически получит адрес в сети, что избавляет нас от необходимости настраивать ее сетевой интерфейс. Можем переходить к проведению атаки. Для проведения атаки нам необходимо узнать IP-адрес Victim. Для этого воспользуемся утилитой **netdiscover**, выполнив команду **sudo netdiscover -r 10.10.10.0/24**, как показано на изображении ниже.

![](../../_images/3a4fff84f8c8.webp)

В результате найдено два адреса. Мы знаем, что адрес **10.10.10.1** точно принадлежит MikroTik, значит, адрес жертвы - **10.10.10.200**. Теперь разрешим атакующей машине пропускать трафик через себя, изменив значение 0 на 1 в файле **/proc/sys/net/ipv4/ip_forward** командой `sudo sh -c 'echo 1 > /proc/sys/net/ipv4/ip_forward'`
либо sudo sysctl -w net.ipv4.ip_forward=1

![](../../_images/21aa77c2c7fd.webp)

В файл успешно записалась единица, значит можем приступать к перехвату трафика. Для этого запустим утилиту **arpspoof**, чтобы начать рассылку поддельных ARP-ответов, используя следующие команды одновременно:

1. `arpspoof -i enp0s3 -t 10.10.10.1 10.10.10.200`
2. `arpspoof -i enp0s3 -t 10.10.10.200 10.10.10.1`

![](../../_images/aa24698380ac.webp)

На изображении можем увидеть, что пакеты **ARP-ответов** успешно отправляются на нужные IP-адреса и отравляют их **ARP-таблицы**. Чтобы увидеть перехваченный трафик воспользуемся программой Wireshark, чтобы посмотреть, какие пакеты исходят от жертвы. В трафике будет пакет, адресованный 8.8.8.8 на порт 12345, в котором вы найдёте уникальное значение к кейсу.

![](../../_images/d9a45f057fc3.webp)

## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

Выше мы провели атаку на устройство Victim методом ARP Spoofing. Необходимо найти уникальное значение внутри UDP-пакета, исходящего с Debian. Пример: **osL4l0ug79lzEHouNXgS9QXoCHEj0E**

Примечание к данному вопросу:

1. Для захвата пакета с уникальным значением в сетевом трафике можно использовать утилиту **tcpdump** вместе с **фильтрами захвата**, которые настроены на актуальный интерфейс **enp0s3**, протокол **UDP** и порт **12345**.

Защититься от атаки ARP Spoofing можно, ограничив горизонтальное общение в домене, а также включив две функции безопасности сетевого оборудования: **DHCP Snooping** и **DAI (Dynamic ARP Inspection)**.

> **DHCP Snooping** - создаёт таблицу привязок **MAC-IP** и назначает разные уровни доверия сетевым портам, отслеживая **DHCP-трафик**.

> **DAI (Dynamic ARP Inspection)** - это технология **валидации ARP-пакетов**. Коммутатор проверяет каждый входящий **ARP-кадр** и извлекает из него MAC и IP отправителя, а потом сверяет с ранее сформированной **DHCP Snooping** доверенной таблицей привязок. Если данные некорректны, то кадр отбрасывается.

Для начала ограничим горизонтальное взаимодействие между хостами на MikroTik, выполнив следующие команды:

1. `/interface bridge port set [find interface=ether2] horizon=1`
2. `/interface bridge port set [find interface=ether3] horizon=1`

![](../../_images/afcc4db9a50c.webp)

Можем увидеть, что идентификатор горизонта у интерфейсов одинаковый, а значит они не могут общаться между друг другом без участия MikroTik, так мы исключаем возможность перехвата трафика в обход ограничениям коммутатора, напрямую с жертвой. Теперь включим добавление ARP-записей DHCP-сервером с помощью команды `/ip dhcp-server set [find name=server] add-arp=yes`. С этого момента DHCP-сервер будет вести учёт выданных адресов.

![](../../_images/dc0cdff6d2bb.webp)

Затем включим DHCP Snooping и режим ARP reply-only (разрешающий ARP только для известных записей) на мосте с помощью команды `/interface bridge set [find name=br] dhcp-snooping=yes arp=reply-only`.

![](../../_images/a35d178ed3bd.webp)

При повторном запуске утилиты **arpspoof** с идентичными параметрами, что и при атаке в первый раз, мы не увидим нужных пакетов в трафике, так как после настройки защиты, атакующая машина не может выдавать себя за другое устройство.
