# Guided Case 2.22 — Adaptix

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 3. Кибератаки и защита от них / Фрэймворки постэксплуатации

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии с схемой ниже:

![](../../_images/4cf6128efbe7.webp)

Первая сеть **192.168.1.0/24**, которая состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с **GUI** и интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу **установка Debian**, только при создании требуется загрузить графический интерфейс, поставить минимум 4ГБ оперативной памяти и минимум 20ГБ обычной памяти.
   
   - IP-адрес - 192.168.1.250
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **VictimX** с интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу [**установка Debian**](https://wiki.ptsecurity.com/spaces/PTCybergrad/pages/670549543/%D0%9D%D0%B0%D1%81%D1%82%D1%80%D0%BE%D0%B9%D0%BA%D0%B0+Debian+12).
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.2.1

Третья сеть **10.0.0.0/8** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 10.0.0.1
   - Маска - 255.0.0.0
2. **Suricata** с интерфейсом **enp0s3**:
   
   - IP-адрес - 10.255.255.254
   - Маска - 255.0.0.0
   - Сетевой шлюз - 10.0.0.1

> У виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

> В данном кейсе используется Adaptix **v1.2**

Для установки на Debian-машине фреймворка **Adaptix** выполним следующие команды:

- `sudo git clone https://github.com/Adaptix-Framework/AdaptixC2.git` - установка **Adaptix** с git репозитория
- `sudo chmod -R 777 AdaptixC2 && cd AdaptixC2` - дадим всем файлам в папке полные права перейдем в директорию
- `./pre_install_linux_all.sh all` - запустим скрипт для установки зависимостей
- `make server-ext` - соберем серверную часть
- `cd dist && ./ssl_gen.sh` - перейдем в директорию дист и запустим файл ssl_gen.sh

После запуска **ssl_gen.sh** на все просто отвечаем нажатием **Enter**, кроме поля **Common Name**, тут вводим адрес машины на которой находится **Adaptix**

![](../../_images/f7352f48478e.webp)

Затем установим клиентскую часть от root, для работы с сервером с помощью команды `cd .. && make client`

![](../../_images/bb463fa888f3.webp)

После установки в папке **dist** будут лежать **AdaptixClient** и **adaptixserver**

![](../../_images/73acd7578b88.webp)

Для работы с Adaptix следует запустить команды в следующем порядке:

- `export GOFLAGS="-buildvcs=false" && ./adaptixserver -profile profile.yaml &` - отключаем информацию о контроле версий и запускам сервер с указанием файла конфигурации
- `./AdaptixClient` - запуск клиента **Adaptix**

![](../../_images/708031c01531.webp)

Далее откроется окно клиента, куда необходимо ввести следующие данные:

- **User** - operator1
- **Password** - pass
- **URL** - https://127.0.0.1:4321/endpoint
- **Name** - First

![](../../_images/dadb7b5d47e1.webp)

Нажмем **Сonnect**, далее откроется рабочее окно фреймворка. Для прослушивания соединения и создания агента, нужно воспользоваться **Listeners**. Для этого нажмем на значок "наушники" в верхней панели, должна появится вкладка **Listeners**. Снизу под ней нужно нажать правой кнопкой мыши и выбрать **Create**

> Listeners - это компоненты C2-фреймворка, которые принимают входящие подключения от запущенных агентов. Listener определяет, каким способом агент будет связываться с сервером управления: например, используемый протокол, адрес и порт подключения. При создании агента параметры Listener используются для настройки канала связи между ним и сервером Adaptix.

![](../../_images/186e839f7246.webp)

После этого откроется окно, в котором нужно задать обязательные параметры:

- **Name** - TCP
- **Protocol** - external (tcp)
- **Host & port (Bind)** - 0.0.0.0 4444
- **Callback addresses** - адрес машины с **Adaptix**

![](../../_images/2ef29343cc1e.webp)

Далее нажимаем **Edit** и на вкладке **Listeners** появится прослушиваемое соединение

![](../../_images/f1d69e45a0cf.webp)

Теперь создадим агента для обратного подключения, для этого нужно нажать правой кнопкой мыши на прослушиваемое соединение и выбрать **Generate agent**

![](../../_images/bd101647c5ad.webp)

Откроется окно создания агента, в котором необходимо выбрать:

- **Agent** - gopher
- **OS** - Linux
- **Arch** - amd64
- **Format** - Binary .ELF

> При указании параметров в этом окне, сами параметры не отображаются

![](../../_images/eb653de3a1de.webp)

Нажимаем **Generate** и выбираем место сохранения файла

![](../../_images/74cc4e5b099d.webp)

Файл сохранился, теперь можно его перенести на уязвимую машину и запустить командой `./agent.bin`

![](../../_images/7736c8044d83.webp)

В таблице сессий должно отобразится подключение от машины-жертвы

![](../../_images/9f1adf2f67f7.webp)

Теперь нажмем правой кнопкой мыши по подключенной сессии и выберем **Console**

![](../../_images/0c4fc2cf978f.webp)

Снизу должна отобразиться отдельная вкладка с консолью. Можем увидеть, что ожидается ввод команд в интерактивной строке **gopher >**. Выполним в ней команду `shell id`, чтобы узнать, какими правами мы обладаем в системе

![](../../_images/282643609627.webp)

Посмотрим на логи в EveBox, которые появились в записях во время атаки.

![](../../_images/37f9a1720ca4.webp)

В EveBox сработало правило из открытого набора [**PT Rules**](https://rules.ptsecurity.com/view/ptopen-all.rules):

```
alert tcp any any -> any any (msg: "TOOLS [PTsecurity] AdaptixC2 Response"; flow: established, to_client; dsize: 17; stream_size: server, <=, 18; content: "AdaptixC2|20|server|0a|"; startswith; reference: url, github.com/Adaptix-Framework/AdaptixC2; reference: url, www.virustotal.com/gui/file/4df6ecd60bc6b583277ba77b45767c446e1723e2b4e77b31ddc885e276d23610/detection; reference: url, rules.ptsecurity.com; classtype: attempted-admin; sid: 10016592; rev: 1;)

```

Обнаружение строится на последовательной проверке направления движения трафика от сервера к клиенту, а также ограничению по размеру передаваемых данных в TCP-сессии и поиска текстового маркера баннера сервера. Сначала система проверяет, что TCP-соединение уже установлено, затем происходит анализ ограничений по размеру: объем данных текущего пакета должен быть строго равен **17** байтам.

Откроем карточку инцидента и изучим его подробнее

![](../../_images/7fdc966bca30.webp)

Видим следующую информацию:

- **Timestamp** - 2026-06-24 14:24:58.796
- **Protocol** - TCP
- **Source** - 192.168.1.250, порт отправки: 4444
- **Destination** - 192.168.2.249, порт назначения: 54444
- **In Interface** - dummy0
- **Signature** - TOOLS [PTsecurity] AdaptixC2 Response
- **Category** - попытка получения прав администратора
- **Severity** - 1, является наивысшим уровнем опасности
- **Action** - allowed, трафик был пропущен системой обнаружения вторжений, так как она работает в режиме мониторинга

Управляющий сервер отправил на хост жертвы **4** пакета, передав **314** байт данных, в ответ от атакуемого хоста на сервер пришло **4** пакета общим объемом **280** байт. Обмен данными происходил через порт **4444**, на котором развернут слушатель Adaptix. Характер обмена передачи стартового текстового баннера-приветствия полностью соответствует этапу первичного установления соединения между сервером Adaptix и агентом.
