## Стенд / введение

Для выполнения кейса необходимо скачать Server_Scan.ova, и MikroTik_Router.ova, а затем развернуть виртуальные машины в Virtual Box по аналогии с разделом 2.1 ICMP

Первая сеть **192.168.1.0/24**, которая состоит из:

1. Маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с интерфейсом **enp0s3**
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. Маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **ServerScan** с интерфейсом **enp0s3**
   
   - IP-адрес - 192.168.2.100
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.2.1

Для выполнения данного кейса необходимо скачать **OVA-образ** виртуальной машины **ServerScan**, заготовленный Positive Technologies, скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/0eadf6eb044245698f39/?op=view). **ServerScan** уже настроен, требуется только подключить с правильными сетевыми параметрами

> У всех виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

Основным видом сканирования в реальности является TCP-сканирование, в нем всё выстроено вокруг **трехстороннего рукопожатия**. Основные виды сканирования, которые следует знать:

1. **TCP Connect Scanning**. - полное установление соединения с портом, используется флаг **-sT**
   
   - Плюс: метод точней других
   - Минус: Очень шумный, в логах целевого сервера останется запись о каждом подключении
2. **SYN Scanning** - полуоткрытое сканирование, которое не завершает рукопожатие, используется флаг **-sS**
   
   - Плюсы: Быстро, эффективно. Сервисы часто не успевают залогировать такое соединение, так как оно не было завершено
   - Минус: Современные IDS легко видят этот паттерн
3. **Стелс методы: FIN, NULL и Xmas** - эти методы используют недоработки в стандартах RFC, если отправить пакет с нестандартными флагами на закрытый порт, система обязана ответить RST. Если порт открыт, система должна просто проигнорировать странный пакет.
   
   - **NULL Scan** - пакет без флагов, используется через флаг **-sN**
   - **FIN Scan** - пакет только с флагом завершения связи, используется через флаг **-sF**
   - **Xmas Scan** - пакет где включены флаги FIN, PSH и URG, используется через флаг **-sX**
4. **TCP ACK Scanning** - отправляется пакет с флагом ACK, для изучения поведения фаервола, если приходит ответ RST, значит порт не фильтруется, если ответа нет - порт зафильтрован. Используется через флаг **-sA**

##### Отправка пакетов с помощью Nping

При сканировании **nmap** автоматически отправляет необходимые пакеты и на основании ответов определяет состояние портов. Если же нужно самостоятельно сформировать отдельный сетевой пакет и подробно изучить ответ, можно использовать утилиту **nping**.

**Nping** входит в набор инструментов Nmap и позволяет задавать используемый протокол, порт назначения, TCP-флаги и количество отправляемых пакетов.

Например, отправим один TCP-пакет с флагом SYN на порт 80: `sudo nping --tcp -p 80 --flags syn --count 1 -v3 192.168.2.100`

В этой команде:

- **--tcp** – использовать протокол TCP;
- **-p 80** – указать порт назначения;
- **--flags syn** – установить в TCP-заголовке флаг SYN;
- **--count 1** – отправить один пакет;
- **-v3** – вывести подробную информацию об отправленном пакете и полученном ответе.

В выводе **nping** отправленные пакеты обозначаются как `SENT`, а полученные ответы – как `RCVD`. При высоком уровне детализации содержимое пакета также отображается в шестнадцатеричном формате: каждая пара символов соответствует одному байту. Например: **45 00 00 2c**

## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

С помощью **nping** отправьте один TCP-пакет с флагом SYN на порт 1337 узла `192.168.2.100` и проанализируйте полученный ответ. **Какие **четыре байта находятся в конце полученного пакета? Запишите их в шестнадцатеричном формате без пробелов. Пример ответа: **00000000**

> Подсказка: В nmap есть встроенная утилита nping.

Самым массовым решением для защиты являются системы IDS/IPS, они позволяют настроить систему на отслеживание трафика по множеству факторов, в нашем случае нужно делать блокировку при превышении порога SYN-пакетами с одного IP.

Наша задача - мгновенно уничтожать любые пакеты от хостов, которые уже были уличены в сканировании, не тратя ресурсы маршрутизатора на их повторный анализ, для этого используем флаги:

- **chain=forward** - указывает, что правило обрабатывает транзитный трафик, который проходит через маршрутизатор
- **src-address-list=Port_Scanners** - проверяет, занесен ли IP-адрес отправителя в список нарушителей под названием Port_Scanners
- **action=drop** - уничтожить пакет без отправки каких-либо уведомлений атакующему

Используем команду `/ip/firewall/filter/add chain=forward src-address-list=Port_Scanners action=drop comment="IPS: Drop traffic from banned scanners"`

Далее нужно обнаруживать сканеры и ограничивать поступающие запросы, для этого используем флаги:

- **protocol=tcp** - правило реагирует только на пакеты протокола TCP.
- **connection-state=new** - проверяет только первые пакеты новых соединений
- **dst-limit=3/1m,3,src-address** - механизм подсчета скорости где 3/1m - разрешенная средняя скорость, не более 3 новых соединений в минуту, src-address - заставляет маршрутизатор вести этот подсчет индивидуально для каждого отдельного IP-адреса.
- **action=add-src-to-address-list** - действие, выполняемое при превышении лимита, маршрутизатор берет IP-адрес нарушителя и заносит его в список
- **address-list=Port_Scanners** - название черного списка
- **address-list-timeout=30m** - время блокировки.

Запишем команду:

```
/ip/firewall/filter/add chain=forward protocol=tcp connection-state=new dst-limit=3/1m,3,src-address action=add-src-to-address-list address-list=Port_Scanners address-list-timeout=30m comment="Strict Ban slow and smart scanners"
```

и запустим сканирование `nmap -sS 192.168.2.100`.

![](../../_images/e11ebe7e1f77.webp)

Видим, что маршрутизатор заблокировал ip, с которого происходила атака.
