## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии с схемой ниже:

![](../../_images/eef985fcc3ff.webp)

Первая сеть **192.168.1.0/24**, которая состоит из:

1. Маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с интерфейсом **enp0s3**
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. Маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **ServerScan** с интерфейсом **enp0s3**
   
   - IP-адрес - 192.168.2.100
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.2.1

Для выполнения данного кейса необходимо скачать **OVA-образ** виртуальной машины **ServerScan**, заготовленный Positive Technologies, скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/0eadf6eb044245698f39/?op=view). **ServerScan** уже настроен, требуется только подключить с правильными сетевыми параметрами

> У всех виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

Назначим IP-адреса на физические порты в MikroTik

```
/ip/address/add address=192.168.1.1/24 interface=ether2 comment="Subnet 1 - intnet"
/ip/address/add address=192.168.2.1/24 interface=ether3 comment="Subnet 2 - intnet1"

```

Выполним следующие команды:

- `/ip/pool/add name=pool-intnet ranges=192.168.1.10-192.168.1.250` - создаем пул IP-адресов для DHCP на ether2
- `/ip/dhcp-server/network/add address=192.168.1.0/24 gateway=192.168.1.1` - настраиваем параметры выдачи на ether2
- `/ip/dhcp-server/add name=dhcp-intnet interface=ether2 address-pool=pool-intnet disabled=no` - запускаем DHCP-сервер на порту ether2

Запустим Debian-машину и установим на ней nmap командой `sudo apt install nmap`.

Сканирование ICMP пакетами можно разделить на внешнюю и внутреннюю сеть. Сканирование ICMP пакетами чаще всего оказывается плохой идеей, так как трафик блокируется файрволом, за исключением некоторых видов запросов, связанных с служебными запросами. Внутри сети ICMP пакеты чаще всего остаются нетронутыми, в силу простоты проверки локального оборудования на работоспособность.

Рассмотрим основные виды ICMP запросов, благодаря которым можно построить карту сети:

1. **ICMP Echo Request** - анализ TTL позволяет косвенно определить, что за оборудование в сети, используется флаг **-PE**
2. **ICMP Timestamp Request** - позволяет узнать системное время устройства, что также позволяет косвенно рассмотреть вид системы, используется флаг **-PP**
3. **ICMP Address Mask Request** - запрос маски подсети, используется флаг **-PM**

## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какое значение **TTL** отдает сервер при сканировании?

Пример ответа: **128**

> Помните, что при прохождении каждого маршрутизатора, значение TTL уменьшается на единицу. В ответе требуется исходное значение от сервера

Теперь настроим защиту от сканирования на уровне маршрутизатора MikroTik. Маршрутизатор должен перехватывать и уничтожать транзитные ICMP-пакеты, поэтому запросы должны даже не доходить до целевого сервера. Также, для обеспечения более тонких настроек аналогичную защиту можно настроить и на самом сервере.

Для написания правила, чтобы разрешить сообщения о недоступности сети или хоста понадобятся флаги:

- **chain=forward** - forward означает, что правило применяется только к транзитным пакетам, которые проходят сквозь маршрутизатор, если запрос адресован самому маршрутизатору он честно ответит
- **protocol=icmp** - включает фильтрацию по протоколу icmp
- **icmp-options=3:0-255** - критерий отбора пакетов по их типу и коду в формате **тип:код**. Число 3 - это **ICMP Type 3**, более известный как **Destination Unreachable**. Диапазон 0-255 - разрешает абсолютно все подтипы кодов для этого сообщения
- **action=accept** - действие, которое выполнится, если пакет совпал со всеми условиями выше.
- **comment="..."** - текстовое примечание, используется для удобства при чтение правил

Запишем правило - `/ip/firewall/filter add chain=forward protocol=icmp icmp-options=3:0-255 action=accept comment="Allow ICMP Destination Unreachable"`.

Также напишем правило для разрешения сообщений об истечении времени жизни пакета `/ip/firewall/filter add chain=forward protocol=icmp icmp-options=11:0-255 action=accept comment="Allow ICMP Time Exceeded"`

В этом правиле видоизменился флаг **icmp-options=11:0-255**, тут число 11 - это **ICMP Type 11**, более известное как Time Exceeded, генерируется сетевыми устройствами, когда отправленный пакет уничтожается из-за невозможности вовремя дойти до цели.

Остальное входящие ICMP пакеты будем просто сбрасывать командой `/ip/firewall/filter add chain=forward protocol=icmp action=drop comment="Drop all other ICMP traffic through router"`.

Флаг **action=drop** прямо указывает на то, что все остальные поступающие сетевые пакеты сбрасываются. Теперь запустим сканирование и увидим, что у нас отсутствуют какие либо ответы, как это продемонстрировано ниже
