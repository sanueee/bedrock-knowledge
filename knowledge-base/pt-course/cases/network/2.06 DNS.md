## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/42b7b917972f.webp)

**Виртуальная инфраструктура состоит из:**

1. Маршрутизатора **MikroTik1** с адресом 192.168.10.1/24 внутри сети с DNS1, Server1, и адресом 10.0.0.1/30 внутри сети с MikroTik2
2. Маршрутизатора **MikroTik2** с адресом 192.168.20.1/24 внутри сети с DNS2 и Server2, и адресом 10.0.0.2/30 внутри сети с MikroTik1
3. Debian-машины **DNS1** с адресом 192.168.10.10/24 и шлюзом 192.168.10.1
4. Debian-машины **Server1** с Nginx и адресом 192.168.10.50/24 и шлюзом 192.168.10.1
5. Debian-машины **DNS2** с адресом 192.168.20.10/24 и шлюзом 192.168.20.1
6. Debian-машины **Server2** с Nginx и адресом 192.168.20.50/24 и шлюзом 192.168.20.1

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

В данном кейсе будем использовать динамическую маршрутизацию в инфраструктуре, по аналогии как делали раньше. Для этого сначала назначим интерфейсам соответсвующие адреса, которые указаны на схеме выше, а затем настроим экземпляры протокола OSPF, используя только одну зону - главную магистраль. После чего перейдем к настройке служебных файлов для корректной работы выделенного DNS-сервера (**DNS1**).

Для начала откроем файл настройки DNS-зон **/etc/bind/named.conf.local** и настроим его под себя, для этого нам понадобится прописать конфигурации двух зон:

1. **edtechlab.intern** - внутренняя зона, для которой данный сервер будет главным (master), а записи зоны будут храниться в файле **/etc/bind/db.edtechlab.intern**.
2. **positive.intern** - внешняя зона, при запросе к которой сервер будет только пересылать запрос на другой сервер, который является главным для этой зоны (192.168.20.10). Отредактируем содержимое файла, вставив конфигурацию ниже.

```
zone "edtechlab.intern" {  
	type master;
	file "/etc/bind/db.edtechlab.intern";
};  

zone "positive.intern" {  
	type forward;
	forward only;
	forwarders { 192.168.20.10; };
};

```

Теперь пропишем стандартные настройки в файле **/etc/bind/named.conf.options**, для того чтобы сервер знал как работать с зонами.

```
options {  
	directory "/var/cache/bind";

	recursion yes; 
	listen-on { any; };
	listen-on-v6 { any; };
	allow-query { any; }; 

	dnssec-validation no; 
};

```

Скопируем шаблон настройки (**cp /etc/bind/db.local /etc/bind/db.edtechlab.intern**) и отредактируем его под себя, открыв с помощью текстового редактора **nano** (**nano /etc/bind/db.edtechlab.intern**). В итоге содержимое должно выглядеть так:

```
$TTL 604800
@ IN SOA ns.edtechlab.intern. admin.edtechlab.intern. (  
	2
	604800
	86400
	2419200
	604800 )
  
@   IN NS ns.edtechlab.intern. 
ns  IN A 192.168.10.10
srv1 IN A 192.168.10.50

```

Перезапуситим службу DNS-сервера для применения изменений командой `systemctl restart bind9`

После настройки файлов конфигурации их содержимое должно выглядеть так:

![](../../_images/43038ab6e886.webp)

Аналогично редактируем содержимое служебных файлов второго DNS-сервера (DNS2)

DNS2 будет ответственен за зону **positive.intern**, а перенаправлять запросы в зону **edtechlab.intern**, добавим конфигурацию в файл **/etc/bind/named.conf.local**

```
zone "positive.intern" {  
	type master;  
	file "/etc/bind/db.positive.intern";  
};  

zone "edtechlab.intern" {  
	type forward;  
	forward only;  
	forwarders { 192.168.10.10; };  
};

```

Запишем идентичные настройки для второго сервера в файл **/etc/bind/named.conf.options**.

```
options {  
	directory "/var/cache/bind";  

	recursion yes;  
	listen-on { any; };  
	listen-on-v6 { any; };  
	allow-query { any; };  

	dnssec-validation no;  
};

```

Копируем шаблон уже для зоны **positive.intern** (**cp /etc/bind/db.local /etc/bind/db.positive.intern**) и редактируем конфигурацию:

```
$TTL 604800  
@ IN SOA ns.positive.intern. admin.positive.intern. (  
	2  
	604800  
	86400  
	2419200  
	604800 )  

@   IN NS ns.positive.intern.  
ns  IN A 192.168.20.10  
srv2 IN A 192.168.20.50

```

Перезапускаем службу **bind9** и проверяем содержимое конфигурационных файлов, чтобы оно соответствовало изображению ниже.

![](../../_images/83a09e620177.webp)

Также, чтобы хосты знали, к какому DNS-серверу обращаться для разрешения доменных имён в IP-адреса, **перезапишем **файл **/etc/resolv.conf** на каждом ПК, добавив адрес DNS-сервера соответствующей сети следующими командами:

1. DNS1 - `sudo sh -c 'echo "nameserver 192.168.10.10" > /etc/resolv.conf'`
2. DNS2- `sudo sh -c 'echo "nameserver 192.168.20.10" > /etc/resolv.conf'`

Выполним проверку наличия записи и доступности серверов на DNS1 утилитой **nslookup**, которая запросит адерса наших доменных имен. Выполним следющие команды:

1. `nslookup srv1.edtechlab.intern`
2. `nslookup srv2.positive.intern`

![](../../_images/99e9e0ec935e.webp)

Теперь попытаемся получить доступ к веб странице, с помощью предустановленной службы **nginx** поднимем веб-сервер на Server1 командой `systemctl start nginx`, а затем добавим HTML-заголовок "&lt;h1>EDTECHLAB DNS WORKS&lt;/h1>" в файл **/var/www/html/index.html**. Такие же действия выполним на Server2, то есть, запускаем **nginx** на Server2 и добавляем заголовок "&lt;h1>POSITIVE DNS WORKS&lt;/h1>" в файл **/var/www/html/index.html**. Затем на DNS2 выполним HTTP запросы к обоим серверами. Воспользуемся командами ниже.

![](../../_images/0fa4d4c93096.webp)

## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

Мы настроили DNS-сервера типов Resolver и Forwarder и получили доступ к доменным именам внутри виртуальной инфраструктуры. После выполнения настроек сетевых интерфейсов и DNS-конфигураций необходимо запустить **checker_dns **на машине **DNS1** с помощью команды `sudo chmod +x ~/checkers/checker_dns && sudo ~/checkers/checker_dns`
