# Guided Case 2.3 — Динамическая адресация

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 2. Методы конфигурации сети / IP-адресация

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/c9c6fb4f8d14.webp)

Данная виртуальная инфраструктура состоит из следющих устройств:

1. Маршрутизатор MikroTik со статическим адресом - 192.168.1.1
2. Выделенный DHCP-сервер со статическим адресом - 192.168.1.2
3. Debian-машина **Debian** с динамическим адресом

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

> У всех виртуальных машин должно быть по **1** сетевому адаптеру VirtualBox в режиме **Internal Network**

На MikroTik и Debian назначим IP-адреса на сетевых интерфейсах, в соответствии со схемой выше. А также обратим внимание на то, что по умолчанию на MikroTik включен DHCP клиент. Проверим состояние клиента с помощью команды **ip dhcp-client print**

![](../../_images/245b59b1ea82.webp)

Можем увидеть, что DHCP клиент имеет статус поиска (**searching**). В нашем случае у MikroTik назначен статический IP-адрес, поэтому данный клиент необходимо отключить, выполнив команду **ip dhcp-client disable ether1**

![](../../_images/9a05aa229665.webp)

При повторной проверке можем увидеть, что теперь статус изменился на **stopped**.

Так как DHCP-сервер вынесен на отдельную виртуальную машину Debian, для выполнения кейса необходимо использовать предустановленную службу `isc-dhcp-server` и подключить машину к маршрутизатору через сетевой адаптер в VirtualBox. Сам сервер не выдает себе адрес динамически, поэтому нам необходимо выдать ему статический адрес **192.168.1.2/24** и указать шлюз **192.168.1.1**, как на изображении далее.

![](../../_images/ce5aae052aa9.webp)

Далее перейдем к настройке самого DHCP-сервера. В конфигурационном файле **/etc/default/isc-dhcp-server** комментируем строку **INTERFACESv4=""** и впишем, ранее настроенный сетевой интерфейс **enp0s3**. Затем необходимо отредактировать файл **/etc/dhcp/dhcpd.conf** как на изображении ниже.

![](../../_images/71af27d1b612.webp)

Можем увидеть, что при такой настройке DHCP-сервер выдает устройствам в сети **192.168.1.0/24** адреса из доступного диапазона **192.168.1.100-192.168.1.200**, а также говорит адрес шлюза по умолчанию. Чтобы включить DHCP-сервер воспользуемся командой `sudo dhcpd -4 -d -cf /etc/dhcp/dhcpd.conf enp0s3`, которая запустит службу с выводом логов, использованием только IPv4, конкретного конфигурационного файла (**/etc/dhcp/dhcpd.conf**) и определённого интерфейса (**enp0s3**). Корректную работу службы можем увидеть ниже.

![](../../_images/7a6a4301daa8.webp)

Теперь на хосте Debian запросим новый адрес с помощью утилиты **dhclient**, выполнив команду `sudo dhclient enp0s3`.
