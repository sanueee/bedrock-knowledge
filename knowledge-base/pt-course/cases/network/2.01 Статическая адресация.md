# Guided Case 2.1 — Статическая адресация

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 2. Методы конфигурации сети / IP-адресация

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/8dc6794b2880.webp)

Есть одна сеть **192.168.1.0/24**, в которой находятся 2 виртуальные машины:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с интерфейсом **enp0s3**:
   
   - IP-адрес - 192.168.1.10
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1

Для выполнения данного кейса необходимо скачать **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

> Настройки **CPU**, **RAM** и **диска** на скачанных виртуальных машинах изменять не нужно

После скачивания подключиться к виртуальной машине можно с помощью графического интерфейса VirtualBox со следующими учётными данными:

1. Login - **pt-admin**
2. Password - **pt-3dt3chl@b**

> У всех виртуальных машин должно быть по **1** сетевому адаптеру VirtualBox в режиме **Internal Network**

На маршрутизаторе MikroTik, выставим адрес **192.168.1.1/24** на интерфейс **ether1**. Для этого воспользуемся командой `/ip address add address=192.168.1.1/24 interface=ether1`, а затем проверим конфигурацию с помощью команды `ip address print`

![](../../_images/c7f55b00a466.webp)

Можем увидеть, что в списке выданных адресов добавилась запись **192.168.1.1/24**. Мы выдали адрес на интерфейс маршрутизатора, теперь перейдем к настройке сетевого интерфейса Debian-машины. Для этого на Debian узле с помощью утилиты `nano` открываем файл **/etc/network/interfaces** и добавляем конфигурацию для сетевого интерфейса **enp0s3** в соответствии с изображением ниже.

![](../../_images/30342496fb5d.webp)

После сохранения содержимого файла перезапускаем службу настройки сетевых интерфейсов **networking.service** (или просто networking) командой `sudo systemctl restart networking` и переходим к проверки доступности узлов в сети. Воспользуемся утилитой `ping`, которая будет отправлять ICMP пакеты на указанный IP-адрес. Выполним команду `ping 192.168.1.1` на виртуальной машине Debian.

![](../../_images/d2b1f28d4f42.webp)

В результате выполнения проверки доступности мы видим, что интерфейсы работают исправно и корректно маршрутизируют пакеты данных.
