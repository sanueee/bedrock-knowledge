## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какое значение лежит в файле **Readme** на машине-жертве?

Посмотрим на логи в EveBox, которые появились в записях во время атаки.

![](../../_images/8fa0ff0530cb.webp)

В EveBox сработало правило из открытого набора [PT Rules](https://rules.ptsecurity.com/):

```
alert tcp any any -> any 23 (msg: "ATTACK [PTsecurity] Telnetd Authentication Bypass attempt (CVE-2026-24061)"; flow: established, to_server; content: "|ff fa 27|"; content: "|00|USER|01|"; distance: 0; content: "-f"; distance: 0; pcre: "/USER\x01[^\x00\xff]*?-f/"; flowbits: set, Telnetd.exploit.flg; reference: cve, 2026-24061; reference: url, www.opennet.ru/opennews/art.shtml?num=64649; reference: url, rules.ptsecurity.com; classtype: attempted-admin; sid: 10016325; rev: 4;)
```

Правило, которое зафиксировало атаку, ищет заданную последовательность байт **ff fa 27**. Если данные байты найдены, то запускается относительная цепочка проверок, которая должна подтвердить, что в пакете передаются вредоносные параметры. Сразу за управляющими байтами Suricata ожидает увидеть маркер объявления переменной окружения **USER**, если этот маркер присутствует, анализатор проверяет значение самой переменной на наличие флага **-f**. Финальным этапом проверки выступает регулярное выражение, оно удостоверяется в корректности структуры данных и защищает систему от ложных срабатываний. Если все условия совпали, Suricata генерирует предупреждение об атаке.

Откроем карточку инцидента и изучим его подробнее.

![](../../_images/14a2a3b1e074.webp)

Видим следующую информацию:

- **Timestamp** - 2026-06-10 19:59:50.492
- **Protocol** - TCP
- **Source** - 192.168.1.252, порт отправки: 39280
- **Destination** - 192.168.2.251, порт назначения: 23
- **in interface** - dummy0
- **Signature** - ATTACK [PTsecurity] Telnetd Authentication Bypass attempt (CVE-2026-24061).
- **Category** - Попытка получения прав администратора
- **Severity** - 1, является наивысшим уровнем опасности
- **action** - allowed, трафик был пропущен системой обнаружения вторжений, так как она работает в режиме мониторинга

Атакующий отправил на сервер 158 пакетов, а в ответ от сервера получил 96 пакетов, такие объемы данных для протокола Telnet могут косвенно указывать на то, что в ней выполнялись какие-то команды.
