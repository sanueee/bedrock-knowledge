# Guided Case 2.5 — Динамическая маршрутизация

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 2. Методы конфигурации сети / Маршрутизация

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/3339359bc268.webp)

**Виртуальная инфраструктура состоит из:**

1. Маршрутизатора **MikroTik1** с адресом 10.0.21.2/30 внутри сети с MikroTik2 и Router ID 1.1.1.1
2. Маршрутизатора **MikroTik2** с адресом 10.0.21.1/30 внутри сети с MikroTik1, адресом 10.0.32.2/30 внутри сети с MikroTik3, адресом 10.0.24.1/30 внутри сети с MikroTik4 и Router ID 2.2.2.2
3. Маршрутизатора **MikroTik3** с адресом 192.168.1.1/24 внутри сети с Debian1, адресом 10.0.32.1/30 внутри сети с MikroTik2 и Router ID 3.3.3.3
4. Маршрутизатора **MikroTik4** с адресом 192.168.2.1/24 внутри сети с Debian2, адресом 10.0.24.2/30 внутри сети с MikroTik2 и Router ID 4.4.4.4
5. Debian-машины **Debian1** с адресом 192.168.1.10/24 и шлюзом 192.168.1.1
6. Debian-машины **Debian2** с адресом 192.168.2.10/24 и шлюзом 192.168.2.1
7. Области OSPF backbone (**главная магистраль**), внутри которой находится соединение между MikroTik1 и MikroTik2
8. Области OSPF area1, внутри которой находится соединение между MikroTik2 и MikroTik3, а также сегмент с Debian1
9. Области OSPF area2, внутри которой находится соединение между MikroTik2 и MikroTik4, а также сегмент с Debian2

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

Для начала, настроим сетевые интерфейсы на устройствах инфраструктуры, опирайся на схему инфраструктуры.

MikroTik1:

1. `/ip address add address=10.0.21.2/30 interface=ether1` - назначает адрес 10.0.21.2/30 на интерфейс ether1

MikroTik2:

1. `/ip address add address=10.0.32.2/30 interface=ether1` - назначает адрес 10.0.32.2/30 на интерфейс ether1
2. `/ip address add address=10.0.21.1/30 interface=ether2` - назначает адрес 10.0.21.1/30 на интерфейс ether2
3. `/ip address add address=10.0.24.1/30 interface=ether3` - назначает адрес 10.0.24.1/30 на интерфейс ether3

MikroTik3:

1. `/ip address add address=192.168.1.1/24 interface=ether1` - назначает адрес 192.168.1.1/24 на интерфейс ether1
2. `/ip address add address=10.0.32.1/30 interface=ether2` - назначает адрес 10.0.32.1/30 на интерфейс ether2

MikroTik4:

1. `/ip address add address=10.0.24.2/30 interface=ether1` - назначает адрес 10.0.24.2/30 на интерфейс ether1
2. `/ip address add address=192.168.2.1/24 interface=ether2` - назначает адрес 192.168.2.1/24 на интерфейс ether2

Для хостов Debian1 и Debian2 назначим соответсвующие IP-адреса: Debian1 - **192.168.1.10/24** Debian2 - **192.168.2.10/24**

Затем на каждом маршрутизаторе необходимо создать экземпляры OSPF, к которым мы присоединим области, содержащие информацию о сетях внутри себя. Начнем с MikroTik1. Этот маршрутизатор имеет только один сетевой интерфейс, который является главной магистралью (**backbone**), для его настройки необходимо выполнить следующие команды:

1. `/routing ospf instance add name=default router-id=1.1.1.1` - создает экземпляр OSPF с Router ID 1.1.1.1
2. `/routing ospf area add name=backbone area-id=0.0.0.0 instance=default` - создает backbone-область OSPF
3. `/routing ospf interface-template add interfaces=ether1 networks=10.0.21.0/30 area=backbone` - добавляет сеть 10.0.21.0/30 в backbone-область

![](../../_images/787297b59594.webp)

В свою очередь, MikroTik2 является пограничным маршрутизатором, поэтому для его настройки понадобится больше команд, по сравнению с первым, так как ему надо знать о всех областях в топологии. Используем следующие команды:

1. `/routing ospf instance add name=default router-id=2.2.2.2` - создает экземпляр OSPF с Router ID 2.2.2.2
2. `/routing ospf area add name=backbone area-id=0.0.0.0 instance=default` - создает backbone-область OSPF
3. `/routing ospf area add name=area1 area-id=0.0.0.1 instance=default` - создает область OSPF area1
4. `/routing ospf area add name=area2 area-id=0.0.0.2 instance=default` - создает область OSPF area2
5. `/routing ospf interface-template add interfaces=ether1 networks=10.0.32.0/30 area=area1` - добавляет сеть 10.0.32.0/30 в область area1
6. `/routing ospf interface-template add interfaces=ether2 networks=10.0.21.0/30 area=backbone` - добавляет сеть 10.0.21.0/30 в backbone-область
7. `/routing ospf interface-template add interfaces=ether3 networks=10.0.24.0/30 area=area2` - добавляет сеть 10.0.24.0/30 в область area2

![](../../_images/88ae1f7f4ce7.webp)

MikroTik3 имеет два интерфейса, которые находятся в области **Area1**, для его настройки выполним 4 команды:

1. `/routing ospf instance add name=default router-id=3.3.3.3` - создает экземпляр OSPF с Router ID 3.3.3.3
2. `/routing ospf area add name=area1 area-id=0.0.0.1 instance=default` - создает область OSPF area1
3. `/routing ospf interface-template add interfaces=ether1 networks=192.168.1.0/24 area=area1` - добавляет сеть 192.168.1.0/24 в область area1
4. `/routing ospf interface-template add interfaces=ether2 networks=10.0.32.0/30 area=area1` - добавляет сеть 10.0.32.0/30 в область area1

![](../../_images/dba73add99a4.webp)

Как и третий маршрутизатор, у MikroTik4 есть 2 интерфейса в одной области:

1. `/routing ospf instance add name=default router-id=4.4.4.4` - создает экземпляр OSPF с Router ID 4.4.4.4
2. `/routing ospf area add name=area2 area-id=0.0.0.2 instance=default` - создает область OSPF area2
3. `/routing ospf interface-template add interfaces=ether1 networks=10.0.24.0/30 area=area2` - добавляет сеть 10.0.24.0/30 в область area2
4. `/routing ospf interface-template add interfaces=ether2 networks=192.168.2.0/24 area=area2` - добавляет сеть 192.168.2.0/24 в область area2

![](../../_images/f5c2411852a0.webp)
