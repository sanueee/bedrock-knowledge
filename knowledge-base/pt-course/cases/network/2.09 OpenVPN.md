# Guided Case 2.9 — OpenVPN

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 2. Методы конфигурации сети / VPN и Proxy

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/26c7d262f8da.webp)

**Виртуальная инфраструктура состоит из:**

1. Debian-машины **External PC** с адресом 10.0.0.2, подключенного к VPN Server
2. Debian-машины **VPN Server** с адресом 10.0.0.1 со стороны External PC и адресом 192.168.2.2 со стороны MikroTik
3. Маршрутизатора **MikroTik** с адресом 192.168.2.1 внутри сети с VPN Server и адресом 192.168.1.1/24 внутри локальной сети
4. Debian-машины **Internal PC** с адресом 192.168.1.20/24 и шлюзом 192.168.1.1
5. Debian-машины **Internal Server** с адресом 192.168.1.10/24 и шлюзом 192.168.1.1
6. VPN-туннеля с адресным пространством 10.8.0.0/24 между External PC и VPN Server

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

Для начала выдадим всем сетевым интерфейсам устройств адреса, которые соответствуют схеме. Единственное, что мы не трогаем, - это сеть **10.8.0.0/24**.

На VPN-сервере создаем директорию для сертификатов (`make-cadir ~/openvpn-ca`) в домашней директории пользователя **pt-admin** и переходим в нее, а затем инициализируем PKI и создаем сертификат центра сертификации командами:

1. `./easyrsa init-pki` - инициализирует PKI
2. `./easyrsa build-ca` - создает корневой сертификат CA (**Common Name: pt-ca**)

> PKI (Public Key Infrastructure) - система управления цифровыми сертификатами и криптографическими ключами для строгой аутентификации пользователей и устройств в виртуальных частных сетях.

Теперь необходимо создать сертификаты и ключи для сервера и клиента. Далее эти значения будут использоваться в качестве приватных (**.key**) и публичных (**.crt**) ключей для прохождения аутентификации сервером и клиентом. **Для сервера**:

1. `./easyrsa gen-req server nopass` - генерирует запрос на сертификат сервера (**Common Name: server**)
2. `./easyrsa sign-req server server` - подписывает сертификат сервера (**details: yes**)

**Для клиента**:

1. `./easyrsa gen-req client nopass` - генерирует запрос на сертификат клиента (**Common Name: client**)
2. `./easyrsa sign-req client client` - подписывает сертификат клиента (**details: yes**)

После создания ключей необходимо создать параметры DH (**Diffie-Hellman**) командой **./easyrsa gen-dh**, которые используются для безопасного согласования общего секрета между клиентом и сервером. На основе этого секрета формируются сеансовые ключи, применяемые для шифрования VPN-трафика алгоритмом AES-256-CBC. А для того чтобы защитить **TLS-канал** OpenVPN создадим **tls-ключ**, выполнив **openvpn --genkey secret ta.key**. Данный ключ позволит серверу принимать только те подключения, которые имеют этот ключ, и отсеивать другие еще до **TLS-handshake**.

Теперь перенесем часть созданных файлов, которые относятся к серверной части, в директорию **openvpn**. Воспользуемся командой `sudo cp ~/openvpn-ca/pki/ca.crt ~/openvpn-ca/pki/issued/server.crt ~/openvpn-ca/pki/private/server.key ~/openvpn-ca/pki/dh.pem ~/openvpn-ca/ta.key /etc/openvpn/`. После переноса файлов, в директории **openvpn** создадим конфигурационный файл **/etc/openvpn/server.conf**. Данный файл должен регулировать работу VPN-сервера, для этого внесем в него следующие данные:

```
port 1194
proto udp
dev tun

ca /etc/openvpn/ca.crt
cert /etc/openvpn/server.crt
key /etc/openvpn/server.key
dh /etc/openvpn/dh.pem

server 10.8.0.0 255.255.255.0

push "route 192.168.1.0 255.255.255.0"

keepalive 10 120

tls-auth /etc/openvpn/ta.key 0

cipher AES-256-CBC
auth SHA256

plugin /usr/lib/x86_64-linux-gnu/openvpn/plugins/openvpn-plugin-auth-pam.so login
username-as-common-name

persist-key
persist-tun

verb 3

```

Так как в настройках сервера мы указали авторизацию по имени пользователя на сервере (**username-as-common-name**), создадим дополнительного пользователя **client** с паролем **pt-t3st-us3r**. А затем разрешим серверу маршрутизировать трафик через себя, раскомментировав строку **net.ipv4.ip_forward=1** в файле **/etc/sysctl.conf**, как показано на изображении ниже.

![](../../_images/90450bc447c1.webp)

Перечитаем конфигурацию, для применения изменений командой `sudo sysctl -p`. Затем вручную добавим маршрут до внутренней сети в таблицу маршрутизации, используя команду `ip route add 192.168.1.0/24 via 192.168.2.1`, и завершаем настройку VPN-сервера запуском и перезагрузкой службы **openvpn@server**.

![](../../_images/953bf74c8b35.webp)

Перейдем к настройке маршрутизатора. На маршрутизаторе необходимо добавить статический маршрут из VPN-туннеля во внутреннюю сеть командой `/ip route add dst-address=10.8.0.0/24 gateway=192.168.2.2`, а также настроить правила **firewall**, чтобы VPN-трафик мог проходить во внутреннюю сеть. Добавим нужные правила командами:

1. `/ip firewall filter add chain=forward src-address=10.8.0.0/24 action=accept comment="allow OpenVPN clients"` - разрешает трафик из VPN в LAN
2. `/ip firewall filter add chain=input src-address=10.8.0.0/24 action=accept comment="allow ping/admin from OpenVPN if needed"` - разрешает доступ к роутеру из VPN

Далее настроим клиентскую сторону. Сначала передадим клиентские ключи и сертификаты с сервера на клиент с помощью утилиты **scp**, используем команду `scp ~/openvpn-ca/pki/ca.crt ~/openvpn-ca/pki/issued/client.crt ~/openvpn-ca/pki/private/client.key ~/openvpn-ca/ta.key pt-admin@10.0.0.2:.` Они нам понадобятся, чтобы клиент мог проверить подлинность сервера, а сервер подлинность клиента. Теперь в той директории, куда мы скачали данные с сервера, создадим и настроим конфиг **client.ovpn**, внеся в него следующие данные:

```
client
dev tun
proto udp

remote 10.0.0.1 1194

ca ca.crt
cert client.crt
key client.key

tls-auth ta.key 1

cipher AES-256-CBC
auth SHA256

auth-user-pass login.txt

verb 3

```

После того, как мы сохраним конфигурационный файл, настройка устройств будет завершена.

Сначала создадим файл с аутентификационными данными **login.txt** в той же директории, в которой лежит** client.ovpn**, командой `printf "client\npt-t3st-us3r\n" > login.txt`. Для того чтобы запустить VPN в фоновом режиме, на клиенте запускаем OpenVPN с указанием конкретного конфига **client.ovpn**, командой `sudo openvpn --config client.ovpn --daemon`, а для отключения выполним командой **sudo pkill openvpn**. Если все прошло успешно, применив команду `ip addr` мы сможем увидеть новый сетевой интерфейс **tun0**

![](../../_images/2e7a0ad273c8.webp)

Теперь проверяем доступ к внутренним устройствам в сети 192.168.1.0/24, они должны отвечать нам, как показано ниже на изображении.

![](../../_images/b62874847e39.webp)
