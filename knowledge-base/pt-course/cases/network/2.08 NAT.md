# Guided Case 2.8 — NAT

> [!info] Путь в курсе

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/8bae4722270a.webp)

**Виртуальная инфраструктура состоит из:**

- External network - внешней сети
- маршрутизатора **MikroTik1** с двумя статическими адресами 10.0.10.1/24 (ether1) и 10.0.0.2/24 (ether2)
- маршрутизатора **MikroTik2** с двумя адресами, статическими 10.0.0.1/24 (ether1), 10.0.20.1/24 (ether2) и динамическим 192.168.X.X/24 (ether3)
- Debian-машины **Debian1** со статическим адресом 10.0.10.10/24 и шлюзом 10.0.10.1
- Debian-машины **Debian2** со статическим адресом 10.0.20.10/24 и шлюзом 10.0.20.1

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

У данных виртуальных машин используются сетевые адаптеры VirtualBox в режиме **Internal Network**, кроме единственного адаптера типа **Bridged Network**, соединяющего **MikroTik2** и **External Network**

Для начала настроим сетевые интерфейсы на маршрутизаторах и хостах в соответствии со схемой и ее описанием. Затем на обоих маршрутизаторах необходимо добавить маршруты по умолчанию, используя следующие команды:

1. MikroTik1 - `/ip route add dst-address=0.0.0.0/0 gateway=10.0.0.1`
2. MikroTik2 - `/ip route add dst-address=0.0.0.0/0 gateway=<адрес маршрутизатора вашей домашней сети> `(Данный маршрут может быть выдан автоматически DHCP-сервером домашней сети)

После настройки сетевых интерфейсов необходимо включить правила для функционирования NAT на обоих маршрутизаторах, чтобы оба хоста могли выходить во внешнюю сеть. Для этого воспользуемся командами:

1. MikroTik1 - `/ip firewall nat add chain=srcnat out-interface=ether2 action=masquerade`.
2. MikroTik2 - `/ip firewall nat add chain=srcnat out-interface=ether3 action=masquerade`.

Настроив технологию NAT теперь мы можем выходить в интернет с хостов Debian1 и Debian2, проверим это, применив команду **ping global.ptsecurity.com** на Debian2.

![](../../_images/8fc31acca218.webp)

Мы можем видеть, что ICMP пакеты успешно доходят до поддомена **global.ptsecurity.com**, а значит внешние ресурсы доступны изнутри локальной сети 10.0.20.0/24. Но доступны внутренние ресурсы извне? Рассмотрим это на примере двух сетей 10.0.10.0/24 и 10.0.20.0/24. Для этого подготовим Debian1, подняв сервер **Nginx** на 80-ом порту и внеся кастомную запись в файл **/var/www/html/index.html** с помощью следующих команд:

1. `sudo systemctl enable nginx`
2. `sudo systemctl start nginx`
3. `sudo sh -c "echo '<h1>PORT FORWARDING</h1>' > /var/www/html/index.html"`
4. `sudo systemctl restart nginx`

Теперь необходимо добавить новые правила перенаправления трафика на обоих MikroTik, для этого используем команды:

1. MikroTik1 - `/ip firewall nat add chain=dstnat protocol=tcp dst-port=80 action=dst-nat to-addresses=10.0.10.10 to-ports=80`
2. MikroTik2 - `/ip firewall nat add chain=dstnat protocol=tcp dst-port=80 action=dst-nat to-addresses=10.0.0.2 to-ports=80`

После того, как мы настроили правила перенаправления трафика, пакеты могут проходить по маршруту **10.0.20.10 -> 10.0.10.10**. Проверим доступность сервера с Debian2, для этого выполним команду `curl "http://10.0.20.1/"`, которая отправит HTTP запрос на адрес маршрутизатора (**10.0.20.1**) и порт 80.

![](../../_images/10aa5f4267db.webp)

В результате выполнения команды мы можем видеть, что запрос был успешно доставлен, а нам вернулось корректное содержимое страницы.
