# Self-study Case 2.2 — Настройка масок

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 2. Методы конфигурации сети / IP-адресация

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии со схемой ниже:

![](../../_images/a4a20058e185.webp)

Есть одна сеть **192.168.1.0/24**, в которой находятся 3 виртуальные машины:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. Debian-машина **Debian1** с интерфейсом **enp0s3**:
   
   - IP-адрес - 192.168.1.10
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1
3. Debian-машина **Debian2** с интерфейсом **enp0s3**:
   
   - IP-адрес - 192.168.1.200

Для выполнения данного кейса необходимо скачать новый или клонировать ранее скачанный **OVA-образ** виртуальной Debian-машины, заготовленной Positive Technologies. В данном образе уже есть предустановленный набор программного обеспечения, а скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/b4275685f64849189a2a/?op=view)

> У всех виртуальных машин должно быть по **1** сетевому адаптеру VirtualBox в режиме **Internal Network**

Перед началом решения практического кейса кратко вспомним основные функции маски подсети:

1. Определяет, какая часть IP-адреса относится к хосту, а какая определяет сеть
2. Позволяет понять, находятся ли устройства в одной сети
3. Используется для логического разделения сети на подсети

## Вопрос
*тип: open_answer, макс. баллов: 1, попыток: 3*

Необходимо настроить сетевые интерфейсы на устройствах Debian1 и Debian2 так, чтобы они имели доступ ко всем устройствам в сети. После настройки сетевых конфигураций необходимо запустить **checker_masks** на **Debian1 **с помощью команды `sudo chmod +x ~/checkers/checker_masks && sudo ~/checkers/checker_masks`
Пример: **osL4l0ug79lzEHouNXgS9QXoCHEj0E**
