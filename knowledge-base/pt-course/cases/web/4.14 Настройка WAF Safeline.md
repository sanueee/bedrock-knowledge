## Стенд / введение

Для выполнения данного кейса нам необходимо создать виртуальную машину путем **клонирования** базового образа **Debian-12-Gold**, который был сделан в статье **"Настройка Debian 12"**

- У данной виртуальной машины должен быть **1** сетевой адаптер VirtualBox в режиме **NAT**, а также проброшенные порты:

| Name | Protocol | Host IP | Host Port | Guest IP | Guest Port |
|---|---|---|---|---|---|
| waf-admin | TCP | 127.0.0.1 | 9443 |  | 9443 |
| web-app | TCP | 127.0.0.1 | 8000 |  | 8000 |

Поле guest ip следует оставить пустым, Virtualbox автоматически назначит IP-адрес гостевой машины, выделенный из пула внутренней NAT-сети

- Учётные данные от виртуальных машин остаются такими, какие вы назначали при установке образа

Для начала необходимо скачать необходимые утилиты, а также веб-приложение которое развернем для демонстрации практики. Для этого запустим команды:

```
apt install apache2 libapache2-mod-php unzip php curl
wget -O newspulse.zip https://storage.ptsecurity.com/seafhttp/f/ad32a43cfead4baab524/?op=download
```

По умолчанию **apache** настроен так, что корневой директорией сайта является **/var/www/html/**, а внутри неё находится стандартная заглушка index.html. Поскольку нам нужно развернуть собственное приложение, очистим директорию /var/www/ от стандартных файлов и распакуем архив:

```
sudo rm -rf /var/www/*
sudo unzip /home/edtechlab_user/newspulse.zip -d /var/www/
```

![](../../_images/881bc6d3242e.webp)

Поскольку команды выполняются с правами суперпользователя, все распакованные файлы будут принадлежать пользователю root. Однако веб-сервер Apache по умолчанию работает от имени пользователя www-data, и у него могут возникнуть проблемы с доступом к файлам. Чтобы этого избежать, назначим корректного владельца, `chown -R www-data:www-data /var/www/newspulse`

Далее необходимо настроить Apache так, чтобы он отдавал файлы нашего приложения и слушал нужный порт. Основной конфигурационный файл виртуального хоста по умолчанию находится по пути** /etc/apache2/sites-available/000-default.conf.**
В содержимом файле необходимо изменить два параметра:
**DocumentRoot **- путь к корневой директории сайта. По умолчанию он указывает на **/var/www/html**, его нужно изменить на **/var/www/newspulse/public**.
**&lt;VirtualHost *:8080>**** - директива, определяющая ip-адрес интерфейса *(***** означает все доступные сетевые интерфейсы) и порт, на котором данный виртуальный хост будет принимать входящие соединения.

![](../../_images/6fc3252ba5d5.webp)

Однако конфигурация сетевых параметров разделена между двумя логическими уровнями. Первый уровень - глобальная конфигурация портов. Файл **/etc/apache2/ports.conf** содержит директивы **Listen**, которые указывают веб-серверу, на каких сетевых интерфейсах и портах необходимо открыть сокеты для приема входящих соединений. Эти директивы выполняются на этапе инициализации процесса **Apache**, до обработки каких-либо виртуальных хостов. Если порт не указан в этом файле, Apache физически не будет слушать его, и все входящие соединения на этот порт будут отклонены на уровне операционной системы.
Второй уровень - конфигурация виртуальных хостов. Файлы из директории **/etc/apache2/sites-available/** (в том числе 000-default.conf) определяют, как именно Apache должен обрабатывать запросы, поступившие на уже открытые порты. Директива &lt;VirtualHost *:8080> лишь указывает, что данный виртуальный хост должен обслуживать запросы на порту 8080, но она не заставляет Apache открыть этот порт.
Таким образом, для корректной работы веб-приложения на нестандартном порте необходимо также изменить прослушиваемый порт в **/etc/apache2/ports.conf **на 8080.

![](../../_images/745afdee8240.webp)

Для того чтобы веб-сервер применил внесенные изменения в конфигурационные файлы, необходимо перезапустить службу apache2 с помощью команды `systemctl restart apache2`

Далее необходимо установить и настроить WAF Safeline
Запустим команду: `bash -c "$(curl -fsSLk https://waf.chaitin.com/release/latest/manager.sh)" -- --en`

![](../../_images/71330f5657a1.webp)![](../../_images/0289727d1184.webp)

По окончании работы установочного скрипта в терминале отобразится сообщение об успешном развертывании всех необходимых компонентов. Кроме того, система автоматически сгенерирует и выведет учетные данные для первоначального доступа к веб-интерфейсу панели управления

![](../../_images/fb2200ada835.webp)

Перейдем на **http://localhost:9443**, где авторизуемся под ранее выданные учетные данные

После успешной аутентификации система перенаправит вас на главную панель управления Safeline. Интерфейс предоставляет сводную информацию о состоянии системы безопасности, включая статистику заблокированных атак, текущую загрузку вычислительных ресурсов и статус мониторинга защищаемых веб-узлов.

![](../../_images/2b7c89478a9a.webp)

Далее добавим наше веб-приложение в конфигурацию WAF. Для этого перейдем в раздел **Applications.** Учитывая, что **Safeline **работает внутри изолированного Docker-контейнера, а наше веб-приложение запущено непосредственно на хост-машине. Если указать в настройках WAF адрес 127.0.0.1, контейнер попытается обратиться к самому себе, а не к хосту, что приведет к ошибке соединения.
Чтобы обеспечить корректную связь, необходимо использовать IP-адрес виртуального сетевого моста Docker, который выступает шлюзом между контейнерами и хост-системой.
Выполните в терминале хост-машины команду для просмотра сетевых интерфейсов **ip a | grep docker0.**

![](../../_images/91e3a7288f22.webp)

Теперь перейдем по адресу `http://127.0.0.1:8000` Видим наше веб-приложение.

![](../../_images/b3dd0d5def73.webp)

Для проверки корректности функционирования WAF необходимо cформировать запрос, добавив потенциально вредоносный скрипт в query-параметр. Запрос будет выглядеть следующим образом: `http://127.0.0.1:8000/?id=<script>alert(1)</script>`

![](../../_images/2c9b77f3b8bc.webp)

Видим что запрос был заблокирован. Также в панели управления можем просмотреть данный запрос. Для этого перейдем в раздел **Attacks**. Далее выберем подраздел **logs** где увидим заблокированный запрос. Нажмем details чтобы просмотреть подробную информацию о запросе.

![](../../_images/dd046122c00b.webp)

Журнал WAF содержит детализированную информацию о каждом инциденте безопасности, включая полезную нагрузку, временную метку события и сам **HTTP-запрос**.

![](../../_images/abbc2176821a.webp)
