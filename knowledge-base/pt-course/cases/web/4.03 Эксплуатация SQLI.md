# Guided Case 4.3 — Эксплуатация SQLI

>
> **Теория:** [3.02 SQL Injection](../../web/3%20Анализ%20уязвимостей%20веб-приложений/3.02%20SQL%20Injection.md)

## Стенд / введение

- Для выполнения кейса скачайте [**Ova-образ**](https://storage.ptsecurity.com/seafhttp/f/43c39edeb5364b3aa9e0/?op=view) виртуальной машины. В образе уже предустановлено всё необходимое ПО, веб-приложение запущено и работает на сетевом порту 5000
- Для доступа к виртуальным машинам с хост-машины настроен проброс портов в **VirtualBox**. Доступ к веб-приложению осуществляется через обращение к **http://localhost:5000**
- В качестве СУБД используется **MySQL**

Перейдем по адресу **http://127.0.0.1:5000**, где расположено веб-приложение. Нас встречает домашняя страница книжного магазина.

![](../../_images/d67d6d836403.webp)

С главной страницы можно перейти в каталог, или на страницу новостей. Перейдем в раздел **каталог. **В данном разделе увидим список книг, а также поле поиска. Поиск по определению подразумевает обращение к базе данных с учетом входных данных пользователя. Далее веб-приложение формирует запрос, выполняет запрос к базе данных, после выдает результат. На основе этого можем предположить, что поле поиска может быть потенциально уязвимо.

![](../../_images/a3a2d65dce0a.webp)

Однако для проверки наличия уязвимости необходимо понимать как строится запрос. При вводе в поле поиска, например, части имени автора, система возвращает книги данного автора. Это означает, что для нахождения совпадения не требуется полное вхождение строки, а достаточно наличия подстроки в искомом атрибуте. Отсюда можем предположить, что запрос может строится через оператор **LIKE**, например: **SELECT * FROM books WHERE author_name LIKE '%' . $userInput . '%';**

> В операторе **LIKE** символ **%** означает любое количество символов.

Теперь попробуем посмотреть поведение базы данных, если мы попробуем изменить логику запроса через **%'**. Если мы попробуем ввести такую полезную нагрузку, % из нашего ввода остаётся внутри строки, а следующая за ним одинарная кавычка принудительно закрывает строковый литерал шаблона поиска. Система управления базами данных интерпретирует **LIKE '%'** как завершённое выражение. Оставшиеся символы **%’** оказываются "за пределами" строки, что нарушает синтаксис **SQL** и приводит к ошибке парсинга запроса.

![](../../_images/4ee0dbeee07b.webp)

Возникшая ошибка подтверждает, что веб-приложение не валидирует и не экранирует пользовательский ввод, позволяя ему напрямую модифицировать структуру исполняемого запроса. Теперь попробуем получить информацию из служебной базы данных **information_schema.**

> **information_schema** - это стандартизированная системная схема (виртуальная база данных), хранящая метаданные обо всех объектах текущей базы данных. Она содержит информацию о таблицах, представлениях, столбцах, типах данных, правах доступа и хранимых процедурах.

Для этого воспользуемся оператором **UNION**, чтобы объединить запросы. Однако если мы просто напишем: `UNION SELECT * FROM information_schema -- `, мы увидим ошибку.

> В MySQL после двух дефисов **--** обязательно должен стоять пробел - только в этом случае СУБД распознает их как начало однострочного комментария. Это требование обусловлено тем, что символ дефиса также используется в арифметических выражениях, и без пробела парсер не сможет отличить комментарий от операции вычитания.

![](../../_images/8913634944f9.webp)

Как было описано в теории, при использовании оператора **UNION **количество столбцов в двух запросах должно совпадать. Поэтому для начала нужно узнать количество столбцов в нашей исходной таблице с книгами. Для этого есть два подхода:

- использовать **ORDER BY N**, где N - количество столбцов. Данная функция используется для сортировки по N-му столбцу . Можем повышать значение N до тех пор пока не получим ошибку
- Второй метод включает в себя отправку серии **UNION SELECT** с различным количеством нулевых значений. При неправильном количестве столбцом система управления базами данных будет выдавать ошибку. Например:

```
UNION SELECT name,mail, NULL, NULL FROM USERS
UNION SELECT name,mail, NULL, NULL, NULL FROM USERS
и т.д.
```

![](../../_images/6cdca571f84c.webp)

В данном случае будет 8 столбцов, на 9 мы получим ошибку. Определив количество столбцов, переходим к выявлению их типов данных. Для этого формируем серию запросов **UNION SELECT**, в которых поочерёдно подставляем строковое значение в каждый столбец, а остальные заполняем **NULL**. В результате запрос будет выглядеть подобным образом: `%' UNION SELECT 'a',NULL,NULL,NULL,NULL,NULL,NULL,NULL FROM information_schema.tables WHERE table_schema = database() -- `.

![](../../_images/deb19f921ac5.webp)

В результате тестирования видим, что второй столбец имеет строковый тип данных, о чем свидетельствует символ 'a' которые мы добавили в запрос.

![](../../_images/7a964b5c9dac.webp)

Получим информации о именах таблиц, находящихся в текущей базе данных с помощью команды: `%' UNION SELECT NULL,table_name,NULL,NULL,NULL,NULL,NULL,NULL FROM information_schema.tables WHERE table_schema = database() -- `.

![](../../_images/a3b3c9909a99.webp)

Видим, что есть таблицы users, books, news. После получения перечня таблиц необходимо определить приоритетную цель для извлечения данных. В данном контексте таблица **users **представляет наибольший интерес. Для просмотра содержимого таблицы, необходимо добавить фильтр `table_name='users'`, ограничивающий выборку только этой таблицей.** **В результате полезная нагрузка будет выглядеть следующим образом: `%' UNION SELECT NULL,column_name,NULL,NULL,NULL,NULL,NULL,NULL FROM information_schema.columns WHERE table_schema = database() and table_name='users' -- `.

> В данном случае необходимо использовать уже** information_schema.columns**, так как мы хотим узнать имена столбцов конкретной таблицы

![](../../_images/853239141b8b.webp)

В результате мы получаем структуру таблицы: столбцы **id**, **username**, **email**, **password**. Зная имена полей, можно перейти к извлечению конкретных данных, например, содержимого столбца **username**.

![](../../_images/d3cfec44f3a3.webp)

## Вопрос №1
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какой **email **у пользователя **helen_v? **Пример:** j.smith@mail.com**

## Вопрос №2
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какой пароль у пользователя **john_smith**? Пример: **userpass123**
