## Стенд / введение

Для выполнения данного кейса нам необходимо создать виртуальную машину путем **клонирования** базового образа **Debian-12-Gold**, который был сделан в статье **"Настройка Debian 12"**

- У данной виртуальной машины должен быть **1** сетевой адаптер VirtualBox в режиме **NAT**, а также проброшенные порты:

| Name | Protocol | Host IP | Host Port | Guest IP | Guest Port |
|---|---|---|---|---|---|
| dashboard | TCP | 127.0.0.1 | 8080 |  | 8080 |

Поле **guest ip** следует оставить пустым, Virtualbox автоматически назначит IP-адрес гостевой машины, выделенный из пула внутренней NAT-сети.

- Учётные данные от виртуальных машин остаются такими, какие вы назначали при установке образа

При анализе защищённости приложения используют не один инструмент, а сразу несколько. Каждый инструмент выдаёт собственный отчёт в собственном формате, и когда таких отчётов становится много, разобраться в них вручную становится тяжело. **DefectDojo** создан, чтобы упорядочить все отчёты в одном месте. Это открытая платформа управления уязвимостями от **OWASP**. Она работает как единая точка сбора, то есть в неё загружают отчёты разных инструментов, а она приводит их к общему виду, объединяет повторы и позволяет вести каждую уязвимость от момента обнаружения до исправления.

Перейдем к установке **DefectDojo. **Запустим виртуальную машину с установленной Debian и войдем под своим пользователем. **DefectDojo **разворачивается с помощью **Docker**. **Docker **и установка пакетов требуют административных прав, которые даёт команда **sudo**. Чтобы установить **sudo**, переключимся на суперпользователя `su -` Команда запросит пароль **root**, заданный при установке системы.

Обновим список пакетов и установим **sudo **с помощью команды `apt update && apt install -y sudo`

Разрешим пользователю выполнять команды с правами администратора, добавив его в группу **sudo** `usermod -aG sudo pt-intern`

Вернёмся из режима суперпользователя `exit`

![](../../_images/c5f8db33cfe6.webp)

Членство в группе применяется только при новом входе, поэтому выйдем из системы и зайдем снова.

Установим **Git**, которым скачаем проект, и вспомогательные пакеты для защищённого соединения `sudo apt install -y git curl ca-certificates` **curl** понадобится, чтобы загрузить установщик **Docker**, а **ca-certificates** обеспечивает шифрованное соединение при скачивании.

Далее установим **Docker **с помощью команды** **`curl -fsSL https://get.docker.com | sudo sh`. Утилита **curl** скачивает скрипт установки с сайта **Docker**, а **sudo sh** сразу его выполняет. Скрипт сам ставит **Docker** и всё необходимое окружение.

![](../../_images/3d8c9e75113d.webp)

Добавим **Docker **в автозапуск и запустим его `sudo systemctl enable --now docker` **enable** включает автозапуск **Docker** при загрузке системы, а **--now** запускает его сразу. **Docker** нужен потому, что **DefectDojo** поставляется набором контейнеров. **Docker** запускает эти контейнеры и связывает их между собой.

Скачаем проект из официального репозитория `git clone https://github.com/DefectDojo/django-DefectDojo`

![](../../_images/2bf629015246.webp)

Затем перейдем в появившуюся директорию и поднимем контейнеры `sudo docker compose up -d`

![](../../_images/862421d57eee.webp)

Файл проекта уже описывает, из каких частей состоит **DefectDojo **и как они связаны. Это база данных, кэш, веб-сервер и само приложение. Команда **docker compose up** читает это описание и поднимает всё сразу. При первом запуске на пустой базе **DefectDojo** создаёт учётную запись администратора и один раз показывает сгенерированный для неё пароль в журнале служебного контейнера. Прочитаем этот пароль `sudo docker compose logs initializer | grep "Admin password:"`

![](../../_images/ed311adfc15f.webp)

**docker compose logs initializer** выводит журнал служебного контейнера, который отвечает за начальную настройку. Скопируем пароль, он нужен будет для входа. Затем откроем браузер и перейдем по адресу **http://localhost:8080**. Введем логин **admin** и пароль, который мы посмотрели.

![](../../_images/91fe7683ffe3.webp)

После входа откроется главная страница **DefectDojo**. Платформа развёрнута и готова к работе.

![](../../_images/adcab1877c45.webp)

На странице **Dashboard** собрана общая сводка. Вверху четыре окна, они показывают число активных сессий проверки, новых находок за последнюю неделю, закрытых за неделю и принятых рисков. Ниже два графика по серьёзности находок. Слева расположено меню разделов. Разберем для чего нужен каждый раздел:

- **Dashboard.** Текущая сводная страница.
- **Assets.** Приложения и системы, которые защищаем. Здесь создаётся запись о приложении, в которую потом поступают находки.
- **Engagements.** Сессии проверки внутри приложения. Одна сессия это один прогон сканеров или один пентест.
- **Findings.** Все найденные уязвимости в едином списке. Это главный рабочий экран, здесь находки сортируют, помечают ложные и отслеживают исправление.
- **Finding Groups.** Объединение связанных находок в группы для удобства работы.
- **Components.** Программные компоненты и библиотеки, из которых собрано приложение.
- **Endpoints.** Адреса и узлы, на которых работает приложение.
- **Reports.** Готовые отчёты по находкам для выгрузки.
- **Metrics.** Графики и показатели по уязвимостям во времени.
- **Users.** Управление учётными записями и правами доступа.
- **Calendar.** Календарь запланированных проверок и событий.
- **Questionnaires.** Анкеты для оценки приложений по безопасности.
- **Configuration.** Системные настройки платформы.
- **Upgrade.** Сведения об обновлении версии.
- **Collapse Menu.** Сворачивает боковое меню и освобождает место.

В следующей практике мы будем использовать Sast-анализаторы для анализа защищенности веб-приложения **NetTool. **Для этого нам нужно приложение-приёмник и ключ доступа.

Сначала создадим объект. Откроем раздел **Assets **и нажмем **Add Asset**.

![](../../_images/ce36fe7693ac.webp)

В форме обязательны четыре поля, они помечены звёздочкой. В поле **Name **впишем **NetTool**. В поле **Description** добавим короткое описание, например **Educational application for practice**. Поле **Organization** поставим **Research and Development**. Поле **SLA Configuration **заполним значением **No SLA Enforced**. Остальные поля необязательны, Поэтому нажимаем **Sumbit**. Так появляется приложение, в которое будут попадать находки сканеров. Зайди внутрь него.

![](../../_images/671f1f80f828.webp)

Пока здесь нет ни сессий, ни находок, они появятся после первого импорта отчёта.

![](../../_images/34e67f3e5f9e.webp)

Теперь получим ключ доступа к API. Откроем меню пользователя в правом верхнем углу, и выберем **API v2 Key**.

![](../../_images/0578fee65069.webp)

На открывшейся странице наш токен показан в строке **Your current API key is**, это набор букв и цифр. Кнопка **Generate New Key **ниже перевыпускает ключ, если он скомпрометирован.

![](../../_images/2f83ff6289ee.webp)

Теперь у платформы есть приложение-приёмник и личный ключ доступа. В следующей практике мы воспользуемся Sast-анализаторами и отправим их отчёты именно в **NetTool**.
