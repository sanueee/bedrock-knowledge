# Guided Case 4.7 — Эксплуатация Command Injection

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 3: Анализ уязвимостей веб-приложений / Command Injection
>
> **Теория:** [3.06 Command Injection](../../web/3%20Анализ%20уязвимостей%20веб-приложений/3.06%20Command%20Injection.md)

## Стенд / введение

- Для выполнения кейса скачайте [**OVA-образ**](https://storage.ptsecurity.com/seafhttp/f/67baee2d5c15471eb946/?op=view) виртуальной машины. В образе уже предустановлено всё необходимое ПО, веб-приложение запущено и работает на сетевом порту 5000
- Для доступа к виртуальным машинам с хост-машины настроен проброс портов в **VirtualBox**. Доступ к веб-приложению осуществляется через обращение к **http://localhost:5000**
- В целевом приложении присутствует эндпоинт **/admin** для доступа к админ-панели

Перейдем к исследованию веб-приложения. Для этого в браузере перейдем по **http://localhost:5000/**

![](../../_images/59c59b37c88b.webp)

Перейдя по адресу, видим домашнюю страницу сервисного центра по ремонту и техническому обслуживанию авто. Из исходных данных известно, что существует эндпоинт** /admin.**

> **Эндпоинт** - это адрес, по которому можно обратиться к сервису или API, чтобы получить данные или выполнить действие.

Перейдя по нему, увидим панель авторизации для администраторов сайта, где также указаны учетные данные для авторизации. Данные утечки характерны для ранних стадий жизненного цикла программного обеспечения. В результате в производственную среду попадают тестовые учетные данные, отладочная информация и служебные интерфейсы.

![](../../_images/d57b49336a4a.webp)

После успешной авторизации под учетными данными, нас перенаправляет на страницу инструментов для диагностики проблем с сетевым подключением к внешним сервисам и API. Попробуем использовать утилиту **ping** для сайта **example.com**

![](../../_images/b40178b53217.webp)

В результате увидим результат работы утилиты. Теперь, для дальнейшего удобства и наглядности, запустим Burp Suite и попробуем вместе с ресурсом для проверки example.com ввести еще одну команду, например **ls**, используя разделитель команд **;** . Перейдем в **Burp Suite** в раздел **HTTP history**, и найдем наш запрос с URI **/admin/network-tools.php**

![](../../_images/680eb0fd6987.webp)

В результате помимо вывода утилиты **ping**, видим файлы текущей директории.

В переданном POST-параметре **host** наблюдается значение **example.com%3B+ls**, где после имени хоста располагаются последовательности **%3B** и **+**, а затем команда **ls**. Такое представление обусловлено использованием формата **application/x-www-form-urlencoded**, который применяется для передачи данных HTML-форм. Перед отправкой браузер кодирует специальные символы согласно стандарту URL-кодирования: символ **;** преобразуется в **%3B**, а пробел в **+**. После обработки запроса веб-сервер или фреймворк автоматически выполняет обратное преобразование, поэтому приложение получает исходное значение **example.com; ls**

Можем убедиться, что после вывода утилиты **ping** выводится результат команды, которую мы добавили после **;**.

## Вопрос №1
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какой **полный путь** к текущей рабочей директории? Пример: **/home/user/www**

## Вопрос №2
*тип: open_answer, макс. баллов: 1, попыток: 3*

Какое **содержание **файла **/pt-intern/passwd**? Пример: **pt_intern_990c1d41**
