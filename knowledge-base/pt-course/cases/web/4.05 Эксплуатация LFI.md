# Guided Case 4.5 — Эксплуатация LFI

> **Теория:** [3.04 LFIRFI (LocalRemote File Inclusion)](../../web/3%20Анализ%20уязвимостей%20веб-приложений/3.04%20LFIRFI%20%28LocalRemote%20File%20Inclusion%29.md)

## Стенд / введение

- Для выполнения кейса скачайте [**Ova-образ**](https://storage.ptsecurity.com/seafhttp/f/54b652fb3fe7493e964e/?op=view) виртуальной машины. В образе уже предустановлено всё необходимое ПО, веб-приложение запущено и работает на сетевом порту 5000
- Для доступа к виртуальным машинам с хост-машины настроен проброс портов в **VirtualBox**. Доступ к веб-приложению осуществляется через обращение к **http://localhost:5000**
- Веб-приложение сохраняет определённые данные из входящих запросов, которые регистрируются в файле **/var/www/html/logs/access.log**

Перейдем по адресу **http://127.0.0.1:5000**. Mы видим домашнюю страницу веб-приложения университета, из которой можно перейти на другие страницы. Запустим **Burp Suite** и пройдемся по разным частям веб-приложения.

![](../../_images/bb6c21cafad9.webp)

Просмотрим запросы в **Burp Suite** во вкладке **HTTP History. **Навигация по веб-приложению показывает, что загрузка страниц реализована через **GET-параметр page**, который определяет путь к включаемому файлу. Например: i**ndex.php?page=pages/prospective.php**. Подобная архитектура потенциально может быть местом возникновения уязвимости **LFI**.

![](../../_images/246096cbc995.webp)

Так например, попробуем в качестве параметра **page** передать **/etc/passwd**

![](../../_images/5494ab9386dd.webp)

Как было указано ранее, данное веб-приложение ведет журнал пользовательской активности. Если мы просмотрим журнал логирования, увидим время запроса, IP-адрес и значение заголовка **User-Agent**. Учитывая наличие уязвимости и тот факт, что LFI позволяет не только читать, но выполнять файлы, это можно использовать. Суть уязвимости заключается в том, что специалист по анализу защищенности может внедрить **PHP-код** в заголовок **User-Agent**, который будет записан в лог-файл без какой-либо санитизации. Например, модифицируем значение заголовка на: `<?php system('ls'); ?>`. После этого, используя уязвимость LFI, обращаемся к файлу журнала **logs/access.log**. При включении данного файла интерпретатор PHP выполнит внедрённую команду, что приведёт к выводу содержимого текущей директории сервера.

![](../../_images/6fb393e178b3.webp)
