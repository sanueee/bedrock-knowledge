## Стенд / введение

Для выполнения данного кейса нам необходимо создать виртуальную машину путем **клонирования** базового образа **Debian-12-Gold**, который был сделан в статье **"Настройка Debian 12"**

- У данной виртуальной машины должен быть **1** сетевой адаптер VirtualBox в режиме **NAT**, а также проброшенные порты:

| Name | Protocol | Host IP | Host Port | Guest IP | Guest Port |
|---|---|---|---|---|---|
| dashboard | TCP | 127.0.0.1 | 8080 |  | 8080 |
| ssh | TCP |  | 2222 |  | 22 |

- Поле **guest ip** следует оставить пустым, Virtualbox автоматически назначит IP-адрес гостевой машины, выделенный из пула внутренней NAT-сети.
- Учётные данные от виртуальных машин остаются такими, какие вы назначали при установке образа.
- Также понадобится тестовое веб-приложение [**app.py**](https://storage.ptsecurity.com/seafhttp/f/9a875e95eafa4a08a533/?op=view) (учебное приложение **NetTool** на **Python** с намеренно добавленными уязвимостями).

Специалист по анализу защищённости проверяет не только работающее приложение, но и его исходный код. Такой подход называется статическим анализом (**SAST**). Инструмент читает код, не запуская его, и ищет в нём небезопасные конструкции по набору правил.

В этой практике мы рассмотрим два **SAST**-анализатора. **Bandit** работает только с **Python** и проверяет код по встроенному набору правил для типичных небезопасных конструкций. **Semgrep** поддерживает много языков и работает по подключаемым наборам правил. Инструменты устроены по-разному и охватывают разные классы проблем, поэтому на практике их часто применяют вместе. Результаты обоих мы отправим в **DefectDojo**, который развернули ранее. Так все находки окажутся в одном месте и в едином виде, и с ними можно будет работать как с единым списком.

Работаем на той же виртуальной машине, что и в прошлой практике. **DefectDojo** развёрнут, объекты **NetTool** в нём создан. Давайте проверим работу **SAST**-анализаторов в связке с **Defectdojo** на примере тестового веб-приложения. Для этого перенесем файл на виртуальную машину. Воспользуемся **scp** через проброс порта **SSH**. Перед этим установим SSH-сервер

```
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

Теперь с хоста скопируем файл. `scp -P 2222 C:/PT/app.py pt-intern@localhost:~/`

![](../../_images/3d098525463d.webp)

На виртуальной машине помести его в отдельную папку, дальше работаем из неё.

```
mkdir -p ~/nettool
mv ~/app.py ~/nettool/app.py
```

![](../../_images/28bdb59ba7c3.webp)

Теперь когда у нас приложение находится на ВМ мы можем перейти к установке **SAST**-анализаторов с помощью менеджер пакетов **Python**.

```
sudo apt install -y python3-pip
sudo pip install --break-system-packages bandit semgrep
```

Флаг **--break-system-packages** отключает встроенную защиту Debian, которая запрещает установку пакетов **Python** глобально. Без него **pip** заблокирует установку, ссылаясь на защиту системного окружения.

## Вопрос №1
*тип: open_answer, макс. баллов: 1, попыток: 3*

Запустите первый чекер. Он проверит, что Bandit и Semgrep установлены и работают. Скачайте его командой `wget -O checker1 "https://storage.ptsecurity.com/seafhttp/f/bfcb0430d1054c599cb8/?op=download"` и запустите. **Какой флаг** выводит чекер?

> *После скачивания необходимо установить бит выполнения с помощью утилиты ****chmod***

После установки анализаторов стоит учесть, что каждый из них сохраняет отчёт в формате **JSON**, ведь именно такой формат требуется для интеграции с **DefectDojo**. Для начала запустим **Bandit** в директории с нашим веб-приложением: `bandit -r . -f json -o bandit.json`

![](../../_images/3f8f17c5937b.webp)

Флаг **-r** включает рекурсивный обход, Bandit проверит файлы во вложенных папках, а не только в текущей. Точка указывает, что сканировать нужно текущую папку. Флаг **-f json** задаёт формат отчёта, **-o bandit.json** имя файла.

Теперь **Semgrep**. Ему нужно указать набор правил. У **Semgrep** есть общедоступный реестр наборов, и он сам скачивает нужный по имени, для этого требуется интернет. Есть широкий режим **--config auto**, который подтягивает сразу много наборов. Он удобен, но наборы в нём пересекаются, и одно и то же слабое место отмечается несколькими правилами. Чтобы результат оставался читаемым, мы указываем один набор **p/flask**: `semgrep scan --config p/flask --json --output semgrep.json .`

![](../../_images/19673e22e34c.webp)

Здесь **p/flask** это имя набора в реестре, **Semgrep** скачает его сам. Точка в конце указывает сканировать текущую папку.

## Вопрос №2
*тип: open_answer, макс. баллов: 1, попыток: 3*

Запустите **checker2**. Он проверит, что SAST-анализаторы отработали корректно. Скачайте его командой `wget -O checker2 "https://storage.ptsecurity.com/seafhttp/f/0d60f5440d83426998e4/?op=download"` и запустите `./checker2 `в директории **nettool**. **Какой флаг** выводит чекер?

> *После скачивания необходимо установить бит выполнения с помощью утилиты ****chmod***

Отчёты отправляются в **DefectDojo** одной командой через его программный интерфейс. Понадобится **API-ключ**, сохранённый в прошлой практике. Отправляем отчёт **Bandit**, заменив параметр **Token **на значение** API v2 key, **который указан** **в **DefectDojo**.

```
curl -sS -X POST "http://localhost:8080/api/v2/import-scan/" \
  -H "Authorization: Token 5dfc38a022306e9f77b4a10650abd8aa4f287f99" \
  -F "scan_type=Bandit Scan" \
  -F "file=@bandit.json" \
  -F "product_name=NetTool" \
  -F "engagement_name=SAST" \
  -F "auto_create_context=true" \
  -w "\nHTTP %{http_code}\n"

```

Затем отчёт **Semgrep**.

```
curl -sS -X POST "http://localhost:8080/api/v2/import-scan/" \
  -H "Authorization: Token 5dfc38a022306e9f77b4a10650abd8aa4f287f99" \
  -F "scan_type=Semgrep JSON Report" \
  -F "file=@semgrep.json" \
  -F "product_name=NetTool" \
  -F "engagement_name=SAST" \
  -F "auto_create_context=true" \
  -w "\nHTTP %{http_code}\n"

```

- **\** - это символ продолжения команды
- **-H** - Добавляет пользовательский заголовок в **HTTP**-запрос.
- **-F** - Отправляет данные в формате **multipart/form-data**
- **-w** - Выводит дополнительную информацию после выполнения запроса.

Разберём поля. **scan_type** это точное имя разборщика в **DefectDojo**, регистр и пробелы важны. **file** это файл отчёта. **product_name=NetTool** направляет находки в созданное ранее приложение. **engagement_name=SAST** создаёт внутри него сессию проверки. **auto_create_context=true** разрешает завести недостающую сессию автоматически.

Откроем в **DefectDojo** раздел **Findings**.

![](../../_images/9390e05c9e44.webp)

Здесь **DefectDojo** собрал все находки в единый список из отправленных ему отчетов.

![](../../_images/3698dfad844e.webp)

Откроем любую находку и найдем блок **Location** и **Line Number**. Там указаны файл **app.py** и номер строки. Так каждая находка привязана к конкретному месту в коде, и её легко сверить с исходником.

![](../../_images/7a2952d7f399.webp)

Обратим внимание, что на строке 16 файла **app.py** **Semgrep** обнаружил уязвимость **CWE 78** (**OS Command Injection**). В поле **Description** ниже приведено описание найденной проблемы. Вернёмся к общему списку через вкладку **Open Findings**.

![](../../_images/e903bd591533.webp)

Обрати внимание на две выделенные строки. Первую нашёл **Bandit**, вторую **Semgrep**, но это одна и та же уязвимость. Оба инструмента указали на строку 16 файла **app.py**, где команда собирается из пользовательского ввода. **Bandit** дал ей понятное название, **Semgrep** обозначил именем своего правила и кодом **CWE 78**. Когда несколько инструментов находят одно и то же место, в списке появляется несколько записей об одной проблеме.

Таким образом, мы можем сгруппировать находки по реальной проблеме.

**Command Injection, строка 16.** Нашли оба. У **Bandit** это **Subprocess Call With Shell=True**, у **Semgrep** правило **subprocess-injection**. Команда формируется из пользовательского ввода и выполняется системной оболочкой.

![](../../_images/5d96607b20d4.webp)

**SQL Injection, строка 26.** Нашли оба. У **Bandit** **Possible SQL Injection Vector**, у **Semgrep** **tainted-sql-string**. Запрос к базе собирается из пользовательского ввода.

![](../../_images/92b50fa05872.webp)

**Code Injection, строка 36.** Нашли оба. У **Bandit** **Use of Possibly Insecure Function**, у **Semgrep** **eval-injection**. Пользовательский ввод передаётся в функцию, вычисляющую выражение.

![](../../_images/c3c2533133a5.webp)

**XSS, строка 44.** Нашёл только **Semgrep**, правило **python.flask.security.injection.raw-html-concat**, **CWE 79**. Пользовательский ввод без обработки попадает в HTML-код страницы. Bandit такие конструкции не проверяет.

![](../../_images/def97c735266.webp)

**Flask debug=True, строка 58.** Нашли оба. У **Bandit** **A Flask App Appears to Be Run With Debug=True**, у **Semgrep** правило **debug-enabled**, **CWE 489**. Приложение запущено в режиме отладки, что недопустимо на рабочем сервере.

![](../../_images/16e157d992f4.webp)

**Bind** на все интерфейсы, строка 58. Нашли оба. У Bandit **Possible Binding to All Interfaces**, у **Semgrep **правило **app-run-param-config**, **CWE 668**. Приложение слушает на всех сетевых интерфейсах.

![](../../_images/86d6183f88f1.webp)

Оба SAST-анализатора нашли большую часть уязвимостей, но **XSS** в строке 44 обнаружил только** Semgrep**. Дело не в том, что один лучше другого, а в том, что анализаторы заточены под разные классы проблем, и XSS входит в зону **Semgrep**, но не** Bandit**. Поэтому их применяют в связке, каждый закрывает свою область.
