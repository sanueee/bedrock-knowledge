# Guided Case 4.9 — Эксплуатация XXE

> [!info] Путь в курсе
> Глава 4: Веб-приложения и безопасность веб-приложений / Часть 3: Анализ уязвимостей веб-приложений / XXE (XML External Entity)
>
> **Теория:** [3.08 XXE (XML External Entity)](../../web/3%20Анализ%20уязвимостей%20веб-приложений/3.08%20XXE%20%28XML%20External%20Entity%29.md)

## Стенд / введение

- Для выполнения кейса скачайте [**Ova-образ**](https://storage.ptsecurity.com/seafhttp/f/a01aea7c67c549b38624/?op=view) виртуальной машины. В образе уже предустановлено всё необходимое ПО, веб-приложение запущено и работает на сетевом порту 5000
- Для доступа к виртуальным машинам с хост-машины настроен проброс портов в **VirtualBox**. Доступ к веб-приложению осуществляется через обращение к **http://localhost:5000**

Перейдем по адресу **http://localhost:5000**

Видим страницу создания аккаунта на платформе для обсуждения новостей и различных статей.

![](../../_images/1d084c3c99f5.webp)

После регистрации, мы перемещаемся на домашнюю страницу платформы:

![](../../_images/c610aacb02ab.webp)

Анализируя веб-приложение, увидим, что мы можем перейти на страницу профиля.

![](../../_images/c737c8acf58b.webp)

Видим, что мы можем изменить **username**, а также загрузить изображение для профиля, в формате **SVG**. Как было сказано ранее, SVG основан на структуре **XML**. Это может быть потенциальной уязвимостью

Попробуем загрузить SVG, содержащий DTD, в котором определяется внешняя сущность **&xxe**, ссылающаяся на системный файл **/proc/meminfo**, показывающий информацию об использовании оперативной памяти
Содержание SVG выглядит следующим образом:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
  <!ENTITY xxe SYSTEM "file:///proc/meminfo">
]>
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 600" width="800" height="600">
  <rect width="800" height="600" fill="#0f172a"/>
  <text x="10" y="30" font-family="monospace" font-size="12" fill="#10b981">&xxe;</text>
</svg>
```

Для удобства просмотрим ответ через **Burp Suite. **Отправим в **repeater** данный запрос

![](../../_images/2916716a405b.webp)

Далее, при отправке запроса уже из **repeater**, Необходимо нажать **follow redirection**, чтобы перейти к дальнейшему ответу веб-приложения.

![](../../_images/28c86d2a5127.webp)

В результате увидим информацию о cpu в ответе:

![](../../_images/042fb4461bd2.webp)
