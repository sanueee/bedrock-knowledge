###### Что такое Bash

**Bash** - это командная оболочка и язык сценариев. Оболочка принимает команды из терминала, разбирает их и запускает нужные программы. Bash можно использовать двумя способами:

1. **Интерактивно** - вводить команды вручную в терминале.
2. **В виде скриптов** - сохранять последовательность команд в файл и запускать этот файл как программу.

###### Что такое Bash-скрипт

> **Bash-скрипт** - это текстовый файл с командами, которые Bash выполняет сверху вниз.

Скрипты используют для автоматизации повторяющихся действий. Например, вместо нескольких ручных команд для проверки лог-файла можно один раз написать скрипт и запускать его с нужными аргументами.

> Обычно Bash-скрипты имеют расширение **.sh**. Само расширение не делает файл исполняемым: для запуска через **./имя-файла** важны права доступа и строка с интерпретатором в начале файла.

###### Подготовка рабочей директории

Перед началом создадим отдельную директорию. В ней будут лежать скрипт, тестовые данные и созданные отчёты.

```
mkdir -p ~/bash-lab
cd ~/bash-lab
pwd
```

Команда `mkdir -p` создаёт директорию **~/bash-lab**, а **cd** переходит в неё. Команда `pwd` выводит текущую директорию и помогает убедиться, что работа идёт в нужном месте.

> Все дальнейшие команды предполагают, что мы находимся в директории **~/bash-lab**.

###### Подготовка тестового лог-файла

Создадим файл, с которым будет работать скрипт. Для этого используем команду `cat` и перенаправление ввода.

В команде используются два перенаправления:

- **<< 'EOF'** указывает Bash считать многострочный текст до строки, содержащей только **EOF**, и передать этот текст команде **cat**;
- **> sample.log** перенаправляет вывод **cat** в файл **sample.log**.

В результате Bash считывает введённые строки до маркера **EOF**, команда **cat** выводит их, а перенаправление **>** записывает этот вывод в файл. Выполним команду и введём строки лога. После каждой строки нажимаем Enter. Когда все строки будут введены, укажем **EOF** на отдельной строке и снова нажмём Enter.

```
cat > sample.log << 'EOF'
2026-05-25 10:00:01 INFO user alice logged in from 192.168.1.10
2026-05-25 10:01:15 ERROR failed password for bob from 10.0.0.5
2026-05-25 10:02:41 INFO service nginx restarted
2026-05-25 10:04:02 WARN suspicious request from 172.16.4.20
2026-05-25 10:05:33 ERROR connection timeout from 10.0.0.5
2026-05-25 10:06:11 INFO backup completed
EOF
```

> Во время ввода Bash может выводить приглашение **>**. Оно означает, что оболочка ожидает продолжение многострочного блока. После ввода строки **EOF** файл **sample.log** будет создан.

**EOF** не является специальной командой. Это маркер окончания блока. Его можно заменить другим словом, например **END**, **TEXT** или **LOG**. Название **EOF** расшифровывается как **End Of File**, то есть "конец файла". Завершающий маркер должен находиться на отдельной строке без пробелов до или после слова. Иначе Bash не распознает его и продолжит ждать ввод. Кавычки в конструкции **<< 'EOF'** означают, что Bash передаст текст внутри блока буквально. Например, если в тексте встретится имя переменной с символом **$**, Bash не будет подставлять её значение. Если **sample.log** уже существует, перенаправление **>** полностью перезапишет его содержимое.

> Такой способ передачи многострочного текста команде называется **here document**, или **heredoc**.

###### Текстовые редакторы

Прежде чем писать скрипт, разберёмся, чем редактировать текстовые файлы. Длинные команды и скрипты вводить одной строкой или собирать через **heredoc** весьма неудобно, поэтому для работы с кодом и конфигурационными файлами используют текстовые редакторы.

В текстовой консоли или обычной удалённой SSH-сессии мы не можем воспользоваться привычными редакторами, например тот же **VSCode**. В таких случаях используют консольные редакторы, которые запускаются прямо в терминале. Для начала достаточно знать три варианта: `vim`, `nano` и `micro`.

**vim** - один из самых известных консольных редакторов. Он развился из редактора **vi**, связанного с UNIX-системами, и часто уже установлен в Linux-дистрибутивах.

Главная особенность **vim** - режимы работы. В одном режиме пользователь перемещается по файлу и выполняет команды, в другом вводит текст. Поэтому новичкам этот редактор может показаться непривычным.

> Если случайно открыли **vim** и не знаете, как выйти, нажмите **Escape**, введите **:q** и нажмите **Enter**.

**nano** - простой консольный редактор с более понятным управлением. Он тоже часто уже установлен в Linux-дистрибутивах. В этом кейсе будем использовать именно **nano**.

Основные сочетания клавиш, которые нам пригодятся:

- **^O** - сохранить файл;
- **^X** - выйти из редактора

> Символ **^** обозначает клавишу **Ctrl**. Например, **^O** означает **Ctrl + O**. При сохранении Nano предложит подтвердить имя файла: для этого нажмём **Enter**.

**micro** - более современный консольный редактор. В нём используются привычные сочетания клавиш, например **Ctrl + S** для сохранения и **Ctrl + Q** для выхода.

Однако **micro** обычно не установлен по умолчанию. Чтобы им воспользоваться, нужно его скачать.

> О работе с пакетными менеджерами поговорим в следующих кейсах

###### Версия 1. Минимальный скрипт

Создадим файл скрипта: `nano bash-lab.sh`

Напишем самый примитивный код:

```
#!/bin/bash
# Shell-script v1

echo "my first shell script"
```

Разберём строки:

- **#!/bin/bash** - шебанг
- **# Shell-script v1** - комментарий
- **echo "my first shell script"** - команда, которая выводит текст в терминал

**Что такое шебанг**

Первая строка **#!/bin/bash** называется **shebang**. Она нужна, когда скрипт запускается как отдельная программа: **./bash-lab.sh** Операционная система открывает файл, читает первую строку и понимает, что содержимое файла нужно передать интерпретатору **/bin/bash**. Но мы можем запустить скрипт через Bash явно: `bash bash-lab.sh` Эта команда работает без дополнительных прав, потому что программу Bash мы указали самостоятельно.

Раз мы поставили шебанг, попробуем запустить скрипт как исполняемый файл. Скорее всего у нас это не получится: система ответит "Permission denied". Всё правильно, в целях безопасности мы должны должны сами разрешить выполнение скрипта.

Сделаем скрипт исполняемым с помощью команды: `chmod +x bash-lab.sh`

Разберём команду:

- **chmod** изменяет права доступа файла
- **+x** добавляет право на исполнение; (**x** означает "executable")
- **bash-lab.sh** - файл, для которого меняются права

После этого запустим скрипт как программу: **./bash-lab.sh** Часть **./** означает "файл из текущей директории". Для такого запуска одновременно нужны шебанг и право на исполнение.

> Подробнее о правах доступа поговорим в следующих кейсах. Пока достаточно помнить: право **x** разрешает запускать файл как программу.

###### Версия 2. Добавляем переменные

Пока скрипт просто выводит заранее заданную строку. Добавим переменные, чтобы хранить в них значения, которые понадобятся программе.

Откроем файл **bash-lab.sh** в редакторе **nano** и полностью заменим его содержимое следующим кодом:

```
#!/bin/bash
# Shell-script v2

script_name="bash-lab"
version="0.2"
default_file="sample.log"

echo "$script_name version $version"
echo "Default file: $default_file"
```

С переменными мы уже знакомились в кейсе 1.1. Теперь пришло время с ними поработать.

Переменная - это имя, за которым хранится значение. В переменной можно сохранить текст, число, имя файла или путь к нему. В нашем коде переменная **default_file** хранит имя лог-файла, а **version** - номер версии скрипта. В Bash переменная создаётся так: **name="value"**. Вокруг знака **=** не должно быть пробелов.

Так задавать переменную неправильно: **name = "value"**. Почему? Bash просто не распознает присваивание из-за пробелов. Он попытается запустить команду **name** и передать ей аргументы **=** и **value**. Если такой команды нет, появится ошибка вида **name: command not found**.

Чтобы получить значение переменной, перед её именем ставят символ **$**. Например, в строке: `echo "$script_name version $version"` Bash подставляет значения переменных **script_name** и **version** внутрь текста, который выводит команда **echo**.

Запустим обновлённый скрипт: `./bash-lab.sh`

![](../../_images/0478d8df173b.webp)

###### Версия 3. Принимаем аргументы командной строки

Скрипт становится полезнее, если ему можно передавать данные при запуске.

Например: **./bash-lab.sh sample.log**. Здесь **sample.log** - это аргумент командной строки. Скрипт получает его при запуске и сможет использовать как имя файла.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v3

script_name="bash-lab"
version="0.3"

target_file="$1"

echo "$script_name version $version"
echo "Script name: $0"
echo "Arguments count: $#"
echo "Target file: $target_file"
```

В этой версии используются специальные параметры Bash:

- **$0** - имя или путь, с помощью которого был запущен скрипт
- **$1** - первый аргумент скрипта
- **$#** - количество переданных аргументов

> Это не весь список параметров, но пока остановимся на этом

Запустим скрипт с именем файла: `./bash-lab.sh sample.log`

![](../../_images/1ed15b3fbef9.webp)

В этом случае:

- **$0** содержит **./bash-lab.sh**
- **$1** содержит **sample.log**
- **$#** равно **1**

Строка: **target_file="$1"** сохраняет первый аргумент в переменную **target_file**. Теперь запустим скрипт без аргументов: **./bash-lab.sh**

![](../../_images/788a93c59971.webp)

Скрипт запустится, но как мы видим, переменная **target_file** окажется пустой. В следующей версии добавим проверку, чтобы пользователь сразу видел, что имя файла не передано.

###### Версия 4. Проверяем аргументы через if

Добавим проверку: если имя файла не передано, скрипт покажет подсказку и завершит работу.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v4

script_name="bash-lab"
version="0.4"

target_file="$1"

if [ "$#" -eq 0 ]; then
    echo "Usage: $0 <log-file>"
    exit 1
fi

echo "$script_name version $version"
echo "Target file: $target_file"
```

**Как работает if**

Конструкция **if** позволяет выполнять команды только при соблюдении условия.

Общий вид:

```
if команда_проверки; then
    команды_если_проверка_успешна
fi
```

Если при невыполнении условия нужно выполнить другой набор команд, используют блок **else**:

```
if команда_проверки; then
    команды_если_проверка_успешна
else
    команды_если_проверка_неуспешна
fi
```

В нашем скрипте блок **else** не нужен. Если пользователь не передал имя файла, скрипт выводит подсказку и завершает работу.

**Что проверяет скрипт**

Рассмотрим условие: **[ "$#" -eq 0 ]**. **$#** содержит количество аргументов, с которыми был запущен скрипт.

При запуске без аргументов: **./bash-lab.sh** значение **$#** равно **0**. Оператор **-eq** означает "равно" при сравнении целых чисел. Поэтому условие читается так: "если количество переданных аргументов равно нулю". Если условие выполняется, скрипт выводит подсказку и завершает работу.

![](../../_images/1d5aa2c2ad2d.webp)

**Проверки в квадратных скобках**

Конструкция **[ ... ]** используется для проверки условий. Пробелы после `[`** **и перед `]` обязательны, потому что **[** получает остальные части записи как аргументы.

Правильно будет так: **[ "$#" -eq 0 ]**. Но в таком случае: **["$#" -eq 0]**, Bash не сможет правильно разделить команду проверки и её аргументы.

Основные операторы сравнения целых чисел:

- **-eq** - равно
- **-ne** - не равно
- **-gt** - больше
- **-lt** - меньше
- **-ge** - больше или равно
- **-le** - меньше или равно

**Завершение работы скрипта**

Внутри условия выполняется команда: **exit 1**

Она немедленно завершает работу скрипта. Число после **exit** называется кодом завершения.

По соглашению:

- **0** означает успешное завершение команды;
- любое другое число обычно означает, что команда завершилась с ошибкой или не смогла выполнить ожидаемое действие.

В нашем случае скрипт не получил обязательный аргумент, поэтому завершается с кодом **1**.

> Техническая деталь: Bash проверяет условие **if** по коду завершения команды проверки. Конструкция **[ "$#" -eq 0 ]** возвращает код **0**, если условие выполнено, и ненулевой код, если нет. Пока достаточно запомнить: Bash выполняет блок **then**, когда проверка успешна.

Проверим оба варианта запуска:

![](../../_images/9f718cc09223.webp)

На этом этапе скрипт проверяет только отсутствие аргументов. Если передать лишний аргумент: **./bash-lab.sh sample.log extra**, скрипт продолжит работу и использует только первый аргумент: **sample.log**.

###### Версия 5. Проверяем существование файла

Теперь скрипт знает, передано ли имя файла. Однако пользователь может указать файл, которого не существует: **./bash-lab.sh missing.log**. Добавим проверку существования файла.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v5

script_name="bash-lab"
version="0.5"

target_file="$1"

if [ "$#" -eq 0 ]; then
    echo "Usage: $0 <log-file>"
    exit 1
fi

if [ ! -f "$target_file" ]; then
    echo "Error: file not found: $target_file"
    exit 1
fi

echo "$script_name version $version"
echo "Target file: $target_file"
echo "File exists"
```

Здесь появилась ещё одна проверка: **[ ! -f "$target_file" ]**

Оператор **-f** проверяет, существует ли по указанному пути обычный файл.

> Обычный файл - это файл с данными, а не директория.

Символ **!** означает отрицание. Поэтому условие читается так: "если по указанному пути нет обычного файла".

Полезные проверки файлов:

- **-f file** - существует обычный файл
- **-d dir** - существует директория
- **-e path** - путь существует
- **-r file** - файл доступен для чтения
- **-w file** - файл доступен для записи
- **-x file** - файл исполняемый
- **! условие** - отрицание условия

###### Версия 6. Получаем информацию о файле

Теперь скрипт работает только с существующими файлами. Получим из файла первую полезную информацию - количество строк.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v6

script_name="bash-lab"
version="0.6"

target_file="$1"

if [ "$#" -eq 0 ]; then
    echo "Usage: $0 <log-file>"
    exit 1
fi

if [ ! -f "$target_file" ]; then
    echo "Error: file not found: $target_file"
    exit 1
fi
```

###### Версия 9. Реализуем режим preview через while

Режим **preview** должен выводить первые пять строк файла. Эту задачу можно было бы решить одной командой `head -n 5`, но здесь специально используем цикл **while**: так мы разберём чтение файла построчно, счётчик и досрочное завершение цикла.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v9

script_name="bash-lab"
version="0.9"

mode="$1"
target_file="$2"

if [ "$#" -eq 0 ]; then
    echo "Usage: $0 <mode> <log-file>"
    echo "Modes: info, preview, scan, help"
    exit 1
fi

case "$mode" in
    help)
        echo "Usage: $0 <mode> <log-file>"
        echo "Modes: info, preview, scan, help"
        ;;
    info)
        if [ -z "$target_file" ]; then
            echo "Error: log file is required for mode: $mode"
            exit 1
        fi

        if [ ! -f "$target_file" ]; then
            echo "Error: file not found: $target_file"
            exit 1
        fi

        line_count=$(wc -l < "$target_file")
        echo "$script_name version $version"
        echo "Target file: $target_file"
        echo "Lines: $line_count"
        ;;
    preview)
        if [ -z "$target_file" ]; then
            echo "Error: log file is required for mode: $mode"
            exit 1
        fi

        if [ ! -f "$target_file" ]; then
            echo "Error: file not found: $target_file"
            exit 1
        fi

        preview_count=0

        while IFS= read -r line; do
            preview_count=$((preview_count + 1))
            echo "$preview_count: $line"

            if [ "$preview_count" -ge 5 ]; then
                break
            fi
        done < "$target_file"
        ;;
    scan)
        if [ -z "$target_file" ]; then
            echo "Error: log file is required for mode: $mode"
            exit 1
        fi

        if [ ! -f "$target_file" ]; then
            echo "Error: file not found: $target_file"
            exit 1
        fi

        echo "Scan mode is not implemented yet"
        ;;
    *)
        echo "Error: unknown mode: $mode"
        exit 1
        ;;
esac
```

**Как работает цикл while**

Общий вид цикла **while**:

```
while условие; do
    команды
done
```

Цикл сначала выполняет проверку. Если проверка завершается успешно, Bash выполняет команды внутри цикла. Затем Bash снова выполняет проверку. Цикл повторяется, пока проверка завершается успешно.

В режиме **preview** сначала создаём переменную-счётчик: **preview_count=0**. Счётчик нужен, чтобы нумеровать выводимые строки и остановиться после пятой строки. Значение **0** задаём до начала цикла: в этот момент ещё не прочитана ни одна строка. На каждой итерации счётчик будет увеличиваться на единицу.

Проверка цикла выглядит так: **IFS= read -r line** Эта строка состоит из нескольких частей:

1. **IFS=** - временно задаёт пустое значение переменной **IFS** только для команды **read**
2. **read** - читает одну строку из стандартного ввода
3. **-r** - запрещает считать обратную косую черту **\\** специальным символом
4. **line** - имя переменной, в которую будет записана прочитанная строка

**IFS** расшифровывается как *Internal Field Separator*, то есть "внутренний разделитель полей". В обычном режиме Bash использует пробел, табуляцию и перевод строки, когда разделяет полученный текст на части. Префикс **IFS=** временно отключает такое разделение для команды **read**. Благодаря этому строка из файла сохраняется без потери пробелов в начале и конце.

Пробелы в строке **IFS= read -r line** важны:

- **IFS=** - отдельное временное присваивание переменной
- **read** - команда, которую Bash должен выполнить
- **-r** и **line** - аргументы этой команды

Если написать **IFS=read**, Bash воспримет это как присваивание переменной **IFS** значения **read**, а команду чтения не запустит.

По умолчанию стандартный ввод - это текст, который вводят с клавиатуры. В нашем коде часть: **done < "$target_file"** перенаправляет содержимое файла на стандартный ввод всего цикла. Поэтому команда **read** получает строки не с клавиатуры, а из файла **$target_file**. Когда файл заканчивается, **read** больше не может прочитать строку, завершает проверку неуспешно, и цикл останавливается.

Внутри цикла выполняется строка: **preview_count=$((preview_count + 1))** Конструкция **$((...))** выполняет целочисленную арифметику. Здесь Bash берёт текущее значение **preview_count**, прибавляет к нему **1** и сохраняет новый результат обратно в ту же переменную.

После увеличения счётчика команда: `echo "$preview_count: $line"` выводит номер строки и её содержимое. Сначала счётчик становится равен **1**, поэтому первая строка будет показана с номером **1**. Затем выполняется проверка:

```
if [ "$preview_count" -ge 5 ]; then
    break
fi
```

Оператор **-ge** означает "больше или равно". Когда счётчик достигает **5**, команда **break** немедленно завершает ближайший цикл **while**. Поэтому шестая строка уже не будет прочитана и выведена. Запустим режим **preview**: `./bash-lab.sh preview sample.log`

![](../../_images/1737c715aeb5.webp)

###### Версия 10. Выносим повторяющийся код в функции

Сейчас у нас в скрипте есть несколько повторяющихся действий:

- Проверка, что файл существует
- Проверка, что файл не пустой

Эти действия повторяются в каждом кейсе, и чем чаще мы держим повторяющийся код, тем труднее его проверять и изменять. Вот бы все проверки хранились где-то в одном месте, и кейсы просто к ним обращались… Давайте так и сделаем: для этого созданы функции. Функция объединяет несколько команд под одним именем, после чего эти команды можно запускать одной строкой.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script v10

script_name="bash-lab"
version="0.10"

print_usage() {
    echo "Usage: $0 <mode> <log-file>"
    echo "Modes: info, preview, scan, help"
}

err() {
    echo "Error: $1"
    exit 1
}

require_log_file() {
    local mode="$1"
    local file="$2"

    if [ -z "$file" ]; then
        err "log file is required for mode: $mode"
    fi

    if [ ! -f "$file" ]; then
        err "file not found: $file"
    fi
}

show_info() {
    local file="$1"
    local line_count

    line_count=$(wc -l < "$file")

    echo "$script_name version $version"
    echo "Target file: $file"
    echo "Lines: $line_count"
}

show_preview() {
    local file="$1"
    local limit=5
    local counter=0
    local line

    while IFS= read -r line; do
        counter=$((counter + 1))
        echo "$counter: $line"

        if [ "$counter" -ge "$limit" ]; then
            break
        fi
    done < "$file"
}

mode="$1"
target_file="$2"

if [ "$#" -eq 0 ]; then
    print_usage
    exit 1
fi

case "$mode" in
    help)
        print_usage
        ;;
    info)
        require_log_file "$mode" "$target_file"
        show_info "$target_file"
        ;;
    preview)
        require_log_file "$mode" "$target_file"
        show_preview "$target_file"
        ;;
    scan)
        require_log_file "$mode" "$target_file"
        echo "Scan mode is not implemented yet"
        ;;
    *)
        err "unknown mode: $mode"
        ;;
esac
```

Сейчас код стал выглядеть куда более структурированным. Давайте разбираться, что поменялось.

**Как объявлять и вызывать функции**

Функцию объявляют так:

```
имя_функции() {
    команды
}
```

В строке **print_usage() {** объявляется функция с именем **print_usage**. Команды внутри фигурных скобок не выполняются в момент объявления. Они выполнятся только когда мы вызываем функцию. Чтобы вызвать функцию, указываем только её имя: **print_usage**. Скобки при вызове не ставим. Запись **print_usage()** нужна только при объявлении функции.

**Аргументы функций**

Функция получает аргументы так же, как скрипт. Однако внутри функции **$1**, **$2** и **$#** относятся к аргументам именно **этой функции,** а не к аргументам всего скрипта. Например, вызов: **require_log_file "$mode" "$target_file"** Перед вызовом функции Bash подставляет значения переменных **mode** и **target_file**.

Например, у нас в основной части скрипта (вне функций) указано:

```
mode="preview"
target_file="sample.log"
```

Bash фактически вызовет функцию так: **require_log_file "preview" "sample.log". **После этого внутри функции значения специальных параметров будут следующими:

- **$1** - preview
- **$2** - sample.log
- **$#** - 2

Переменные **mode** и **target_file** были созданы вне функций. Такие переменные будем называть **глобальными**: к ним можно обратиться из основной части скрипта и из функций. В начале функции **require_log_file** полученные аргументы сохраняются в переменные с понятными именами:

```
local mode="$1"
local file="$2"
```

После выполнения этих строк:

- локальная переменная **mode** содержит первый аргумент, на примере это **preview**;
- локальная переменная **file** содержит второй аргумент, на примере это **sample.log**.

Ключевое слово **local** создаёт переменную, которая существует **только внутри текущей функции.** После завершения функции она перестаёт быть доступна. Это помогает не смешивать переменные функции с переменными основной части скрипта. Например, переменная **file** внутри **require_log_file** не изменяет глобальную переменную **target_file**. Названия переменных могут быть разными, потому что функция получает нужное значение через свой аргумент **$2**.

**Функция обработки ошибок**

Функция **err** принимает текст ошибки первым аргументом: **err "file not found: $file"**. Внутри функции **$1** подставляется в строку **"Error: $1"**, после чего **exit 1** завершает скрипт. Благодаря этому для всех ошибок используется единый формат сообщений.

```
for mode_name in info preview scan help; do
```

```
#!/bin/bash
# Shell-script v12

script_name="bash-lab"
version="0.12"

print_usage() {
    echo "Usage: $0 <mode> <log-file>"
    echo
    echo "Modes:"

    for mode_name in info preview scan help; do
        echo "- $mode_name"
    done
}

err() {
    echo "Error: $1"
    exit 1
}

require_log_file() {
    local mode="$1"
    local file="$2"

    if [ -z "$file" ]; then
        err "log file is required for mode: $mode"
    fi

    if [ ! -f "$file" ]; then
        err "file not found: $file"
    fi
}

show_info() {
    local file="$1"
    local line_count

    line_count=$(wc -l < "$file")

    echo "$script_name version $version"
    echo "Target file: $file"
    echo "Lines: $line_count"
}

show_preview() {
    local file="$1"
    local limit=5
    local counter=0
    local line

    while IFS= read -r line; do
        counter=$((counter + 1))
        echo "$counter: $line"

        if [ "$counter" -ge "$limit" ]; then
            break
        fi
    done < "$file"
}

scan_ips() {
    local file="$1"

    grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' "$file"
}

mode="$1"
target_file="$2"

if [ "$#" -eq 0 ]; then
    print_usage
    exit 1
fi

case "$mode" in
    help)
        print_usage
        ;;
    info)
        require_log_file "$mode" "$target_file"
        show_info "$target_file"
        ;;
    preview)
        require_log_file "$mode" "$target_file"
        show_preview "$target_file"
        ;;
    scan)
        require_log_file "$mode" "$target_file"
        scan_ips "$target_file"
        ;;
    *)
        err "unknown mode: $mode"
        ;;
esac
```

**Как работает grep**

В функции **scan_ips** выполняется команда: `grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' "$file"`

Команда **grep** ищет текст, который соответствует указанному шаблону. В этой команде:

- **-E** включает расширенные регулярные выражения
- **-o** выводит только найденный фрагмент, а не всю строку лога
- текст в одинарных кавычках - **регулярное выражение**
- **$file** - путь к файлу, который передаётся в функцию

Флаги **-Eo** можно записать вместе, как в примере, или отдельно: **-E -o**. Результат будет одинаковым. Одинарные кавычки вокруг шаблона важны. Они передают выражение в **grep** без обработки со стороны Bash. В частности, Bash не будет пытаться интерпретировать символ **\** и другие специальные символы шаблона.

**Разбираем регулярное выражение**

Шаблон имеет вид: **([0-9]{1,3}\.){3}[0-9]{1,3}**

1. **[0-9]** - одна цифра от **0** до **9**
2. **{1,3}** - повторить предыдущий элемент от одного до трёх раз
3. **[0-9]{1,3}** - число длиной от одной до трёх цифр
4. **\.** - обычная точка
5. **(...)** - группа элементов
6. **(...){3}** - повторить группу три раза

Точка в регулярных выражениях имеет специальное значение: без экранирования она соответствует любому символу. Обратная косая черта `\` перед точкой отменяет это специальное значение, поэтому `\.` ищет именно символ точки.

Фрагмент **([0-9]{1,3}\.){3}** находит три части вида **<число.>**. Последний фрагмент **[0-9]{1,3}** находит четвёртую числовую часть без точки в конце. Вместе они образуют структуру **число.число.число.число**.

Этот шаблон не проверяет, является ли найденное значение корректным IPv4-адресом. Например, **999.999.999.999** соответствует шаблону, хотя в IPv4 каждый октет должен находиться в диапазоне от **0** до **255**. Поэтому в этом кейсе называем результаты **IP-подобными значениями**, а не валидными IP-адресами.

> Советуем разобраться подробнее о том, как работают регулярные выражения. С их помощью можно научиться находить более конкретные вещи. Для проверки написания регулярных выражений рекомендуем пользоваться сервисами для проверок, например [**данным сервисом**](https://regex101.com/)

Запустим режим **scan**: `./bash-lab.sh scan sample.log`

В этой версии одинаковые значения могут выводиться несколько раз. Например, **10.0.0.5** встречается в **sample.log** в двух строках и будет выведен дважды.

###### Версия 13. Убираем повторы через pipe

В лог-файле одно IP-подобное значение может встречаться много раз. Для отчёта полезнее получить список без повторов. Передадим вывод **grep** команде **sort -u**.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

###### Версия 14. Сохраняем отчёт в файлы

Скрипт уже выводит информацию в терминал. Добавим режим **report**, который сохранит результаты в файл **report.txt**. Сообщения об ошибках команд, которые выполняются при формировании отчёта, будут сохранены отдельно в **error.log**.

Полностью заменим содержимое **bash-lab.sh** на следующий код:

```
#!/bin/bash
# Shell-script: final version

script_name="bash-lab"
version="1.0"
report_file="report.txt"
error_file="error.log"

print_usage() {
    echo "Usage: $0 <mode> <log-file>"
    echo
    echo "Modes:"

    for mode_name in info preview scan report help; do
        echo "- $mode_name"
    done

    echo
    echo "Examples:"
    echo "  $0 info sample.log"
    echo "  $0 preview sample.log"
    echo "  $0 scan sample.log"
    echo "  $0 report sample.log"
}

err() {
    echo "Error: $1"
    exit 1
}

require_log_file() {
    local mode="$1"
    local file="$2"

    if [ -z "$file" ]; then
        err "log file is required for mode: $mode"
    fi

    if [ ! -f "$file" ]; then
        err "file not found: $file"
    fi

    if [ ! -r "$file" ]; then
        err "file is not readable: $file"
    fi
}

show_info() {
    local file="$1"
    local line_count

    line_count=$(wc -l < "$file")

    echo "$script_name version $version"
    echo "Target file: $file"
    echo "Lines: $line_count"
}

show_preview() {
    local file="$1"
    local limit=5
    local counter=0
    local line

    while IFS= read -r line; do
        counter=$((counter + 1))
        echo "$counter: $line"

        if [ "$counter" -ge "$limit" ]; then
            break
        fi
    done < "$file"
}

scan_ips() {
    local file="$1"

    grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' "$file" | sort -u
}

make_report() {
    local file="$1"

    {
        echo "Report for: $file"
        echo "Generated by: $script_name $version"
        echo "Lines: $(wc -l < "$file")"
        echo
        echo "Unique IP-like strings:"
        scan_ips "$file"
    } > "$report_file" 2> "$error_file"

    echo "Report saved to: $report_file"
    echo "Errors saved to: $error_file"
}

mode="$1"
target_file="$2"

if [ "$#" -eq 0 ]; then
    print_usage
    exit 1
fi

case "$mode" in
    help)
        print_usage
        ;;
    info)
        require_log_file "$mode" "$target_file"
        show_info "$target_file"
        ;;
    preview)
        require_log_file "$mode" "$target_file"
        show_preview "$target_file"
        ;;
    scan)
        require_log_file "$mode" "$target_file"
        scan_ips "$target_file"
        ;;
    report)
        require_log_file "$mode" "$target_file"
        make_report "$target_file"
        ;;
    *)
        err "unknown mode: $mode"
        ;;
esac
```

**Проверка читаемости файла**

В функции **require_log_file** появилась новая проверка:

```
if [ ! -r "$file" ]; then
    err "file is not readable: $file"
fi
```

Оператор **-r** проверяет, доступен ли файл для чтения текущему пользователю. Скрипт использует содержимое лог-файла в режимах **info**, **preview**, **scan** и **report**, поэтому существование файла само по себе недостаточно: у Bash должна быть возможность его прочитать.

**Стандартные потоки и перенаправление вывода**

Во время работы команда получает данные через стандартный ввод и выводит два вида сообщений:

| stdin | 0 | стандартный ввод: данные, которые команда получает на вход |
|---|---|---|
| stdout | 1 | обычный вывод команды |
| stderr | 2 | сообщения об ошибках |

В режиме **report** используется блок команд:

```
{
    команда1
    команда2
    команда3
} > report.txt 2> error.log
```

Фигурные скобки объединяют несколько команд в один блок. Перенаправления после закрывающей скобки применяются ко всему этому блоку:

- **> report.txt** записывает обычный вывод блока в файл **report.txt**
- **2> error.log** записывает поток ошибок блока в файл **error.log**

Символ **>** создаёт файл, если его ещё нет, или полностью перезаписывает существующий файл. Поэтому каждый новый запуск режима **report** формирует свежий отчёт.

В функции **make_report** вместо имён файлов напрямую используются переменные **$report_file** и **$error_file**. Их значения были заданы в начале скрипта:

```
report_file="report.txt"
error_file="error.log"
```

Сообщения расположены после закрывающей скобки. Поэтому они выводятся в терминал, а не попадают в **report.txt**:

```
echo "Report saved to: $report_file"
echo "Errors saved to: $error_file"
```
