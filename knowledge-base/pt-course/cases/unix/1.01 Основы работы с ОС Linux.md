##### Зачем нужен терминал

Терминал используется там, где нет графического интерфейса, что верно для подавляющего большинства Linux-серверов в мире, или где графический интерфейс не даёт нужной точности. Раньше, на заре развития вычислительных устройств, взаимодействие с ними происходило при помощи **телетайпов** - электромеханических печатных машинок, которые направляли набранный текст в устройство и печатали ответ на бумаге. Сейчас, с развитием технологий, в качестве таких машинок выступают программы - **эмуляторы терминала**, которые часто называют просто **терминалами**, хоть это и не совсем технически верно.

С терминалом можно столкнуться в разных ситуациях. Например, при подключении к серверу по протоколу SSH, открывается удалённая терминальная сессия: команды вводятся на вашем компьютере, а применяются на удалённом сервере. Также терминальный вход может быть доступен напрямую в системе через **tty** - текстовую консоль без графического интерфейса.

> В Linux можно быстро переключаться между **tty**. Когда вы запустите виртуальную машину, по умолчанию будет открыта сессия в **tty1**, но если вам нужно создать ещё одну сессию, выполните сочетание клавиш **Ctrl+Alt+&lt;F1-F6>**. Держать несколько сессий бывает удобно, когда нам нужно работать с несколькими окнами: как вкладки в браузере.

Примеры реальных задач, которые удобнее выполнить только через терминал:

- подключиться к удалённому серверу по SSH
- посмотреть содержимое конфигурационного файла
- создать директорию для резервной копии
- проверить значение переменной окружения
- записать вывод команды в файл

##### Что происходит после ввода команды

Когда пользователь вводит строку в терминале, внутри происходит несколько шагов.

![](../../_images/4d9496a2732e.webp)

Сразу определим понятия:

| Терминал | Интерфейс для текстового ввода и вывода. В современной рабочей среде это программа-эмулятор терминала | GNOME Terminal , Konsole , iTerm2 , Windows Terminal |
|---|---|---|
| Shell | Командная оболочка. Она читает введённую строку, интерпретирует её и запускает команды | bash , zsh , fish , sh |
| Команда | То, что пользователь просит выполнить. Это может быть отдельная программа, встроенная команда shell или ярлык оболочки (alias) | pwd , cd , ls , echo |
| Опция | Модификатор поведения команды. Обычно начинается с - или -- | ls -l , ls --all |
| Аргумент | Значение, с которым работает команда. Часто это путь к файлу или директории | cat file.txt , cd /etc |

> **Alias** - ярлык оболочки, который можно задать для того, чтобы не приходилось вручную вводить более длинную или сложную команду. К примеру, команду **systemctl suspend**, которая будет уводить систему в режим сна, можно вызывать командой **zzz**, задав alias с помощью **alias zzz="systemctl suspend"**. И если необходимо отменить alias, то существует обратная команда: **unalias**.

> Опции также принято называть "флагами"

Терминал сам по себе не решает, что означает команда. Он передаёт введённый текст оболочке. Командная оболочка разбирает строку, находит команду, запускает её и возвращает результат в терминал. Теперь разберёмся с командами и их анатомией.

##### Структура команды

Общий вид команды можно представить, как **команда [-опции] [аргументы]**. К примеру, команда `ls -la /var/log` означает:

- **ls** - команда для просмотра содержимого директории,
- **-la** - две короткие опции, записанные вместе,
- **/var/log** - путь, содержимое которого нужно показать (то есть аргумент).

> Короткие опции (одна буква) обычно пишутся с одним дефисом (**-l**), а длинные - с двумя (**--all**). Короткие опции зачастую можно объединять, вместо **ls -l -a** проще написать **ls -la**. Конкретный набор опций зависит от программы. Например, версию можно запросить через опции **-v** или **--version**, а сами опции можно узнать через **-h** или **--help**.

Порядок аргументов может быть критически важен. Например команда `cp source.txt backup.txt` означает, что мы копируем содержимое файла source.txt в backup.txt. Если мы перестановим аргументы (`cp backup.txt source.txt`), то смысл команды изменится: мы скопируем содержимое файла backup.txt в source.txt.

На этой виртуальной машине при выполнении команды `ls` директории подсвечиваются синим цветом, а обычные файлы остаются белым. Это помогает быстрее отличать одни объекты от других в выводе команды. Но такое бывает не всегда и не везде. Цветовая схема зависит от настроек командной оболочки и терминала, а где-то и вовсе может отсутствовать по умолчанию.

## Вопрос №2
*тип: open_answer, макс. баллов: 1, попыток: 3*

**Сколько** видимых объектов содержится внутри директории terminal-lab? Пример: **8**

**Разбор / ответ:**

Выполним команду `ls terminal-lab`, внутри домашней директории. Терминал выведет нам **6** объектов.

![](../../_images/61a56e04e56b.webp)

Частые варианты использования команды **ls**:

- **ls** - показать содержимое текущей директории;
- **ls -l** - подробный вывод: права, владелец, размер, дата изменения;
- **ls -la** - показать все файлы, включая скрытые;
- **ls -lh** - показать размеры в удобном для чтения виде;
- **ls /etc** - показать содержимое конкретной директории.

> Писать длинные названия файлов и директорий вручную бывает утомительно. Поэтому в оболочках есть вспомогательные средства (одно из них - **автодополнение**). Попробуйте написать предыдущую команду частично, допустим, `ls term` и нажать **TAB** на клавиатуре. Оболочка **bash**, в которой мы сейчас находимся, найдёт файлы или директории, начинающиеся с этих символов, и предложит заполнить за вас. Если вариант один, **bash** допишет сам. Если несколько, то покажет варианты. Автодополнение очень помогает как при вызове команд, так и при упоминании длинных файлов и без него в терминале будет трудно.

С помощью команды `cd` мы можем перейти между директориями.

![](../../_images/df22d7eaa951.webp)

Частые варианты использования **cd**:

- **cd /etc/nginx** - перейти по абсолютному пути
- **cd ..** - перейти на уровень выше
- **cd ~** - перейти в домашнюю директорию пользователя
- **cd -** - вернуться в предыдущую директорию
- **cd project/myapp** - перейти по относительному пути

Давайте разберём подробнее. Путь указывает, где находится файл или директория. Есть 2 типа путей - **абсолютные** и **относительные**:

| Абсолютный путь | Начинается от корня файловой системы / . Он не зависит от текущей директории, и всегда указывает на одно и то же место | /etc/nginx/nginx.conf |
|---|---|---|
| Относительный путь | Отсчитывается от текущей директории . Если текущая директория будет другой, тот же относительный путь может указывать уже на другое место или не работать | nginx/nginx.conf ./nginx/nginx.conf |

При работе с относительными путями используются специальные обозначения, которые помогают обращаться к текущей директории или к директории уровнем выше. Рассмотрим некоторые специальные обозначения.

**Точка** означает текущую директорию. К примеру, команда `ls .` покажет нам то же самое, что и просто команда **ls**

![](../../_images/d69952483f8d.webp)

**Две точки** означают директорию уровнем выше. Например, если мы находимся в директории **/home/user/project/myapp**, то выполнив команду **cd ..** мы окажемся в **/home/user/project**

> Точки важны для случаев, когда нам необходимо чётко указать оболочке или программе какой-то конкретный путь. С этим вы столкнётесь по ходу модудя.

**Домашняя директория через ~**

Символ **~** означает домашнюю директорию текущего пользователя. К примеру, если пользователь - **user**, то символ **~** будет указывать на **/home/user**.

##### Скрытые файлы

В UNIX-системах файлы и директории, имя которых начинается с точки, считаются **скрытыми**. Вспомним, когда мы выполняли команду **ls** в домашней директории, мы увидели только директорию **terminal-lab**. Однако если мы выполним команду `ls -a` или её эквивалент `ls --all`, то увидим скрытые файлы, например **.bashrc**, конфигурационный файл оболочки bash.

![](../../_images/6ad48d773c0e.webp)

> Скрытый файл не является каким-то защищённым файлом. Точка в начале имени только скрывает его из обычного вывода команды **ls**.

##### Справочник у команды

Команд бывает много, и аргументов у них ещё больше. Всё запомнить невозможно, и не сильно нужно, если знать, как посмотреть справку о конкретной команде. Выше мы уже упоминали про опцию **--help**:

```
ls --help
cp --help
rm --help
```

У некоторых команд краткая справка вызывается через опцию **-h**, но это не универсальное решение. В какой-то программе **-h** может означать вызов справки, а в какой-то означать совершенно другую опцию. Кроме краткой справки также можно посмотреть полное руководство через утилиту **man**

```
man ls
man cp
man rm
```

![](../../_images/97752017d004.webp)

> **--help** удобно использовать, когда нужно быстро вспомнить опцию. Утилита`man` полезна, когда нужно понять поведение команды подробнее.

##### Работа с файлами и директориями

В терминале базовые операции с файлами можно выполнить командами: `mkdir`, `touch`, `cp`, `mv`, `rm`. Это далеко не полный список команд, но пока такого набора нам хватит. Давайте создадим директорию **backup** в домашней директории.

> Чтобы быстро вернуться в домашнюю директорию, используем `cd ~`

Чтобы создать директорию **backup**, воспользуемся командой `mkdir backup`, и сразу выполним `ls`.

![](../../_images/a8c9e4fd182b.webp)

С помощью команды `mkdir -p project/myapp/logs` мы можем создать цепочку директорий. Это удобно в тех случаях, когда промежуточных директорий ещё не существует. А даже если они есть, то никакого конфликта не будет.

![](../../_images/20193864196a.webp)

После того, как мы создали директорию, давайте создадим файл. Мы это можем сделать, например, командой `touch readme.txt`

![](../../_images/f94207cedcde.webp)

> Если файла нет, то он будет создан пустым. Если файл есть, то **touch** обновит время его изменения.

После того, как мы создали файл, давайте его скопируем с помощью команды **cp** Команда cp работает так: **cp <источник> <назначение>** Первым аргументом указывается, **что копируем**, вторым - **куда копируем** или **под каким именем** сохранить копию. Например, скопируем наш созданный файл в директорию **terminal-lab** с помощью команды `cp readme.txt terminal-lab`

![](../../_images/abd70103efb3.webp)

Частые варианты использования **cp**, кроме описанного выше:

- `cp readme.txt backup.txt` - скопировать содержимое файла в другой файл с другим названием (Если файла нет, то он создастся)
- `cp readme.txt backup/readme.txt `- скопировать содержимое файла в файл, находящийся в другой директории
- `cp -r project/project_backup` - рекурсивно скопировать директорию со всем её содержимым

Но кроме копирования файлов мы также можем их перемещать с помощью **mv**, например:

- `mv report.txt documents/` - перенос файла в директорию
- `mv project/archive/project/` - перенос директории в другую директорию

Порядок аргументов такой же, как у **cp**: сначала источник, потом назначение. Также с помощью команды `mv` можно переименовывать файлы. Делается это просто: первым аргументом пишется файл который хотим переименовать, а вторым аргументом: какое новое имя ему присваиваем: `mv old.txt new.txt`

![](../../_images/7be91f39c499.webp)

Если файл или директорию можно создать, то их можно и удалить, к примеру с помощью команды `rm`

![](../../_images/ba1013438722.webp)

Для удаления директории с содержимым используется рекурсивный режим `rm -r test_dir/`

![](../../_images/389da47384ca.webp)

Также есть более осторожный режим:

- `rm -i file.txt`
- `rm -ri old_project/`

![](../../_images/a9ce6b8676d4.webp)

##### Как читать файлы

В терминале часто нужно открыть файл не для редактирования, а просто для просмотра. Для этого используются следующие утилиты:

- `cat`
- `less`
- `head`
- `tail`
- и другие

Утилита** cat** удобна для коротких файлов: небольших заметок, простых конфигураций или файлов с одним значением. Например, чтобы прочитать содержимое файла `readme.txt`, выполним команду `cat readme.txt`.

![](../../_images/a1ec8853661c.webp)

Команда выводит содержимое файла целиком в терминал. Для небольших файлов это удобно, но при работе с длинными логами вывод быстро уйдёт за пределы окна терминала. В таких случаях лучше использовать утилиту `less`. Например, откроем лог пакетного менеджера: `less /var/log/dpkg.log.1`

![](../../_images/f967fc34cb7f.webp)

Утилита `less` позволяет просматривать файл постранично и перемещаться по его содержимому. Основные действия внутри `less`:

- **стрелки клавиатуры **- перемещение по файлу;
- **/слово - **поиск по слову;
- **n** - следующий результат поиска;
- **q** - выход из утилиты.

##### Перенаправление вывода

Обычно команда выводит результат своей работы в терминал. Однако этот вывод можно записать в файл или передать на вход другой команде. Оператор **>** записывает вывод команды в файл. Например, команда **echo** выводит переданный ей текст, а оператор **>** перенаправляет этот вывод в файл: `echo "Hello" > file.txt`

![](../../_images/bd29c90a5d0f.webp)

Если файла **file.txt** не существует, он будет создан. Если файл уже существует, его содержимое будет заменено новым. Например, выполним команды:

```
echo "Hello" > file.txt
echo "Who am I" > file.txt
cat file.txt
```

![](../../_images/b7305c97635b.webp)

В файле останется только строка **Who am I?**, поскольку при повторном использовании оператор **>** перезаписал его содержимое. Чтобы не перезаписывать файл, а добавить данные в его конец, используется оператор **>>**

```
echo "Hello" > file.txt
echo "Who am I?" >> file.txt
cat file.txt
```

![](../../_images/eb8a31d42e8d.webp)

Оператор **>>** сохраняет существующее содержимое файла и добавляет новый вывод в его конец.

##### Передача вывода между командами

Оператор **|**, также называемый **pipe** или конвейером, передаёт вывод одной команды на вход другой.

Для поиска строк, содержащих определённый текст, используется утилита **grep**. Она может самостоятельно прочитать указанный файл: `grep "install" /var/log/dpkg.log.1`. Эта команда выведет из файла **/var/log/dpkg.log.1** только строки, содержащие текст **install**.

Утилита **grep** также может получать данные через конвейер: `cat /var/log/dpkg.log.1 | grep "install"`.

Команда выполняется следующим образом:

- `cat /var/log/dpkg.log.1` выводит содержимое файла;
- оператор **|** передаёт этот вывод команде **grep**;
- `grep "install"` оставляет только строки, содержащие текст **install**.

В данном случае обе рассмотренные команды дадут одинаковый результат. Вывод **grep**, как и вывод другой команды, можно передать дальше по конвейеру. Например, утилита **wc** с параметром **-l** подсчитывает количество полученных строк: `grep "INFO" /var/log/dpkg.log.1 | wc -l`. Сначала **grep** отбирает строки, содержащие текст **INFO**, после чего оператор **|** передаёт их утилите **wc**, которая подсчитывает количество строк.

##### Переменные

Иногда приложению нужно передать настройки или временные значения: режим запуска, адрес базы данных, порт, имя пользователя и другие параметры. Для этого в shell используются переменные. Переменной называют имя, за которым хранится значение. Shell-переменная создаётся так: **MYVAR=hello**

> **Важно!** Вокруг символа **=** не должно быть пробелов

Прочитать значение переменной можно используя символ **$**

![](../../_images/d68d162331c5.webp)

Такая переменная доступна в текущей shell-сессии, но не передаётся автоматически программам, которые из неё запускаются. Ниже пример команды `bash -c 'echo "$MYVAR"'`

![](../../_images/c124eb7c21b7.webp)

Новый процесс **bash** не получит **MYVAR**, потому что переменная не экспортирована в окружение. Чтобы переменную увидели дочерние процессы, её нужно **экспортировать**, к примеру с помощью команды `export MYVAR=hello`

![](../../_images/5b2f3c183a1c.webp)

Удалить переменную можно командой `unset MYVAR`

![](../../_images/085adb931a62.webp)

> Программа, которую вы запускаете из **shell** получает только переменные окружения. Так ей можно передать настройки, например режим работы, порт или адрес сервера. Обычная shell-переменная остаётся доступной только в текущей оболочке.

Посмотреть активные переменные окружения можно командой `env`

![](../../_images/1fd6c505d1d2.webp)

Основные переменные окружения:

- **HOME** - домашняя директория пользователя
- **PATH** - список директорий, где shell ищет исполняемые файлы
- **USER** - имя текущего пользователя
- **SHELL** - путь к текущей shell
- **PWD** - текущая рабочая директория

##### .env

Переменные можно задавать вручную, если их немного или если приложение нужно запустить один раз. Но если программу с одними и теми же настройками нужно запускать часто, удобнее хранить эти настройки в отдельном файле. Для этого часто используют файл **.env**. Содержимое такого файла может выглядеть так:

```
APP_ENV=development
DB_HOST=localhost
DB_PORT=5432
```

> **.env** - это не системный механизм Linux. Система не сканирует директории в поисках этого файла и не загружает его в текущую сессию автоматически.

Чтобы значения из **.env** начали использоваться, файл должен прочитать конкретный инструмент или приложение. Подробнее с **.env**-файлами вы познакомитесь позже.
