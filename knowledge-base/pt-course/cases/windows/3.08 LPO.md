# Guided Case 3.8 — LPO

> [!info] Путь в курсе
> Глава 3: Windows-системы и их безопасность / Часть 1: Host-Base Windows / Локальные политики
>
> **Теория:** [1.17 Локальные политики](../../windows/1%20Host-Base%20Windows/1.17%20Локальные%20политики.md)

## Стенд / введение

Для выполнения данного кейса необходимо скачать [**OVA-образ**](https://storage.ptsecurity.com/seafhttp/f/cc138432c0754faab4d5/?op=view) виртуальной машины, заготовленной Positive Technologies. У данной виртуальной машины должен быть 1 сетевой адаптер VirtualBox в режиме **bridge**

К виртуальной машине можно подключиться с помощью графического интерфейса VirtualBox со следующими учётными данными:

**Windows VM:**

- Login - **admin**
   
   - Password - **admin**
- Login - **student**
   
   - Password - **student**

**Цель практики:** Работа с локальной политикой безопасности

Зайдем в **LPO**. Нажимаем **WIN + R** и вводим **secpol.msc**

![](../../_images/2933951726e1.jpg)

#### Политика паролей

Начнём с самого базового уровня защиты - требований к паролю. Перейдем в **Account Policies → Password Policy**

![](../../_images/0a699a4a3d9f.webp)

Настроим следующие значения(дважды кликаем по политике и вписываем значение):

- **Minimum password length** - **12**
- **Enforce password history** - **5**
- **Maximum password age** - **60**
- **Minimum password age** - **1**

![](../../_images/136b58213590.webp)

#### Политика блокировки учётной записи

Сложный пароль не защищает от простого перебора, если порог блокировки слишком высок. Проверим текущее значение по умолчанию. Переходим в **Account Policies → Account Lockout Policy** и смотрим **Account lockout threshold** - по умолчанию оно равно **10**.

![](../../_images/2d6ff1e7c8c5.jpg)

Убедимся в этом на практике, не выходя из admin. Открываем **cmd** и пробуем аутентифицироваться как student прямо из командной строки: `runas /user:student cmd`. Каждый раз система запрашивает пароль student - три раза подряд вводим неверный

![](../../_images/ecfc05ddcfde.jpg)

Теперь понизим порог блокировки. Дважды кликаем по **Account lockout threshold**. Ставим значение **3**

![](../../_images/fa6f7a811654.webp)

Проверим ещё раз, что настройка реально работает: `runas /user:student cmd`, три раза подряд вводим неверный пароль

![](../../_images/815d86c09e5b.webp)

> После третьей попытки runas возвращает другую ошибку - учётная запись заблокирована, вместо привычной "неверный пароль"

Проверим статус учётной записи: `net user student`

![](../../_images/52c73168ada7.webp)

Учетная запись заблокирована. Разблокируем ее - `net user student /active:yes`

![](../../_images/f642c861180d.jpg)

#### Политика аудита

Настроенные политики паролей и блокировки работают "молча" - без аудита мы не узнаем, что кто-то пытался подобрать пароль или создал нового пользователя. Проверим, включён ли аудит по умолчанию. Переходим в **Local Policies → Audit Policy** и смотрим текущие значения - **Audit account logon events**, **Audit account management** стоят **No auditing**

![](../../_images/c0d9b317ffd1.jpg)

Убедимся, что без аудита события действительно не логируются. Ранее мы заходили под student с неверным паролем. Открываем **Event Viewer**, переходим в **Windows Logs → Security** и ищем событие с **Event ID 4625**(неудачный вход) - его там нет

![](../../_images/0f709a7b38ed.webp)

Теперь включим логирование:

- Дважды кликаем по **Audit account management.** Отмечаем чекбоксы **Success** и **Failure**
- Дважды кликаем по **Audit account logon events.** Отмечаем чекбоксы **Success** и **Failure**

![](../../_images/cc7656983dd1.webp)

Повторяем неудачный вход тем же способом: `runas /user:student cmd` с неверным паролем

![](../../_images/9dc41024f9d7.webp)

Теперь событие с **Event ID 4625** (An account failed to log on) появляется

![](../../_images/7e7819f36302.webp)

Теперь создадим и удалим тестового пользователя, чтобы проверить аудит управления учётными записями:

- Создаём пользователя: `net user audittest Password12345 /add`
- Удаляем пользователя : `net user audittest /delete`

![](../../_images/8e726b03cbbf.webp)

В **Event Viewer** находим события с **Event ID 4720** (A user account was created) и **4726** (A user account was deleted)

![](../../_images/dcce8c70e5c7.webp)

#### Политика брандмауэра

Аудит и права пользователя контролируют, что происходит и что разрешено внутри системы, но не ограничивают сетевое взаимодействие с ней. Брандмауэр - следующий рубеж, который определяет, какой трафик может достигать компьютера извне. В левой панели **secpol.msc** находим узел **Windows Defender Firewall with Advanced Security** и раскрываем его

![](../../_images/5043888814e7.jpg)

Кликаем по корневому узлу **Windows Defender Firewall with Advanced Security on Local Computer**. В центральной панели, в блоке **Overview**, смотрим состояние каждого профиля (**Domain, Private, Public**) - включён ли брандмауэр, и какое действие задано по умолчанию для входящих и исходящих соединений

![](../../_images/c07f06f44c3b.webp)

Если хотя бы для одного профиля брандмауэр выключен, нажимаем на ссылку **Windows Defender Firewall Properties**. На вкладке нужного профиля выставляем **Firewall state: On (recommended)** и повторяем для остальных вкладок (Domain Profile, Private Profile, Public Profile). Нажимаем **OK**

![](../../_images/6e4a0a89a658.webp)

Проверим доступность внешнего сайта до включения ограничений. Открываем браузер и заходим на **example.com** - это официальный тестовый домен IANA с единственным статичным IP-адресом, удобный для демонстрации. Страница загружается

![](../../_images/d30c823d39a5.webp)

Узнаём IP-адрес домена: `nslookup example.com`. Команда возвращает несколько адресов (обычно два IPv4 и два IPv6) - для правила потребуются все, иначе браузер может подключиться по адресу, оставшемуся незаблокированным

![](../../_images/738d8cabf69b.webp)

Создадим правило, блокирующее исходящие соединения к этим адресам, чтобы убедиться, что правила брандмауэра реально влияют на доступность внешних ресурсов. В левой панели кликаем правой кнопкой по **Outbound Rules** и выбираем **New Rule**

![](../../_images/093864008890.webp)

В мастере создания правила отмечаем тип **Custom** и нажимаем **Next**

![](../../_images/fc423418d686.webp)

На шаге **Protocol type** выбираем из выпадающего списка **TCP**, в поле **Remote port** указываем **80**, **443 **и нажимаем **Next**

![](../../_images/360292f767e8.webp)

На шаге **Scope** в блоке **Which remote IP addresses does this rule apply to** выбираем **These IP addresses**, нажимаем **Add** и по очереди вводим каждый из адресов, полученных через **nslookup** (все IPv4 и IPv6 из списка). Нажимаем **Next**

![](../../_images/5e9f327a55df.webp)

На шаге **Action** отмечаем **Block the connection** и нажимаем **Next**

![](../../_images/9660819b2518.webp)

На шаге **Profile** оставляем отмеченными все три профиля (**Domain, Private, Public**) и нажимаем **Next**

![](../../_images/f77f471d5263.webp)

Вводим имя правила, **Block example.com**, и нажимаем **Finish**

![](../../_images/bd96fa6c2755.webp)

Обновляем страницу браузера (**Ctrl+F5**) - **example.com** больше не открывается

![](../../_images/fd8aa98fc674.webp)

> Брандмауэр работает на уровне сетевого трафика, а не учётных записей или процессов - этим он дополняет, а не заменяет, политики паролей, блокировки, аудита и прав пользователя, рассмотренные выше.

#### Назначение прав пользователя

Аудит показывает, что произошло, но не мешает произойти. Права пользователя определяют, что именно кому разрешено делать на уровне системы - это следующий рубеж защиты. Переходим в **Local Policies → User Rights Assignment**

![](../../_images/8d3b071dc32f.jpg)

Посмотрим, как можно точечно запретить вход конкретному пользователю, не отключая учётную запись целиком. Находим политику **Deny log on locally.** Добавляем пользователя student

![](../../_images/7fec1867513b.webp)

Проверим: `runas /user:student cmd` с верным паролем. Теперь система отклоняет вход с сообщением о запрете входа этим способом

![](../../_images/2ce97a186735.webp)
