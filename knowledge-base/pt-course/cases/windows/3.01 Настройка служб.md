### Создание и настройка службы

Прежде чем работать со службами из командной строки, познакомимся с графической оснасткой управления службами. Это основной визуальный инструмент администратора: через него удобно осмотреть состояние служб, разобраться в их параметрах и выполнить базовые операции.

Откройте оснастку: нажмём **Win + R**, введём **services.msc** и нажмём **OK**

![](../../_images/d503cae9c973.jpg)

Либо нажмите **Win**, введите **Services** и откройте приложение **Services**

![](../../_images/c10f261edb8d.webp)

Откроется консоль **Services** со списком всех служб системы. Колонки списка:

![](../../_images/dd3bc74525ad.jpg)
- **Name** - отображаемое имя службы (**DisplayName**, а не внутреннее имя)
- **Description** - текстовое описание назначения службы
- **Status** - текущее состояние: **Running** (работает), пусто (остановлена), **Paused** (приостановлена)
- **Startup Type** - тип запуска: **Automatic**, **Automatic (Delayed Start)**, **Manual**, **Disabled**
- **Log On As** - учётная запись службы (**Local System**, **Local Service**, **Network Service** или доменная/локальная учётная запись)

Базовые операции над службой выполняются правым кликом по ней или через взаимодействие с GUI кнопками: **Start**, **Stop**, **Pause**, **Resume**, **Restart**.

![](../../_images/7e5ed0352184.jpg)

Чтобы посмотреть и изменить параметры, выберем **Properties** - откроется окно с четырьмя вкладками:

![](../../_images/ee56377c2879.jpg)

Вкладка **General** - внутреннее имя (**Service name**), отображаемое имя (**Display name**), описание, путь к исполняемому файлу (**Path to executable**), список **Startup type** и кнопки управления состоянием

![](../../_images/a8ff486d450c.jpg)

Вкладка **Log On** - учётная запись службы: **Local System account** либо **This account** с указанием конкретной учётной записи (например, **NT AUTHORITY\LocalService**). Именно здесь в GUI выполняется понижение привилегий

![](../../_images/3342ce5e74a5.jpg)

Вкладка **Recovery** - реакция на сбой (**Restart the Service**, **Run a Program**, **Restart the Computer**)

![](../../_images/6dd003235bd8.jpg)

Вкладка **Dependencies** - службы, от которых зависит данная, и зависящие от неё

![](../../_images/7331e0624ce0.jpg)

Важное ограничение: через **services.msc создать новую службу нельзя** - в GUI нет такой функции. Графическая консоль позволяет только управлять существующими службами и менять их параметры. Создание выполняется командой (**sc.exe** или **New-Service**), после чего служба появляется в списке (обновим его клавишей **F5**).

Именно поэтому основное задание выполняется через **PowerShell** и **sc.exe**: это основной рабочий инструмент администратора, он покрывает весь жизненный цикл службы, детерминирован и пригоден для автоматизации и проверки чекером. GUI оставляем для визуального контроля - все следующие шаги выполняются из командной строки.

Нажмём **Win**, введём в поиск **Windows PowerShell**, выберем запуск от имени Администратора

![](../../_images/dcf52215ffdc.webp)

В открывшемся терминале создадим рабочий каталог и вложенный каталог с пробелом в имени, чтобы воспроизвести типичную ошибку установщика - не процитированный путь: `New-Item -ItemType Directory -Path 'C:\Lab\Lab Audit Agent' -Force`

![](../../_images/46d6fb146993.webp)

Поместим туда скачанный файл **agent.exe** - это легитимный исполняемый файл службы. Предполагается, что мы сохранили его в каталог загрузок: `Copy-Item 'C:\Users\admin\Downloads\agent.exe' 'C:\Lab\Lab Audit Agent\agent.exe'`

Теперь зарегистрируйте службу через **sc.exe** с **не процитированным** путём, содержащим пробел, под учётной записью **LocalSystem**: `sc.exe --% create LabAuditAgent binPath= "C:\Lab\Lab Audit Agent\agent.exe" start= demand obj= LocalSystem`

Должно появиться [SC] CreateService SUCCESS.

![](../../_images/bfc6a9cdc500.webp)

Разбор синтаксиса **sc.exe**:

- **--%** - stop-parsing символ **PowerShell**: он велит **PowerShell** передать остаток строки внешней программе дословно. Без него **Windows PowerShell** искажает двойные кавычки в аргументах нативных программ, и **sc.exe** вместо создания службы печатает справку. **--%** нужен во всех командах **sc.exe**, где в значении есть кавычки
- Обрамляющие кавычки вокруг пути нужны только для того, чтобы пробел в **Lab Audit Agent** не разбил аргумент при разборе. В **ImagePath** реестра **sc.exe** сохраняет путь **без** этих кавычек - так и возникает не процитированный путь, который позже станет уязвимостью
- **start= demand** - тип запуска **Manual**; **obj= LocalSystem** - учётная запись

Задайте отображаемое имя и описание службы. Описание задаётся отдельной подкомандой **sc.exe description** (у **sc.exe config** нет параметра для описания):

```
sc.exe --% config LabAuditAgent DisplayName= "Lab Audit Agent Service"
sc.exe --% description LabAuditAgent "Audit agent service for the practice 6"
```

После каждой команды появится [SC] ChangeServiceConfig SUCCESS .

![](../../_images/4ec7d53e2eff.webp)

Каждая служба имеет дескриптор безопасности (**Security Descriptor**) - набор правил, кто и что может делать со службой (запускать, останавливать, менять конфигурацию). Просмотрим его в формате **SDDL**:

- Показать текущий дескриптор в формате SDDL: `sc.exe sdshow <Имя_службы>`
- Установить новый дескриптор: `sc.exe sdset <Имя_службы> "<SDDL-строка>"`

В выводе мы увидим строку вида **D:(A;;CCLCSWRPWPDTLOCRRC;;;SY (A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)...**

![](../../_images/e46a0a3430ce.webp)

Это и есть дескриптор:

- **D: (DACL)**: Определяет, кому какие действия разрешены или запрещены
- **A;**: Разрешение (**A**ccess Allowed)
- **D;**: Запрет (**D**enied)
- **;;[права]**: Строка с правами доступа (см. таблицу)
- **;;;[SID]**: SID пользователя или группы

Помимо **sc.exe** у нас есть возможность создавать службы с помощью **New-Service**. **New-Service** - нативный способ **PowerShell** создать службу. Он принимает путь обычной строкой и не требует **--%**. Создайте тренировочную службу **LabTempAgent** для отработки операций:

```
New-Service -Name LabTempAgent `
    -BinaryPathName '"C:\Program Files\Lab Temp Agent\temp.exe"' `
    -DisplayName "Lab Temp Agent" `
    -Description "Temporary service for least-privilege practice" `
    -StartupType Manual
```

![](../../_images/70e5acf977ea.webp)

Внешние одинарные кавычки - синтаксис **PowerShell**, внутренние двойные попадут в **ImagePath** реестра буквально, поэтому путь сразу окажется закавыченным. **New-Service** по умолчанию создаёт службу под **LocalSystem**.

Поуправляйте состоянием и типом запуска через **Set-Service**:

```
Set-Service -Name LabTempAgent -StartupType Automatic
Get-Service -Name LabTempAgent | Select-Object Name, StartType
Set-Service -Name LabTempAgent -StartupType Manual
Get-Service -Name LabTempAgent | Select-Object Name, StartType
```

После первой пары команд **StartType** будет **Automatic**, после третьей команды - снова **Manual**

![](../../_images/c55aa66e7fe2.webp)

Удалим тренировочную службу - в дальнейшем сценарии она не нужна: `sc.exe delete LabTempAgent`

Убедимся, что службы больше нет (команда должна вернуть ничего): `Get-Service -Name LabTempAgent -ErrorAction SilentlyContinue`

![](../../_images/71d511943014.webp)

Важной частью является принцип наименьших привилегий. Например, LabAuditAgent служба не требует прав уровня системы - ей достаточно минимального контекста. Понизьте её учётную запись с **LocalSystem** до встроенной **LocalService**. Это и есть применение принципа наименьших привилегий: даже если злоумышленник найдёт способ выполнить свой код через эту службу, он получит лишь бесправный контекст.

Для начала посмотрим какие права сейчас имеет служба **LabAuditAgent :**`Get-CimInstance -ClassName Win32_Service -Filter "Name='LabAuditAgent'" | Select-Object Name, PathName, StartName, StartMode`

![](../../_images/0e4f9f6227d5.webp)

Теперь понизим права **LabAuditAgent** , для встроенных виртуальных учётных записей пароль - пустая строка: `sc.exe --% config LabAuditAgent obj= "NT AUTHORITY\LocalService" password= ""`

![](../../_images/f970d0c4a6ce.webp)

Здесь три правила синтаксиса **sc.exe**, на которых легко ошибиться: между **obj=** и значением обязателен пробел; параметр **password= ""** обязателен при смене на встроенные виртуальные учётные записи; и символ **--%** обязателен, так как значение **NT AUTHORITY\LocalService** содержит пробел.

Проверьте конфигурацию службы через **CIM** и через **sc.exe qc**:

```
Get-CimInstance -ClassName Win32_Service -Filter "Name='LabAuditAgent'" | Select-Object Name, PathName, StartName, StartMode
sc.exe qc LabAuditAgent
```

В выводе **StartName** должно быть **NT AUTHORITY\LocalService**, **PathName** - путь с пробелом, **StartMode** - **Manual**

![](../../_images/7d78fe383a82.webp)

Теперь служба **LabAuditAgent** работает с правами **LocalService**.

#### Настроим сетевой мост

Чтобы машина Debian смогла принять соединение от Windows, обе виртуальные машины должны видеть друг друга. По умолчанию в **VirtualBox** в режиме **NAT** каждая ВМ изолирована в собственной сети и получает один и тот же адрес, поэтому напрямую друг друга машины не видят. Нужно добавить каждой ВМ второй сетевой адаптер для связи между ними, оставив первый (NAT) для доступа в интернет.

Выключим обе виртуальные машины. Для каждой из них в **VirtualBox** откройте **Settings -> Network**:

- **Adapter 1**: оставьте **Attached to: NAT** (доступ в интернет)

![](../../_images/5873cf698c14.webp)
- **Adapter 2**: включим (**Enable Network Adapter**) и выберем **Bridged Adapter**

![](../../_images/f6245dee18b1.webp)

Запустим обе машины. Проверьте адреса второго адаптера:

- На **Windows** откроем **Command Prompt** и выполним **ipconfig**. Найдём второй адаптер (например, **Ethernet 2**) и запишем его **IPv4 Address** (в примере стенда - **192.168.0.107**)

![](../../_images/16a46a508add.webp)
- На **Debian** откройте терминал и выполним **ip a**. Найдём второй интерфейс и запишем его адрес (в примере стенда - **192.168.0.108**)

![](../../_images/807440bdc31f.jpg)

Проверьте связь - с Windows выполним проверку доступности Debian: **ping 192.168.0.108**

Если приходят ответы, связь установлена

![](../../_images/d3555b6c1e32.webp)

#### Unquoted Service Path

**Что такое Unquoted Service Path.** Когда путь к исполняемому файлу службы содержит пробелы и **не** заключён в кавычки, **SCM** при запуске передаёт строку функции **CreateProcess**, которая трактует пробел как разделитель и пробует запустить кандидатов слева направо. Для пути **C:\Lab\Lab Audit Agent\agent.exe** без кавычек кандидаты такие:

- сначала **C:\Lab\Lab.exe**
- потом **C:\Lab\Lab Audit .exe**
- и только потом полный путь **C:\Lab\Lab Audit Agent\agent.exe**

Если злоумышленник может записать файл **C:\Lab\Lab.exe**, то при следующем запуске службы выполнится **его** файл вместо легитимного. Это техника [**MITRE ATT&CK T1574.009**](https://mitre.ptsecurity.com/en-US/T1574.009?product=siem) (**Hijack Execution Flow: Path Interception by Unquoted Path**).

Уязвимость срабатывает только при трёх условиях **одновременно**:

- путь службы содержит пробел и не заключён в кавычки
- у непривилегированного пользователя есть право записи в один из промежуточных каталогов пути
- служба работает под привилегированной учётной записью - тогда перехваченный код получает её права

Третье условие - ключевое для последствий атаки. Именно его мы уже ослабили в первой части, понизив службу до **LocalService**: даже если перехват состоится, чужой код выполнится с минимальными правами. Дальше мы увидим это на практике.

Найдём уязвимые службы средствами **PowerShell** - фильтр выбирает службы, чей путь не начинается с кавычки и содержит пробел: `Get-CimInstance -ClassName Win32_Service | Where-Object { $_.PathName -notmatch '^"' -and $_.PathName -match ' ' } | Select-Object Name, PathName, StartName`

![](../../_images/025b98000c44.webp)

Такой поиск действительно находит все подозрительные службы, но среди результатов оказывается очень много системных служб (например, **svchost.exe** с ключами **-k**, **-p** и **/**). Они не представляют интереса для нас, так как их пути ведут к легитимным исполняемым файлам Windows, а не к потенциально перехватываемым точкам в пользовательских каталогах.

Чтобы избавиться от лишней информации, добавим в фильтр исключения для типичных аргументов  **-k**, **-p** и **/** :

```
Get-CimInstance -ClassName Win32_Service |
	Where-Object {
		$_.PathName -notmatch '^"' -and
	    $_.PathName -match ' ' -and
        $_.PathName -notmatch '-k' -and
        $_.PathName -notmatch '-p'-and
        $_.PathName -notmatch '/'
    } | Select-Object Name, PathName, StartName

```

В выводе мы должны увидеть только **LabAuditAgent** с путём **C:\Lab\Lab Audit Agent\agent.exe**. Именно так, после правильной фильтрации, мы находим целевую уязвимую службу без ложных срабатываний на системные компоненты

![](../../_images/3bf61c17b3a1.webp)

Второе условие уязвимости - право записи в промежуточный каталог. В реальной атаке оно возникает из-за ошибки прав установщика; здесь мы воспроизводим его явно. выдадим группе **BUILTIN\Users** право записи в **C:\Lab**: `icacls 'C:\Lab' /grant 'BUILTIN\Users:(OI)(CI)W'`

Флаги **(OI)** (Object Inherit) и **(CI)** (Container Inherit) распространяют право записи (**W**) на вложенные объекты. В выводе должно появиться **Successfully processed 1 files.** Подтвердим право: `icacls 'C:\Lab'`

В выводе должна присутствовать строка **BUILTIN\Users:(OI)(CI)(W)**

![](../../_images/31ffa768ce02.webp)

Ранее мы установили файл-перехватчик **revshow.exe** (раздаётся со страницы практики). Это учебная программа, которая при запуске под любой учётной записью определяет, **под кем** и **с какими привилегиями** она выполняется, делает один быстрый сетевой запрос на машину Debian и передаёт туда эту информацию, а также оставляет локальный файл-маркер **C:\Windows\Temp\hijack_proof.txt**.

> **revshow.exe** по умолчанию настроен на адрес Debian из примера стенда (**192.168.0.108**, порт **4444**). Если адрес Вашей Debian другой, то вам необходимо поменять ip на **192.168.0.108**

Сначала на **Debian** запустим слушателя, который примет соединение. Откройте терминал:

![](../../_images/e635fea6c924.webp)![](../../_images/4455f78b8854.webp)![](../../_images/12c7ce6a75d2.webp)

В терминале Debian выполним: `nc -lvnp 4444`

Команда **nc -lvnp 4444** слушает входящие TCP-соединения на порту **4444** и печатает всё, что пришло. Оставьте это окно открытым

![](../../_images/c97ce9012b0c.jpg)

Теперь на свою виртуальную машину **Windows** скачайте **revshow.exe** и переместим в Downloads

![](../../_images/91db488dfd49.jpg)

После зайдём в терминал и выполним эти команды:

```
Copy-Item 'C:\Users\admin\Downloads\revshow.exe' 'C:\Lab\Lab.exe'
Test-Path 'C:\Lab\Lab.exe'
```

Если мы все сделали правильно, то команда **Test-Path** должна вернуть **True**

![](../../_images/ce3d07bc3754.webp)

Так мы можем проверить это вручную, перейдя в каталог **C:\Lab\**

![](../../_images/aec88757c377.jpg)

Запустим службу - **SCM** при разборе пути первым найдёт **C:\Lab\Lab.exe** и запустит его вместо ожидаемого **agent.exe**: `sc.exe start LabAuditAgent`

![](../../_images/bea84453b679.webp)

Поскольку **C:\Lab\Lab.exe** не отвечает **SCM** по протоколу управления службой, через некоторое время **SCM** вернёт ошибку запуска (например, **StartService FAILED 1053**) - это ожидаемо и провалом практики не является. Но **до** этого перехватчик успевает выполниться: сделать запрос на Debian и записать маркер.

Переключитесь на **Debian**: в окне **nc** появилась строка с информацией о перехваченном процессе - имя учётной записи и её привилегии:

![](../../_images/70feb2bb66c6.jpg)

Вернитесь на **Windows** и проверьте локальный маркер:

```
Test-Path 'C:\Windows\Temp\hijack_proof.txt'
Get-Content 'C:\Windows\Temp\hijack_proof.txt'
```

**Test-Path** должна вернуть **True**, а содержимое маркера будет содержать **user=NT AUTHORITY\LOCAL SERVICE**

![](../../_images/4929d93acf61.webp)

Перехват состоялся: вместо легитимной службы **SCM** запустил подменённый файл, и тот выполнил код и связался с машиной злоумышленника. Это и есть эксплуатация **Unquoted Service Path**.

Однако обратим внимание на то, **с какими правами** выполнился перехватчик: и на Debian, и в локальном маркере видно **NT AUTHORITY\LOCAL SERVICE** с минимальным набором привилегий - потому что ранее мы понизили службу до **LocalService**. Если бы служба осталась под **LocalSystem**, перехваченный код выполнился бы с правами **SYSTEM** - максимальными на машине, и злоумышленник получил бы полный контроль. Принцип наименьших привилегий не предотвратил сам перехват, но обесценил его результат: атакующий получил бесправный контекст, из которого развить атаку гораздо труднее.

#### Устраняем уязвимость

Исправьте путь службы. Внутренние **"** экранируют кавычки, чтобы в **ImagePath** реестра путь попал уже закавыченным; символ **--%** обязателен по той же причине, что и при создании: `sc.exe --% config LabAuditAgent binPath= "\"C:\Lab\Lab Audit Agent\agent.exe"\"`

![](../../_images/6b7275722562.webp)

Проверьте, что фильтр обнаружения больше не находит **LabAuditAgent**:

```
$vulnService = Get-CimInstance -ClassName Win32_Service |
    Where-Object {
        $_.Name -eq 'LabAuditAgent' -and
        $_.PathName -notmatch '^"' -and
        $_.PathName -match ' '
    } |
    Select-Object Name, PathName
if ($vulnService) {
    Write-Host "attention: A vulnerable service has been detected!" -ForegroundColor Red
    $vulnService
} else {
    Write-Host "The LabAuditAgent service is safe or not found" -ForegroundColor Green
}

```

Скрипт должен вывести зелёным сообщение о безопасности: путь службы теперь заключён в кавычки, и **CreateProcess** больше не пытается запускать промежуточные кандидаты

![](../../_images/b34ef4076434.webp)

Пути без кавычек уже само по себе закрывает уязвимость - **SCM** перестаёт обращаться к промежуточным точкам. В реальной защите этого мало: дополнительно снимают лишнее право записи на каталог (**icacls 'C:\Lab' /remove 'BUILTIN\Users'**) и удаляют подменённый файл. Здесь мы намеренно оставим **C:\Lab\Lab.exe** на месте - так нагляднее: файл-перехватчик всё ещё лежит на диске, но из-за исправленного пути больше не получает управление. Это и проверим дальше.

Перед проверкой удалим старый файл-маркер **hijack_proof.txt**, оставшийся от предыдущего перехвата, чтобы убедиться в чистоте эксперимента:

```
del "C:\Windows\Temp\hijack_proof.txt" -Force
Test-Path "C:\Windows\Temp\hijack_proof.txt"
```

Команда вернёт **False** - файл успешно удалён

![](../../_images/3247837bd583.webp)

Теперь запустим службу снова: `sc.exe start LabAuditAgent`

![](../../_images/c48988616381.webp)

Обратим внимание: в окне **nc** на Debian на этот раз ничего не появилось. Это значит, что подменный файл **Lab.exe** больше не запускается - **SCM** теперь корректно разбирает закавыченный путь и идёт сразу к настоящему **agent.exe**. Проверим, что файл-маркер перехвата не создался: `Test-Path "C:\Windows\Temp\hijack_proof.txt"`

Команда вернёт **False** - перехвата не произошло

![](../../_images/14b5cbf88ead.webp)

Само сообщение **StartService FAILED 1053** при запуске останется и сейчас: настоящий **agent.exe** - это учебная программа, а не полноценная служба, поэтому она не отвечает **SCM** по протоколу управления службой и завершается с этой ошибкой. Для нас важно другое - какой именно файл был запущен. Легитимный **agent.exe** при старте создаёт в каталоге **C:\Lab** журнал **agent_log.txt** с отметкой о запуске. Проверим, что выполнился именно он, а не перехватчик:

```
Test-Path 'C:\Lab\agent_log.txt'
Get-Content 'C:\Lab\agent_log.txt'
```

В выводе появится запись вида **Servise LabAuditAgent successfully launched the agent.exe 17:26:37**. Это и есть подтверждение, что уязвимость устранена: маркер перехвата больше не создаётся, а вместо подменённого **Lab.exe** служба запускает настоящий **agent.exe**.

![](../../_images/a88a23030516.webp)
