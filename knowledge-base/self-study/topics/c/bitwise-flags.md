# Битовые флаги / Bitwise flags в C

## Что это

Идиома упаковки набора bool-опций в одно целое число, где каждый бит = отдельный флаг. Видно везде в Unix-API: `open()`, `fcntl()`, `mmap()`, `setsockopt()`, `epoll_ctl` events, сигнальные маски.

## Ключевые термины (English)

- **bitmask** — целое число, где биты используются как набор boolean-флагов.
- **bitwise OR** (`|`) — установить бит.
- **bitwise AND** (`&`) — проверить или очистить бит.
- **bitwise NOT** (`~`) — инвертировать все биты, используется для создания маски очистки.
- **bit set / bit clear / bit test** — три базовые операции.

## Как работает

Флаги определены как степени двойки в системных заголовках (`<fcntl.h>`, `<sys/socket.h>`...):
```c
#define O_RDONLY    0
#define O_WRONLY    1
#define O_RDWR      2
#define O_CREAT     64       /* бит 6 */
#define O_NONBLOCK  2048     /* бит 11 */
#define O_APPEND    1024     /* бит 10 */
```

Три базовые операции:
```c
flags |= O_NONBLOCK;     // установить бит (set)
flags &= ~O_NONBLOCK;    // сбросить бит (clear)
if (flags & O_NONBLOCK)  // проверить бит (test)
```

`~O_NONBLOCK` = маска со всеми единицами кроме бита 11. `&=` с ней очистит только нужный бит, остальные сохранит.

## Паттерн read-modify-write для fcntl

```c
int flags = fcntl(fd, F_GETFL);    // прочитать ВЕСЬ набор
flags |= O_NONBLOCK;                // изменить нужный бит
fcntl(fd, F_SETFL, flags);          // записать обратно
```

**Антипаттерн** — затирание всех флагов:
```c
fcntl(fd, F_SETFL, O_NONBLOCK);     // ПЛОХО: затрёт O_APPEND и всё остальное
```
`F_SETFL` записывает **значение целиком**, а не "добавляет бит". Если был `O_APPEND` — исчезнет.

## Идиома `!!x` — нормализация в строгие 0/1

```c
if (!!(flags & O_NONBLOCK) == !!non_block) return ANET_OK;  // из Redis anet.c
```

Проблема: `flags & O_NONBLOCK` даёт **0 или 2048** (значение бита). `non_block` — параметр `int`, может быть любым ненулевым (1, 42, -1). Чтобы сравнить **по смыслу "включён vs выключен"**, надо привести оба к `{0, 1}`.

`!x` — логическое НЕ: 0 → 1, не-0 → 0. `!!x` — двойное НЕ: 0 → 0, не-0 → 1. Результат — строгий boolean.

Без `!!`: `2048 == 1` дало бы false, хотя оба означают "включено" — баг.

## Две разные категории флагов у fcntl

Часто путают:
- **File status flags** (`F_GETFL`/`F_SETFL`): `O_NONBLOCK`, `O_APPEND`, `O_ASYNC`. Свойства открытого файла (как читать/писать).
- **File descriptor flags** (`F_GETFD`/`F_SETFD`): только `FD_CLOEXEC` сейчас. Свойства самой записи в таблице дескрипторов процесса (закрывать ли при `exec`).

Это **разные наборы**, разные команды, разные значения. Не пытаться установить `FD_CLOEXEC` через `F_SETFL` — не сработает.

## Сколько битов

Тип обычно `int` — 32 бита на Linux. Реально используется ~15–20 бит, остальные зарезервированы под расширения. "Сколько всего" — не фиксированная константа, зависит от ОС и года.

## Пример (из Redis anetSetBlock)

```c
int anetSetBlock(char *err, int fd, int non_block) {
    int flags = fcntl(fd, F_GETFL);
    if (flags == -1) { /* ... */ }

    /* Уже установлен в нужное состояние — выйти */
    if (!!(flags & O_NONBLOCK) == !!non_block) return ANET_OK;

    if (non_block) flags |= O_NONBLOCK;     // включить
    else           flags &= ~O_NONBLOCK;    // выключить

    if (fcntl(fd, F_SETFL, flags) == -1) { /* ... */ }
    return ANET_OK;
}
```

Полный набор идиом: get → нормализовать через `!!` → проверить надо ли менять → set/clear через `|=` / `&= ~` → write.

## Подводные камни

- **`F_SETFL` без предварительного `F_GETFL`** — затрёшь чужие флаги. Всегда read-modify-write.
- **Сравнение результата `&` без `!!`** — наступишь на маски с большим значением.
- **Путаница `F_SETFL` vs `F_SETFD`** — ставишь `FD_CLOEXEC` не туда, удивляешься почему утечка fd при `exec`.
- **`flags & X == Y`** — приоритет операторов: `==` сильнее `&`. Пиши `(flags & X) == Y`.
