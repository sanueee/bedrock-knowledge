# Скилл: ctf

Используется для регулярных CTF-сессий на picoCTF.
Цель — закреплять знания через offensive-угол: видеть свой код глазами атакующего.

---

## Платформа

**picoCTF** — образовательная CTF-платформа от Carnegie Mellon University.
- URL: https://play.picoctf.org/
- Бесплатная, регистрация открытая.
- Задачи разбиты по категориям и сложности (Easy / Medium / Hard).
- Есть постоянные практические таски (picoGym) и сезонные соревнования (picoCTF events).
- Каждое задание = найти **flag** в формате `picoCTF{...}`.

### Категории picoCTF

| Категория | Что качает | Релевантно builder'у? |
|-----------|-----------|----------------------|
| **General Skills** | Linux CLI, base64, file, grep, git, простые скрипты | Да — разогрев, словарь утилит |
| **Forensics** | file/strings/xxd, Wireshark, stegano, ELF/PE формат, метаданные | Да — это половина работы СЗИ-аналитика |
| **Binary Exploitation (pwn)** | stack/heap, ASLR, GDB, format strings, ROP | **Да** — builder СЗИ должен понимать что защищает |
| **Reverse Engineering** | objdump, Ghidra, IDA, ассемблер, разбор бинаря | **Да** — половина работы внутреннего разработчика антивируса |
| **Cryptography** | RSA, AES, padding oracles, hash extension | Частично — приоритет на этапе 2 |
| **Web Exploitation** | XSS, SQLi, SSRF, JWT, IDOR | Низкий приоритет — не вектор |

**Приоритеты для builder'а сейчас (этап 1):**
1. General Skills — закрыть быстро.
2. Forensics — параллельно с блоком A/B.
3. Reverse Engineering Easy — после первых задач блока B.
4. Binary Exploitation Easy — после reading-сессии по ELF и стеку.

Web и сложную крипту сейчас **не предлагать**.

---

## Цель CTF в стратегии fn2s

Пользователь — **builder**, не pen-tester. CTF здесь не для накопления флагов, а для:

1. **Tooling reflexes** — `objdump`, `strings`, `xxd`, `gdb`, `radare2`, `pwntools`, `ghidra` должны быть в пальцах. Это инструменты которыми СЗИ-разработчик пользуется ежедневно (анализ образцов, отладка драйверов, разбор крашей).
2. **Понимание того что защищает** — нельзя писать антивирус не понимая как работает packer/obfuscator. Нельзя писать sandbox не понимая sandbox escape.
3. **Чтение бинаря** — параллельно с reading-code (исходники), CTF учит читать **результат компиляции**. Это нужно когда исходников нет.
4. **Python через практику** — pwntools, scapy, Crypto. Это естественный путь к Python из CLAUDE.md ("когда упрёмся — учим минимально достаточный фрагмент").

CTF — **не критический путь**. Это параллельный трек ~1-2 часа на сессию.

---

## Триггеры

Счётчиков **нет**. CTF инициируется **только пользователем** — он сам следит за темпом (ориентир 1-2 челленджа в неделю, цель 30+ к концу 2026).

Прямые запросы: "дай ctf-задачу", "хочу picoctf", "ctf-сессия".

`give-task` CTF **не предлагает**. Если пользователь долго не зовёт — это его решение, не сигнал к проактивному напоминанию.

## Алгоритм

### 1. Прочитай контекст

Прочитай roadmap:
- `knowledge-base/roadmap/00-roadmap.md` → "Текущая позиция" (активный блок) и `roadmap/archive.md` → выполненные темы (для подбора категории под уровень).
- `roadmap/journal.md` → раздел `## CTF` → журнал решённых тасков. Это единственный авторитетный журнал CTF. Чтобы не предлагать повторно.

Прочитай `knowledge-base/ctf/picoctf/` — структура каталогов с writeup'ами для деталей.

### 2. Подбери категорию под уровень

Сверься с приоритетами выше. Не предлагать категорию, для которой нет фундамента:
- **Pwn/Reverse** — не раньше чем пользователь прошёл задачи с указателями и читал ассемблер.
- **Crypto (сложнее base64/XOR)** — не раньше этапа 2.
- **Web** — пропускать пока сам не запросит.

### 3. Сформулируй задание

Конкретно:
```
Платформа: picoCTF (https://play.picoctf.org/practice)
Категория: <General Skills / Forensics / Reverse / Pwn>
Сложность: Easy (или Medium если уже закрыты Easy)
Количество тасков: 2-3 за сессию
Время: 60-90 минут
```

**Конкретные таски не назначаем** — пусть выберет сам в указанной категории и сложности.
Причина: на picoCTF задачи появляются/убираются, плюс важна привычка читать и выбирать задачу из списка.

Если пользователь просит конкретику — указать **тип** задачи ("задача на format string", "задача на stegano в PNG"), а не имя.

### 4. Создай файл-писмейкер сессии

Создай `knowledge-base/ctf/picoctf/session-NN.md` с шаблоном:

```markdown
---
session: NN
platform: picoctf
date: YYYY-MM-DD
category: <категория>
difficulty: <Easy/Medium>
status: in-progress
---

# CTF Session NN — <дата>

## Цель сессии
<категория, сколько тасков, на чём фокус>

## Решённые таски
*(заполняется после)*

## Нерешённые / частично
*(заполняется после — это важнее)*

## Новые инструменты / приёмы
*(idioms, флаги утилит, неожиданные решения)*

## Связанные темы
*(wikilinks на topics/)*
```

### 5. После сессии — разбор

Когда пользователь возвращается с результатами:
- Спроси какие таски решил, какие застряли.
- На каждый решённый — короткий вопрос "что было ключевой идеей?" (не флаг, а **техника**).
- На нерешённые — спроси где упёрся. Если нужен hint — давать **направление**, не решение ("проверь что в этом бинарнике stack canary включён", а не "вот payload").

После разбора — для каждого нетривиального таска создать **отдельный writeup**:

`knowledge-base/ctf/picoctf/<category>/<task-name>.md` со структурой:

```markdown
---
task: <picoCTF task name>
category: <категория>
difficulty: <уровень>
date: YYYY-MM-DD
solved: true|false
---

# <Task Name>

## Условие
<краткое описание>

## Подход
<как думал, что пробовал>

## Решение
<команды / payload / код>

## Что узнал нового
<главное — техника, инструмент, идея>

## Ключевые термины (English)
<глоссарий — `format string`, `stack canary`, `nop sled` и т.д.>
```

Затем `vault-write` создаёт/обновляет связанные `topics/` записи (например, `topics/binary/format-strings.md`).

### 6. Обнови журнал

- Добавить запись в раздел "CTF" в `knowledge-base/roadmap/journal.md`. Формат:
  ```
  | NN | <дата> | <платформа> | <категория> | [[ctf/<platform>/<cat>/<task>\|<task>]] | <главное что узнал> |
  ```
  Одна строка на каждый решённый таск (не на сессию). Если таск нерешён — в журнал не добавлять.

```
        ├── session-02.md

        └── pwn/
```

Если позже добавятся другие платформы (HackTheBox, RootMe) — рядом с `picoctf/`.

## Чего не делать

- Не предлагать категории вне приоритетов builder'а (Web, сложная крипта на этапе 1).
- Не давать готовые решения как hint — направление, не код.
- Не пропускать writeup для нетривиальных тасков — flag без writeup = впустую потраченное время.
- Не забывать связку с `topics/` — техника из CTF должна быть прилинкована к концептуальной записи.
- Не делать CTF-сессии длиннее 90 минут — это параллельный трек, не основной.
- Не предлагать CTF из `give-task` или другого скилла — пользователь сам решает темп.

## Обнови skills

На основе переписки и замечаний пользователя — обнови `.claude/skills/*.md`.
Конкретизируй, подстраивайся под стиль общения, записывай замечания.
При необходимости создавай новые скиллы.
Цель: идеальное понимание без толчков "посмотри в тот файл".
