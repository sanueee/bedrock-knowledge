# Скилл: give-task

Используется когда пользователь говорит "у меня есть N часов/минут" или "дай задание".

---

## Алгоритм

### 0. Проверки перед выдачей задания

Перед тем как смотреть стратегию — пройти три проверки. Каждая может перенаправить пользователя на другой скилл или другую задачу. Только если все они чистые — переходить к шагу 1.

#### 0.1. Счётчики

Прочитай `strategy/learning-strategy.md` → "Текущая позиция". Там три счётчика:

**Счётчик reading-code (≥ 4) — приоритет 1, обязательный:**
"Ты выполнил 4 writing-задачи с последнего reading. Перед следующей writing — нужна reading-сессия по чужому коду."
Не делать опциональным — это часть стратегии. Сразу → скилл `reading-code`.

**Счётчик мок-собеса (≥ 8) — приоритет 2, мягкий:**
"Ты выполнил 8 задач с последнего мок-собеса. Хочешь сначала проверить знания?"
Если согласен → скилл `mock-interview`.

**Счётчик CTF (≥ 5) — приоритет 3, мягкий:**
"Ты выполнил 5 задач с последнего CTF. Хочешь сначала CTF-сессию на picoCTF? Или продолжим с writing?"
Если согласен → скилл `ctf`.

Если сработали несколько счётчиков — порядок: сначала reading-code (обязательный), затем мок-собес следующей сессией, CTF — третьим. Не запускать всё в одну сессию.

#### 0.2. Незакрытые закрепляющие задания после мок-собесов

Найди в `strategy/learning-strategy.md` все блоки `#### Interview NN — <дата>` и для каждого посмотри раздел "Закрепляющие задания". Сверь со списком "Текущий прогресс" в `CLAUDE.md` — выполнены ли они.

Если есть невыполненные закрепляющие задания — **они приоритетнее следующей темы по стратегии**. Предложить их первым же сообщением: "После Interview NN остались закрепляющие задания (перечислить), их нужно закрыть до перехода к <следующая тема>". Без этого пробелы из мок-собеса остаются непроработанными.

Оформление: одним сшитым task'ом `task-NN-interviewMM-reinforce.md` (несколько микро-программ внутри одного файла) — это дешевле для vault и нагляднее как блок работы над пробелами.

Если все проверки чистые — продолжай к шагу 1.

### 1. Прочитай стратегию

Прочитай `strategy/learning-strategy.md` → раздел "Текущая позиция".
Там написано: текущий блок, последний task, следующая тема, функции, место для кода.
Там же "Освоенные темы" — проверить что не предлагаешь уже пройденное.
Не читать весь файл — достаточно этих двух разделов.

### 2. Определи масштаб по времени

| Время | Тип задачи |
|-------|------------|
| < 30 мин | Концептуальная задача или чтение с вопросом. Без написания кода. |
| 30–60 мин | Задача на одну конкретную функцию или системный вызов. |
| 1–2 часа | Мини-утилита с полным циклом: написать → собрать → протестировать. |
| 2+ часов | Новый task: задание → код → ревью → документация в vault. |

### 3. Сформулируй задание

Конкретно:
- Что написать (название, что принимает, что выводит).
- Какие функции/системные вызовы использовать — брать из "Следующая задача" в стратегии.
- **Какие хедеры подключать.** Для каждой функции/типа из задания указать `#include` явно. Не "разберётся по man" — список хедеров в задании. Это снимает класс ошибок "implicit declaration", "забыл `<errno.h>`", "не знал что `pthread_*` в `<pthread.h>`" и формирует привычку держать соответствие функция→хедер в голове. Для часто используемых функций мок-собеса — особенно строго (`errno` → `<errno.h>`, `pthread_*` → `<pthread.h>`, `O_*` флаги → `<fcntl.h>`).
- На каком Linux-механизме тренироваться.
- Где сохранить код (`linux/proc/`, `linux/fd/` и т.д.).
- Что создать в vault (`knowledge-base/tasks/task-NN.md`).

**Домен сейчас: C + Linux syscalls (Блок A).**
Не предлагать задачи по Python, Rust, сетям или другим темам без явного запроса.

### 4. Создай файл задания

Создай `knowledge-base/tasks/task-NN.md` сразу — с заполненным разделом "Задание".
Остальные разделы оставить пустыми — заполнит `vault-write` по итогам.

---

## Чего не делать

- Не давать задание без чтения стратегии — иначе задания будут хаотичными.
- Не давать задание которое уже выполнено (проверить "Освоенные темы" в learning-strategy.md).
- Не давать две темы сразу — одна задача, один навык.
- Не придумывать задачи "из головы" — только по стратегии.
