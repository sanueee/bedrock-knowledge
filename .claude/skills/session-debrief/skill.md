# Скилл: session-debrief

Используется когда пользователь пишет "прочитай CLAUDE.md" после завершения сессии.
Это сигнал: сессия завершена, нужно зафиксировать результаты в vault.

---

## Алгоритм

### Шаг 1 — Задай один вопрос

Спроси что было сложным или непонятным в этой сессии.
Один вопрос, кратко. Не список. Подожди ответа.

Пример: "Что вызвало затруднение — сам системный вызов или логика обработки ошибок?"

### Шаг 2 — Обнови tasks/

Найди или создай `knowledge-base/tasks/task-NN.md`.
Заполни или обнови:
- **Моё решение** — реальный подход пользователя (не план из задания).
- **Ошибки и трудности** — всё что было сложным, включая ответ из Шага 1. Честно.
- **Что бы сделал иначе** — рефлексия по итогам сессии.
- **Ключевые функции** — что использовал и зачем.
- **Связанные темы** — [[wikilinks]] на topics/.

### Шаг 3 — Обнови topics/

Для каждой концепции которая всплыла в сессии:
- Если файла нет → создай в правильной подпапке (`topics/c/` или `topics/linux/`).
- Если файл есть → обнови если появился лучший пример или уточнение.
- Примеры кода — только из реального кода сессии, не generic.

### Шаг 4 — Обнови 00-roadmap.md

- Статус задачи: выполнено / в процессе / пауза.
- Если освоил что-то новое — добавь в стек.
- Обнови прогресс текущего этапа если применимо.

### Шаг 5 — Обнови CLAUDE.md

Только если:
- Изменился стек (освоил новую технологию/концепцию).
- Изменился статус задачи в "Текущий прогресс".

---

## Чего не делать

- Не пропускать Шаг 1 — ответ пользователя важен для честной фиксации трудностей.
- Не писать "всё прошло отлично" — если были трудности, фиксировать их.
- Не создавать topics/ файлы с generic примерами — только из реального кода сессии.
