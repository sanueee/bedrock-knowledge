# Скилл: session-debrief

Триггеры:
- пользователь пишет "на этом все" / "на этом всё" / "заканчиваем"
- пользователь пишет "прочитай CLAUDE.md" В КОНЦЕ сессии (после выполнения задания)
- пользователь правильно ответил на 2–3 уточняющих вопроса из `explain-code` подряд
  и не путался в ответах → предложить: "Кажется разобрались. Закончим сессию?"
  Дождаться подтверждения перед запуском дебрифа.

Это сигнал: сессия завершена, нужно зафиксировать результаты и обновить файлы.

---

## Алгоритм

### 1. Задай один вопрос

Спроси что было сложным или непонятным в этой сессии.
Один вопрос, кратко. Не список. Подожди ответа.

Пример: "Что вызвало затруднение — сам системный вызов или логика обработки ошибок?"

### 2. Зафиксируй в vault

Используй скилл `vault-write`.
Передай ответ из Шага 1 — повторно не спрашивай.

Что обновить:
- `knowledge-base/tasks/task-NN.md` — моё решение, ошибки, рефлексия
- `knowledge-base/topics/` — каждая концепция которая всплыла в сессии

### 3. Обнови `00-roadmap.md`

`knowledge-base/00-roadmap.md` — **единственный** файл который обновляется по статусу. Стратегия (план) и CLAUDE.md (контекст) трогаются редко (см. Шаг 4).

**Обновить дату в frontmatter** (`обновлено: YYYY-MM-DD`) — всегда.

**Раздел "Текущая позиция"** — обновить все строки которые изменились:
1. "Активный блок" — если сменился (B1 → весь B завершён → C/D).
2. "Выполненные темы блока X" — дописать **что именно** усвоено (не "task-N выполнен", а концепции — например "EPIPE/ECONNRESET, partial read, sigaction(SIGPIPE, SIG_IGN)"). Если завершилась /theory-сессия — обновить "Фундамент".
3. "Последний выполненный task" — новое значение с датой.
4. "Следующий шаг" — следующий пункт главного трека с функциями/путями (из стратегии → раздел блока).
5. "Параллельные блоки/треки доступны сейчас" — пересмотреть. Если параллельный блок стал доступен после завершения текущего task'а (например после B1 открылся C) — добавить. Если параллельный блок завершён или больше не релевантен — убрать. `give-task` читает эту секцию для предложения выбора.
6. Счётчики (`мок-собес +1`, `reading-code +1`, `CTF +1`). Исключение: сама сессия была CTF/reading/мок-собесом — её счётчик не инкрементируется (сбрасывается в своём скилле).
7. "Невыполненные закрепляющие задания" — если после мок-собеса появились reinforce-задачи, добавить `[[task-NN-interviewMM-reinforce]]`. Если пользователь только что закрыл reinforce — удалить.

**Разделы журналов** — добавить строку:
- "Задачи — writing" — для обычных task'ов.
- "Reading-сессии" — для reading-NN.
- "Theory-сессии" — для /theory сессий.
- "Мок-собесы" — для interview-NN (формат: 3 колонки).
- "CTF" — для CTF-тасков (по таску, не сессии).

**Разделы тем** — если в задаче всплыли новые темы, добавить `[[wikilink]]` в "Темы — Linux/Networking/C/Reading/...".

**Раздел "Чекпойнты этапа 1"** (внизу roadmap) — обновить **счётчики прогресса** в скобках `(сейчас: N)`. Это **легко забыть** — секция далеко от "Текущей позиции" и редко всплывает в контексте.
- `picoCTF: ... (сейчас: N)` — после каждого CTF-таска +1. Считать по строкам в журнале CTF.
- `Reading-code: ... (сейчас: N)` — после каждой reading-сессии +1. Считать по строкам в журнале Reading.
- Если чекбокс достигнут (`30+ CTF` / `≥6 reading`) — поставить `[x]` вместо `[ ]`.
- Прочие чекпойнты (scanner, detector, OWASP) — отметить `[x]` только если соответствующий проект/тема действительно закрыты, не по ощущению.

### 4. Обнови CLAUDE.md (редко) и стратегию (очень редко)

**CLAUDE.md** — обновлять только если:
- Изменился стек или его уровень (новый язык, освоил Rust, etc.) → правка таблицы "Текущий стек и уровень".
- Поменялось что-то в "Кто я" (возраст, курс, тип).

**Стратегия (`learning-strategy.md`)** — обновлять только если:
- Появилась новая тема которую стоит добавить в план блока (новый `#### BN — ...`).
- Изменился приоритет или вектор — обсудить с пользователем перед правкой "Главный вектор" или "Карьерная стратегия".
- Завершился весь мок-собес — добавить блок `#### Interview NN` после блока активной темы (slot для слабых мест и закрепляющих заданий).

Стратегия **не содержит** меток `[✅]` / `[ТЕКУЩИЙ]` / "Текущая позиция" — это план без статуса. Не пытаться обновлять статус в стратегии.

### 5. Обнови skills

На основе переписки и замечаний пользователя — обнови .claude/skills/*.md.
Конкретизируй, подстраивайся под стиль общения, записывай замечания.
При необходимости создавай новые скиллы.
Цель: идеальное понимание без толчков "посмотри в тот файл".

---

## Чего не делать

- Не пропускать Шаг 1 — ответ важен для честной фиксации трудностей.
- Не писать "всё прошло отлично" — если были трудности, фиксировать их.
- Не запускать дебриф если пользователь просто читает CLAUDE.md не в конце сессии.
