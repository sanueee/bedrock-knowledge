# Скилл: plan-block

Проектирование нового учебного блока: когда подходит его очередь — превратить прозаическое описание из стратегии в карту заданий. Также владеет **структурой блока** и **гейтом закрытия** (правила, на которые опирается `give-task`).

Не путать с `give-task` (выдаёт одно задание из уже спроектированного блока) и `refactor` (структура документов-инструкций).

---

## Триггеры

- Подходит очередь блока, описанного в стратегии только прозой (будущий блок становится активным).
- Прямой запрос: "спроектируй блок", "распиши блок X", "сколько заданий в блоке".
- Из `give-task`, если активный блок ещё не расписан по заданиям.

---

## Структура блока (инвариант — источник истины)

Базовая структура — **21 задание**:
- **16 атомарных** — одна тема на задание.
- **4 интеграционных** — **каждое 5-е задание** (позиции 5, 10, 15, 20). Не новая теория, а **синтез последних 4 атомарных в одной задаче** под давлением.
- **1 магнум опус** — финал блока, **последнее** задание. Определяется в начале блока, к нему ведут все остальные. Сдаётся отдельной репой на GitHub с README.

**Размер гибкий.** 21 — минимум, не потолок. Глубина темы растягивает блок (26, 31, 36...). Инвариант сохраняется: атомарные пачками по 4, **интеграционное — каждое 5-е**, опус — последнее. Поэтому позиции интеграционных и номер опуса **зависят от размера** (блок B = 26 → интеграционные 5/10/15/20/25, опус 26). Конкретные позиции активного блока — в `roadmap/00-roadmap.md`.

**Исключение — учебник-driven блоки (Rust по The Book).** Идут **линейно по главам**: одна глава (или пара) = одно задание `C-N`. Почти все атомарные. Структура «4+1» **не применяется**, правило «каждое 5-е интеграционное» — тоже. `C-N` = «N-е задание по главам», не «позиция N в карте». Главы-проекты The Book (12 — minigrep, 20 — web server) играют роль естественных синтез-точек.

---

## Гейт закрытия блока

1. Магнум опус сдан.
2. **Blank-slate ретест** самой сложной темы блока — без подсказок и без vault. Не пишется с нуля → точечно вернуться, ретест повторить. Только после прохождения — блок закрыт.

При закрытии: детальный дамп тем переезжает в `archive.md`, в диспетчере остаётся статус ✅ (исполняет `session-debrief`).

---

## Алгоритм проектирования

### 1. Подними прозу блока

Прочитай раздел блока в `strategy/learning-strategy.md` (будущие блоки описаны абзацем: якорь, что освоить). Это вход.

### 2. Карта тем — ДО магнум опуса

Сначала разложи темы (атомарные кирпичи), **потом** выбирай опус. Не наоборот — иначе часть тем натянута под выбранный опус.

### 3. Опус и размер

- Сформулируй магнум опус (якорный проект блока) — что входит, какие компоненты.
- Прикинь, во сколько атомарных тем он раскладывается. Не влезает в 16 — растягивай блок кратно 5 (+интеграционное каждое 5-е).
- Размер фиксируется здесь, на сессии дизайна.

### 4. Разложи по позициям

- Атомарные — пачками по 4, в логическом порядке (простое → сложное, под опус).
- Интеграционное — каждое 5-е, синтез предыдущих 4. Если 4 темы не сочетаются естественно — карта тем плохо разложена, переразложить (не натягивать интеграцию).
- Последнее — опус.

### 5. Запиши результат

- **`strategy/learning-strategy.md`** → раздел блока: заменить прозу на список заданий (одно задание = краткая сводка темы + функции). Заголовок блока — со структурой («N заданий: атомарные + интеграционные на …, опус — …»).
- **`roadmap/00-roadmap.md`** → если блок становится активным: позиция, структура, следующий шаг.

Дальнейшие правки (удаление выполненных заданий, перенос в archive) — `session-debrief`. Этот скилл только **создаёт** карту.

---

## Чего не делать

- Не выбирать опус раньше карты тем.
- Не проектировать будущие блоки впрок — только когда подходит очередь (иначе темы натянуты, план протухает).
- Не применять «4+1» к учебник-driven блокам.
- Не пропускать интеграционные на позициях, кратных 5.
