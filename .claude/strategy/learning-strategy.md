Этот файл читается перед выдачей каждого задания (скилл `give-task`).

---

## Принципы

1. **Спираль, не линия** — темы возвращаются на новом уровне. Сначала "как использовать", потом "как работает внутри".
2. **Код раньше теории** — сначала написать и сломать, потом читать man.
3. **Одна тема — один task** — не смешивать `fork()` и `epoll` в одном задании.
4. **Каждый task завершается vault-записью** — иначе знание не зафиксировано.
5. **Раз в 8 задач — мок-собес** — по пройденным темам, в формате вопрос-ответ без кода.

## Текущий этап: Этап 1 — Фундамент

Цель этапа: знать Linux изнутри на уровне системных вызовов, понимать сетевой стек, начать Rust.

### Блок A — Linux Internals (C) [ТЕКУЩИЙ]

Освоенные темы (не давать снова):
- /proc filesystem: чтение /proc/\<pid\>/status
- directory traversal: opendir/readdir
- file descriptors: /proc/\<pid\>/fd/, readlink
- string formatting: snprintf, fprintf, PRIu64
- sorting: qsort с компаратором
- error handling: внешний мир vs внутренняя логика

**Следующие темы по порядку:**

#### A4 — Процессы: fork, exec, wait
Цель: понять как создаются процессы в Linux.
Задание-шаблон: написать программу которая форкает дочерний процесс, дочерний выполняет команду через execv, родитель ждёт через waitpid и печатает exit code.
Функции: `fork()`, `execv()`, `waitpid()`, `WEXITSTATUS()`
Файлы для чтения: `man 2 fork`, `man 2 execv`, `man 2 waitpid`
Место в vault: `linux/proc/` для кода, `topics/linux/` для теории

#### A5 — Сигналы: signal, kill, sigaction
Цель: понять межпроцессное взаимодействие через сигналы.
Задание-шаблон: написать программу с обработчиком SIGINT и SIGTERM, которая при получении сигнала пишет в лог и корректно завершается.
Функции: `sigaction()`, `sigset_t`, `kill()`
После: добавить обработку сигналов в предыдущий fork-проект.

#### A6 — Pipes и IPC
Цель: данные между процессами через pipe.
Задание-шаблон: родитель и дочерний процесс общаются через pipe — дочерний пишет, родитель читает.
Функции: `pipe()`, `dup2()`, `read()`, `write()`

#### A7 — /proc/net: чтение сетевого состояния
Цель: мост между Linux internals и сетями.
Задание-шаблон: прочитать /proc/net/tcp, распарсить hex-адреса и порты, вывести список активных TCP-соединений.
Функции: fopen/fgets + strtol для hex-парсинга
Место: `linux/proc/` для кода, `topics/linux/` и `topics/networking/` для теории

#### A8 — Потоки: pthreads
Цель: параллелизм на уровне потоков.
Задание-шаблон: параллельный сбор данных из /proc — несколько потоков читают разные PID, результат в общий массив с мьютексом.
Функции: `pthread_create()`, `pthread_join()`, `pthread_mutex_t`

### Блок B — Сетевой стек (C) [после A7–A8]

#### B1 — TCP-сокеты: первый клиент-сервер
Простейший echo-сервер и клиент.
Функции: `socket()`, `bind()`, `listen()`, `accept()`, `connect()`, `send()`, `recv()`

#### B2 — Разбор пакетов: raw sockets / pcap
Перехват и парсинг пакетов на уровне Ethernet/IP/TCP.
Библиотека: libpcap

#### B3 — Написать простой port scanner
Применение сокетов: connect() с таймаутом на диапазон портов.

#### B4 — DNS: ручной запрос
Собрать DNS-запрос вручную, отправить UDP, распарсить ответ.

### Блок C — Rust [параллельно или после B1]

#### C1 — The Book главы 1–4
Не задание на код — чтение с вопросами. Ownership, borrowing, lifetimes.
Формат < 30 мин: один вопрос на понимание конкретной концепции.

#### C2 — Переписать procinfo на Rust
Первый реальный Rust-код. То что уже знаешь на C — переписать.
Цель: почувствовать разницу в работе с памятью и строками.

#### C3 — Переписать fdlist на Rust
То же что C2, но с directory traversal и симлинками.

#### C4 — Rust: обработка ошибок (Result, Option, ?)
Отдельная тема — Rust-идиома которая нет аналога в C.

### Блок D — Первый живой проект [Этап 2, ~месяц 8–10]

Кандидаты (выбрать один по интересу когда придёт время):
- **netmon** — мониторинг сетевых соединений в реальном времени (C + /proc/net + ncurses)
- **procwatch** — демон который следит за процессами и логирует аномалии
- **portknock** — реализация port knocking на сырых сокетах
