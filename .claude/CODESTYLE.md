# CODESTYLE.md — конвенции кода на C

**Источник:** стиль зафиксирован 2026-08-09 по итогам B-20 (`sections/networking/ping-sweep/`) — пользователь назвал этот код самым удачным по единообразию из написанного. Эталон: `net.h` + `net.c` + `sweep.c`.

**Кому адресован:** и пользователю (при написании), и Claude (при генерации примеров, при `/check`, при выдаче задания). Claude обязан сверять предлагаемый код с этим файлом и отмечать расхождения в ревью — но **отдельной секцией**, не смешивая со багами.

**Статус:** живой документ. Стиль меняется — правится здесь, а не «помнится».

---

## 1. Форматирование

**Отступ** — 4 пробела, табов нет.

**Скобки — стиль Allman:** открывающая `{` на своей строке, на уровне конструкции.

```c
int send_msg(const int fd, const uint8_t *buf, const struct in_addr *addr)
{
    if (sent < 0)
    {
        perror("sendto"); return 1;
    }
}
```

**Тело из одного оператора — без скобок,** на следующей строке с отступом:

```c
if (want > RCV_BUF_MAX)
    want = RCV_BUF_MAX;

for (size_t i = 0; i < *count; i++)
    (*list)[i].addr.s_addr = htonl(network + 1 + i);
```

**Исключение — короткий выход по ошибке** пишется в две строки с блоком, оба оператора на одной строке:

```c
if (*list == NULL)
{
    fprintf(stderr, "allocation target list error\n"); return 1;
}
```

**Длина строки** — мягкий предел ~120 символов. Прототипы в хедере могут быть длиннее, если разбивка вредит читаемости. Длинный `printf` разбивается по строковым литералам (компилятор склеит соседние литералы сам):

```c
fprintf(stderr, "warning: SO_RCVBUF = %d, requested %d (capped by net.core.rmem_max);"
                " some replies may be dropped\n", rcvbuf_actual, rcvbuf);
```

**Пустая строка** — между логическими шагами внутри функции и между функциями (ровно одна).

## 2. Имена

| Сущность | Правило | Пример |
|---|---|---|
| Функции | `snake_case`, глагол+объект | `send_packets`, `create_target_list`, `answer_to_structs` |
| Переменные | `snake_case`, без венгерской нотации | `prefix_len`, `t_end_send`, `rcvbuf_actual` |
| Структуры | `struct` + существительное в единственном числе | `struct target` |
| enum-типы | `typedef enum` + суффикс `_status` для кодов исходов | `host_status`, `parse_status`, `defnet_status` |
| enum-значения | `UPPER_SNAKE` с префиксом домена | `HOST_ALIVE`, `PARSE_BAD_ADDR`, `DEFNET_NO_ROUTE_FILE` |
| Константы | `#define`, `UPPER_SNAKE`, в хедере под `// consts` | `PAYLOAD_SIZE`, `TIMEOUT_MAX_MS`, `RCV_BUF_PER_TARGET` |
| Файловые глобалы | `static`, `snake_case` | `static size_t hosts_up` |

**Имя должно называть содержимое, а не намерение.** Аккумулятор, в котором лежит сумма, называется `rtt_sum`, а не `rtt_avg` — среднее появляется только в момент деления. Это не косметика: неверное имя прячет забытое деление.

**Имена по осям, а не по алфавиту.** Парные величины получают общий префикс: `t_send`/`t_recv`, `rtt_min`/`rtt_sum`/`rtt_max`, `hosts_up`/`hosts_unreachable`.

## 3. Структура файлов

**Библиотека отдельно от точки входа.** `net.h` (интерфейс) + `net.c` (реализация) + `<program>.c` (только `main` и разбор аргументов). Причина — `main` не должен расти: на B-19 он дошёл до 125 строк прежде, чем пришла декомпозиция.

**`#include` — один на строку, с комментарием, что именно из него берётся:**

```c
#include <sys/socket.h>      // socket, sendto, recvfrom, setsockopt, SOL_SOCKET, SO_RCVTIMEO
#include <netinet/ip_icmp.h> // struct icmphdr, ICMP_ECHO, ICMP_ECHOREPLY
```

Комментарий не украшение: он показывает, какой хедер станет лишним после рефакторинга, и заставляет думать, откуда взят каждый символ.

**Хедер обязан быть самодостаточным.** Он подключает всё, что использует в своих объявлениях (`ssize_t` → `<sys/types.h>`, `struct iphdr` → `<netinet/ip.h>`). Проверка: хедер, включённый **первым** в пустом `.c`, должен компилироваться. Иначе тип из прототипа объявится заново в параметр-скоупе и даст `incompatible pointer type` в самом неожиданном месте.

**Порядок в хедере:** include guard → includes → `// consts` (`#define`) → типы (`enum`, `struct`) → `// prototypes`.

**Порядок функций в `.c` — по фазам работы программы,** в том порядке, в каком их зовёт `main`; внутри фазы сначала «главная», затем её вспомогательные:

```
разбор аргументов → построение данных → отправка → приём → отчёт → утилиты
```

Прототипы в хедере идут в **том же** порядке, что определения в `.c`, и группируются пустой строкой по фазам. Тип возврата выровнен в колонку:

```c
int       parse_cidr(char *input, int count, struct in_addr *ip, int *prefix_len);
void      recv_packets(const int fd, const uint16_t id, ...);
uint16_t  compute_checksum(const uint8_t *data, size_t len);
long long now_ms(void);
```

## 4. Контракты функций

**Статус — через `return`, данные — через out-параметр.** Так делает `inet_pton`, и так же должен делать свой код. Никогда не кодировать ошибку значением данных, если домен значения занят полностью (`uint32_t` IPv4-адрес не может нести `-1`: `0xFFFFFFFF` — это broadcast; урок B-18, sentinel-коллизия).

```c
int parse_cidr(char *input, int count, struct in_addr *ip, int *prefix_len);
//  ^ parse_status                     ^ out                ^ out
```

**Число различимых исходов определяется до написания тела.** Если их больше двух — это `enum`, а не `int` с магическими числами. `parse_status` в B-20 имеет девять значений, и каждое соответствует одному конкретному сообщению в `main`.

**`const` на всех входных параметрах,** включая скаляры — это документация направления данных:

```c
void recv_packets(const int fd, const uint16_t id, const size_t count,
                  struct target *list, const long long deadline_ms);
//                ^^^^^ in           ^^^^^ in     ^^^^^ in
//                                   list — in-out, поэтому без const
```

**Три оси, которые проговариваются для каждого параметра до кода:** направление (in / out / in-out), владение и время жизни, число исходов. Указатель внутрь локального буфера **не** уходит наружу — либо копия значения, либо `T**` при общей области видимости.

## 5. Обработка ошибок

**Кто печатает.** Ошибки разбора входных данных печатает **вызывающий** — функция возвращает код, `main` разворачивает его в `switch` с человеческим текстом. Ошибки системных вызовов печатает **место обнаружения** через `perror` (там есть `errno`, и он умрёт при следующем вызове).

```c
int error = parse_cidr(argv[1], argc, &in, &prefix_len);
switch (error)
{
    case PARSE_OK:
        break;
    case PARSE_BAD_ADDR:
        fprintf(stderr, "error: not a valid IPv4 address\n");
        exit(EXIT_FAILURE);
    ...
}
```

**Формат сообщений:** `stderr`, строчными, с префиксом `error: ` / `warning: `, без точки в конце, с подсказкой что делать, если она есть (`try: sudo setcap cap_net_raw+ep ./ping`).

**Фатальное отделяется от восстановимого.** Сбой на одной цели из 254 (`sendto` вернул `-1`) — печать и продолжение обхода; сбой создания сокета — выход. Формулировать явно, для каждой ветви.

**Guard clause вместо вложенности.** В фильтрующем цикле — серия ранних `continue`, каждый со своей причиной, а не одно `if` на пять условий:

```c
if (ntohs(icmp->un.echo.id) != id)
    continue;
if (seq < 1 || seq > count)
    continue;
if (src.sin_addr.s_addr != list[seq-1].addr.s_addr)
    continue;
if (list[seq-1].status == HOST_ALIVE)
    continue;
```

Порядок проверок — от дешёвых к дорогим и от общих к частным; каждая проверка стоит **до** чтения, которое без неё станет out-of-bounds.

**Прерываемые вызовы всегда в цикле по `EINTR`,** с присваиванием в **явных** скобках (рецидив ×4 на B-19):

```c
while ((sent = sendto(fd, buf, ECHO_SIZE, 0, (struct sockaddr *)&sending, sizeof(sending))) && errno == EINTR)
    errno = 0;

while (nanosleep(&req, &rem) == -1 && errno == EINTR)
    req = rem;
```

**Каждый выход из функции закрывает ресурсы, которые она открыла.** Чек-лист перед сдачей файла: для каждого `fd = ` и каждого `calloc` — найти все `return`/`continue`/`break` между открытием и закрытием.

## 6. Работа с байтами и сетевыми данными

**Byte order решается вопросом «в каком виде данные СЕЙЧАС и что ждёт потребитель»,** а не привычкой. Арифметика над адресами — в host order (`ntohl` на входе, `htonl` при записи в `sin_addr`). Имя функции обязано совпадать с направлением: `ntohl` при network→host, даже если на LE это байт-в-байт та же операция, что `htonl`.

**Всё, что пришло из сети, — недоверенный вход.** Индекс, взятый из пакета, проверяется по границам **до** обращения к массиву. Длина, взятая из пакета (`ihl * 4`), проверяется с двух сторон: не меньше минимума и не больше остатка буфера.

**Смещения считаются от полей, не от `sizeof`,** когда протокол это допускает: `ip->ihl * 4`, а не `sizeof(struct iphdr)` — заголовок может нести options.

**Комментарии-обоснования там, где код выглядит избыточным.** Одна строка, объясняющая неочевидный контракт ядра, экономит переоткрытие темы:

```c
// ядро возвращает удвоенное значение; меньше запрошенного = упёрлись в rmem_max
```

## 7. Комментарии

- Язык — русский. Термины, имена функций, флаги — английские, без транслитерации.
- Комментарий отвечает на **«почему»**, а не «что». `// увеличиваем i` — мусор; `// не фатально: работаем с дефолтом` — по делу.
- Однострочные метки-разделители внутри длинной функции допустимы и полезны: `// stats`, `// printing`, `// skip other packets`.
- Поля структуры комментируются с указанием **когда** заполняются: `struct timespec t_send; // момент отправки ЭТОЙ цели; для RTT`.
- Закомментированный код — только явно отладочный, блоком `/* ... */`, и удаляется при закрытии задания.

## 8. Чего избегать

- **`\` для переноса** внутри выражения (`rtt = a + \`) — в C перенос свободен, обратный слэш нужен только в макросах и не нужен внутри выражений; пробел после него превращается в ошибку компиляции. Оставлять только там, где он обязателен.
- **Точность вместо ширины в `printf`.** `%.4d` печатает `0064` (минимум цифр), ширину задаёт `%4d`; для строк `%.20s` — это обрезание, а выравнивание колонки — `%-15s`.
- **Утилитарная функция, вызывающая `exit()`** (как `get_int`). Библиотечный код возвращает статус, решение о завершении принимает `main`.
- **Мутация глобального состояния в функции с именем `print_*`.** Печать читает, а не считает; деление аккумулятора — в локальную переменную.
- **`sizeof` в сравнении со знаковым**: `ssize_t n >= sizeof(x)` конвертирует `n` в беззнаковый, `-1` пройдёт проверку. Ошибку syscall ловить как `< 0` до сравнений с размерами.
- **Магические числа** в проверках протокола — только именованные `#define` или `sizeof` конкретной структуры.

## 9. Сборка

```
gcc -Wall -Wextra -g <files> -o <bin> [-lcap-ng -lpcap]
```

`-Wall -Wextra` — не опция, а часть определения «собралось». Перед закрытием задания — прогон с `-fsanitize=address,undefined`.

`#include <cstddef>`, `<cerrno>` и прочие C++-хедеры — автоподстановка VS Code при Tab-переключении, удаляются перед сборкой.

**Собранные бинарники удаляются после прогона,** а не заносятся в `.gitignore`: в папке задания остаются только `*.c`, `*.h` и `task-*.md`. Бинарник пересобирается одной командой, а правило игнорирования под каждое имя копит мусор.
