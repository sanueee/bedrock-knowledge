## Задание

Расширение procinfo: если запустить без аргументов — вывести топ-5 процессов по VmRSS (самые прожорливые по памяти).

**Требования:**
- Без ps/top/внешних утилит
- Перебрать все процессы в `/proc/` через `opendir`/`readdir`
- Сортировка по убыванию VmRSS

**Функции для использования:**
- `opendir` / `readdir` / `closedir` — итерация по `/proc/`
- `strtoul` + проверка `endptr` — фильтр числовых имён (PID)
- `snprintf` — сборка пути `/proc/<pid>/status`
- `qsort` с компаратором — сортировка массива структур

**Где сохранить:** `sections/linux/procinfo-top5/procinfo2.c`

---

## Моё решение

Реализовал `ProcessTop()`. Алгоритм:
1. `opendir("/proc/")` — открыть директорию
2. `readdir()` в цикле — перебрать все записи
3. Фильтрация числовых имён через `strtoul` + проверка `endptr`
4. Для каждого PID — `fopen("/proc/<pid>/status")` + `fgets` в цикле
5. Накопление в фиксированный массив `ProcInfo proc_arr[1024]`
6. `qsort` с компаратором по `vmrss_kb` по убыванию
7. Вывод первых `min(5, count)` записей

Структура данных:
```c
typedef struct {
    char     pid[21];
    uint64_t vmrss_kb;
    char     name[64];
} ProcInfo;
```

## Ключевые функции

| Функция | Зачем |
|---------|-------|
| `opendir` / `readdir` / `closedir` | итерация по содержимому `/proc/` |
| `strtoul` + проверка `endptr` | фильтр: имя папки — число => это PID |
| `snprintf` | сборка пути `/proc/<pid>/status` в один вызов |
| `fopen` / `fgets` / `fclose` | чтение status-файла построчно |
| `qsort` | сортировка массива структур |

## Что узнал

- `qsort` ожидает `const void *` в компараторе — внутри нужно явное приведение типа
- `opendir` возвращает `DIR*`, `readdir` — `struct dirent*` — читать сигнатуру в man page перед использованием
- `proc_arr` и `curr_proc` должны быть объявлены на уровне цикла по процессам, не внутри цикла по строкам файла
- Инициализировать структуру `curr_proc = {0}` — защита от мусора на стеке

## Ошибки и трудности

**`proc_arr` и `curr_proc` внутри цикла по строкам** — добавлял элемент в массив на каждой строке, а не на каждый процесс. Нужно было поднять объявления выше.

**Неверная сигнатура компаратора** — написал `int cmp_proc(ProcInfo *a, ProcInfo *b)`. `qsort` ожидает `const void *` — компилятор ругается.

**Многострочный `fprintf` с `\`** — отступы после `\` входят в строку вывода, колонки съехали.

## Что бы сделал иначе

- Сразу инициализировать `curr_proc = {0}` — защита от мусора на стеке
- Использовать `i < 5 && i < count` вместо проверки `vmrss_kb == 0` — надёжнее
- Не трогать `#include` не глядя
